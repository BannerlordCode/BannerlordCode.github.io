# 版本差异（1.4.6 / 1.4.5 / 1.3.15）

> 本文所有数字都来自对三份源码树的直接扫描（`bannerlord-1.4.6/`、`bannerlord-1.4.5/Bannerlord.Source/`、`bannerlord-1.3.15/`），**没有一条是从记忆或旧文档抄来的**。凡是扫描无法证明的，本文写「未核实」。

## 结论先说

**1.4.6 相对 1.4.5 的真实变化是：源码布局变了 + 多了几个工具程序集 + 少量生成噪声，玩法 API 基本是增量的，没有任何玩法类型被删除。**

对 mod 作者最重要的一句话：**如果你已经在 1.4.5 上跑通了，升级到 1.4.6 基本不需要改代码；需要重新确认的是那些你依赖「程序集归属」的反射/patching 代码。**

## 三个源码树的形态

| 版本 | 源码根 | 布局 | 扫描到的 `.cs` 文件 |
| --- | --- | --- | --- |
| 1.4.6 | `bannerlord-1.4.6/` | 90 个顶层目录，目录名 ≈ 程序集名，玩法模块平铺 | 11385 |
| 1.4.5 | `bannerlord-1.4.5/Bannerlord.Source/` | `bin/`（核心程序集）+ `Modules.SandBox/`、`Modules.Multiplayer/` 等玩法模块 | 8572 |
| 1.3.15 | `bannerlord-1.3.15/` | 按 `TaleWorlds.*` 平铺，与 1.4.6 同构 | 5196 |

这就是 1.4.6 最大的「变化」：**同一棵树的两种排版**。1.3.15 与 1.4.6 的布局接近，所以从 1.3.15 迁到 1.4.6 的路径最短。

**统计口径**（本文所有模块级数字都按此计算，便于复现）：只统计 `TaleWorlds.*` / `SandBox` / `StoryMode` 目录，排除每个模块的 `Properties/`（那里只有编译器生成的 `AssemblyInfo.cs`），类型以「文件去重后的文件名」为单位。

| 口径 | 1.4.6 | 1.4.5 | 1.3.15 |
| --- | --- | --- | --- |
| 玩法模块目录数 | 71 | 66 | 54 |
| 去重类型文件数（排除 `Properties/`） | 6478 | 6278 | 5126 |
| 去重类型文件数（含 `Properties/AssemblyInfo.cs`） | 6549 | — | — |

## 1.4.6 相对 1.4.5 的模块级差异

### 新增目录（6 个）

| 新增目录 | 文件数 | 判断 |
| --- | --- | --- |
| `TaleWorlds.MountAndBlade.SteamWorkshop` | 8 | Steam 创意工坊工具（`Program` / `ToolTask` / `CreateItemTask` / `GetItemTask` / `UpdateItemTask` / `ItemVisibility` / `ToolDebugManager`）。真实新增，但与 mod API 无关 |
| `TaleWorlds.MountAndBlade.Launcher` | 2 | 启动器入口（`Program`）。真实新增，与 mod API 无关 |
| `TaleWorlds.MountAndBlade.GauntletUI.CodeGenerator` | 2 | 预制体代码生成器（`Program`） |
| `TaleWorlds.MountAndBlade.SaveSystem.CodeGenerator` | 2 | 存档收集代码生成器（`Program`） |
| `TaleWorlds.MountAndBlade.Multiplayer.GauntletUI.AutoGenerate` | 84 | 多人界面预制体生成物；1.4.5 中同名目录写作 `AutoGenerated` —— **是改名，不是新增** |
| `TaleWorlds.MountAndBlade.Multiplayer.2` | 121 | 与 `TaleWorlds.MountAndBlade.Multiplayer`（同样 121 个文件）同名同量级，判断为导出工具产生的重复目录，**不是新功能** |

另有三个第三方/工具目录在 1.4.6 顶层出现、在 1.4.5 的对应位置没有：`StbSharp`（13 个文件）、`ManagedStarter`（1 个文件）、`netstandard`（1 个文件）。它们属于噪声排除范围。

### 删除目录

玩法模块层面**零删除**。1.4.5 有、1.4.6 没有的只有 `TaleWorlds.MountAndBlade.Multiplayer.GauntletUI.AutoGenerated`（对应上面改名后的 `AutoGenerate`）以及 1.4.5 布局目录 `bin`、`Modules.*`（布局差异，不是模块消失）。

### 类型层面的差异全部是「增量」

按模块逐个比对（1.4.6 有、1.4.5 无的类型名）：

| 差异来源 | 出现在哪些模块 | 性质 |
| --- | --- | --- |
| `EmbeddedAttribute`、`IsReadOnlyAttribute` | 几乎所有托管模块（Core / Library / Engine / GauntletUI / CampaignSystem.ViewModelCollection / MountAndBlade.ViewModelCollection 等各 +2） | 编译器生成的 attribute 被导出工具写成文件，**不是新 API** |
| `*.2` 同名重复文件 | `IMbEvent.2`–`.8`、`MbEvent.2`–`.8`、`EnumHelper.2`、`ReferenceAction.2/.3`、`ReferenceIMBEvent.2/.3`、`ReferenceMBEvent.2/.3`、`WeakNativeObjectReference.2`、`MPPerkCondition.2`、`MissionObjectiveTarget.2`、`MessageContractCreator.2`、`MessageContractHandler.2`、`AssemblyInfo` | 同名类型被拆成多个文件的导出噪声，**不是新类型** |
| `TaleWorlds.CampaignSystem` +22 | 即上面两组噪声的合计 | 玩法 API 无新增 |

**没有任何模块出现类型删除。**

## 枢纽类型的成员统计（含统计口径警告）

用 `tools/class-version-diff.mjs` 同款正则抽取每个类型的可见成员（public/protected/internal，去 private），得到的数量：

| 类型 | 1.4.6 | 1.4.5 | 1.3.15 | 1.4.6 → 1.3.15 |
| --- | --- | --- | --- | --- |
| `Campaign` | 222 | 178 | 222 | +0 |
| `Hero` | 235 | 183 | 233 | +2 |
| `Clan` | 156 | 127 | 156 | +0 |
| `MobileParty` | 308 | 249 | 299 | +9 |
| `Mission` | 387 | 352 | 386 | +1 |
| `Agent` | 515 | 467 | 508 | +7 |
| `Game` | 50 | 43 | 50 | +0 |
| `MBSubModuleBase` | 30 | 30 | 30 | +0 |
| `SaveManager` | 6 | 6 | 6 | +0 |
| `ViewModel` | 16 | 16 | 16 | +0 |
| `ScreenManager` | 66 | 64 | 67 | −1 |
| `ScreenLayer` | 39 | 36 | 39 | +0 |
| `TextObject` | 30 | 29 | 28 | +2 |
| `CampaignGameStarter` | 15 | 13 | 15 | +0 |

> **统计口径警告（重要）**：这些是**下界**，不是精确 API 数量。1.4.5 的反编译把 partial 类的成员散在多个文件里，正则只数到主文件，因此 1.4.5 一列系统性偏低（例如 `Campaign` 178 vs 222）。**不要把「1.4.6 比 1.4.5 多 44 个成员」当成新增功能读** —— 同一个数字在 1.3.15 上也是 222，说明 1.4.5 的低值是抽取问题而不是版本差异。判断版本差异请以逐类签名为准（`node tools/class-version-diff.mjs <Type>`，注意该工具目前硬编码到 1.4.5，1.4.6 需要另行核对）。
>
> 同名文件会互相覆盖索引：`AutoGeneratedSaveManager` 在 Core / CampaignSystem / SandBox / StoryMode 各有一份，只按文件名索引会取到其中一份。跨版本比较时**必须按命名空间定位类型**。

## 1.4.6 独有的「空壳」模块

- `TaleWorlds.NavigationSystem`：整个目录只有 `Properties/AssemblyInfo.cs`，**没有任何游戏类型**。1.4.5 的同路径目录也是 1 个文件。它不是「新增的导航系统」，不要按导航 API 去那里找类型。
- `TaleWorlds.InputSystem` 有 15 个类型（`IInputManager`、`Input`、`InputContext`、`InputKey`、`InputState`、`GameKey`、`HotKey` 等），**但没有名为 `InputManager` 的类**。写 `InputManager.X` 的旧示例在 1.4.6 上编译不过。

## mod 迁移清单

从 1.3.15 或 1.4.5 迁到 1.4.6，按这个顺序自查：

1. **检查反射与 patching 的程序集名**。用上表的实际命名空间核对，尤其是 `MBObjectManager`、`ScreenManager`、`ViewModel`、`MBSubModuleBase`。
2. **不要按「多出来的成员」改代码**。1.4.6 相对 1.4.5 的成员增量大多是反编译产物分布差异。
3. **重新生成文档索引**：若你的项目用 `tools/class-version-diff.mjs`，它当前硬编码 1.3.0/1.3.15/1.4.5 三个 root，需要新增 `1.4.6: 'bannerlord-1.4.6'` 才能产出 1.4.6 列。
4. **多人 / 平台相关代码单独回归**：`TaleWorlds.MountAndBlade.Multiplayer*` 与 `TaleWorlds.PlatformService*` 在本文属噪声排除范围，本文不做结论。
5. **第三方库不要 import**：1.4.6 顶层多了 `StbSharp`、`ManagedStarter`、`netstandard` 目录，那是导出产物，引用它们不会在游戏里工作。

## 未核实 / 本次无法证明的部分

- **玩法行为差异**：源码树只能证明类型与成员的有无，不能证明运行时行为差异。1.4.6 是否修了某个战斗或战役逻辑 bug，本次**未核实**。
- **游戏内部版本号与商店版本对应关系**：`bannerlord-1.4.6` 的名字是否等于玩家看到的客户端版本号，**未核实**。
- **1.3.15 逐模块明细差异**：上面 1.3.15 的模块/类型计数是按同一口径扫出来的，但没有逐模块做 1.4.6↔1.3.15 的差异归类，**逐模块差异未核实**。
- **签名级 diff**：`tools/class-version-diff.mjs` 尚未支持 1.4.6 root，因此逐类签名差异需要先扩展该工具再跑。

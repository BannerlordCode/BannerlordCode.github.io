# TradeAgreement

**命名空间:** `TaleWorlds.CampaignSystem.CampaignBehaviors`  
**模块:** `TaleWorlds.CampaignSystem`  
**类型:** `public struct TradeAgreement`（嵌套于 `TradeAgreementsCampaignBehavior`）  
**源文件:** `bin/TaleWorlds.CampaignSystem/TaleWorlds.CampaignSystem.CampaignBehaviors/TradeAgreementsCampaignBehavior.cs`

## 概述

`TradeAgreement` 是**两个王国（`Kingdom`）之间一份生效中的双边贸易/通行协议**的轻量记录：它保存缔约双方（`Kingdom1` / `Kingdom2`）、协议的到期时间（`EndTime`），以及协议有效期内因商队互访而累计的金币收益（`Kingdom1GoldGained` / `Kingdom2GoldGained` 及其历史总量）。它本身不实现任何外交逻辑，只是 `TradeAgreementsCampaignBehavior` 维护的 `_tradeAgreements` 列表中的一个条目；协议的缔结来自外交决策（`TradeAgreementDecision` 经王国投票），有效期与每次商队访问的收益来自 `TradeAgreementModel`，而到期、宣战与王国灭亡都由该 Behavior 负责清理。

## 心智模型

把 `TradeAgreement` 想成「一份**正在生效**的王国间贸易契约的存根」，而不是外交系统本身。它**以值类型（`struct`）的形式存放在 `TradeAgreementsCampaignBehavior._tradeAgreements` 列表里**，所以你读到的 `TradeAgreement` 是列表条目的副本——直接改副本上的字段不会写回列表，必须经由 Behavior 的方法把返回值重新赋回列表。`MakeTradeAgreement` 在外交决策通过（或玩家以雇佣兵身份接受提议）时被调用，用 `CampaignTime.Now + duration`（默认 1 年，见 `TradeAgreementModel.GetTradeAgreementDurationInYears`）算出 `EndTime` 并写入列表、广播 `OnTradeAgreementSigned`。协议的**生命周期是惰性的**：`HasTradeAgreement` 在被查询时才检查 `EndTime.IsPast`，过期就自动 `EndTradeAgreement`；两王国间**宣战**会立即解除协议并对领袖施加 -50 关系惩罚（`ApplyBrokenTradeAgreementPenalty`）；任一王国**灭亡**则移除其全部协议（`EndTradeAgreementsOfKingdom`）。收益在商队互访时累加（`SettlementEntered` 调 `AddGainedGoldToKingdom`，默认每次 +500 金），在王国向家族分金时扣减（`OnGoldSharedInKingdom`）。读取请走 `ITradeAgreementsCampaignBehavior.HasTradeAgreement` / `GetTradeAgreementEndDate`；**不要**直接 `new` 一个 `TradeAgreement` 或改列表，否则会绕过事件广播、战争惩罚与存档一致性。

## 何时使用 / 何时不要使用

- **用**：在外交/经济 UI 或自定义 Behavior 中，通过 `ITradeAgreementsCampaignBehavior.HasTradeAgreement(kingdomA, kingdomB, out var agreement)` 判断两王国是否处于贸易协议中，并读取 `EndTime`、双方收益统计；用 `GetTradeAgreementEndDate` 取到期日。
- **用**：要缔结或解除协议时，调用 `MakeTradeAgreement` / `EndTradeAgreement`（经 `Campaign.Current.GetCampaignBehavior<ITradeAgreementsCampaignBehavior>()` 取得）；缔结前先用 `TradeAgreementModel.CanMakeTradeAgreement` 校验条件（非交战、非灭国、未超上限 2、相邻、双方有城镇与港口等）。
- **不要用**：不要 `new TradeAgreement(...)` 后自行塞进某集合——它不会被序列化、不会触发 `OnTradeAgreementSigned`、也不会被 `HasTradeAgreement` 的过期检查看到。
- **不要用**：不要直接修改读到的 `TradeAgreement` 副本上的 `Kingdom1GoldGained` 等字段（它是 struct 副本，改动不持久），也不要直接改 `EndTime` 去“续期”——续期/解除必须走 Behavior。
- **不要用**：不要抛开 `HasTradeAgreement` 只用 `EndTime` 判断“是否有效”，因为协议可能在你读取之后因宣战或过期被悄悄移除；每次需要有效协议时都重新调 `HasTradeAgreement`。

## 依赖图

- 上游 / 持有者：
  - [TradeAgreementsCampaignBehavior](../TradeAgreementsCampaignBehavior) 创建、持有并清理 `_tradeAgreements` 列表，是 `TradeAgreement` 唯一权威来源；它实现 `ITradeAgreementsCampaignBehavior`。
  - [Kingdom](../Kingdom) 是 `Kingdom1` / `Kingdom2` 缔约方；协议随王国灭亡（`OnKingdomDestroyed`）或宣战（`WarDeclared`）被移除。
  - [Campaign](../Campaign) 提供 `GetCampaignBehavior<ITradeAgreementsCampaignBehavior>()` 与 `Models.TradeAgreementModel`，以及 `CampaignTime.Now` 等时间基准。
- 下游 / 协作：
  - [TradeAgreementModel](../TradeAgreementModel)（`DefaultTradeAgreementModel`）计算有效期 `GetTradeAgreementDurationInYears`、每次商队访问收益 `GetProfitPerCaravanVisit`（默认 500）与缔结可行性 `CanMakeTradeAgreement`（上限 2）。
  - [TradeAgreementDecision](../TradeAgreementDecision) 是王国投票决定是否缔结协议的外交决策；通过后由 Behavior 调 `MakeTradeAgreement`。
  - [CampaignEvents](../CampaignEvents) 上的 `OnTradeAgreementSigned` / `OnTradeAgreementEnded` 是其它系统观察协议变更的观察点。
- 存档：
  - [SaveableFieldAttribute](../../save-system/SaveableFieldAttribute) 标注的 7 个字段（`Kingdom1`/`Kingdom2`/`EndTime`/四个金币字段）经 `TradeAgreementsCampaignBehaviorTypeDefiner`（id 312260）随战役存档序列化；`Kingdom` 引用也会被 `AutoGeneratedInstanceCollectObjects` 收集。

## 风险

- **值类型陷阱**：`TradeAgreement` 是 `struct`，`HasTradeAgreement` / 列表索引返回的是副本。直接写 `agreement.Kingdom1GoldGained += x` 不会持久化；金币变更必须经 `AddGainedGoldToKingdom` / `OnGoldSharedInKingdom`，并由 Behavior 把返回值重新赋回 `_tradeAgreements[index]`。
- **绕过外交与事件**：自己 `new` 并塞进集合或手动改列表，既不广播 `OnTradeAgreementSigned`，也不参与 `HasTradeAgreement` 的过期判定，还会让 UI、外交 AI（`CanMakeTradeAgreement` 的“已存在协议/上限”检查）看不见它，导致重复缔结或坏逻辑。
- **引用已灭亡的 Kingdom**：`Kingdom1` / `Kingdom2` 是引用；若某王国已灭亡但其协议未被 `EndTradeAgreementsOfKingdom` 清理（例如你绕过 Behavior 直接写入），读取或 `EndTime` 比较可能在已销毁对象上产生空引用/悬挂引用。
- **过期未清理的误解**：`HasTradeAgreement` 在查询时才解除过期协议，且 `EndTime.IsPast` 用 `CampaignTime` 比较。若你只缓存 `EndTime` 而不重新查询，可能把“实际上已被解除”的协议当成有效。
- **改 EndTime 续期**：直接改副本的 `EndTime` 无效（见值类型陷阱）；即便改到列表里的条目，也跳过了应有的外交/通知流程，并可能与宣战惩罚逻辑冲突。
- **存档一致性**：四个金币字段是可变 `SaveableField`，若你在 Behavior 之外直接改列表里的条目再读档，序列化/反序列化以 Behavior 的 `_tradeAgreements` 为准，外部改动会被忽略或造成不一致。

## 成员说明

### 缔约方与生命周期（只读）

| 成员 | 类型 | 用途 | 副作用 | 何时调用 |
| --- | --- | --- | --- | --- |
| `Kingdom1` | `Kingdom`（只读，`[SaveableField(1)]`） | 缔约王国之一。顺序无语义（查询时双向匹配）。 | 无 | 读取缔约方、判断哪一方是“己方” |
| `Kingdom2` | `Kingdom`（只读，`[SaveableField(2)]`） | 缔约王国之二。 | 无 | 同上 |
| `EndTime` | `CampaignTime`（只读，`[SaveableField(3)]`） | 协议到期时刻（`Now + duration`）。`IsPast` 为真表示过期。 | 无（解除由 Behavior 在 `HasTradeAgreement` 中执行） | 读取到期日；判断前总是重新 `HasTradeAgreement` |
| 构造函数 `TradeAgreement(Kingdom, Kingdom, CampaignTime)` | 方法 | 用两王国与到期时间建一个全新协议，四个金币字段清零；`this = default` 后再赋值。 | 仅初始化本副本，不写入列表 | 仅由 `MakeTradeAgreement` 在 Behavior 内调用，外部不要直接 new |

### 金币收益统计（可变，但必须经 Behavior 写回）

| 成员 | 类型 | 用途 | 副作用 | 何时调用 |
| --- | --- | --- | --- | --- |
| `Kingdom1GoldGained` | `int`（`[SaveableField(4)]`） | 自上次向家族分金以来，`Kingdom1` 通过商队互访累计获得的金币（未分配部分）。 | 可变；直接改副本无效 | 读收益展示；变更走 `AddGainedGoldToKingdom` / `OnGoldSharedInKingdom` |
| `Kingdom2GoldGained` | `int`（`[SaveableField(5)]`） | 同上，对应 `Kingdom2`。 | 同上 | 同上 |
| `Kingdom1GoldGainedTotal` | `int`（`[SaveableField(6)]`） | `Kingdom1` 自协议生效以来的历史累计收益（含已分配）。 | 随 `AddGainedGoldToKingdom` 增长，不被分金扣减 | 读历史统计 |
| `Kingdom2GoldGainedTotal` | `int`（`[SaveableField(7)]`） | 同上，对应 `Kingdom2`。 | 同上 | 同上 |
| `AddGainedGoldToKingdom(Kingdom, int)` | 方法（返回 `this`） | 把 `gold` 加到匹配的那一方：当前收益 +gold，历史总量也 +gold；不匹配方则加到另一方。 | 改字段后**返回新副本**，Behavior 须 `_tradeAgreements[index] = ...` 写回 | 由 `SettlementEntered` 在商队进入对方城镇时调用（收益来自 `TradeAgreementModel.GetProfitPerCaravanVisit`） |
| `OnGoldSharedInKingdom(Kingdom, int)` | 方法（返回 `this`） | 王国向家族分金时，从匹配方的当前收益扣减 `share`（不影响历史总量）。 | 改字段后返回新副本，须写回列表 | 由 `OnTradeGoldDistributedInKingdom` 在分金时调用 |

## 示例

### 示例 1：查询两王国间是否处于生效中的贸易协议

```csharp
using TaleWorlds.CampaignSystem;
using TaleWorlds.CampaignSystem.CampaignBehaviors;

// 取实现 ITradeAgreementsCampaignBehavior 的外交 Behavior（TradeAgreementsCampaignBehavior）
ITradeAgreementsCampaignBehavior tradeBehavior =
    Campaign.Current.GetCampaignBehavior<ITradeAgreementsCampaignBehavior>();

// out 参数返回协议副本；若已过期，HasTradeAgreement 内部会先解除再返回 false
if (tradeBehavior.HasTradeAgreement(kingdomA, kingdomB, out var agreement))
{
    Kingdom partyOfA = agreement.Kingdom1 == kingdomA ? agreement.Kingdom1 : agreement.Kingdom2;
    CampaignTime expiresOn = agreement.EndTime;             // 到期时刻
    bool stillValid = !expiresOn.IsPast;                    // 此时应为 true
    int profitOfA = agreement.Kingdom1GoldGained;           // A 方自上次分金以来累计收益
    int profitTotalA = agreement.Kingdom1GoldGainedTotal;   // A 方历史累计收益
}
```

`HasTradeAgreement` 是唯一可信的“是否有效”入口；不要在别处缓存 `EndTime` 自行判断是否过期。

### 示例 2：在满足条件时用模型与 Behavior 缔结一份贸易协议

```csharp
using TaleWorlds.CampaignSystem;
using TaleWorlds.CampaignSystem.CampaignBehaviors;

var model = Campaign.Current.Models.TradeAgreementModel;

// CanMakeTradeAgreement 检查：非交战、非灭国、未超上限(默认2)、相邻、双方有城镇与港口等
if (model.CanMakeTradeAgreement(kingdomA, kingdomB, checkOtherSideSupport: false, out var reason))
{
    CampaignTime duration = model.GetTradeAgreementDurationInYears(kingdomA, kingdomB); // 默认 1 年
    Campaign.Current
        .GetCampaignBehavior<ITradeAgreementsCampaignBehavior>()
        .MakeTradeAgreement(kingdomA, kingdomB, duration); // 写入 _tradeAgreements 并广播 OnTradeAgreementSigned
}
```

缔结通常来自王国投票（`TradeAgreementDecision`）；玩家以雇佣兵身份被提议时则由 `OnTradeAgreementOfferedToPlayer` → `AcceptOffer` 直接 `MakeTradeAgreement`。不要让 mod 绕过这套流程直接构造 `TradeAgreement`。

# Module Map

> Three things per assembly: **what it is**, **where the docs put it**, and **whether you should care**.

## Why this page exists

`bannerlord-1.5.3/` has **68 `TaleWorlds.*` directories** at its root, but the documentation has only
**19 buckets**. The relationship is not one-to-one: a single assembly is split across several buckets
by responsibility, and a bucket can gather namespaces from several assemblies. Without this table you
will hunt for the same class in two places and find it in neither.

The mapping is not a judgement call. The namespace rules in `tools/_dir-map-canonical.json` are applied
to the real 1.5.3 namespace set with **longest-prefix-wins** matching, producing 19 buckets. Of the
**534** distinct namespace declarations across `TaleWorlds.*` / `SandBox*` / `StoryMode*`, **442** carry
non-noise types and land in those buckets.

> **A bucket is not a page.** A bucket name in the tables below is a slug, not a link: the bucket index
> pages are **not written** in this tree. Eight of the 19 buckets have at least one hand-written type
> page (all in Chinese, under `zh/api/`); the other 11 have none. Per-bucket counts are on the
> [version home](../).

The **Pages** column is `written / total types` for the primary bucket: the counts come from
`tools/_v153_inventory.json` (field `types[].dir`, a read-only report generated by
`tools/_v153_inventory.mjs`) plus a file count of `content/v1.5.3/zh/api/`. A `—` means this assembly
does not own the pages counted in that row's bucket — the bucket total belongs to another assembly.
`TaleWorlds.MountAndBlade` splits three ways: `core` 2 types, `mission` 5 types, and the remaining
2 065 in `mission-ext`; the 3 written pages among them are `MBSubModuleBase`, `Mission` and
`MissionState`.

### Assemblies that are not mod-facing

These exist in the source tree but are build-time generators, third-party libraries or launcher
components. **They are visible in the 1.5.3 source, but the running game does not let mods depend on
them.** They are listed so you are not confused when you meet them while reading source.

| Assembly | What it is |
|---|---|
| `TaleWorlds.GauntletUI.CodeGenerator` | Build-time prefab code generator |
| `TaleWorlds.MountAndBlade.GauntletUI.CodeGenerator` / `.AutoGenerated.0/.1` | Same, for battle UI |
| `TaleWorlds.MountAndBlade.SaveSystem.CodeGenerator` | Save-field code generator |
| `TaleWorlds.MountAndBlade.Launcher` / `.Launcher.Library` / `.Launcher.Steam` | Launcher |
| `TaleWorlds.MountAndBlade.SteamWorkshop` | Workshop CLI tool |
| `TaleWorlds.Starter.Library` | Mod development starter template |
| `TaleWorlds.MountAndBlade.DedicatedCustomServer.ClientHelper` | Dedicated server client helper |
| `GalaxyCSharp` | Scripting bridge |
| `Newtonsoft.Json` / `jose-jwt` / `Steamworks.NET` / `StbSharp` / `System.Management` / `System.Numerics.Vectors` | Third-party dependencies (plus reference assemblies `mscorlib` / `netstandard`) |
| `ManagedStarter` | Managed bootstrap entry point |

> **Source tree ≠ runtime reference.** `bannerlord-1.5.3/` also bundles the launcher, the code
> generators, third-party libraries and reference assemblies (`mscorlib` alone holds 2 695 files, plus
> `netstandard`) — 11 487 `.cs` in total. But when you compile a mod you reference the DLLs in the game
> install, not this source tree. So a third-party namespace that shows up under `core-extra` in the
> inventory is **not** automatically part of the moddable API.

> **Two assemblies named in older versions of this table do not exist in the 1.5.3 source**:
> `TaleWorlds.Engine.InputSystem` and `TaleWorlds.ObjectManager`. Engine input lives in
> `TaleWorlds.InputSystem`; `MBObjectManager` lives in `TaleWorlds.ObjectSystem`. See
> [Migrating from 1.4.5](../migration-from-1.4.5) for the full evidence on the `ObjectManager` → `ObjectSystem`
> rename, which happened long before 1.4.5.

**Two traps worth memorizing**

1. `TaleWorlds.ObjectSystem` lands in `campaign-ext`. There is **no** `objectsystem` bucket.
2. `TaleWorlds.ScreenSystem` is merged into `gui`. There is **no** `screensystem` bucket.

**One trap about the Pages column**: 11 of the 19 buckets have zero pages. Reading a row that says
`mission-ext · 0 / 2 065` means the types are real and the documentation is absent — not that the
bucket does not exist.

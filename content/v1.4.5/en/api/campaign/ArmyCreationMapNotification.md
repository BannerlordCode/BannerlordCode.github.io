# ArmyCreationMapNotification

**Namespace:** `TaleWorlds.CampaignSystem.MapNotificationTypes`
**Module:** `TaleWorlds.CampaignSystem`
**Type:** `public class ArmyCreationMapNotification : InformationData`
**Base:** `InformationData`
**File:** `bin/TaleWorlds.CampaignSystem/TaleWorlds.CampaignSystem.MapNotificationTypes/ArmyCreationMapNotification.cs`

## Overview

`ArmyCreationMapNotification` is the data carrier behind the "army created" entry in the map corner notification bar. It draws nothing itself: deriving from [InformationData](../../core-extra/InformationData), it packs one piece of text plus one [Army](../Army) reference and leaves the rest to the UI layer. `MapNotificationVM` looks the type up in a table, finds `ArmyCreationNotificationItemVM`, constructs it with `Activator.CreateInstance(vmType, data)`, and that item subscribes to `OnPartyJoinedArmyEvent` / `ArmyDispersed` / `OnClanChangedKingdomEvent` so it removes itself the moment the player actually joins, the army disperses, or the player's clan changes kingdom.

The only state is `[SaveableProperty(1)] public Army CreatedArmy { get; private set; }`. The `DescriptionText` the caller supplies is conventionally borrowed from [ArmyCreationLogEntry](../ArmyCreationLogEntry).GetEncyclopediaText() — **the same text object feeds both the log and the notice**.

## Mental Model

Think of it as **a pure DTO plus one reflection contract**. Three stages happen in order, and a break in any of them means the notice never reaches the screen:

1. **Write.** `Campaign.Current.CampaignInformationManager.NewMapNoticeAdded(data)` (`CampaignInformationManager.cs:100`) → `AddInformationData` → `MBInformationManager.AddNotice`. This is the only sanctioned entry point.
2. **Lookup.** `MapNotificationVM.GetNotificationFromData(data)` uses `data.GetType()` for an exact `_itemConstructors` dictionary hit. The `ArmyCreationMapNotification` → `ArmyCreationNotificationItemVM` mapping is **hard-written in the `MapNotificationVM` constructor** (`Bannerlord.Source/bin/TaleWorlds.CampaignSystem.ViewModelCollection/TaleWorlds.CampaignSystem.ViewModelCollection.Map/MapNotificationVM.cs:117`), not inferred from the base class. **A type missing from that table is silently discarded** — `GetNotificationFromData` returns null and `AddMapNotification` returns without a word.
3. **Self-removal.** The VM's constructor subscribes to three campaign events and calls `ExecuteRemove()` on any match.

The mental anchor that matters most is the difference between **"has no expiry" and "is registered"**. This type **does not override `IsValid()`**, so the base returns true and the notice never ages out; it disappears purely because the VM's three event listeners fire. That is the opposite of [AllianceOfferMapNotification](../AllianceOfferMapNotification), which carries a `TriggerTime` and relies on `IsValid()` for timed eviction. Confusing the two paths is how you end up writing mod logic that leaves a stale notice behind after an army disbands.

The second anchor is that **`CreatedArmy` is a live reference**. `[SaveableProperty(1)]` stores the `Army` object itself, not a StringId. While the notice lives, a dispersed army still has a non-null `CreatedArmy` whose `LeaderParty` may already be null — which is exactly why the VM writes `GoToMapPosition(Army?.LeaderParty?.Position ?? MobileParty.MainParty.Position)`.

## Examples

The only official shape, copied from [DefaultLogsCampaignBehavior](../DefaultLogsCampaignBehavior).OnArmyCreated:

```csharp
ArmyCreationLogEntry armyCreationLogEntry = new ArmyCreationLogEntry(army);
LogEntry.AddLogEntry(armyCreationLogEntry);
if (army.LeaderParty.MapFaction == MobileParty.MainParty.MapFaction && army.LeaderParty != MobileParty.MainParty)
{
    Campaign.Current.CampaignInformationManager.NewMapNoticeAdded(
        new ArmyCreationMapNotification(army, armyCreationLogEntry.GetEncyclopediaText()));
}
```

Raise the same notice with your own wording — the usual mod use case:

```csharp
Army myArmy = MobileParty.MainParty.Army;
if (myArmy != null)
{
    TextObject custom = new TextObject("{=mykey}Your warband has gathered under {RULER.NAME}.");
    custom.SetTextVariable("RULER", Hero.MainHero.CharacterObject);
    Campaign.Current.CampaignInformationManager.NewMapNoticeAdded(new ArmyCreationMapNotification(myArmy, custom));
}
```

Ask whether an unhandled army-created notice is still pending — `InformationDataExists<T>` is the sanctioned existence query:

```csharp
bool pending = Campaign.Current.CampaignInformationManager.InformationDataExists<ArmyCreationMapNotification>(null);
Debug.Print("pending army-created notices = " + pending, 0);
```

## Risks and crash boundaries

- **The VM must be registered or the notice vanishes silently.** `MapNotificationVM` looks the type up exactly; an unregistered type returns null from `GetNotificationFromData` and is dropped without an error. A custom `InformationData` subclass in a mod **must** also register a VM in `_itemConstructors`, or it is invisible for reasons no log will tell you.
- **`CreatedArmy` may already be stale.** It is a live reference; after dispersion it still points at that object. The VM guards with `Army?.LeaderParty?.Position ?? ...`; do not assume `LeaderParty` is non-null in your own reads.
- **The constructor dereferences.** A null `army` yields a null `CreatedArmy`; there is no validation and no `Debug.FailedAssert`.
- **`IsValid()` is not overridden, so the notice never expires.** The base returns true. Real cleanup is done by the VM's three `CampaignEvents` listeners; in a headless environment with no VM the notice stays in `CampaignInformationManager._mapNotices`, and `OnGameLoaded`'s `RemoveAll(t => t == null || !t.IsValid())` will not clear it either.
- **`TitleText` allocates per access.** Do not read it in a hot loop.
- **It is serialized.** `[SaveableProperty(1)]` plus `AutoGeneratedInstanceCollectObjects` collects `CreatedArmy`; `SaveableCampaignTypeDefiner.cs` and `AutoGeneratedSaveManager` own the id mapping. Adding fields to this or the base class means updating the SaveManager.
- **No text override hook.** Changing the title means deriving and reimplementing `TitleText`, which in turn means registering another VM.
- **Missing audio fails quietly.** If the event name is absent from the resource bundle you simply get no sound.

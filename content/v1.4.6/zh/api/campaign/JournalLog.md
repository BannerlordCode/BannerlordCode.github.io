> 节 schema：本页采用 7 节（按出现顺序）：概述 / 心智模型 / 怎么用 / 关键成员 / 真实示例 / 参见 / 导航

## 概述

`JournalLog` 是战役日志（Journal）体系里的**记录行**，不是容器。一条 `JournalLog` 只回答一个问题：「在某个战役时刻，关于某件事，玩家看到了哪一句话？」它把时间（`LogTime`）、正文（`LogText`）、可选的任务名（`TaskName`）、进度与进度总量（`CurrentProgress` / `Range`）、以及记录类型（`Type`）绑成一个整体，一次性写完，此后几乎不可变。

它在层级上处于最底下的一层。任务与问题（`QuestBase` / `IssueBase`）各自持有一串 `JournalLog`；`JournalLogsCampaignBehavior` 把这些串合并、按时间排好；再交给 `JournalLogEntry`（`LogEntry` 的子类，进 `LogEntryHistory`）当作 UI 上「一张卡片」的内容。所以同一个日志界面里同时存在两种东西，必须分清：

- **条目容器**：`JournalLogEntry` —— 任务日志 UI 真正读的对象。它有自己的标题、相关英雄（`RelatedHero` / `Antagonist`）、结局状态，并对外暴露 `GetEntries()`（`JournalLogEntry.cs:117`）。
- **记录行**：`JournalLog` —— 本页。只被容器聚合，自己不参与 UI 布局，也不直接进 `LogEntryHistory`。

分清这一点的实际收益是：在 `JournalLogEntry` 上加字段是给「卡片」加东西，在 `JournalLog` 上加字段是给「卡片里的一行」加东西；而**追加一行**和**追加一张卡片**走的是两条完全不同的 API（见下文「怎么用」）。

## 心智模型

**一、它是数据行，不是服务。** 除开存档管线自动生成的几个方法（`JournalLog.cs:14`、`JournalLog.cs:20`、`JournalLog.cs:28`），这个类只有 4 个手写成员：构造函数（`JournalLog.cs:70`）、`UpdateCurrentProgress`（`JournalLog.cs:81`）、`HasBeenCompleted`（`JournalLog.cs:87`）、`GetTimeText`（`JournalLog.cs:93`），加上 5 个公开只读字段。它不订阅事件、不持有 `Campaign` 引用、不做 IO、不解析文本。

**二、构造即定稿，唯一例外是进度。** 5 个字段里除 `CurrentProgress` 外全是 `readonly`（`JournalLog.cs:118`、`JournalLog.cs:122`、`JournalLog.cs:126`、`JournalLog.cs:130`、`JournalLog.cs:134`），构造函数一次写完（`JournalLog.cs:70`）；唯一能变的 `CurrentProgress` 带私有 setter（`JournalLog.cs:67`），外部只能走 `UpdateCurrentProgress`（`JournalLog.cs:81`）。想改「这一行写什么」的 mod 必须重建对象，而不是原地改字段。

**三、进度是一对数字。** `HasBeenCompleted()` 的实现就是 `CurrentProgress >= Range`（`JournalLog.cs:87`）。而构造参数的默认值是 `currentProgress = 0, range = 0`（`JournalLog.cs:70`），于是**默认构造出来的记录一出生就是「已完成」**。要让 UI 显示进度条、或让 `HasBeenCompleted()` 有意义，两个值都必须显式给。

**四、时间文本是相对量，每次现算。** `GetTimeText()` 拿 `CampaignTime.Now` 减去 `LogTime` 的天数差（`JournalLog.cs:93`），再在 `str_today` / `str_yesterday` / `str_DAY_days_ago` 三条游戏文本里选一条。它不缓存结果，所以同一条记录昨天显示「今天」、今天显示「昨天」。`LogTime` 同时也是容器合并时的排序依据（`JournalLogsCampaignBehavior.cs:132`）。

**五、谁往里写：只有原版行为。** `JournalLogsCampaignBehavior` 是唯一的原版写入者。它订阅任务与问题的五类事件（`JournalLogsCampaignBehavior.cs:14`），在任务开始（`JournalLogsCampaignBehavior.cs:53`）、任务完成（`JournalLogsCampaignBehavior.cs:66`）、任务日志追加（`JournalLogsCampaignBehavior.cs:41`）、问题日志追加（`JournalLogsCampaignBehavior.cs:29`）、以及玩家亲自解决某个问题时（`JournalLogsCampaignBehavior.cs:79`），把最新的 `JournalLog` 列表整体灌进 `JournalLogEntry`（`JournalLogsCampaignBehavior.cs:94`、`JournalLogsCampaignBehavior.cs:104`）。它自己**不生产**记录，只当搬运工。

**六、记录从哪来：任务与问题的 `AddLog` 家族。** 真正的生产者在 `QuestBase` 上，一共三个公开入口，正好对应 `LogType` 的三个值：

| 入口 | 造出的 `LogType` | 典型语义 |
| --- | --- | --- |
| `AddLog(text)`（`QuestBase.cs:373`） | `Text` | 纯文本一行，无进度 |
| `AddDiscreteLog(text, taskName, currentProgress, targetProgress)`（`QuestBase.cs:382`） | `Discreate` | 离散步骤，例如「已护送 2/4 段」 |
| `AddTwoWayContinuousLog(text, taskName, currentProgress, range)`（`QuestBase.cs:391`） | `TwoWayContinuous` | 可增可减的连续量 |

三个方法做的事完全一样：`new JournalLog(CampaignTime.Now, ...)`、加进任务自己的列表、然后广播 `OnQuestLogAdded`（`QuestBase.cs:373`、`QuestBase.cs:382`、`QuestBase.cs:391`）。记录列表本身通过只读属性暴露（`QuestBase.cs:88`，问题侧对应 `IssueBase.cs:531`）。这解释了一个容易困惑的点：**`LogType` 不是给你挑的样式开关，而是「你用哪个入口建的」的副产物** —— 想建 `Discreate` 记录，用 `AddDiscreteLog`，而不是自己 `new` 完再塞。

**七、搬运工怎么合并两个来源。** 任务和问题各自有一串记录，但它们要出现在同一张卡片上。`GetEntries(issue)` 的做法是：拿问题自己的列表，如果问题绑定了任务，就按 `LogTime` 找到插入点，把任务的记录整段插进去（`JournalLogsCampaignBehavior.cs:132`）；任务侧同理，会先解析出它对应的问题再转调（`JournalLogsCampaignBehavior.cs:157`）。搬运工的入口是 `CreateRelatedLog`（`JournalLogsCampaignBehavior.cs:94`、`JournalLogsCampaignBehavior.cs:104`）与 `GetRelatedLog`（`JournalLogsCampaignBehavior.cs:115`、`JournalLogsCampaignBehavior.cs:121`）——后者按「是否与本对象相关」在历史里反查已有的卡片。

**八、存档。** `CurrentProgress` 带 `SaveableProperty(3)`（`JournalLog.cs:67`），5 个字段带 `SaveableField(0)` 到 `SaveableField(2)` 以及 `(4)`、`(5)`（`JournalLog.cs:118`、`JournalLog.cs:122`、`JournalLog.cs:126`、`JournalLog.cs:130`、`JournalLog.cs:134`）—— 槽位 3 被那个属性占掉了，所以字段编号不连续，这不是笔误。`AutoGeneratedInstanceCollectObjects`（`JournalLog.cs:20`）只把引用类型的 `LogTime` / `LogText` / `TaskName` 登记进对象图，`CurrentProgress` / `Range` / `Type` 是值类型，由 `AutoGeneratedGetMemberValue*` 系列按成员名取值（`JournalLog.cs:28`、`JournalLog.cs:34`、`JournalLog.cs:40`、`JournalLog.cs:46`、`JournalLog.cs:52`、`JournalLog.cs:58`）。

## 怎么用

### 怎么拿到

按常见程度排，有三种来源：

1. **从任务或问题上读**。`QuestBase.JournalEntries`（`QuestBase.cs:88`）和 `IssueBase.JournalEntries`（`IssueBase.cs:531`）就是 `MBReadOnlyList<JournalLog>`；原版搬运工正是这么取的（`JournalLogsCampaignBehavior.cs:132`、`JournalLogsCampaignBehavior.cs:157`）。
2. **从 UI 侧容器上读**。`JournalLogEntry.GetEntries()` 返回该卡片当前聚合的所有记录（`JournalLogEntry.cs:117`）。它返回 `IEnumerable<JournalLog>`，每次调用都重新枚举内部列表。
3. **自己构造**。需要造一条测试记录时用构造函数（`JournalLog.cs:70`）。注意 `logText` 必须是 `TextObject`，传裸 `string` 编译不过。

想**追加**记录则不该用构造函数，而该用任务侧的三个入口（`QuestBase.cs:373`、`QuestBase.cs:382`、`QuestBase.cs:391`）—— 它们会顺带完成「入列表 + 广播事件」这两件你自己做不全的事。

### 典型用法

构造一条记录、推进它的进度、再读回展示所需的两个值 —— 这是 `JournalLog` 上全部的可写 / 可读路径：

```csharp
var log = new JournalLog(
    CampaignTime.Now,
    new TextObject("{=myMod}你击退了劫匪"),
    taskName: null,
    currentProgress: 0,
    range: 3,
    type: LogType.Text);

log.UpdateCurrentProgress(3);
bool finished = log.HasBeenCompleted();   // 3 >= 3 ⇒ true
TextObject when = log.GetTimeText();      // "今天" / "昨天" / "N 天前"
```

`readonly` 字段不能重新赋值，但字段里的 `TextObject` 本身是可变的 —— 想改这一行显示的变量值，改 `TextObject` 而不是改字段。`SetTextVariable` 有 `TextObject` / `string` / `float` / `int` 四个重载（`TextObject.cs:335` 是 `int` 那个）：

```csharp
log.LogText.SetTextVariable("DONE", 2);
log.LogText.SetTextVariable("TOTAL", 3);
```

遍历某个条目容器里的记录，筛出「还没做完的行」，自己拼时间前缀：

```csharp
foreach (JournalLog entry in journalLogEntry.GetEntries())
{
    if (!entry.HasBeenCompleted())
    {
        InformationManager.DisplayMessage(
            new InformationMessage(entry.GetTimeText() + " " + entry.LogText));
    }
}
```

`UpdateCurrentProgress` 虽然公开，但**在任务里请优先用 `QuestBase.UpdateQuestTaskStage`**（`QuestBase.cs:411`）：它会先在任务自己的列表里按引用比对，确认这条记录确实属于本任务，再调 `UpdateCurrentProgress`。它需要你留着 `AddLog` 家族返回的那个 `JournalLog` 引用：

```csharp
JournalLog progressLog = AddDiscreteLog(
    new TextObject("{=myMod}已护送 {DONE}/{TOTAL} 段路"),
    new TextObject("{=myMod}护送商队"),
    currentProgress: 1,
    targetProgress: 4);

// 之后每次只推进进度
UpdateQuestTaskStage(progressLog, 2);
```

要撤掉一行，用 `RemoveLog`（`QuestBase.cs:400`）：它按引用从列表里移除，找不到会触发 `Debug.FailedAssert` —— 也就是说**拿一个不属于本任务的 `JournalLog` 去调它，是明确的编程错误**，不会静默失败。

### 坑

- **默认 `range = 0` ⇒ 一出生就「已完成」。** 构造时省略 `currentProgress` / `range`（`JournalLog.cs:70`），`HasBeenCompleted()` 立刻返回 `true`（`JournalLog.cs:87`）。原版自己在很多纯文本记录上也正是这么用的（`range = 0`），因为那些行本来就不显示进度；但如果你想显示进度条却忘了传 `range`，UI 会一直显示「已完成」。
- **除 `CurrentProgress` 外，所有字段都改不了。** `LogTime` / `LogText` / `TaskName` / `Range` / `Type` 都是 `readonly`（`JournalLog.cs:118`、`JournalLog.cs:122`、`JournalLog.cs:126`、`JournalLog.cs:130`、`JournalLog.cs:134`），而且全部参与存档。想让某行的文案换掉，只能新建一条 `JournalLog` 并让容器重新 `Update`（`JournalLogEntry.cs:129`、`JournalLogEntry.cs:139`）—— 注意 `JournalLogEntry.Update` 是**整体替换**内部列表，不是增量修改。
- **`CurrentProgress` 没有公开 setter。** 属性本身是 `{ get; private set; }`（`JournalLog.cs:67`），唯一合法写入口是 `UpdateCurrentProgress`（`JournalLog.cs:81`）或任务侧的 `UpdateQuestTaskStage`（`QuestBase.cs:411`）。直接赋值编译不过。
- **枚举值拼写是 `Discreate`，但方法名是 `AddDiscreteLog`。** `LogType`（`LogType.cs:6`）的四个值是 `None` / `Text` / `Discreate` / `TwoWayContinuous`，源码原文如此（拼错的 `Discreate` 被存档固化，改不了）；而 `QuestBase` 上对应的入口叫 `AddDiscreteLog`（`QuestBase.cs:382`），拼写正确。按直觉写 `LogType.Discrete` 会编译失败，按直觉写 `AddDiscreateLog` 也会。
- **不要自己 `new` 一条记录再想办法塞进 UI。** UI 读的是 `JournalLogEntry`，而它只由 `JournalLogsCampaignBehavior` 更新（`JournalLogsCampaignBehavior.cs:94`、`JournalLogsCampaignBehavior.cs:104`）；该行为只从任务/问题的 `JournalEntries` 里捞数据（`JournalLogsCampaignBehavior.cs:132`、`JournalLogsCampaignBehavior.cs:157`）。**可行路径只有一条**：在你自己的任务或问题上调用 `AddLog` 家族（`QuestBase.cs:373`、`QuestBase.cs:382`、`QuestBase.cs:391`），行为会在下一次任务开始 / 完成 / 日志追加时自动把它捞进卡片（`JournalLogsCampaignBehavior.cs:53`、`JournalLogsCampaignBehavior.cs:66`、`JournalLogsCampaignBehavior.cs:41`、`JournalLogsCampaignBehavior.cs:29`）。
- **问题的更新只在玩家亲自解决时被搬运。** `OnIssueUpdated` 的第一件事就是比对 `issueSolver == Hero.MainHero`，不是玩家本人解决就直接返回（`JournalLogsCampaignBehavior.cs:79`）。所以给 AI 领主解决的问题补记录，在日志里看不到。
- **`GetTimeText()` 依赖战役时钟。** 它读 `CampaignTime.Now`（`JournalLog.cs:93`），在战役未启动的上下文里调用拿不到有意义的值；同理，`LogTime` 一旦构造就无法重设（`JournalLog.cs:118`）。
- **`Type` 只在构造时生效。** 它是 `readonly`（`JournalLog.cs:134`）且参与存档取值（`JournalLog.cs:58`）。想换类型只能重建记录，而重建意味着换一个 `AddLog` 入口（`QuestBase.cs:373`、`QuestBase.cs:382`、`QuestBase.cs:391`）。

## 真实示例

场景：写一个自定义的「护送商队」任务，每送完一段路就更新一条带进度的记录，全部送完再追加一条结清文本。要点是**用 `AddLog` 家族生产记录、用 `UpdateQuestTaskStage` 推进进度、留着返回的引用**。

```csharp
public class EscortCaravanQuest : QuestBase
{
    private JournalLog _progressLog;

    private void OnCaravanArrived(int segmentIndex)
    {
        if (_progressLog == null)
        {
            // 第一次：建一条带任务名的进度记录。
            // targetProgress 必须显式给（这里 4 段），否则 HasBeenCompleted() 立刻为 true。
            _progressLog = AddDiscreteLog(
                new TextObject("{=myMod}已护送 {DONE}/{TOTAL} 段路"),
                new TextObject("{=myMod}护送商队"),
                currentProgress: 1,
                targetProgress: 4);

            // LogText 字段是 readonly，但它指向的 TextObject 可以改变量
            _progressLog.LogText.SetTextVariable("DONE", 1);
            _progressLog.LogText.SetTextVariable("TOTAL", 4);
            return;
        }

        // 之后每次只推进进度：先确认记录属于本任务，再写进度
        UpdateQuestTaskStage(_progressLog, segmentIndex);
        _progressLog.LogText.SetTextVariable("DONE", segmentIndex);

        if (_progressLog.HasBeenCompleted())
        {
            AddLog(new TextObject("{=myMod}商队安全抵达，报酬已结清"));
        }
    }
}
```

UI 侧（或任何想读日志的地方）拿到的不是任务，而是条目容器。遍历它聚合的记录，把未完成的行带上相对时间前缀显示出来：

```csharp
foreach (JournalLog entry in journalLogEntry.GetEntries())
{
    if (!entry.HasBeenCompleted())
    {
        InformationManager.DisplayMessage(
            new InformationMessage(entry.GetTimeText() + " " + entry.LogText));
    }
}
```

最后，如果你要自己重现「任务 + 问题合并成一条时间线」这件事，原版搬运工的算法就是下面这样：先按 `LogTime` 找到插入点，再把任务的记录整段插进问题的列表（`JournalLogsCampaignBehavior.cs:132`）。

```csharp
var merged = issue.JournalEntries.ToMBList();
JournalLog questFirst = issue.IssueQuest.JournalEntries.FirstOrDefault();
if (questFirst != null)
{
    int i;
    for (i = 0; i < merged.Count; i++)
    {
        if (merged[i].LogTime > questFirst.LogTime)
        {
            i--;
            break;
        }
    }
    merged.InsertRange(i, issue.IssueQuest.JournalEntries);
}
```

## 一、六节清单与别名表（lead-5 于 2026-10-04 补入 · boss #8543 裁定）

### 〇.0 ★ 别名归并必须用【共现证据】，不许按语义相近（lead-5 实测，boss 采纳）

判据 = 同页是否同时出现候选组里的两个标题。

实测（v1.4.5/zh/api 非空壳 2,750 页）{导航, 依赖关系, 依赖图, 参见}：
  同页共现 ≥2 个 = 342 页
    AccompanyingCharacter.md → 导航 + 依赖关系
    AgeModel.md               → 依赖图 + 参见

⇒ 归并方向：导航 独立成一节（索引清单）；依赖关系 / 依赖图 / 参见 归为一节（三种用途相近）。

⚠ 为什么这条比清单本身更耐用：
  合并不改变「有没有这一节」的总数，
  但它会让【只有导航、没有参见】的页被判成「参见已齐」
  ⇒ 方向是【把缺判成有】，比把有判成缺更危险。
  它属于「小的非零数」家族里最坏的一个形态：分母不变、分子虚高、输出完全正常。

### 〇.3 ⚠ 非等价：「何时使用」族【不是】「怎么用」的别名

```text
共现证据（非空壳 2,750 页）：
  只有「何时使用」而无「怎么用」 = 274   ← 单独出现 ⇒ 不可能是别名
  两者都有                      =  76
  只有「怎么用」                = 2,156

「怎么用」   = 怎么拿到（源树 · file:行号 · 入口）+ 典型用法 + 坑
「何时使用」 = 该不该读这一页 · 该改哪个模型 · 什么不能做
```

混进别名表会让「缺怎么用」的分档静默少算 —— 而分档错，基数就错。

## 〇之二、空壳签名（lead-5 于 2026-10-04 补入）

**只用形状 A。** 形状 B（`先从命名空间…`）在 8,545 页里只命中 **1** 页，且是同页两句的巧合 —— **不要用它。**

| 档 | 判据 | 页数 | 处置 |
| --- | --- | ---: | --- |
| `shell_strict` | description 含「的自动生成类参考。」**且**正文含形状 A 之一 | 6,586 | 铺告示 |
| `desc_only` | description 命中、正文无形状 A | 1,958 | 铺告示，**另开一列**，不并入任一边 |
| `no_desc` | description 未命中 | — | 手写 |

形状 A 三个子串（任一命中即算）：
`它有什么状态` · `它允许你做什么` · `它保存的状态`

**⇒ `desc_only` 那一档【不要因为「形状不同」就不铺告示】。**
今天的教训是「小的非零数先怀疑签名不完整」，不是「小的非零数先当成另一个东西」。
**逐页定性它们是独立的一件事，不阻塞开工。**

## 二、不是「加一行对账」，是【让输出里出现一个不该出现的值】

「对账」暗示要有人去看；「不该出现的值」会在没人看的时候自己报警。
今天 /tmp 两次事故 + lead-6 自己两次静默失败，共同根因都是【输出很整齐，
而输出里没有一行用来对账】。所以下面四条都写成同一种形态：
让某个数在正常情况下【不该等于它】，而它等于了。

1. **临时清单带自身唯一标识** —— 例 `lead6-w58-batch04.pages.txt`
   ⇒ 禁止 /tmp 下的固定名（/tmp 共享，已害两次：worker-59、worker-62）
   ⇒ 不该出现的值：清单文件名等于别人的名字
2. **凡度量输出里出现【自己清单之外的页名】** ⇒ 立即停止，该轮判为无效并重跑
   ⇒ 这不是异常处理，这是判据的一部分
   ⇒ 不该出现的值：输出里的页名不在我的清单里
3. **引用必须带【全页引用数】**，不只带增量
   ⇒ 不该出现的值：全页 0 却没有 git diff（那不是「没引用」，是「没做」）
4. **tier 编号按 boss 的口径** —— tier1 只算非空壳页
   ⇒ 不该出现的值：报出的 tier1 数字等于「全桶无该段的页数」（那是把空壳也算进去了）

## 三、清单文件卫生（boss #8333 加，与前三条并列）

清单测的是【写之前输入是什么】；四条验收测的是【写完之后对不对】。
清单错了，后面所有验收都会在错误的集合上运行，并给出一个漂亮的 0。

· **非注释行必须全部是可解析的仓库相对路径。**
· **首行必须是注释**，写明 `N_before` 与采样时刻（不许裸写 `N_before = 941 …` 这种赋值行 ——
  工具只跳过 # 行，它会被当成一条路径 ⇒ 1/942 解析不了 ⇒ exit 2）
· **清单从【工具自己写的输出文件】取，不解析 stdout** —— stdout 的分段是给人看的，文件才是契约
  （实例：段标题正则要求全大写，而 `CITED BUCKET (162) — deep-written pages…` 含小写，
    没被认成标题 ⇒ 从 stdout 切路径时切错段，多切了 162 页）
· **派单前跑一次执行层拒绝门**（lead-8 的 `--refuse-cited`），exit 0 才算清单成立

## 四、对照必须先证明自己生效过

· 「对照通过」之前，先【故意改坏】一次，尺的输出必须变化
· 若输出没变：那不是「通过」，是「对照没跑起来」
· 一个没生效的对照，和一个干净的正向对照，输出看起来一模一样。
  区别只在于有没有一个「不该出现却出现了」的信号。
· 正例（worker-66）：第一版负向对照因 sed 转义失败而没生效，
  它把那轮结果判为假对照丢弃后重做 —— 这比「对照通过」更值钱。

## 五、修改共享输入前必须先告知（boss #8478 裁定）

凡修改【正在被他人消费】的清单 / 输入 / 共享文件，必须先告知消费方，或写入副本。
- 否则「让契约更严」会变成「让别人的尺当场炸掉」。
- 今天这一格是双向的：lead-6 给清单加注释炸了 worker-65 的三个尺；
  worker-65 当场报出「这会静默破坏每一个度量」—— 它没有硬跑。

**⇒ 规则三只约束了【文件格式】，没约束【修改时机】—— 缺的就是这半句。**
## 六、写作纪律（沿用）

· ① 怎么拿到（源树 · 文件:行号 · 入口）② ≥3 行真实 csharp ③ 取该页风险首条
· 不得搬运同页示例小节；计句排除结构标签与代码块
· 引用落笔前逐条核（批 2 教训：把行号写成裸 `:N` 没落文件名，机器判据①过不了）
· U+FFFD 每写完一页立刻单扫该文件，不等收尾
· 判分器由派单方给定，不由执行方自选 —— 否则各 worker 的产出密度永远不可比
· 退回后先交归因表再修：修改让数变好，归因让下一次不必重查

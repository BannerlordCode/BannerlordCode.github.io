# Version Delta (1.4.6 / 1.4.5 / 1.3.15)

> Every number on this page comes from scanning the three source trees directly (`bannerlord-1.4.6/`, `bannerlord-1.4.5/Bannerlord.Source/`, `bannerlord-1.3.15/`). **Nothing here was written from memory or copied from older docs.** Anything the scan cannot prove is explicitly labelled "not verified".

## The short version

**The real change from 1.4.5 to 1.4.6 is: the source layout changed, a few tooling assemblies appeared, and some generator noise — the gameplay API is essentially additive, and no gameplay type was removed.**

For mod authors, the sentence that matters: **if you already work on 1.4.5, moving to 1.4.6 should not require code changes. What does need re-checking is reflection and patching code that assumes an assembly layout.**

## Shape of the three source trees

| Version | Source root | Layout | `.cs` files scanned |
| --- | --- | --- | --- |
| 1.4.6 | `bannerlord-1.4.6/` | 90 top-level directories, directory name ≈ assembly name, gameplay modules flat | 11385 |
| 1.4.5 | `bannerlord-1.4.5/Bannerlord.Source/` | `bin/` for core assemblies plus `Modules.SandBox/`, `Modules.Multiplayer/`, … for gameplay | 8572 |
| 1.3.15 | `bannerlord-1.3.15/` | flat by `TaleWorlds.*`, same shape as 1.4.6 | 5196 |

That is the biggest 1.4.6 "change": **the same tree, laid out twice**. 1.3.15 and 1.4.6 share the flat layout, so the shortest migration path runs from 1.3.15 to 1.4.6.

**Counting rule** (all module-level numbers below use it, so they can be reproduced): only `TaleWorlds.*`, `SandBox` and `StoryMode` directories are counted, each module's `Properties/` is excluded (it holds only a generated `AssemblyInfo.cs`), and a "type" is a distinct file name.

| Measure | 1.4.6 | 1.4.5 | 1.3.15 |
| --- | --- | --- | --- |
| Gameplay module directories | 71 | 66 | 54 |
| Distinct type files, excluding `Properties/` | 6478 | 6278 | 5126 |
| Distinct type files, including `Properties/AssemblyInfo.cs` | 6549 | — | — |

## Module-level delta, 1.4.6 versus 1.4.5

### Added directories (6)

| Added directory | Files | Verdict |
| --- | --- | --- |
| `TaleWorlds.MountAndBlade.SteamWorkshop` | 8 | Steam Workshop tooling (`Program` / `ToolTask` / `CreateItemTask` / `GetItemTask` / `UpdateItemTask` / `ItemVisibility` / `ToolDebugManager`). Genuinely new, irrelevant to mod API |
| `TaleWorlds.MountAndBlade.Launcher` | 2 | Launcher entry point (`Program`). Genuinely new, irrelevant to mod API |
| `TaleWorlds.MountAndBlade.GauntletUI.CodeGenerator` | 2 | Prefab code generator (`Program`) |
| `TaleWorlds.MountAndBlade.SaveSystem.CodeGenerator` | 2 | Save collection code generator (`Program`) |
| `TaleWorlds.MountAndBlade.Multiplayer.GauntletUI.AutoGenerate` | 84 | Generated multiplayer prefabs. 1.4.5 spells the same directory `AutoGenerated` — **a rename, not an addition** |
| `TaleWorlds.MountAndBlade.Multiplayer.2` | 121 | Same file names and same count as `TaleWorlds.MountAndBlade.Multiplayer` (also 121 files) — a duplicate produced by the export tool, **not a new feature** |

Three third-party/tooling directories also appear at the top level of 1.4.6 where 1.4.5 has no counterpart: `StbSharp` (13 files), `ManagedStarter` (1 file), `netstandard` (1 file). All fall inside the noise exclusions.

### Removed directories

**Zero removals at the gameplay-module level.** The only 1.4.5 directory absent in 1.4.6 is `TaleWorlds.MountAndBlade.Multiplayer.GauntletUI.AutoGenerated` (the rename above), plus the 1.4.5 layout directories `bin` and `Modules.*`, which are layout rather than modules.

### Every type-level difference is additive

Types present in 1.4.6 but absent in 1.4.5, per module:

| Source of the difference | Where it appears | Nature |
| --- | --- | --- |
| `EmbeddedAttribute`, `IsReadOnlyAttribute` | Almost every managed module (Core, Library, Engine, GauntletUI, CampaignSystem.ViewModelCollection, MountAndBlade.ViewModelCollection, … two each) | Compiler-generated attributes written out as files by the export tool — **not new API** |
| `.2`-suffixed duplicate files | `IMbEvent.2`–`.8`, `MbEvent.2`–`.8`, `EnumHelper.2`, `ReferenceAction.2`/`.3`, `ReferenceIMBEvent.2`/`.3`, `ReferenceMBEvent.2`/`.3`, `WeakNativeObjectReference.2`, `MPPerkCondition.2`, `MissionObjectiveTarget.2`, `MessageContractCreator.2`, `MessageContractHandler.2`, `AssemblyInfo` | Same-named types split across several files by the exporter — **not new types** |
| `TaleWorlds.CampaignSystem` +22 | Exactly the two groups above combined | No gameplay API added |

**No module lost a type.**

> **Methodology warning (important).** These are **lower bounds**, not exact API sizes. The 1.4.5 decompile spreads partial-class members across several files and the extractor only sees the main file, so the 1.4.5 column is systematically low (`Campaign` 178 versus 222). **Do not read "1.4.6 has 44 members more than 1.4.5" as new functionality** — the same figure is 222 on 1.3.15, which shows the low 1.4.5 value is an extraction artefact, not a version difference. For real version deltas compare signatures per class (`node tools/class-version-diff.mjs <Type>` — note that tool is hard-coded to 1.4.5 and needs a 1.4.6 root to emit a 1.4.6 column).
>
> Same-named files also collide in a filename-only index: `AutoGeneratedSaveManager` exists in Core, CampaignSystem, SandBox and StoryMode, and a filename index silently returns only one of them. **Cross-version comparison must locate types by namespace.**

## Empty shells worth knowing about in 1.4.6

- `TaleWorlds.NavigationSystem` contains exactly one file, `Properties/AssemblyInfo.cs`, and **no game types at all**. The 1.4.5 directory of the same name also holds one file. It is not "a newly added navigation system"; do not go looking for navigation API there.
- `TaleWorlds.InputSystem` has 15 types (`IInputManager`, `Input`, `InputContext`, `InputKey`, `InputState`, `GameKey`, `HotKey`, …) but **no class named `InputManager`**. Older samples calling `InputManager.X` will not compile on 1.4.6.

## Mod migration checklist

Moving from 1.3.15 or 1.4.5 to 1.4.6, work through this in order:

1. **Audit reflection and patching against real namespaces.** Use the table above, especially for `MBObjectManager`, `ScreenManager`, `ViewModel` and `MBSubModuleBase`.
2. **Do not "fix" code because 1.4.6 shows more members.** Most of the 1.4.6-versus-1.4.5 member surplus is decompile artefact distribution.
3. **Regenerate your diff tooling.** `tools/class-version-diff.mjs` currently hard-codes the roots 1.3.0 / 1.3.15 / 1.4.5; add `'1.4.6': 'bannerlord-1.4.6'` before it can produce a 1.4.6 column.
4. **Regression-test multiplayer and platform code separately.** `TaleWorlds.MountAndBlade.Multiplayer*` and `TaleWorlds.PlatformService*` are inside the noise exclusions, so this page draws no conclusions about them.
5. **Do not reference the third-party trees.** 1.4.6 exposes `StbSharp`, `ManagedStarter` and `netstandard` directories at the top level; referencing them will not work in the game.

## Not verified / not provable from this scan

- **Gameplay behaviour differences**: a source tree proves the presence of types and members, not runtime behaviour. Whether 1.4.6 fixes a specific battle or campaign bug is **not verified** here.
- **Mapping to the shipping build**: whether the folder name `bannerlord-1.4.6` equals the client version number players see is **not verified**.
- **Per-module breakdown for 1.3.15**: the module and type counts above for 1.3.15 come from the same counting rule, but a per-module 1.4.6↔1.3.15 classification was **not** performed.
- **Signature-level diffs**: `tools/class-version-diff.mjs` has no 1.4.6 root yet, so per-class signature deltas require extending that tool first.

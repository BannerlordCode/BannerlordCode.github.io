## Overview

`IMBVoiceManager` is the bridge to the **battle-voice ("bark") catalogue**. It does one thing conceptually — turn a voice *type* name into a native index — and then a second, separate thing: enumerate the *voice definitions* that a given creature class owns. The file is 17 lines, the type is `internal`, and `[ScriptingInterfaceBase]` sits at `IMBVoiceManager.cs:5`. The split matters and is easy to miss. **Voice types and voice definitions are two different spaces.** A *type* is a semantic slot such as `Grunt`, `Yell` or `Advance`; a *definition* is a concrete recording belonging to a creature class. `GetVoiceTypeIndex(string)` resolves the first, `GetVoiceDefinitionCount*(string className)` and the list call resolve the second — and both enumeration members are keyed on a **class name**, not on a voice type.

## Mental Model

Think of it as **a cast list and a recording cabinet, kept in separate rooms**. The cast list maps a role name to a slot number — `SkinVoiceManager.VoiceType.Grunt` is "role 0, the grunt". The cabinet holds the actual audio, filed by **which creature recorded it**, not by which role it plays. A horse's cabinet and a human's cabinet both contain a grunt recording; they are different recordings with different indices.

That is why the two enumeration members take a `className`. Asking "how many voice definitions does class X have" is a question about the cabinet, and it says nothing about which role those definitions fill. If you enumerate a cabinet expecting to find the grunt, you must then know the role each definition plays — and **this interface provides no member that maps a definition index back to a voice type.**

The boundary that bites is in the wrapper's naming. `SkinVoiceManager.GetVoiceDefinitionListWithMonsterSoundAndCollisionInfoClassName` (`:179`) resolves to the native symbol `get_voice_definitions_with_...` (`IMBVoiceManager.cs:14`), while the managed name says "Get...List". Similarly the count method (`:174`) drops "Monster" from the native name. Reading the managed name as if it were the native name will send you looking for members that are not there.

## Risks and crash boundaries

- **A mod assembly cannot call this interface.** `internal interface IMBVoiceManager` (`IMBVoiceManager.cs:7`), `internal static` field (`MBAPI.cs:42`), `InternalsVisibleTo` limited to three TaleWorlds assemblies (`TaleWorlds.MountAndBlade/Properties/AssemblyInfo.cs:8-10`).
- **Voice types and voice definitions are different spaces.** Types are named slots; definitions are recordings filed by creature class (`IMBVoiceManager.cs:8` vs `:11`/`:14`). **No member maps a definition index back to a voice type**, so you cannot learn what role a definition plays.
- **The list call has no length parameter.** `int[] definitionIndices` (`:15`) is written to at native width. **A stale or wrong count is a memory fault, not an exception** — this is the most dangerous member on the page.
- **Two native round-trips for one logical read.** Count at `SkinVoiceManager.cs:174` and fill at `:179`. Anything that repopulates voices in between desynchronises them.
- **The lookup is a constructor side effect.** `Index = MBAPI.IMBVoiceManager.GetVoiceTypeIndex(typeID)` (`SkinVoiceManager.cs:24`) runs during `new SkinVoiceType(...)`. A `SkinVoiceType` used as a dictionary key therefore resolves against the live catalogue at construction time, and a stale instance keeps a stale index.
- **`SkinVoiceType`'s properties have `private set`.** `TypeID` and `Index` (`SkinVoiceManager.cs:17`, `:19`) are get-only from outside; the only way to change them is to construct a new instance.
- **`GetName()` is a text lookup keyed on `TypeID`, not on the index.** `GameTexts.FindText("str_taunt_name", TypeID)` (`SkinVoiceManager.cs:27-30`) — a voice type with no matching text returns an unresolved `TextObject`.
- **Managed and native names disagree.** Managed `GetVoiceDefinitionList...` (`:179`) vs native `get_voice_definitions_with...` (`IMBVoiceManager.cs:14`); managed `GetVoiceDefinitionCount...` (`:174`) vs native `...count_with_monster...` (`:11`).

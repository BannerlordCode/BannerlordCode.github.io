### Finding A (REAL — actionable) — `IGameStateManagerListener.md` J6 = `stub (no-real-example)`

`classifyPage()` (via `hasRealCsharpExample`, `tools/lib/handwritten-policy.mjs` sha `0024b9e8…`) returns `stub` with the **single** reason `no-real-example`, while the other 4 pages return `deep_pass`. The judge prints it as `J6=stub · deepPass=false · tier=handwritten_deep`.

**Why this is a page defect, not an instrument artefact — verified against source:**
- The page's only ```` ```csharp ```` block is a **declaration-only skeleton**: a class implementing all 5 callbacks whose bodies are *comments only*. It contains no `.method(` invocation and no engine type access, so `hasRealCsharpExample` cannot fire. I dumped the block by hand to confirm.
- The interface itself (`bannerlord-1.4.5/…/IGameStateManagerListener.cs`, 14 lines) is 5 `void` callbacks — nothing callable on the interface.
- **But the page's own prose promises a call it never shows.** The "How to use" text says *"register the listener with `GameStateManager`"*, and `GameStateManager.RegisterListener(IGameStateManagerListener)` **exists at `GameStateManager.cs:102`** (398 lines in 1.4.5 — in range). The example never calls it.
- Contrast with the passing pages, which do show real calls: `IFaction` uses `Clan.PlayerClan`, `Campaign.Current.Factions`, `playerFaction.IsAtWarWith(faction)`; `IViewModel` uses `OnPropertyChangedWithValue(value)`.
⇒ So the classifier is **right**, and this is the same class of gap the 4 other pages avoid: **the example demonstrates the interface shape, not its use.**

Suggested fix (lead-23's call, not mine — I am read-only): add one real call to the example, e.g. register the listener with `GameStateManager.RegisterListener(...)` (`GameStateManager.cs:102`), or have a callback react to a state by calling into a real system. Any of those makes the block call-like and flips `J6` to `deep_pass`.

### Finding B (NOT a page defect — caliber mismatch) — `J2 missing=[…]` on all 5 pages

The judge reports `FAIL` on all 5 with `J2 missing=[概述,心智模型,怎么用,关键成员,真实示例,导航]`. **This is a caliber mismatch, not a page defect**, per lead-20's ruling (#16958 ①): J2's `SECTIONS` array in the judge is Chinese-only (`概述/心智模型/怎么用/关键成员/真实示例/导航`), so it **constructively cannot pass an English page**. The judge itself demonstrates this: the `参见族` slot *does* accept the English alias — it prints `J2 参见族 via=[See also]` — while the six core slots do not. The pages carry the exact English mirror (`Overview | Mental Model | How to use | Key Members | Real Example | See also | Navigation`).
⇒ Record as **`NOT APPLICABLE (caliber: J2 is the v1.4.5/zh line's batch ruler, not a site-wide criterion)`**. J2/J10/J11 are line-local; only **J5R and J3** are cross-line criteria, and both pass here. I flag it only because an unqualified reading of `pass=0 fail=5` would wrongly condemn a compliant batch.

# SandBox / StoryMode / Native 阅读政策（v1.4.5）

这三个区域都能找到“看起来像 API”的代码，但它们解决的问题不同。把官方范例、主线内容和引擎反编译混成同一层，会让模组直接依赖错误的生命周期或内部实现。

## 一句话职责

- **SandBox**：单人战役的官方功能模块和参考实现，适合观察 Behavior、Quest、菜单、对话和战役规则如何组合。
- **StoryMode**：主线战役内容，适合追踪剧情专用的注册和状态流转；一般模组不应把主线对象当作通用扩展点。
- **Native**：引擎的原生实现和托管桥，适合排查渲染、场景、物理、动画、音频或底层崩溃；不是日常业务 API。

## 阅读优先级

```text
先读 TaleWorlds.* 托管 API 和任务指南
    -> 需要官方实现样例时读 SandBox
    -> 需要理解主线注册或剧情状态时读 StoryMode
    -> 只有托管封装不足或崩溃栈指向引擎时才追 Native
```

如果目标是加战役功能，从 [CampaignBehaviorBase](../../api/campaign/CampaignBehaviorBase)、[CampaignEvents](../../api/campaign/CampaignEvents) 和 [CampaignGameStarter](../../api/campaign/CampaignGameStarter) 开始；不要因为 SandBox 中有一个相似类，就绕过这些托管注册边界。

## 三个模块应该怎样读

### SandBox：看组合方式，不复制内部身份

SandBox 最适合回答“官方如何把多个系统接起来”：Behavior 如何注册、事件何时订阅、菜单如何交回 Campaign、Action 如何产生级联。复制的是调用顺序和生命周期判断，不是内部字段、私有 SaveId 或某个具体 NPC 的身份。

当你要改世界状态时仍回到对应的 `*Action.Apply`；当你要改变计算策略时回到 [GameModels](../../api/campaign/GameModels) 和 [GameModelsManager](../../api/core-extra/GameModelsManager)。

### StoryMode：追踪专用状态，回桥到通用入口

StoryMode 的 Behavior、Quest 和剧情对象可能依赖特定主线阶段、标记或存档状态。阅读时先画出“谁创建、谁持有、何时保存、何时结束”，再判断那条路径是否能在一般 Campaign 中成立。

模组若只是要监听英雄、据点或战役时钟，应回到 [Hero](../../api/campaign/Hero)、[Campaign](../../api/campaign/Campaign) 和 [CampaignEvents](../../api/campaign/CampaignEvents)，不要引用主线 Behavior 作为通用服务定位器。

### Native：理解桥接边界，不直接 P/Invoke

Native 代码和 `IMB*` 接口属于托管层与引擎之间的桥。托管封装会在游戏初始化阶段注入函数指针并维护原生对象寿命；直接 `[DllImport("TaleWorlds.Native.dll")]` 会绕过这套初始化。

日常 Mission 逻辑先读 [Mission](../../api/mission/Mission)、[Agent](../../api/mission/Agent) 和 [MissionBehavior](../../api/mission/MissionBehavior)。只有当托管 API 没有能力，或崩溃栈明确落在 Native 时，才把 Native 当作排查材料。即使完成排查，产品代码也应尽量回到已有的托管包装。

## 判断一个范例能否复用

| 问题 | 可以复用的证据 | 不能直接带走的部分 |
|------|----------------|--------------------|
| 接入时机 | `OnGameStart`、`CampaignGameStarter.AddBehavior`、Mission 初始化回调 | 某个模块的私有初始化顺序 |
| 世界变更 | 对应 Action 的 `Apply` 调用和事件结果 | 直接写实体字段、内部列表或私有缓存 |
| 存档 | Behavior 的 `SyncData(IDataStore)` 和稳定 key | AutoGenerated 编号、私有 SaveId、剧情专用对象图 |
| 引擎调用 | 托管封装的参数和生命周期检查 | Native 导出地址、函数指针和直接 P/Invoke |

## 版本与风险

- v1.4.5 的模块拆分和反编译源码只证明本版本的实现事实；迁移到 v1.3.15 或 v1.3.0 时先查版本差异。
- SandBox/StoryMode 的示例可能依赖模块加载顺序，缺少 `SubModule.xml` 依赖时不会自动成立。
- Native 对象、Agent、Scene 和 UI 层的引用都有明确寿命；在结束回调后继续使用会触发空引用、已释放句柄或原生崩溃。
- 任何涉及存档的改动都回到[崩溃与存档边界](../crash-boundary)，不要把反编译字段当作稳定的模组协议。

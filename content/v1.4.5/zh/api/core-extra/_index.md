## 模块心智模型

`core-extra` 是「内容与通用工具」层：它把物品、装备、锻造、旗帜、角色属性、游戏模型、UI 视图模型，以及数学/几何与 IO/网络原语全都收在一处——这是离 `TaleWorlds.Core` 与 `TaleWorlds.Library` 业务代码最近的“大杂烩”桶，几乎任何模块要落地一个可序列化的内容类型或 UI 绑定对象都会落到这里。

从归属上看，本桶大致分两类。一类是**内容类型**：`ItemObject` 用 `ItemTypeEnum`/`ItemTiers` 给武器、盔甲、马匹、货物等定类；`Equipment` 以 12 个槽位（`EquipmentSlotLength = 12`）的 `EquipmentElement` 数组描述一套 Battle/Civilian/Stealth 装备；`Banner` 用 `BannerCode` 字符串序列化图标布局、`Game.Current.CreateBannerVisual` 生成视觉；`Crafting` 与 `CraftingPiece` 支撑武器锻造与精炼公式；`SkillObject`/`BasicCultureObject`/`CharacterCode`/`BodyProperties` 则共同刻画角色的外形、属性与文化归属。另一类是**运行时与表现原语**：`Game` 是全局单例（`Game.Current`），持有 `ObjectManager`、`GameType` 与 `BasicGameModels`；`ViewModel`（位于 `TaleWorlds.Library`）实现 `INotifyPropertyChanged` 驱动 UI 数据绑定；`InformationManager` 是静态消息/询问/提示中枢；`Color` 与各类数学结构（`Vec2`/`Vec3`/`Mat3`/`Quaternion`/`MathF`）提供底层几何与色彩计算。

理解本桶的关键，是意识到它横跨“数据模型”与“表现层”两个关注点：`Equipment`/`ItemObject` 等会被存档系统扫描（`[SaveableRootClass]`/`[SaveableField]`），而 `ViewModel`/`InformationManager` 只在客户端运行、不参与存档。下面列出的入口类型是读懂其余数百个派生/辅助类型的锚点。

## 核心入口类型

- [Equipment](./Equipment) — 12 槽位装备栏，每个槽位是 `EquipmentElement`，可序列化，区分战斗/平民/潜行配置。
- [EquipmentElement](./EquipmentElement) — 装备槽中的单件引用（物品 + Modifier + 颜色），是装备系统的叶子节点。
- [ItemObject](./ItemObject) — 物品主类，`ItemTypeEnum` 覆盖武器/盔甲/马匹/货物，`ItemTiers` 表示品质。
- [ItemRosterElement](./ItemRosterElement) — 物品堆叠条目，用于库存/队伍 roster 的数量化持有。
- [SkillObject](./SkillObject) — 技能定义，绑定到 `CharacterAttribute[]`，角色成长系统的核心。
- [Banner](./Banner) — 旗帜，`BannerCode` 序列化图标布局，经 `Game.Current` 生成视觉。
- [BasicCultureObject](./BasicCultureObject) — 文化定义，持有旗帜配色、`Banner` 与文化属性。
- [BodyProperties](./BodyProperties) — 角色体型（动态 + 静态属性），`CharacterCode` 据此还原外观。
- [Crafting](./Crafting) — 锻造与精炼逻辑，配合 `CraftingPiece` 生成武器设计。
- [CraftingPiece](./CraftingPiece) — 锻造部件（刃/柄/头等），组合成可打造的武器。
- [CharacterCode](./CharacterCode) — 用 `BodyProperties` + 装备码 + 配色压缩出一个可传输的角色快照。
- [Game](./Game) — 全局游戏单例，聚合 `ObjectManager`、`GameType` 与游戏模型。
- [ViewModel](./ViewModel) — UI 数据绑定基类（`INotifyPropertyChanged`），视图层根类型。
- [InformationManager](./InformationManager) — 静态消息/询问/提示派发中枢，表现层与逻辑层的解耦点。
- [Color](./Color) — 色彩结构，`CharacterCode`/`BasicCultureObject` 等大量依赖它做配色。

## 与其他模块的关系

本桶与 `../campaign/` 互补：`CharacterObject`（含完整技能与装备）定义在战役桶，而它的底层零件——`SkillObject`、`Equipment`、`BodyProperties`、`CharacterCode`——都在这里；读角色系统时两桶要对照看。数学原语（`../core/` 的向量/矩阵/四元数约定）虽在本桶也有重复列出，但概念上归 `core`；`ViewModel` 家族则对应专门的 `../viewmodel/` 桶，本桶的 `ViewModel` 是其抽象基类。所有带 `[SaveableField]` 的内容类型都依赖 `../save-system/` 的序列化框架，务必对照其约定。

在崩溃边界上，本桶的 `ViewModel`/`InformationManager` 属纯客户端表现层、不应触发存档异常，而 `Equipment`/`ItemObject` 等数据模型一旦破坏会直接进入存档路径。关于哪些类型可安全在边界外使用、哪些必须受 `try/catch` 保护，参见架构文档 [崩溃边界](../../architecture/crash-boundaries/)。

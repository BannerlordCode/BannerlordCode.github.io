# Clan

**Namespace:** `TaleWorlds.CampaignSystem`
**Module:** `TaleWorlds.CampaignSystem`
**Type:** `public sealed class Clan : MBObjectBase, IFaction`
**Source:** `TaleWorlds.CampaignSystem/Clan.cs`

## 概述

`Clan` 在战役里同时扮演两个角色，这一点决定了它的 API 形状。它既是**家族容器**（`Heroes`、`Companions`、`Fiefs`、`Villages`、`WarPartyComponents`），又是**势力**（实现 `IFaction`，有 `IsMapFaction`、`IsAtWarWith`、`GetStanceWith`、`FactionsAtWarWith`）。所以代码里 `Clan` 和 `Kingdom` 经常出现在同一段逻辑里互换——它们都实现同一个接口，差别在层级。

`sealed`。1.4.6 的声明是 `public sealed class Clan : MBObjectBase, IFaction`，类里 `virtual` 与 `abstract` 出现次数都是 0；四个 `protected` 成员（`AutoGeneratedInstanceCollectObjects` 的 override，以及 `PreAfterLoad` / `AfterLoad` / `OnBeforeLoad` 三个 override）全是基类要求的实现，sealed 之下不构成扩展点。所以没有一个可供派生覆盖的成员。想扩展只能走 [CampaignBehaviorBase](../CampaignBehaviorBase) 与 `IDataStore`，或者挂一个 Campaign 组件。

**`Clan` 与 `Kingdom` 是同一个接口的两个层级。** `MapFaction` 是这个设计的收敛点：家族加入王国后返回 `Kingdom`，没加入就返回自己。判断「这个家族现在算哪一方势力」永远读 `MapFaction`，不要读 `Clan` 本身。

## 心智模型

**`Leader` 是这个类的中枢，而且它可以是 null。** `Gold` 的实现直接写着「取 `Leader.Gold`，`Leader` 为 null 就返回 0」——**没有异常，只有一个静默的 0**。`GetRelationWithClan(other)` 同样是「两边 `Leader` 都有值才算，否则返回 0」。所以任何「读家族钱袋」的逻辑在无主家族上都会拿到 0，看起来像「这个家族没钱」，实际是「这个家族没人管钱」。写家族经济 mod 时先判 `clan.Leader != null`。

**`Tier` 永远不要直接写。** setter 是 private，而且写入时会用 `ClanTierModel.MinClanTier` / `MaxClanTier` 夹一次。公开的升级入口只有两个：`AddRenown(float value, bool shouldNotify = true)` 与 `ResetClanRenown()`。`AddRenown` 内部做了三件事：把 `Renown` 加上、**重算** tier、tier 变了就发 `OnClanTierChanged`。注意它**只处理正向增长**——`if (value > 0f)` 整个方法体包在里面，传 0 或负数是彻底的空操作，扣声望要直接写 `Renown` 再调 `ResetClanRenown()`。

**上限全部转给 `ClanTierModel` 现算，没有缓存。** `RenownRequirementForNextTier` 是 `ClanTierModel.GetRequiredRenownForTier(Tier + 1)`；`CompanionLimit` 是 `ClanTierModel.GetCompanionLimit(this)`；`WarPartyLimit` 是 `ClanTierModel.GetPartyLimitForTier(this, Tier)`。这三个每次访问都要过一次模型，深层循环里先取到局部变量。

**成员集合是缓存出来的，不是实时的。** `Heroes`、`AliveLords`、`DeadLords`、`Companions`、`Fiefs`、`Villages`、`Settlements`、`SupporterNotables`、`WarPartyComponents` 背后全是标着 `[CachedData]` 的私有 `MBList`，靠 `OnLordAdded` / `OnLordRemoved` / `OnCompanionAdded` / `OnWarPartyAdded` / `OnBoundVillageAdded` / `OnFortificationAdded` 这些 `internal` 方法维护；`AliveLords` 与 `DeadLords` 之间搬人则由公开的 `OnHeroChangedState` 负责。mod 代码碰不到这些维护方法，所以**任何直接改集合的操作都会让缓存永久失配**。唯一能从外部正确改变成员关系的公开入口是 `SetLeader(Hero leader)`。

**`SetLeader` 做的比看起来多。** 它写 `_leader`，并且在 `leader != null` 时**顺手把 `leader.Clan` 设成自己**。也就是说它同时改了两侧状态——只改一侧（比如只写 `hero.Clan`）会让 `Clan.Leader` 和 `Hero.Clan` 互相矛盾，而 `Clan.Heroes` 的缓存并不会因此重建。

**战况列表是手动刷新的。** `FactionsAtWarWith` 只是那个私有交战列表的投影，谁往里塞全靠 `UpdateFactionsAtWarWith()`——它清空后遍历 `Kingdom.All` 与 `Clan.All`，把非 `IsEliminated` 且 `IsAtWarWith` 的都加进去。读它之前先确认调用方刷过。真正的即时判定用 `IsAtWarWith(IFaction other)`，它转发 `FactionManager.IsAtWarAgainstFaction`，不依赖缓存。

**`Banner` 的 getter 有条件分支。** 家族是王国统治家族时返回 `Kingdom.Banner`，否则返回自己的 `_banner`。`ClanOriginalBanner` 才是无条件读 `_banner`。想读「这个家族本来的旗」用后者。

**`DistanceToClosestNonAllyFortification` 是唯一一处真正的缓存。** 它用一个私有的脏标志判断要不要重算，而那个标志是 `internal`——mod 代码**只能读不能失效它**——手动改地图拓扑后这个值不会自动重算。

**创立家族的正规路径。** `CreateClan(string stringID)` 内部先把 id 过一遍 `Campaign.Current.CampaignObjectManager.FindNextUniqueStringId<Clan>`，再 `new Clan()` 并 `AddClan(clan)` 登记进战役。`CreateSettlementRebelClan` 与 `CreateCompanionToLordClan` 都是在这个基础上补齐名字、文化、旗帜、领袖与起始封地。注意这两个工厂内部会写 `Tier` 和 `HomeSettlement` 这两个 private-set 成员，**从外部无法复刻**，要造反叛军家族就直接调它们。

**「被消灭」不是删除。** `IsEliminated` 是只读的，唯一的写入点是 `internal void DeactivateClan()`，它把 `_isEliminated` 置 true。家族对象仍在 `Clan.All` 里，仍可被查到，只是被所有遍历判定排除。

## 怎么用

### 怎么拿到它

`Clan` 有公开的无参构造器 `public Clan()`（`TaleWorlds.CampaignSystem/Clan.cs:1033`），但**你不要直接 new**——它只做初始化（`InitMembers()`、`_isEliminated = false`、`NotAttackableByPlayerUntilTime = CampaignTime.Zero`），不进世界列表。官方入口是：

`public static Clan CreateClan(string stringID)`（`Clan.cs:1041`），三步：先 `Campaign.Current.CampaignObjectManager.FindNextUniqueStringId<Clan>(stringID)` 拿到不重复的 id，再 `new Clan()`，最后 `Campaign.Current.CampaignObjectManager.AddClan(clan)`。也就是说**它必须在战役已建立时调用**。

现成的家族：静态属性 `public static Clan PlayerClan`（`:694`，内部就是 `Campaign.Current.PlayerDefaultFaction`）、`public static MBReadOnlyList<Clan> All`（`:1466`，内部 `Campaign.Current.Clans`）、`NonBanditFactions`（`:1476`）、`BanditFactions`（`:1506`）。查询用 `public static Clan FindFirst(Predicate<Clan> predicate)`（`:1447`，`FirstOrDefault`，找不到返回 null）和 `public static IEnumerable<Clan> FindAll(Predicate<Clan> predicate)`（`:1459`）。

### 典型用法

```csharp
using TaleWorlds.CampaignSystem;
using System.Collections.Generic;

// 建一个新家族（必须在战役里）
Clan rebels = Clan.CreateClan("my_mod_rebels");                 // Clan.cs:1041

Clan player = Clan.PlayerClan;                                 // :694

int allClans = Clan.All.Count;                                  // :1466 → Campaign.Current.Clans

// 查家族
Clan target = Clan.FindFirst(c => c.IsBanditFaction && !c.IsEliminated);   // :1447
if (target != null)
{
    // 影响力：有副作用的 setter，见下方「坑」
    target.Influence += 50f;                                      // :529
    target.AddRenown(100, Hero.MainHero);                          // 见页面成员表
    Hero leader = target.Leader;                                   // :705
}

// 两个家族之间的关系
int rel = player.GetRelationWithClan(target);                     // :1269
```

### 最容易踩的坑

**用 `new Clan()` 或直接写 `clan.Influence = x` 来改数值。** `Influence` 的 setter 带副作用：`if (value < this._influence && this.Leader != null) SkillLevelingManager.OnInfluenceSpent(this.Leader, value - this._influence);`（`Clan.cs:535-542`）。也就是说**只要把影响力调低**（不是调高），引擎就会拿 `Leader` 去走一整套技能结算；`Leader` 为 null 时这段被跳过，但 `Leader` 非 null 时你的 mod 会意外触发领主技能提升/AI 回调，而调用点完全看不出来。正确做法是走引擎的动作类（例如 `ChangeClanInfluenceAction.Apply(...)`）或 `AddRenown` 这类语义方法，让关系变化经由官方的 `CampaignEvents.HeroRelationChanged`（`CampaignEvents.cs:519`）广播出去，否则你的数值变了、各处缓存和 UI 却不知道。

第二个坑：`new Clan()` 出来的实例**不在 `Campaign.Current.Clans` 里**，`Clan.All`（`:1466`）、`FindFirst`/`FindAll`（`:1447`/`:1459`）全都看不到它，`GetRelationWithClan` 之类的关系计算也因为它不在世界列表而失效。要让它生效只能走 `CreateClan`（`:1041`）或 `CreateSettlementRebelClan` / `CreateCompanionToLordClan`（`:1722`/`:1756`）这类内部已经调过 `AddClan` 的工厂。

## 真实示例

每日按家族影响力排序，给前十名发奖励。三个坑都在这段里：`Influence` 的 setter 有副作用所以用 `AddRenown` 之外的方式时要小心、`Tier` 只能通过声望改、`Gold` 在无主家族上会静默给 0：

```csharp
public class ClanInfluenceBoard : CampaignBehaviorBase
{
    private readonly List<Clan> _ranked = new List<Clan>();

    public override void RegisterEvents()
    {
        CampaignEvents.DailyTickClanEvent += OnDailyTickClan;
    }

    public override void SyncData(IDataStore dataStore)
    {
        dataStore.SyncData("clanInfluenceRanked", ref _ranked);
    }

    private void OnDailyTickClan(Clan clan)
    {
        if (clan == null || clan.IsEliminated || !clan.IsMapFaction)
        {
            return;
        }

        _ranked.Clear();
        MBReadOnlyList<Clan> all = Clan.All;
        for (int i = 0; i < all.Count; i++)
        {
            if (!all[i].IsEliminated && all[i].Leader != null)
            {
                _ranked.Add(all[i]);
            }
        }

        _ranked.Sort((a, b) => b.Influence.CompareTo(a.Influence));

        int winners = _ranked.Count < 10 ? _ranked.Count : 10;
        for (int i = 0; i < winners; i++)
        {
            Clan top = _ranked[i];
            Debug.Print("#" + (i + 1) + " " + top.Name
                + " influence=" + top.Influence
                + " tier=" + top.Tier + "/" + top.RenownRequirementForNextTier, 0);
        }
    }
}
```

## 风险与边界

- **sealed，没有继承点**：1.4.6 声明为 `public sealed class`，零 `virtual`、零 `abstract`；四个 `protected` 成员全是基类要求的 override，不是扩展点。扩展走 [CampaignBehaviorBase](../CampaignBehaviorBase) 与 `IDataStore`。
- **`Gold` 只读且会静默给 0**：`Leader` 为 null 时返回 0 而不是抛异常。无主家族的钱袋在代码里和「穷光蛋」长得一模一样。
- **本类没有 `Find(stringId)`**：只有 `FindFirst` / `FindAll`，两者都建立在 `Clan.All` 上，而 `All` 转发 `Campaign.Current.Clans`——战役未建立时抛异常。
- **`Tier` 的 setter 是 private**：从外部直接赋值编译不过。走 `AddRenown` / `ResetClanRenown`，或者自己写 `Renown` 再调 `ResetClanRenown`。
- **`AddRenown` 对非正值是空操作**：`if (value > 0f)` 包住整个方法体。扣声望不会降阶。
- **`Renown` 是可写的公开字段**：绕过 `AddRenown` 直接写它，tier 不会自动跟着变。
- **`Aggressiveness` 的 setter 是 internal**：mod 代码改不了，而且引擎侧写入时也会被 `MathF.Clamp` 夹在 0..100。
- **`Tier` / `CompanionLimit` / `WarPartyLimit` / `RenownRequirementForNextTier` 每次访问都过模型**：深层循环里先缓存到局部变量。
- **成员集合是缓存投影**：`Heroes`、`Fiefs`、`Villages`、`Settlements`、`WarPartyComponents`、`SupporterNotables` 背后全是 `[CachedData]` 列表，靠 internal 维护方法更新。mod 直接改集合会让缓存永久失配。
- **`SetLeader` 会连带改 `Hero.Clan`**：只改一侧会让 `Clan.Leader` 与 `Hero.Clan` 矛盾，且 `Clan.Heroes` 缓存不会因此重建。
- **`FactionsAtWarWith` 不会自动刷新**：读之前必须有人调过 `UpdateFactionsAtWarWith()`。要实时判定就用 `IsAtWarWith`。
- **`Banner` 的 getter 有王国分支**：统治家族时返回的是王国的旗。要家族自己的旗读 `ClanOriginalBanner`。
- **`DistanceToClosestNonAllyFortification` 的失效标志是 internal**：手动改地图拓扑后 mod 无法让它重算。
- **`EndMercenaryService` 的布尔参数没被使用**：别指望它做「因为脱离王国而结束服役」的额外清理。
- **`IsEliminated` 只读**：`DeactivateClan` 是 internal。mod 造出来的家族无法走官方消灭流程，遍历时要自己判 `IsEliminated`。
- **`CalculateMidSettlement` 依赖地图场景**：`Campaign.Current.MapSceneWrapper` 为 null 时整段是空转，事后 `FactionMidSettlement` 会是 null。
- **`IFaction.IsKingdomFaction` 是显式实现且恒 false**：不要拿它和 `Clan.IsClan` 一起当成「这是不是王国」的两端。

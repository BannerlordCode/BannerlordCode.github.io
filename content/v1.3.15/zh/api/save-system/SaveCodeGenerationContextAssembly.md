# SaveCodeGenerationContextAssembly

> **一句话职责：** 存档系统在初始化阶段，针对每个加载进来的程序集，把其中所有可保存类型（类、结构体、容器）收集起来并生成对应的自动存档代码。

**命名空间：** `TaleWorlds.SaveSystem.Definition`
**模块：** SaveSystem
**类型：** `internal class SaveCodeGenerationContextAssembly`
**源文件路径：** `bannerlord-1.3.15/TaleWorlds.SaveSystem/Definition/SaveCodeGenerationContextAssembly.cs`

## 概述
存档系统并不是在每次点“保存”时临时反射分析类型，而是在模块加载、`DefinitionContext` 填充完所有可保存类型之后，进入一次性的代码生成阶段。SaveCodeGenerationContextAssembly 就是这次生成过程中“按程序集”分配的工作台：它持有该 assembly 的元数据（`Assembly`、`Location`、`FileName`、`DefaultNamespace`），并接收来自上层 `SaveCodeGenerationContext` 的 `TypeDefinition`、`StructDefinition` 与 `ContainerDefinition`。`Generate()` 会为这些类型逐个生成静态收集方法（`AutoGeneratedStaticCollectObjectsXxx`）、实例收集方法（`AutoGeneratedInstanceCollectObjects`）以及取成员值的委托，最后把所有片段拼成一个实现 `IAutoGeneratedSaveManager` 的 `AutoGeneratedSaveManager` 类。换句话说，你每次调用 `SaveManager.Save` 时真正在跑的“收集对象图”的反射替代代码，就是由这里产出的。

## 心智模型
把它想成“编译期的一次性印章机”，而不是运行期组件。每个被加载的程序集都会对应一个 SaveCodeGenerationContextAssembly 实例，由 `SaveCodeGenerationContext` 创建并填充；填充完成后调用一次 `Generate()`，把内存里的代码模型（`CodeGenerationContext` / `NamespaceCode` / `ClassCode` / `MethodCode`）渲染成字符串源码，再由运行时编译进内存。它只存在于模块初始化那一小段时间，保存和读取请求到达时它早已不在现场——现场跑的是它生成出来的 `AutoGeneratedSaveManager`。所以它没有“状态需要维护”，也没有“每次保存都要重建”的成本，真正的运行时开销被彻底前置了。也正因为它和某个具体 assembly 的版本/类型布局强绑定，任何对可保存类型的改名、增删字段却没重新走初始化流程，都会导致生成代码与运行时类型不一致。

## 何时用 / 何时不要用
- **不要用：** 这是 `internal` 类型，是存档系统自身的编译期脚手架。Modder 永远不应该、也无法直接 `new` 它或调用它的 `Generate` / `GenerateText`。
- **正确做法：** 想要保存游戏，直接调用 `SaveManager.Save(...)`；如果想让自定义类型参与自动序列化，给它加 `[SaveableRootClass]` / `[SaveableField]` / `[SaveableProperty]` 特性，剩下的代码生成由系统自动完成。

## 风险段
- **版本错位即灾难：** 生成代码与运行时类型布局必须一一对应。若你用 Harmony 之类的手段在初始化之后动态新增/重命名了可保存成员，却没有重新触发 `FillWithCurrentTypes` 与生成流程，运行时就会按旧偏移读取，造成静默的字段错位甚至崩溃。
- **internal 边界：** 它是 `internal`，跨模块直接反射调用会随游戏版本失效，不要依赖它。
- **只生成一次：** `Generate()` 会写入 `_managerMethod` / `_managerClass` 等字段，重复调用会叠加代码导致生成文件损坏；这属于系统内部保证，不应由外部触发。

## 成员说明
- `Assembly Assembly` / `string Location` / `string FileName` / `string DefaultNamespace`：该装配单元对应的程序集及其磁盘位置、默认命名空间，主要用于在生成代码里拼出正确的 `global::` 全名。
- `void AddClassDefinition(TypeDefinition)`：把一个可保存类登记进来，`Generate()` 会为它生成收集与取成员值代码。
- `void AddStructDefinition(TypeDefinition)`：同上的结构体版本，结构体按值语义处理（递归展开成员）。
- `void AddContainerDefinition(ContainerDefinition)`：登记 `List` / `Dictionary` / 数组 / `Queue` 等容器，`Generate()` 会按容器类型生成对应的 `AutoGeneratedStaticCollectObjectsForXxx` 委托。
- `bool CheckIfGotAnyNonPrimitiveMembers(TypeDefinition)`：判断一个类型是否包含引用类型或非基础类型的成员，决定生成代码是否需要递归收集子对象。
- `void Generate()`：核心步骤，遍历所有登记的定义，生成 `AutoGeneratedSaveManager` 的 `Initialize(DefinitionContext)` 方法体与各类型的收集/取成员方法。
- `string GenerateText()`：把 `CodeGenerationContext` 渲染为完整的 C# 源文本，交由运行时编译。

## 示例
```csharp
// SaveCodeGenerationContextAssembly 是 internal 的代码生成脚手架，modder 不直接调用。
// 你真正调用的是 SaveManager.Save；它底层依赖这里生成的 AutoGeneratedSaveManager 来收集对象图：
MetaData metaData = new MetaData();
SaveOutput output = SaveManager.Save(Game.Current, metaData, "mySlot", new AsyncFileSaveDriver());
if (!output.Success)
    Debug.Print(output.ErrorMessage);
```

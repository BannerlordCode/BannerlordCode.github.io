**Source facts to preserve:**

- `Hero` is `public sealed class Hero : MBObjectBase, ITrackableCampaignObject, ITrackableBase, IRandomOwner` in `TaleWorlds.CampaignSystem`.
- Constructors assign a unique id through `Campaign.Current.CampaignObjectManager`, register the Hero, and initialize `HeroState`; `CampaignObjectManager` maintains alive/dead lists and receives state changes.
- `Hero.MainHero`, `Hero.OneToOneConversationHero`, `Hero.Find`, `Hero.FindFirst`, `Hero.FindAll`, and `Hero.AllAliveHeroes` are real acquisition/query paths.
- `CurrentSettlement` is derived from party, prisoner party, or `StayingInSettlement`; `PartyBelongedTo` and prisoner ownership are lifecycle-managed rather than normal mod write points.
- `Gold` is clamped at zero and `GiveGoldAction.ApplyBetweenCharacters` routes through `ChangeHeroGold`, limits the giver's available gold, and dispatches the gold-trade event.
- `ChangeState` updates Campaign object-manager membership and dispatches activation/busy callbacks; `KillCharacterAction` handles death marks, party/clan cleanup, events, and `OnDeath` cleanup.
- `GetRelation` reads the effective diplomacy-model relation; relation changes should use `ChangeRelationAction` when a world change is intended. Kingdom membership is a Clan/Kingdom Action concern, not a Hero field write.
- `SaveableProperty` members are evidence that Hero state participates in save loading; a mod must not treat private save ids or `Hero` object graphs as its own save schema.
- `Clan.CreateClan` registers a clan; `Clan.Kingdom` updates caches but kingdom changes should use `ChangeKingdomAction`; influence changes should use `ChangeClanInfluenceAction`.
- `KingdomManager.CreateKingdom` is the complete kingdom creation path; `ChangeRulingClanAction`, `DeclareWarAction`, `MakePeaceAction`, and `DestroyKingdomAction` own their corresponding cascades.
- `MobileParty.CreateParty` creates and registers the party, its `PartyBase`, and component; movement, attachment, army, siege, roster, and destruction state must remain synchronized and destruction uses `DestroyPartyAction`.
- `Settlement` owns a `PartyBase` and a settlement component; town ownership is reflected through `OwnerClan` and changes use `ChangeOwnerOfSettlementAction` so garrison, governor, map-event, village, and notifications remain consistent.
- `PartyBase` is a shared downstream shell for the two party kinds and remains a linked dependency for this wave, not an additional deep page in this wave.

**Required page sections:**

- Every page has informative metadata and source path, then a type-specific mental model and lifecycle/state explanation rather than a shared template paragraph.
- Real acquisition examples use current engine paths such as `Hero.MainHero`, `Hero.Find`, `Hero.FindFirst`, `Clan.PlayerClan`, `Clan.All`, `Kingdom.All`, `MobileParty.MainParty`, `MobileParty.All`, `Settlement.CurrentSettlement`, or `Settlement.Find` as supported by the corresponding source.
- Each page explains the members that modders actually use, including timing and side effects: Hero state/location/relations, Clan membership/influence, Kingdom ruling clan/decisions/armies, Settlement ownership/components, and MobileParty leader/party component/AI/location.
- Safe world-change guidance contrasts entity reads with the relevant `GiveGoldAction`, `KillCharacterAction`, `ChangeRelationAction`, `AddCompanionAction`, `EndCaptivityAction`, `ChangeKingdomAction`, `ChangeRulingClanAction`, `DeclareWarAction`, `MakePeaceAction`, `DestroyPartyAction`, and `ChangeOwnerOfSettlementAction` routes.
- Explicit risks cover null or transitional Campaign state, dead Hero references, direct state/collection writes, unsynchronized Party/Settlement/Clan links, Mission-vs-Campaign lifetime confusion, and save/load cache ordering.
- Parent, sibling, children, related types, and architecture/crash-boundary links resolve under the existing clean-route rules; the two Campaign indexes expose the five entities as task-oriented child entries.
- English is a semantic translation of Chinese, not a signature-generated shell.

# AllianceOfferMapNotification

**Namespace:** `TaleWorlds.CampaignSystem.MapNotificationTypes`
**Module:** `TaleWorlds.CampaignSystem`
**Type:** `public class AllianceOfferMapNotification : InformationData`
**Base:** `InformationData`
**File:** `bin/TaleWorlds.CampaignSystem/TaleWorlds.CampaignSystem.MapNotificationTypes/AllianceOfferMapNotification.cs`

## 概述

`AllianceOfferMapNotification` 是「某国向你提议结盟」那条地图通知的数据载体。结构上极简：一个 [Kingdom](../Kingdom) 引用（谁提议）、一个 `CampaignTime`（截止时刻）、一段文本。真正的信息量在**两个 `if` 分支的落差**——玩家王国只有一个氏族时才发这条通知，多氏族王国根本走不到这里，而是直接往 `Kingdom.UnresolvedDecisions` 里塞一个决议走投票。

它是本桶里少数**会自己过期**的通知之一：`IsValid() => !TriggerTime.IsPast`，而 `TriggerTime` 在构造时算成 `CampaignTime.Now + Campaign.Current.Models.AllianceModel.DurationForOffers`，官方值是 24 小时（`Bannerlord.Source/bin/TaleWorlds.CampaignSystem/TaleWorlds.CampaignSystem.GameComponents/DefaultAllianceModel.cs:117`）。

## 心智模型

把它当成**「一个会自己走完生命周期的限时提议卡」**。完整链路只有四步：

1. **谁决定发。** `AllianceCampaignBehavior.OnAllianceOfferedToPlayerKingdom`（`Bannerlord.Source/bin/TaleWorlds.CampaignSystem/TaleWorlds.CampaignSystem.CampaignBehaviors/AllianceCampaignBehavior.cs:181`）：

   ```csharp
   if (Clan.PlayerClan.Kingdom.Clans.Count == 1)
   {
       TextObject textObject = new TextObject("{=1V8f9vRM}A courier bearing an alliance offer from the {PROPOSER_KINGDOM} has arrived at the court of your realm.");
       textObject.SetTextVariable("PROPOSER_KINGDOM", offeringKingdom.InformalName);
       Campaign.Current.CampaignInformationManager.NewMapNoticeAdded(new AllianceOfferMapNotification(offeringKingdom, textObject));
   }
   else
   {
       AddAllianceDecision(Clan.PlayerClan.Kingdom, offeringKingdom);
   }
   ```

   **「`Clans.Count == 1`」是这条通知的准入门槛**：玩家还在自己的单人氏族阶段（刚建档、没加入王国或王国只有他一个氏族），此时「你的王国」等于「你自己」，所以直接给个人提示。加入任何多人王国后，同一个提议走 `AddAllianceDecision` 进决议系统，**这条通知不再出现**。

2. **写。** `NewMapNoticeAdded` → `AddInformationData` → `MBInformationManager.AddNotice`。

3. **查表。** `_itemConstructors.Add(typeof(AllianceOfferMapNotification), typeof(AllianceOfferNotificationItemVM))`（`Bannerlord.Source/bin/TaleWorlds.CampaignSystem.ViewModelCollection/TaleWorlds.CampaignSystem.ViewModelCollection.Map/MapNotificationVM.cs:130`）。未注册静默丢弃。

4. **过期。** `CampaignInformationManager.OnGameLoaded` 每次读档执行 `_mapNotices.RemoveAll(t => t == null || !t.IsValid())`。**这是本类型与 [ArmyCreationMapNotification](../ArmyCreationMapNotification) 最大的分野**：成立通知不 override `IsValid()`、永不过期；本类型 override 了，所以读档时会被清掉。

最关键的心智锚点是**两个重载构造器的存在意义**。除了一般的 `(Kingdom, TextObject)`，还有一个 `(TextObject description)` 单参重载，它**不设置 `OfferingKingdom`、不设置 `TriggerTime`**——两个字段留在类型默认值（null / `CampaignTime.Zero`）。这不是给 mod 用的便利构造，而是**存档反序列化用的形状**：旧存档里若只存了描述文本，读出来就是这个样子。此时 `IsValid()` 会因为 `CampaignTime.Zero.IsPast` 为真而返回 false，通知读档即被丢弃。写代码时**不要用单参重载发通知**，那样发出去的卡片一进读档就没了。

第二个锚点是 **`TriggerTime` 依赖 `Campaign.Current.Models.AllianceModel`**。构造器第 46 行无条件读它，所以在 **`Campaign` 尚未建立时构造会 NRE**——单参重载不读它，两条路径的依赖强度不同。

## 真实示例

官方唯一构造形态，从 `AllianceCampaignBehavior.OnAllianceOfferedToPlayerKingdom` 照抄：

```csharp
if (Clan.PlayerClan.Kingdom.Clans.Count == 1)
{
    TextObject textObject = new TextObject("{=1V8f9vRM}A courier bearing an alliance offer from the {PROPOSER_KINGDOM} has arrived at the court of your realm.");
    textObject.SetTextVariable("PROPOSER_KINGDOM", offeringKingdom.InformalName);
    Campaign.Current.CampaignInformationManager.NewMapNoticeAdded(new AllianceOfferMapNotification(offeringKingdom, textObject));
}
else
{
    AddAllianceDecision(Clan.PlayerClan.Kingdom, offeringKingdom);
}
```

查这条通知还有多久过期（`IsValid()` 是 public，但 `CampaignInformationManager` 的 `_mapNotices` 列表是 **private**，没有公开枚举口，所以只能靠 `InformationDataExists<T>` 反查）：

```csharp
bool hasOffer = Campaign.Current.CampaignInformationManager.InformationDataExists<AllianceOfferMapNotification>(null);
Debug.Print("pending alliance offers = " + hasOffer, 0);
Debug.Print("offer window = " + Campaign.Current.Models.AllianceModel.DurationForOffers.ToString(), 0);
```

在 mod 里发一张自定义结盟要约（王国按 `StringId` 从 `Kingdom.All` 里找，`CampaignTime` 用 `HoursFromNow` 而不是不存在的 `Add`）：

```csharp
Kingdom target = Kingdom.All.Find((Kingdom k) => k.StringId == "empire");
if (target != null)
{
    TextObject note = new TextObject("{=mykey3}{PROPOSER} offers you an alliance.");
    note.SetTextVariable("PROPOSER", target.InformalName);
    Campaign.Current.CampaignInformationManager.NewMapNoticeAdded(new AllianceOfferMapNotification(target, note));
    Debug.Print("expires around " + CampaignTime.HoursFromNow(24f).ToString(), 0);
}
```

## 风险与边界

- **单参重载是个陷阱。** `AllianceOfferMapNotification(TextObject)` 不设 `TriggerTime`，`TriggerTime` 留在 `CampaignTime.Zero`，`IsValid()` 恒 false。**用它发通知 = 发一张下次读档就被删掉的卡片。** 只有存档反序列化该走这条路。
- **准入门槛是「玩家单人氏族」。** `Clans.Count == 1` 才发通知。多氏族王国走 `AddAllianceDecision` 投票路线。mod 里若绕过这个门槛硬发，语义上等于替玩家王国做了「可以直接拍板」的假设。
- **构造器依赖 `Campaign.Current.Models.AllianceModel`。** 第 46 行无条件解引用 `Campaign.Current` 与 `Models`。**`OnSubModuleLoad` 阶段构造会 NRE**；单参重载不读它，这是两条路径依赖强度的差异。
- **`IsValid()` 只在读档时被批量调用。** `CampaignInformationManager.OnGameLoaded`（第 91 行）里的 `RemoveAll(t => t == null || !t.IsValid())` 是本类型唯一的自动淘汰点。运行期是否有别的轮询取决于 UI 层——不要假设「24 小时后它会自己消失」。
- **通知列表是私有的，无法直接枚举。** `CampaignInformationManager._mapNotices` 是 `private List<InformationData>`（第 25 行），公开出口只有 `NewMapNoticeAdded`（写）与 `InformationDataExists<T>`（查）。想遍历当前所有通知，mod 只能反射或者自己在发通知时记一份账。
- **`OfferingKingdom` 可能为 null。** 只有存档形状会这样；VM 的按钮回调会把它传给行为方法，判空责任在调用方。
- **`DurationForOffers` 是可换的 Model 值。** 换掉 `AllianceModel` 就等于换掉本类型的寿命；想延长要 override `DurationForOffers` 而不是改这里。
- **必须注册 VM。** 未在 `_itemConstructors` 登记的类型被静默丢弃。
- **存档 id 是 1 和 2。** 加字段从 3 起，且必须同步 `AutoGeneratedSaveManager` 的 `AutoGeneratedGetMemberValueOfferingKingdom` / `...TriggerTime` 注册。
- **音效与宣战要约共用。** `event:/ui/notification/peace_offer` 同时被本类型与 [AcceptCallToWarOfferMapNotification](../AcceptCallToWarOfferMapNotification) 使用——做音效 mod 时改一处会同时影响两条。

# sandbox：官方沙盒玩法（`SandBox*`）

> **覆盖状态：本桶 0 张类页。**
> 先说结论：**这是官方玩法的实现代码，不是给 mod 调用的 API 面。** 本页要回答的是「我要改的东西跟它什么关系」，而不是「它有哪些方法」。页面上出现的类型名全部是纯文本，**没有任何一个指向尚未撰写的类页**。

## 这个桶在源码里对应什么

归属规则只有一条前缀 `SandBox` → `sandbox`。前缀匹配，所以 `SandBox.*` 下的所有子命名空间都在本桶。`bannerlord-1.4.6/` 下的 6 个相关目录与实测规模：

| 源码目录 | `.cs` 文件数 | 里面是什么 |
| --- | --- | --- |
| `SandBox/` | 269 | 沙盒战役玩法的实现：任务、遭遇、城镇经营、巷战、竞技场、地下城、教程 |
| `SandBox.View/` | 125 | 沙盒专属的官方界面 |
| `SandBox.ViewModelCollection/` | 96 | 沙盒专属的官方界面数据类（锻造、工坊、部队整备等） |
| `SandBox.GauntletUI/` | 79 | 沙盒的 Gauntlet 部件与预制体 |
| `SandBox.GauntletUI.AutoGenerated.0/` | 395 | 由 prefab 生成的类，权威排除清单按 `AutoGenerated` 后缀排除 |
| `SandBox.GauntletUI.AutoGenerated.1/` | 232 | 同上 |
| **合计** | **1196** | |

在这个范围里以 `SandBox` 开头的命名空间有 **32** 个，命名空间级类型声明数 **1178**。

**两个 `AutoGenerated` 目录是被权威排除清单排除掉的**，不生成任何页面。所以你在 [模块地图](../../architecture/module-map) 里看不到它们，但它们在磁盘上、在你 grep 的时候会出现——**这是预期行为，不是文档漏了**。

**口径定义**：`.cs 文件数` = `find <目录> -name '*.cs' | wc -l`；`命名空间级类型声明数` = 命名空间以该前缀开头的文件里，缩进恰好一个制表符的类型 / 委托声明行数，**不含嵌套类型**。

## 规模里有多少是生成物

按「文件名里含双下划线的 `.cs` 文件数」这个可复跑的口径统计：

```bash
find bannerlord-1.4.6/SandBox bannerlord-1.4.6/SandBox.View \
     bannerlord-1.4.6/SandBox.ViewModelCollection bannerlord-1.4.6/SandBox.GauntletUI \
     bannerlord-1.4.6/SandBox.GauntletUI.AutoGenerated.0 bannerlord-1.4.6/SandBox.GauntletUI.AutoGenerated.1 \
     -name '*.cs' | wc -l            # → 1196
find bannerlord-1.4.6/SandBox* -name '*__*.cs' | wc -l   # → 623
```

也就是 1196 个文件里有 623 个（约一半）带生成物命名特征。加上那两个 `AutoGenerated` 目录本身就占了 627 个文件，**所以「1178 个声明」这个数字里有一大半是不该写页面的 prefab 产物**。真正手写的沙盒玩法类型是两位数到几十的量级，不是四位数。**本桶的价值不在类型数量。**

顺带一个命名空间的坑：`SandBox/` 目录下有一个 `Sandbox/` 子目录（拼写不同，少了一个 `B`），里面只有一个文件 `AutoGeneratedSaveManager.cs`。权威映射把 `Sandbox` 列进 `sourceTypoNamespaces`，**明确排除、不建页**——所以别把 `SandBox` 和 `Sandbox` 混着写。

## 读源码：可复跑的查法

在工作区根目录执行：

```bash
# 本桶到底覆盖哪些目录
ls -d bannerlord-1.4.6/SandBox*

# 有哪些 SandBox 开头的命名空间
grep -rhoE '^namespace SandBox[A-Za-z0-9_.]*' bannerlord-1.4.6/SandBox* --include='*.cs' | sort -u

# 「沙盒挂了哪些战役行为」——本桶最该读的那个问题
grep -rln 'CampaignBehaviorBase' bannerlord-1.4.6/SandBox --include='*.cs' | head -30

# 从模块入口读起
grep -n 'class SandBoxSubModule' bannerlord-1.4.6/SandBox/SandBoxSubModule.cs

# 排除生成物后再看真实类型
find bannerlord-1.4.6/SandBox -name '*.cs' ! -name '*__*' | head -40
```

## 什么时候会碰到它

**你的 mod 从不「调用」沙盒实现，它只是和沙盒住在同一张战役图上。** 三种真实关系，按重要性排序：

1. **插入点关系（最主要）。** 你的行为会和沙盒自带的一批行为一起被加进战役。想知道「沙盒都挂了哪些行为、挂的顺序是什么」，答案在 `SandBoxSubModule` 里。这就是为什么 mod 作者要读本桶——**不是为了调它，是为了知道自己在跟谁抢同一个位置**。要挂行为本身，写的是 [campaign](../campaign) 桶的 `CampaignBehaviorBase` + 战役启动流程。
2. **场景关系（少数 mod）。** 地下城遭遇、竞技场决斗、巷战小游戏这些是沙盒特有的玩法对象。如果你做一个「所有地下城都给奖励」的 mod，你需要认识沙盒的遭遇类型和它们的完成条件。这条路最终会走到本桶。
3. **界面参考（抄写法）。** `SandBox.View` 里的官方界面骨架，以及 `SandBox.ViewModelCollection` 里的少数几个沙盒专属界面数据类，是现成范例。**注意一个容易踩的坑**：锻造（`CraftingVM`）、工坊、部队整备这些看着像「沙盒界面」的类，实际命名空间是 `TaleWorlds.CampaignSystem.ViewModelCollection`，落在 [viewmodel](../viewmodel) 桶，**不在本桶**。别按界面名字猜桶，要按命名空间查。

**心智模型**：把 `SandBox` 想成「官方战役的第一批 mod」。它是玩家装游戏时默认就有的一个大 mod，做的正是你打算做的事（加任务、加行为、改数值、加界面）。所以读它的正确姿势是**对照**——看它怎么用 `CampaignBehaviorBase`、怎么注册游戏模型、怎么在模块入口里挂东西，然后照着做你的一份。**先读 [core](../core) 的模块入口类、再读 [campaign](../campaign) 的 `CampaignBehaviorBase`，再读这里。**

**边界**：本桶里的类型是官方内容实现，没有向后兼容承诺。**不要继承沙盒的任务 / 行为类来做扩展**——它们会在下个版本被改掉。正确做法是继承稳定的基类（`CampaignBehaviorBase`、`MissionBehavior`、`MBSubModuleBase`），把沙盒类型当作**只读的数据来源和参照**。

## 按目录分组的代表性类型（非链接，全部核实，未撰写类页）

下面每个名字都用 `grep -rw` 在对应的 `SandBox*` 目录里核实过。**这是按用途挑的代表性索引，不是待补清单，它们全部没有类页。**

从 `SandBox/`：

- `SandBoxSubModule` — 沙盒玩法的模块入口，**本桶最值得写一页的类型**。要理解「沙盒挂了哪些战役行为派生类、按什么顺序」，从这里读起。写法与 [core](../core) 的模块入口同源
- `SandBoxMissions` — 沙盒相关的 mission 创建入口
- `SandBoxSaveManager` — 沙盒的存档类型注册
- `ArenaDuelMissionController` / `ArenaPracticeFightMissionController` — 竞技场决斗 / 练武的实现
- `ArenaDuelQuestTask` / `ArenaDuelMissionBehavior` — 竞技场任务的步骤与行为
- `AlleyCampaignBehavior` — 巷战（暗巷）玩法对应的战役行为，是「沙盒专属行为」的一个好例子
- `ArenaMasterCampaignBehavior` — 竞技场主持人行为
- `MapEntityVisual` / `EntityVisualManagerBase` — 地图实体的视觉表现（聚落图标之类），属于表现层，改地图图标时才需要

从 `SandBox.View/`（**全部 10 个命名空间级类型，可以全列**）：

- `SandBoxViewSubModule` — 沙盒界面子模块的入口
- `SandBoxViewCreator` / `SandboxView` / `SandBoxViewVisualManager` — 官方界面的创建与视觉管理，抄自定义界面时参照这三个
- `PreloadScreen` / `SaveLoadScreen` — 预载与存读档界面；这两个是沙盒最常被 mod 改的官方界面
- `CampaignMusicHandler` — 战役音乐处理
- `MainHeroSaveVisualSupplier` — 主角外观在存档里的视觉来源
- `IChangeableScreen` — 可切换外观的屏幕接口
- `SandBoxViewCheats` — 调试用的作弊界面

从 `SandBox.ViewModelCollection/`（**全部 5 个命名空间级类型，可以全列**）：

- `TournamentRewardVM` — 锦标赛奖励界面
- `SPOrderOfBattleVM` / `SPScoreboardVM` — 单人模式的战前布阵与计分板
- `SandBoxUIHelper` — 沙盒界面的公共辅助
- `PerkObjectComparer` — 专长（perk）对象的比较器，排序列表时用

从 `SandBox.GauntletUI.AutoGenerated.*`：**不列。** 这两个目录是 prefab 生成物，权威排除清单已排除，不要为它们建页，也不要按双下划线拼接名反查——那种类名是同一套生成机制的产物，按命名空间查桶才准。

# 墓碑 · `tools/_v146_prose_name_check.mjs`（已删除，勿重建同形）

日期：2026-08-22 · 裁决：boss-1 · 实测：worker-61（报告全文见 `_V146_PROSE_NAME_CHECKER_VERDICT.md`）

## 它曾经声称能测什么
从散文（剥掉 ` ```csharp ` 代码块后）提取 PascalCase 标识符，到 `bannerlord-1.4.6` 源码全树做整词匹配，报出「页面出现但源码没有」的词元，输出 `TOTAL_MISSING`。设计隐含假设：**页面出现 PascalCase 字符串 = 页面声称存在该类型**。

## 实测两头各是多少（同一份 104 页快照，同进程内跑完）
| 档 | 口径 | 阳性(页/20) | 阴性误报(页/20) | 真实语料 missing(条) |
|---|---|---|---|---|
| M0 | 现状 | 20/20 | **14/20** | 430 |
| M1 | +词边界 | 20/20 | **6/20** | 153（97 unique） |
| M2 | +否定句 | 20/20 | **6/20** | 136 |
| M3 | M1+白名单 | 20/20 | **6/20** | 20 |

**达标线：阳性 ≥18 且阴性 ≤2。四档无一达标，最好 30% 误报率。**

## 决定性证据
- **M1 档 97 个 unique miss 里，被判定为「源码声明过的类型」的是 0 个** —— 这把自称反查类型名的尺，**在真实语料上从未命中过一个类型**。
- 噪声 **133/153 = 86.9%**（PROPER_NOUN / PLACEHOLDER / FAMILY_WILDCARD / CAMEL_ARTIFACT / FILE_NAME / FIELD_NAME / 否定句内被提及的名字…）。
- **白名单只记忆、不泛化**：白名单由真实语料反推，跑完语料精确率 100%，但阴性仍 6/20 —— 因为 4 个噪声名根本不在语料里。

## 为什么删除而不是调参
**设计前提坏了，不是参数问题。** 它没有「声明锚点」概念：占位符、族名简写、缩写、字段名、字面值、被页面自己否定的名字，全都分不开。加词边界（M1）是唯一真实改进（unique 350→97，且 253/253 均为片段误报、零真阳性损失），但**仍远不达标**。

## 三条不要重蹈的坑（已写进规范）
1. **校验器用自己构造的样本验证自己 = 用同一把尺量自己。** worker-61 首版把 lowerCamel 形参当类型声明塞进阳性集，而报形参名本身就是误报；修掉后首轮那个 20/20 是假的。同形态第三次出现（worker-55 的循环白名单、worker-61 的 M3 达标靠自填 allowlist）。
2. **在已知良品上测误报不能省。** 白名单从自己样本学 → 0/20 完美；换成真实语料独立分类反推 → 立刻回到 6/20。
3. **判别力实测必须用已知输入，不是「结果看起来对不对」。** 本次抓到 5 处「数字完全正常但实现已坏」：token 索引缺前置否定边界、循环漏抄 ALLOW 集、白名单写成「另起一轮」而非事后抑制（抑制完全失效）、档位偷继承另一档的过滤、性能对比拿 selftest 与全语料混用。

## SCOPE_GAP —— 这是尺的边界，不是页面的错（单独记账，勿去「修」）

# IMBEditor

**Namespace:** TaleWorlds.MountAndBlade
**Module:** TaleWorlds.MountAndBlade
**Type:** `internal interface IMBEditor`
**Base:** none
**File:** `bin/TaleWorlds.MountAndBlade/TaleWorlds.MountAndBlade/IMBEditor.cs`

## Overview

`IMBEditor` is the managed-to-native seam for **the scene editor and the replay manager**. It is 96 lines with 29 `[EngineMethod]` bindings, and it covers five concerns: entering and leaving edit mode (`IMBEditor.cs:32`, `:38`, `:41`, `:44`, `:86`), driving the editor camera and scene tree (`:29`, `:17`, `:65`), entity selection and mesh preview (`:20`, `:26`), surfacing problems to the editor UI (`:23`, `:68`, `:71`), and the scene-editor presentation loop plus level/physics toggles (`:47`, `:50`, `:53`, `:77`, `:80`, `:83`).

The wrapper is [`MBEditor`](../../mission-ext/MBEditor), a `public class` (`MBEditor.cs:9`) with **29 forward sites** (`grep -c 'MBAPI.IMBEditor\.'` is 29). But the count is deceptive and this page is explicit about why: two of the forwards are the two `IsEntitySelected` overloads hitting the same bridge member (`MBEditor.cs:63`, `MBEditor.cs:68`), and `SetLevelVisibility` is **never forwarded at all** — its public wrapper has an empty body (`MBEditor.cs:213-215`).

## Mental Model

### What it is / which layer

- It is **editor-only tooling exposed to game code**. Every member here assumes a scene editor exists: `IsEditMode` and `IsEditModeEnabled` (`IMBEditor.cs:11`, `:14`) are how you ask, and in a shipping game both are false and every other call is meaningless.
- It has a **lifecycle with an explicit enter/leave pairing** that must be respected: `EnterEditMode` (`IMBEditor.cs:32`) is matched by `LeaveEditMode` (`:38`) *and* separately by `ExitEditMode` (`:86`) — two different exit symbols, which is the first sign this interface grew organically rather than from a design.
- The **mission-facing half** is a distinct mode: `EnterEditMissionMode` / `LeaveEditMissionMode` (`IMBEditor.cs:41`, `:44`) attach the editor to a live `Mission`, whereas `EnterEditMode` / `LeaveEditMode` attach it to a bare `SceneView`. The wrapper makes the difference visible by typing them differently — `MBEditor.EnterEditMissionMode(Mission)` (`MBEditor.cs:99`) versus `MBEditor.EnterEditMode(SceneView, ...)` (`MBEditor.cs:81`).

### The consequence that matters

**`MBEditor.SetLevelVisibility(List<string>)` compiles, runs, and does nothing.** Its body is empty (`MBEditor.cs:213-215`) — no bridge call, no guard, no `Debug.Print`. So `IMBEditor.SetLevelVisibility` (`IMBEditor.cs:80`) is unreachable *through the public wrapper*, not because the wrapper is missing but because the wrapper is hollow. This is the trap on this page: the normal advice "it's internal, use the public wrapper" produces code that silently fails, and the failure is invisible at runtime because the method returns `void` and raises nothing. The sibling method one line below it, `SetUpgradeLevelVisibility(List<string>)`, *is* real — it joins the list with `|` and forwards it (`MBEditor.cs:202-211`), which is what the bridge's `cumulated_string` parameter means.

### When to use / when not

- **Use** the three replay-state queries (`IsReplayManagerRecording`, `IsReplayManagerRendering`, `IsReplayManagerReplaying`, `IMBEditor.cs:89`, `:92`, `:95`) from mod code that must not disturb a recording, and the warning-reporting members when your mod wants its problems surfaced in the editor rather than only in a log.
- **Do NOT** call the edit-mode members from gameplay code.** Entering edit mode is an editor action with an editor-only lifecycle; calling it from a mission tick puts the game into a state the mission loop does not expect.
- **Do NOT** rely on `SetLevelVisibility`. It does nothing (`MBEditor.cs:213-215`).

## How to use

**How to obtain it.** You cannot reference the interface: it is `internal` (`IMBEditor.cs:8`), the `MBAPI` field is `internal static` (`MBAPI.cs:22`), and `TaleWorlds.MountAndBlade` grants `InternalsVisibleTo` only to `TaleWorlds.MountAndBlade.AutoGenerated`, `TaleWorlds.MountAndBlade.Multiplayer` and `TaleWorlds.Generator.Bannerlord` (`TaleWorlds.MountAndBlade/Properties/AssemblyInfo.cs:8-10`).

The door out is [`MBEditor`](../../mission-ext/MBEditor), `public class MBEditor` at `MBEditor.cs:9` — publicly usable even though it holds only static members. The one exception is `SetLevelVisibility`, whose public signature exists but whose body is empty (`MBEditor.cs:213-215`).

**A typical use.** Ask whether a replay is in progress before doing anything that would corrupt it, and report a problem to the editor UI:

```csharp
using TaleWorlds.MountAndBlade;

public class ReplaySafeSpawn : MissionLogic
{
    public override void OnAgentRemoved(Agent affectedAgent, Agent affectorAgent,
                                        AgentState agentState, KillingBlow blow)
    {
        base.OnAgentRemoved(affectedAgent, affectorAgent, agentState, blow);

        // MBEditor.IsReplayManagerReplaying / IsReplayManagerRecording /
        // IsReplayManagerRendering are public static (MBEditor.cs:162, :167, :172)
        // forwarding to the bridge at IMBEditor.cs:95, :89, :92.
        if (MBEditor.IsReplayManagerRecording() || MBEditor.IsReplayManagerReplaying())
        {
            Debug.Print("unit removed during a replay; skipping side effects", 0);
            return;
        }
    }

    public static void ReportAnomaly(string message)
    {
        // Public static (MBEditor.cs:177) -> IMBEditor.cs:23.
        // Surfaces the message in the editor's warning list.
        MBEditor.AddEditorWarning(message);
    }
}
```

**What to watch out for.** Two things, in this order. First, do not reach for `MBEditor.SetLevelVisibility` — it is a no-op (`MBEditor.cs:213-215`), so a level-visibility change you believe you made never happens and nothing tells you. Second, note that `MBEditor` is a `public class` whose members are all `public static`; nothing about its declaration says "editor only", so a modder scanning for available API can easily call editor members from map-layer code where they return `false` or do nothing.

## Examples

Gate mod side effects on replay state, which is the sanctioned use of this bridge:

```csharp
using TaleWorlds.MountAndBlade;

public class ReplayGuard : MissionLogic
{
    public override void OnMissionTick(float dt)
    {
        base.OnMissionTick(dt);

        // All three are public static on MBEditor (MBEditor.cs:162, :167, :172).
        // Recording and rendering are independent, so check the one you mean.
        bool busy = MBEditor.IsReplayManagerRecording()
                 || MBEditor.IsReplayManagerRendering()
                 || MBEditor.IsReplayManagerReplaying();

        if (busy)
            return;   // do not mutate anything the replay is capturing
    }
}
```

Query the editor without entering it — safe anywhere, because both are pure reads:

```csharp
using TaleWorlds.MountAndBlade;

public static class EditorProbe
{
    public static void Describe()
    {
        // MBEditor.cs:17 and :19. In a shipping game both are false.
        Debug.Print("edit mode on: " + MBEditor.IsEditModeOn, 0);
        Debug.Print("edit mode allowed: " + MBEditor.EditModeEnabled, 0);
    }
}
```

Surface a mod problem where a scene author will see it:

```csharp
using TaleWorlds.Engine;
using TaleWorlds.MountAndBlade;

public static class ModWarnings
{
    public static void ReportSceneProblem(Scene scene, string what)
    {
        // General form — no handles needed (MBEditor.cs:177 -> IMBEditor.cs:23).
        MBEditor.AddEditorWarning("MyMod: " + what);

        // Entity form — needs a live entity (MBEditor.cs:182 -> IMBEditor.cs:68).
        // Only pass an entity from the current scene.
        GameEntity marker = scene.GetFirstEntityWithTag("MyModMarker");
        if (marker != null)
        {
            MBEditor.AddEntityWarning(marker, "MyMod: marker used as a spawn point");
        }
    }
}
```

## Risks and crash boundaries

- **A mod cannot name the interface.** `internal interface` (`IMBEditor.cs:8`) plus `internal static MBAPI` field (`MBAPI.cs:22`) plus `InternalsVisibleTo` limited to three TaleWorlds assemblies (`TaleWorlds.MountAndBlade/Properties/AssemblyInfo.cs:8-10`). Compile-time failure.
- **`MBEditor.SetLevelVisibility` is a silent no-op.** Empty body at `MBEditor.cs:213-215`. No exception, no return value, no warning. This is the single most dangerous entry on this page because it *looks* functional.
- **Editor state is uninitialised outside edit mode.** `TickEditMode` (`IMBEditor.cs:35`) and `TickSceneEditorPresentation` (`IMBEditor.cs:53`) contain no `IsEditMode` guard in the managed code, so calling them when the editor is not up drives state that was never set. In a shipping game that path is simply never valid.
- **Two exits, one entry.** `LeaveEditMode` (`IMBEditor.cs:38`) and `ExitEditMode` (`IMBEditor.cs:86`) are separate native symbols for leaving, and the source does not explain the distinction. Which to call is **UNRESOLVED**; pick the one matching how you entered and do not call both.
- **Raw pointers throughout.** `sceneWidgetPointer`, `entityId`, `sceneId` and `metaMeshId` are `UIntPtr` values taken from managed handles (`MBEditor.cs:83`, `:184`, `:189`, `:73`). Handles from a torn-down scene are freed native addresses.
- **`ToggleEnableEditorPhysics` has no getter.** You can flip it (`IMBEditor.cs:83`) but cannot read it back through this bridge, so a mismatch between your belief and reality is undetectable.
- **`GetAllPrefabsAndChildWithTag` returns an unparsed string.** The wrapper returns it unchanged (`MBEditor.cs:192-195`) and no separator is documented, so string-splitting it is guesswork.
- **Not a save participant.** No `[Serializable]`, no state; editor and replay queries are session-only.

## Cross-Version Notes

The v1.4.5 file is 96 lines with 29 `[EngineMethod]` bindings, and the same file name and namespace appear under the same `Bannerlord.Source/bin/TaleWorlds.MountAndBlade/TaleWorlds.MountAndBlade/` layout in the `bannerlord-1.3.0` and `bannerlord-1.3.15` trees. The **native symbol strings** are the stable contract, and the editor symbol set is among the slowest-changing in the engine. Two things are worth flagging as version-sensitive. First, `MBEditor.SetLevelVisibility`'s hollow body (`MBEditor.cs:213-215`) is a managed-side decision with no native symbol protecting it, so a later version may well have filled it in — do not carry "this is a no-op" forward as an engine-wide truth. Second, the `LeaveEditMode` / `ExitEditMode` duplication (`IMBEditor.cs:38`, `:86`) is the kind of redundancy that tends to collapse to one symbol, which would be a breaking change for a wrapper calling the other. **VERIFIED MEASURED for v1.4.5** (96 lines, 29 members, 29 forward sites in the complete 221-line `MBEditor.cs`); the sibling version trees were not read member-by-member for this page.

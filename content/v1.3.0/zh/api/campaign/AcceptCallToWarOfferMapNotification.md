# AcceptCallToWarOfferMapNotification

**Type:** `public class AcceptCallToWarOfferMapNotification : InformationData`
**Base:** [InformationData](../../core-extra/InformationData)

## 概述

`AcceptCallToWarOfferMapNotification` 是**地图角标上那条「参战号召已被响应」的通知**。它只有 5 个 public 成员：三个 `[SaveableProperty]` 属性、两个 `public override`（`TitleText` / `SoundEventPath`）加一个 `IsValid`。**没有方法，除了构造函数。**

它继承 [InformationData](../../core-extra/InformationData)——那是所有地图通知的基类，负责正文 `Description`。本类覆写的是**标题**与**音效**。

**三个存档属性**（注意编号 1/2/3，与基类的字段编号空间分开）：

- `[SaveableProperty(1)] public Kingdom OfferingKingdom { get; private set; }` —— 响应号召的王国
- `[SaveableProperty(2)] public Kingdom KingdomToCallToWarAgainst { get; private set; }` —— 要打的敌方王国
- `[SaveableProperty(3)] public CampaignTime TriggerTime { get; private set; }` —— **通知的过期时刻**

**`TriggerTime` 在带王国的那个构造器里算出来**：`this.TriggerTime = CampaignTime.Now + Campaign.Current.Models.AllianceModel.DurationForOffers;`。它依赖 [AllianceModel](../AllianceModel) 的 `public abstract CampaignTime DurationForOffers { get; }`（`:24`）——所以**通知的有效期由模型决定，覆盖那个模型就能改所有这类通知的停留时长。**

**`IsValid()` 判的是时间，不是外交状态。**

```csharp
public override bool IsValid()
{
    return !this.TriggerTime.IsPast;
}
```

**一行。** 它不管王国是否被消灭、参战协议是否已结束——**那些状态一变，通知还留在地图上**（直到时间到）。这是本页最实用的一条边界。

## 心智模型

把它当成**「一条带倒计时的静态横幅」**，四段定位：

**第一段：两个构造器，两种语义。** 带王国的那个是三参数：`public AcceptCallToWarOfferMapNotification(Kingdom offeringKingdom, Kingdom kingdomToCallToWarAgainst, TextObject descriptionText) : base(descriptionText)`——它设两个 Kingdom 属性**并顺带算出 `TriggerTime`**。另一个是 `public AcceptCallToWarOfferMapNotification(TextObject description) : base(description)`——**什么都不设**，`OfferingKingdom` 与 `KingdomToCallToWarAgainst` 为 null，`TriggerTime` 是 `default(CampaignTime)`。

**第二个构造器是存档反序列化用的**，不是给 mod 用的。用它 new 出来的通知，`IsValid()` 立刻返回 `!default(CampaignTime).IsPast`。`default(CampaignTime)` 的内部值是什么取决于 `CampaignTime` 的字段布局——但无论具体值如何，**一个零值时间不可能晚于「现在」，所以 `IsValid()` 几乎必然为 false**。结论：**永远用三参数构造器。**

**第二段：标题与音效是硬编码的。**

```csharp
public override TextObject TitleText
{
    get { return new TextObject("{=*}Accept Call To War Offer", null); }
}

public override string SoundEventPath
{
    get { return "event:/ui/notification/peace_offer"; }
}
```

**标题每次读都 `new` 一个 `TextObject`**——不是缓存字段，是 getter 里现造。`{=*}` 前缀表示「英文原文、走本地化回退」。**音效复用的是 `peace_offer` 而不是参战专用音效**——这是 1.3.0 的现状，读它时别以为有个 `call_to_war_offer` 之类的键。

**第三段：`InformationData` 基类负责什么。** 基类提供 `Description`（构造器第一个参数传进去的那个 `TextObject`）以及存档机制。本类的 `AutoGeneratedInstanceCollectObjects` 覆写把三个属性全收集了：

```csharp
base.AutoGeneratedInstanceCollectObjects(collectedObjects);
collectedObjects.Add(this.OfferingKingdom);
collectedObjects.Add(this.KingdomToCallToWarAgainst);
CampaignTime.AutoGeneratedStaticCollectObjectsCampaignTime(this.TriggerTime, collectedObjects);
```

**注意第三行是特殊的** —— `CampaignTime` 是 `struct`，所以它用的是**静态**收集方法 `CampaignTime.AutoGeneratedStaticCollectObjectsCampaignTime(...)` 而不是 `collectedObjects.Add(...)`。前两个是引用类型，直接 Add。

**第四段：谁产生它。** 它由 [AllianceCampaignBehavior](../AllianceCampaignBehavior) 在参战协议启动时创建。类名里的 `Accept...` 是「已被接受」的意思——**这是协议已经成立之后的事后通知，不是「请求你接受」的邀请**。要发邀请的是 `ProposeCallToWarOfferMapNotification`（另一个类型）。

## 真实示例

造一条有效的通知并交给地图通知管理器（照抄 `AllianceCampaignBehavior.cs:128` 的形状）：

```csharp
Kingdom offering = Hero.MainHero.Kingdom;
Kingdom target = Campaign.Current.Kingdoms.First(k => k.IsAtWarWith(offering));

AcceptCallToWarOfferMapNotification notification =
    new AcceptCallToWarOfferMapNotification(
        offering,
        target,
        new TextObject("{=myCallToWar}Your kingdom has joined the war.", null));

if (notification.IsValid())
{
    Campaign.Current.CampaignInformationManager.NewMapNoticeAdded(notification);
    Debug.Print("expires at " + notification.TriggerTime, 0);
}
```

入口是 `public void NewMapNoticeAdded(InformationData informationData)`（`CampaignInformationManager.cs:86`），它转给私有的 `AddInformationData(...)`。**它不检查 `IsValid()`** —— 所以上面的 `if` 是你自己的责任；发一条无效通知不会有任何提示，只会在地图上多一条永远不消失的角标。

查一条通知是否已经存在（真实 API 是泛型谓词查询）：

```csharp
bool alreadyShown = Campaign.Current.CampaignInformationManager
    .InformationDataExists<AcceptCallToWarOfferMapNotification>(
        (AcceptCallToWarOfferMapNotification n) => n.OfferingKingdom == offering);

if (!alreadyShown)
{
    Debug.Print("no call-to-war notice on the map yet", 0);
}

Debug.Print("title = " + new AcceptCallToWarOfferMapNotification(offering, target, new TextObject("x", null)).TitleText.ToString(), 0);
Debug.Print("sound = " + new AcceptCallToWarOfferMapNotification(offering, target, new TextObject("x", null)).SoundEventPath, 0);
```

`InformationDataExists<T>(Func<T, bool> predicate)` 会遍历内部 `_mapNotices` 列表，把每个条目 `as T`，**匹配到且谓词为真（或谓词为 null）就返回 true**。**它没有任何「取出通知并读它的属性」的公开途径** —— `CampaignInformationManager` 没有 `GetActiveNotifications()` 之类的读取 API，`_mapNotices` 是 private。**所以想读一条已存在通知的内容，唯一办法是自己持有一个引用。**

监听「协议结束」并顺带清掉过期通知：

```csharp
public override void RegisterEvents()
{
    CampaignEvents.OnCallToWarAgreementEndedEvent.AddNonSerializedListener(this, this.OnCallToWarEnded);
}

private void OnCallToWarEnded(Kingdom callingKingdom, Kingdom calledKingdom, Kingdom kingdomToCallToWarAgainst)
{
    CampaignEvents.OnCallToWarAgreementEnded.AddNonSerializedListener(this, () =>
        Debug.Print("agreement over: " + calledKingdom.Name + " vs " + kingdomToCallToWarAgainst.Name, 0));
}
```

`OnCallToWarAgreementEndedEvent` 是 `IMbEvent<Kingdom, Kingdom, Kingdom>`，所以委托是 `Action<Kingdom, Kingdom, Kingdom>`。**但注意 `IsValid()` 不会因为这个事件而失效**——通知仍要等到 `TriggerTime` 过去才消失，**这就是「协议已结束但角标还在」的原因**。

## 风险与边界

- **`IsValid()` 只判时间。** `return !this.TriggerTime.IsPast;` —— 王国被消灭、协议终止、玩家已经开战、决议被否决，**全都不影响有效性**。角标会在地图上留到时间到期。
- **单参数构造器造出的通知立即无效。** 它不设 `TriggerTime`，留下的是 `default(CampaignTime)`；零值时间不可能晚于现在，所以 `IsValid()` 几乎必然 false。**mod 里只用三参数版本。**
- **有效期由 `AllianceModel.DurationForOffers` 决定。** `CampaignTime.Now + Campaign.Current.Models.AllianceModel.DurationForOffers;` —— 覆盖那个模型就等于改了所有这类通知的停留时长，而不只是你这一条。
- **`TitleText` 每次读都 new 一个 `TextObject`。** 不是缓存字段。**在循环里反复读会反复分配。**
- **音效复用 `peace_offer`。** `"event:/ui/notification/peace_offer"` 是和平倡议的键，1.3.0 没有专用的参战音效。**别去找 `call_to_war` 音效。**
- **标题是英文硬编码。** `"{=*}Accept Call To War Offer"` —— `{=*}` 是「无本地化条目时按原文显示」的标记。**中文环境下它不会自动翻译。**
- **两个 Kingdom 属性可能为 null。** 单参数构造器下就是 null。所以 `callToWar.OfferingKingdom.Name` 会 NRE —— **必须判空**。`AutoGeneratedInstanceCollectObjects` 里的 `collectedObjects.Add(null)` 不会崩（存档容器忽略），但你的消费代码会。
- **没有任何公开途径读回已存在的通知。** `CampaignInformationManager` 只有 `NewMapNoticeAdded`（写）与 `InformationDataExists<T>`（存在性谓词），内部 `_mapNotices` 是 private，**没有 getter、没有 `GetActiveNotifications()`**。想知道角标上的内容必须自己持有一个引用。
- **`NewMapNoticeAdded` 不校验 `IsValid()`。** 它直接转给私有的 `AddInformationData(...)`。**发一条无效通知不会被拦，只会在地图上多一条永不消失的角标。**
- **`TriggerTime` 是结构体，收集方式特殊。** `CampaignTime.AutoGeneratedStaticCollectObjectsCampaignTime(this.TriggerTime, collectedObjects);` 是**静态**方法，不是 `collectedObjects.Add`。自己写存档代码时别按引用类型处理它。
- **类名里的 `Accept` 是「已被接受」。** 这是协议成立之后的**事后通知**。发邀请的是 `ProposeCallToWarOfferMapNotification`（另一个类型，见 [ProposeCallToWarOfferMapNotification](../ProposeCallToWarOfferMapNotification)）。**搞错这两个会导致在错误的时机弹提示。**
- **`setter` 全部私有。** 三个属性都是 `get; private set;`，外部改不了，只能通过构造器。

## 怎么用

### 怎么拿到它

**它不是被"获取"的，是被"发出去"的。** 没有工厂，没有注册表；你只能 `new`，然后交给 `Campaign.Current.CampaignInformationManager.NewMapNoticeAdded(...)`。构造函数有两个，声明在 `TaleWorlds.CampaignSystem/MapNotificationTypes/AcceptCallToWarOfferMapNotification.cs:84`（三参数版，收 `(Kingdom offeringKingdom, Kingdom kingdomToCallToWarAgainst, TextObject descriptionText)`）和 `:92`（单参数版，收 `TextObject description`，那是存档系统用的）。

**官方生产者是外交行为。** `IAllianceCampaignBehavior.OnCallToWarAgreementProposedToPlayerKingdom` 的实现里，`TaleWorlds.CampaignSystem/CampaignBehaviors/AllianceCampaignBehavior.cs:128` 是全树唯一一处 `new AcceptCallToWarOfferMapNotification(...)`，前面先在 `:125` 拼好描述文案、`:126` 与 `:127` 填两个 `{...}` 变量。

### 典型用法

自己发一条，并且立刻验证它是否还活着：

```csharp
using TaleWorlds.CampaignSystem;
using TaleWorlds.CampaignSystem.MapNotificationTypes;
using TaleWorlds.Localization;

public static class CallToWarNotice
{
    public static void Post(Kingdom offeringKingdom, Kingdom targetKingdom)
    {
        TextObject body = new TextObject("{=*}A call to war has arrived from the {KINGDOM_NAME}.", null);
        body.SetTextVariable("KINGDOM_NAME", offeringKingdom.Name);

        // 一定要用三参数版：只有它会设置 TriggerTime。
        var notice = new AcceptCallToWarOfferMapNotification(offeringKingdom, targetKingdom, body);

        // IsValid() 只判时间，发之前自己确认一次。
        if (!notice.IsValid())
        {
            return;
        }

        Campaign.Current.CampaignInformationManager.NewMapNoticeAdded(notice);
    }

    public static bool StillOnTheMap(Kingdom offeringKingdom)
    {
        // 唯一能问"还有没有"的入口；命中后自己再判 IsValid()。
        return Campaign.Current.CampaignInformationManager.InformationDataExists<AcceptCallToWarOfferMapNotification>(
            n => n.OfferingKingdom == offeringKingdom);
    }
}
```

签名核对：`NewMapNoticeAdded(InformationData)`；`InformationDataExists<T>(Func<T, bool> predicate) where T : InformationData`（`TaleWorlds.CampaignSystem/CampaignInformationManager.cs:92`）—— **一个泛型方法，不要写成非泛型形式**。`TitleText`（`:65`）与 `SoundEventPath`（`:75`）都是无参只读属性。

### 最容易踩的坑

**等这条通知出现，结果在正常的多氏族王国里永远等不到。**

看 `AllianceCampaignBehavior.cs:121` 那个方法的分岔：`AllianceCampaignBehavior.cs:123` 判的是 `if (Clan.PlayerClan.Kingdom.Clans.Count == 1)`。

```
:123  Clans.Count == 1  ->  :128  发地图通知，然后 :129 return
:131  其它情况          ->  :140  new AcceptCallToWarAgreementDecision(...)
                             :141  Clan.PlayerClan.Kingdom.AddDecision(..., true)
```

也就是说**这条地图通知只属于"玩家王国只有一个氏族"这一条支线**。王国有两个以上氏族时，同一个盟友的参战号召走的是另一条路——直接变成一个王国决议（`AcceptCallToWarAgreementDecision`），根本不会有 `AcceptCallToWarOfferMapNotification`。所以：

- 你的 mod 用 `InformationDataExists<AcceptCallToWarOfferMapNotification>` 监听邀请，在任何常规战役里**恒为 false**，因为压根没发过这种通知；
- 反过来，玩家抱怨"看到了邀请通知但点不动"，多半是他处在单氏族支路上——那条路只发通知，不发决议，两者是互斥的；
- 想在两种情况下都拦住，正确做法是同时监听 `AcceptCallToWarOfferMapNotification` 与 `AcceptCallToWarAgreementDecision` 两条路径，而不是指望一条通知覆盖两种流程。

排查时先打印 `Clan.PlayerClan.Kingdom.Clans.Count`，不要先去改监听逻辑。

## 跨版本提示

`AcceptCallToWarOfferMapNotification` 的 public 表面在 `bannerlord-1.3.0/`、`bannerlord-1.3.15/`、`bannerlord-1.4.6/`、`bannerlord-1.4.7/`、`bannerlord-1.5.3/` 五棵树里**完全一致**：3 个 `[SaveableProperty]` 属性（编号 1/2/3）、2 个构造器、2 个 `public override`（`TitleText` / `SoundEventPath`）、1 个 `public override bool IsValid()`。0 新增 / 0 移除 / 0 签名变化。

**变的是基类与相关类型。** [InformationData](../../core-extra/InformationData) 的成员在后续版本有过增补（航海、云端同步相关内容）；`AllianceModel.DurationForOffers` 的数值也可能被调。**只要这三个存档属性的编号不变，你的存档兼容就不会有问题**——`[SaveableProperty(1..3)]` 是跨版本存档契约的一部分。

对 mod 作者的实际含义：**这个类型跨版本几乎零风险。** 唯一要盯的是 `IsValid()` 的语义——**如果后续版本给它加了外交状态检查**（例如协议已结束就返回 false），那么你现在依赖「协议结束后角标仍在」的代码会开始不成立。反过来，若你想让通知在协议结束时立刻消失，**当前版本没有任何钩子能做到，只能自己覆盖 `IsValid()` 或主动移除通知。**

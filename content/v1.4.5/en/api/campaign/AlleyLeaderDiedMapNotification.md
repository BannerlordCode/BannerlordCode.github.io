# AlleyLeaderDiedMapNotification

**Namespace:** `TaleWorlds.CampaignSystem.MapNotificationTypes`
**Module:** `TaleWorlds.CampaignSystem`
**Type:** `public class AlleyLeaderDiedMapNotification : InformationData`
**Base:** `InformationData`
**File:** `bin/TaleWorlds.CampaignSystem/TaleWorlds.CampaignSystem.MapNotificationTypes/AlleyLeaderDiedMapNotification.cs`

## Overview

`AlleyLeaderDiedMapNotification` is the map notice for "one of your alleys lost its leader (or is short of hands)". The data surface is minimal — `[SaveableProperty(10)] public Alley Alley` plus a text and two hard-coded overrides (`TitleText` = `"{=6QoSHiWC}An alley without a leader"`, `SoundEventPath` = `"event:/ui/notification/death"`).

**The real content lives in the VM, not in this type.** `AlleyLeaderDiedMapNotificationItemVM._onInspect` points at `CreateAlleyLeaderDiedPopUp`, which builds an explanation, fills `{DAYS}` from `Campaign.Current.Models.AlleyModel.DestroyAlleyAfterDaysWhenLeaderIsDeath.ToDays`, and then calls `InformationManager.ShowInquiry` with a "learn more / dismiss" pair. "Learn more" runs `NavigationHandler.OpenClan(_alley)` and `ExecuteRemove()`; "dismiss" only runs `base.ExecuteRemove`.

## Mental Model

Read it as **a last-warning entry point with a countdown**. The data carries no countdown itself — the deadline is computed live in the UI layer from `AlleyModel.DestroyAlleyAfterDaysWhenLeaderIsDeath`. Three stages:

1. **It also has no official construction site.** `new AlleyLeaderDiedMapNotification(` returns **0 hits** across the tree (positive control: `new AllianceOfferMapNotification(` returns 1 at `AllianceCampaignBehavior.cs:187`). The only references are `SaveableCampaignTypeDefiner.cs:254`, `AutoGeneratedSaveManager.cs:1605` and `MapNotificationVM.cs:122`. **Just like [AlleyUnderAttackMapNotification](../AlleyUnderAttackMapNotification), a mod has to construct it.**

2. **Its cleanup has nothing to do with events and everything to do with a button press.** `AlleyLeaderDiedMapNotificationItemVM`'s constructor **subscribes to no `CampaignEvents` at all**, unlike `AlleyUnderAttackMapNotificationItemVM` which listens for `SettlementEntered`. It only calls `ExecuteRemove()` from its button callbacks. **So this notice stays in the map corner until the player clicks it and chooses.**

3. **`TitleText` appears twice — once in the data class, once in the VM — with the same key.** Line 14 of this type is `new TextObject("{=6QoSHiWC}An alley without a leader")`, and `CreateAlleyLeaderDiedPopUp` in the VM repeats that exact literal at line 23. **Changing the translation key means changing both.**

The second anchor is that **`{DAYS}` is a constant, not a promise**. The number comes from `AlleyModel.DestroyAlleyAfterDaysWhenLeaderIsDeath` (vanilla: `CampaignTime.Days(4f)`, `Bannerlord.Source/bin/TaleWorlds.CampaignSystem/TaleWorlds.CampaignSystem.GameComponents/DefaultAlleyModel.cs:48`). This type neither stores nor checks whether the deadline has passed; the actual cleanup lives elsewhere. To know whether an alley is still safe, read `Alley.Owner` — never this notice.

The third anchor is that **`NavigationHandler.OpenClan(_alley)` is double-guarded here and nowhere else**. `OpenClanScreenAfterAlleyLeaderDeath` tests `if (base.NavigationHandler != null && _alley != null)`, whereas `_onInspect` is assigned the method group directly. `CreateAlleyLeaderDiedPopUp` itself never touches `_alley`. So a null `Alley` still pops the inquiry, and clicking "learn more" then **silently does nothing** — no crash, but the button appears dead.

## How to use

**How to obtain it.** **Nothing in 1.4.5 constructs it for you** — this page's Risks carries the tree-wide `new AlleyLeaderDiedMapNotification(` probe and its positive control. Construct it yourself and post it through `Campaign.Current.CampaignInformationManager.NewMapNoticeAdded(...)`.

```csharp
Alley orphan = Settlement.Find("Epicrotea").Alleys.First(x => x.State == AreaState.OccupiedByPlayer);
TextObject note = new TextObject("{=mykey6}Your alley in {TOWN} has lost its leader.");
note.SetTextVariable("TOWN", orphan.Settlement.Name);
Campaign.Current.CampaignInformationManager.NewMapNoticeAdded(new AlleyLeaderDiedMapNotification(orphan, note));
```

**The most common pitfall.** **No official construction site exists in 1.4.5.** Do not assume the game posts this under some condition; only a mod can raise it.

## Examples

Raise the notice by hand (1.4.5 never does):

```csharp
Alley orphan = Settlement.Find("Epicrotea").Alleys.First((Alley a) => a.State == AreaState.OccupiedByPlayer);
if (orphan != null)
{
    TextObject note = new TextObject("{=mykey6}Your alley in {TOWN} has lost its leader.");
    note.SetTextVariable("TOWN", orphan.Settlement.Name);
    Campaign.Current.CampaignInformationManager.NewMapNoticeAdded(new AlleyLeaderDiedMapNotification(orphan, note));
    Debug.Print("notice raised, abandon deadline = " + Campaign.Current.Models.AlleyModel.DestroyAlleyAfterDaysWhenLeaderIsDeath.ToDays + " days", 0);
}
```

Sweep the player's alleys for ones at risk of running short of hands:

```csharp
foreach (Alley alley in Settlement.Find("Epicrotea").Alleys)
{
    if (alley.Owner == Hero.MainHero && alley.Settlement != null)
    {
        int troops = Campaign.Current.Models.AlleyModel.GetTroopsOfAlleyForBattleMission(alley).TotalManCount;
        Debug.Print(alley.Tag + " troops=" + troops + " state=" + alley.State, 0);
    }
}
```

Ask whether an alley-leader-died notice is still pending:

```csharp
bool pending = Campaign.Current.CampaignInformationManager.InformationDataExists<AlleyLeaderDiedMapNotification>(null);
Debug.Print("pending alley-leader-died notices = " + pending, 0);
```

## Risks and crash boundaries

- **No official construction site exists in 1.4.5.** `new AlleyLeaderDiedMapNotification(` is 0 hits tree-wide (positive control: `new AllianceOfferMapNotification(` is 1 hit at `AllianceCampaignBehavior.cs:187`). Only the save registration and the UI mapping reference it. **Only a mod can raise it.**
- **The notice neither expires nor listens to events.** `IsValid()` is not overridden (the base returns true, so the load-time `RemoveAll` cannot clear it) and the VM constructor **subscribes to no `CampaignEvents`**. It hangs around until the player clicks it — **a fundamentally different cleanup strategy from [AlleyUnderAttackMapNotification](../AlleyUnderAttackMapNotification)'s "delete on entering town".**
- **`{DAYS}` is a constant, not a deadline.** It comes from `AlleyModel.DestroyAlleyAfterDaysWhenLeaderIsDeath`; this type neither stores it nor checks whether it has elapsed. **To find out whether an alley was actually abandoned, read `Alley.Owner` — not this notice.**
- **A null `Alley` silently kills the "learn more" button.** `OpenClanScreenAfterAlleyLeaderDeath` tests `NavigationHandler != null && _alley != null`, and when that fails it **does nothing without erroring** — the inquiry still pops and dismisses fine, but "learn more" appears broken.
- **The translation key is written twice.** `{=6QoSHiWC}` appears at line 14 of the data class and line 23 of the VM. **Editing one and not the other leaves the UI with two languages for the same heading.**
- **The VM must be registered.** The mapping is a hard-written entry at `MapNotificationVM.cs:122`; an unregistered custom `InformationData` subclass is discarded without an error.
- **`TitleText` allocates per access.** Do not read it in a hot loop.
- **Serialization.** `AutoGeneratedSaveManager.cs:1605` registers the collect delegate and line 1607 registers `AutoGeneratedGetMemberValueAlley`; `SaveableCampaignTypeDefiner.cs:254` holds `AddClassDefinition(typeof(AlleyLeaderDiedMapNotification), 305)`. Adding a field means updating all three.
- **The `SaveableProperty` id is 10.** Identical to [Alley](../Alley)'s `_owner` and to [AlleyUnderAttackMapNotification](../AlleyUnderAttackMapNotification)'s field, but save numbering is per type.

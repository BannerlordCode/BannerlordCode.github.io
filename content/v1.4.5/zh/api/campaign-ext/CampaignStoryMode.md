# CampaignStoryMode

**Namespace:** `StoryMode`
**Module:** `StoryMode`
**Type:** `public class CampaignStoryMode : Campaign`
**Base:** `TaleWorlds.CampaignSystem.Campaign`
**File:** `Modules.StoryMode/StoryMode/StoryMode/CampaignStoryMode.cs`

## 概述

主线战役（Story Mode）与沙盒战役的区别被压缩进这一个类。它继承 `Campaign`，总共有 60 行左右，但相对基类只做了三件额外的事：**注册一种专属的聚落组件**（`TrainingField`，教学靶场）、**多持有一个可存档的 `StoryModeManager`**、**在读档的四段状态机里插三个钩子**。除此之外所有战役逻辑都继承自基类。

承载主线内容的唯一入口是那个带 `[SaveableProperty(9999)]` 的 `StoryMode` 属性。它在构造函数里被 `new StoryModeManager()` 建出来，**setter 是 `private`**——mod 可以读、可以顺着它摸到 `MainStoryLine` / `StoryModeEvents` / `StoryModeHeroes` / `StoryModeBannerEffects`，但**不能替换整个 manager**。对应的存档侧由 `StoryMode/AutoGeneratedSaveManager.cs:647` 把 `(byte)4 / (short)9999` 这个属性 id 绑到 `AutoGeneratedGetMemberValueStoryMode`，`SaveableStoryModeTypeDefiner.cs:25` 则把 `typeof(CampaignStoryMode)` 登记为类定义 1。

三个加载期钩子各挂在不同状态上。`DoLoadingForGameType` 是 `GameType` 上的 `protected abstract` 方法（无参的 `public bool DoLoadingForGameType()` 是它的驱动者，按 `InitializeFirstStep → WaitSecondStep → LoadVisualsThirdState → PostInitializeFourthState` 顺序依次调用），本类在它里面做三件事：

- **状态 0（`InitializeFirstStep`）且 nextState 变了** → `StoryMode.InitializeStoryModeObjects()`，建出 `StoryModeHeroes` 与 `StoryModeBannerEffects`。这两个属性**只在构造函数里是 null**，必须等这一步才填上。
- **状态 2（`LoadVisualsThirdState`）且 nextState 变了** → `Settlement.Find("tutorial_training_field")`，找到就把它的 `StringId` 与 `Position` 塞进 `MapSceneWrapper.AddNewEntityToMapScene`，也就是**把教学靶场的地图实体手动加到场景里**。
- **状态 3（`PostInitializeFourthState`）** → 无条件调 `OnSessionLaunched()`，它转手调 `StoryMode.MainStoryLine.OnSessionLaunched()`。

## 心智模型

把它当成「**战役类型的差异声明**」而不是「主线逻辑的容器」。主线逻辑住在 `StoryModeManager` 及其 `MainStoryLine` / `StoryModeHeroes` / `StoryModeBannerEffects` 里；这个类只回答「当前跑的是不是主线战役」以及「主线战役比沙盒多做了哪几步初始化」。

由此推出三个必须记住的结论。第一，**判断自己是否在主线战役里应该用类型判断而不是标志位**——`StoryModeManager.Current` 的实现就是 `(((Game.Current?.GameType) as CampaignStoryMode)?.StoryMode)`，非主线战役下它返回 null。这是官方给的、零成本的判定方式。第二，**`BeforeRegisterTypes` 的覆盖必须先调 `base`**：基类在这里注册的是全部标准战役类型，本类紧跟着追加 `objectManager.RegisterType<TrainingField>("TrainingField", "TrainingFields", 1u, true, false)`。第三，**`StoryModeHeroes` / `StoryModeBannerEffects` 在 `InitializeStoryModeObjects` 之前是 null**。构造函数只做 `new StoryModeManager()`，而 `StoryModeManager` 的构造函数也只建 `StoryModeEvents` 与 `MainStoryLine`——另外两个属性要等加载状态 0 才建。任何在 `Campaign.OnGameStart` 之前读它们的代码都会 NRE。

最后一个锚点：**`DoLoadingForGameType` 的两个钩子都带 `nextState != gameTypeLoadingState` 的守卫**（即「这一段真的结束了才做事」），只有状态 3 的 `OnSessionLaunched()` 是无条件的。想在主线战役里插自己的加载步骤，正确的位置是覆盖同一个方法、`base.` 之后按 `nextState` 判断，而不是另起一套状态机。

## 真实示例

判断当前是否在主线战役，并摸到主线内容——这是官方 `StoryModeManager.Current` 自己的实现方式：

```csharp
StoryModeManager storyMode = StoryModeManager.Current;
if (storyMode == null)
{
    Debug.Print("not a story mode campaign", 0);
    return;
}

Debug.Print("main story line = " + storyMode.MainStoryLine, 0);
Debug.Print("story mode events = " + storyMode.StoryModeEvents, 0);
```

注意 `StoryModeHeroes` / `StoryModeBannerEffects` 要等 `InitializeStoryModeObjects`（加载状态 0）之后才非 null，会话启动时读是安全的：

```csharp
StoryModeManager storyMode = StoryModeManager.Current;
if (storyMode != null)
{
    Debug.Print("story mode heroes = " + storyMode.StoryModeHeroes, 0);
    Debug.Print("banner effects = " + storyMode.StoryModeBannerEffects, 0);
}
```

复刻状态 2 的动作——把教学靶场实体手动加进地图场景（`SettlementComponent` 是单数属性，所以要 `as` 转成 `TrainingField`）：

```csharp
Settlement trainingField = Settlement.Find("tutorial_training_field");
if (trainingField != null)
{
    TrainingField component = trainingField.SettlementComponent as TrainingField;
    Debug.Print("training field component = " + component, 0);

    IMapScene mapScene = Campaign.Current.MapSceneWrapper;
    mapScene.AddNewEntityToMapScene(trainingField.StringId, trainingField.Position);
}
```

派生一个自己的战役类型，沿用同一套加载时序（注意两个覆盖方法在基类 `GameType` 上分别是 `protected internal abstract` 与 `protected abstract`，跨程序集覆盖时 `BeforeRegisterTypes` 只能用 `protected`）：

```csharp
public class MyStoryMode : CampaignStoryMode
{
    public MyStoryMode(CampaignGameMode gameMode)
        : base(gameMode)
    {
    }

    protected override void DoLoadingForGameType(
        GameTypeLoadingStates current, out GameTypeLoadingStates next)
    {
        // 先让主线战役跑完它自己的三步
        base.DoLoadingForGameType(current, out next);

        // 0 = InitializeFirstStep, 1 = WaitSecondStep,
        // 2 = LoadVisualsThirdState, 3 = PostInitializeFourthState
        Debug.Print("loading step " + (int)current + " -> " + (int)next, 0);
    }
}
```

想在自己战役的会话启动阶段插逻辑，正确挂点是事件而不是那个私有方法：

```csharp
public class MySessionHook : CampaignBehaviorBase
{
    public override void RegisterEvents()
    {
        CampaignEvents.OnSessionLaunchedEvent.AddNonSerializedListener(this, OnMySessionLaunched);
    }

    public override void SyncData(IDataStore dataStore)
    {
    }

    private void OnMySessionLaunched(CampaignGameStarter campaignGameStarter)
    {
        if (StoryModeManager.Current != null)
        {
            Debug.Print("story mode session is up", 0);
        }
    }
}
```

## 风险与边界

- **`StoryMode` 的 setter 是 `private`。** 只能读不能换。想换掉主线内容只能改 `StoryModeManager` 内部，或写自己的 `Campaign` 子类。
- **`StoryModeHeroes` / `StoryModeBannerEffects` 在加载状态 0 之前是 null。** 构造函数只建 `StoryModeEvents` 与 `MainStoryLine`。在 `OnGameInitialization` 之前读会 NRE。
- **`BeforeRegisterTypes` 漏 `base.` 是灾难级的。** 基类注册的是整个战役类型体系，少一次调用会让大量 `MBObjectBase` 类型加载失败。
- **两个加载钩子有 `nextState` 守卫，第三个没有。** 状态 3 的 `OnSessionLaunched()` 每进一次就无条件执行一次；自己的逻辑若也挂这里，注意别做重复初始化。
- **`OnSessionLaunched` 是 `private`。** 外部调不到，只能通过 `CampaignEvents.OnSessionLaunchedEvent` 挂自己的监听。
- **存档强绑定具体类型。** `SaveableStoryModeTypeDefiner.cs:25` 把 `typeof(CampaignStoryMode)` 登记为类定义 1，`AutoGeneratedSaveManager.cs:647` 把属性 id 9999 绑到 `AutoGeneratedGetMemberValueStoryMode`。**自己派生一个 `MyStoryMode` 并不会自动获得存档支持**——需要自己的 `SaveableTypeDefiner` 与 auto-generated manager，否则读档时主线状态会丢。
- **`TrainingField` 的注册 id 是硬编码的 `1u`。** 换 id 会与 `AutoGeneratedSaveManager.cs` 里已有的定义冲突。
- **教学靶场实体是手动加进场景的。** `AddNewEntityToMapScene(string entityId, in CampaignVec2 position)` 的第一个参数是**聚落的 StringId** 而不是 TrainingField 的，位置取的是聚落的 `Position`。
- **`MapSceneWrapper` 依赖 `Campaign.Current`。** 非战役上下文（如主菜单）访问会 NRE。
- **`StoryModeManager.Current` 每次访问都走 `Game.Current?.GameType`。** 在 `Game.Current` 为 null 的场景返回 null，链式调用前务必判空。

## 依赖关系

- 基类：[Campaign](../../campaign/Campaign) 提供全部标准战役逻辑，本类只覆盖 `BeforeRegisterTypes` 与 `DoLoadingForGameType` 两个扩展点
- 主线内容根：[StoryModeManager](../StoryModeManager) 的 `MainStoryLine` / `StoryModeEvents` / `StoryModeHeroes` / `StoryModeBannerEffects` 是本类那个存档属性的全部内容
- 加载时序：`TaleWorlds.Core.GameType` 的 `protected bool DoLoadingForGameType()` 是驱动者，按 `GameTypeLoadingStates` 的四个值依次调用抽象方法
- 专属聚落组件：`TrainingField : SettlementComponent` 由本类 `RegisterType` 注册，挂在 `tutorial_training_field` 这个聚落上
- 地图场景：[IMapScene](../IMapScene) 的 `AddNewEntityToMapScene` 是教学靶场实体的落点，经由 `Campaign.MapSceneWrapper` 取到
- 存档基础设施：`StoryMode/SaveableStoryModeTypeDefiner.cs` 与 `StoryMode/AutoGeneratedSaveManager.cs` 是本类存档能力的真正实现者，两者都把本类按具体类型硬编码
- 判定捷径：`StoryModeManager.Current` 就是 `((Game.Current?.GameType) as CampaignStoryMode)?.StoryMode`，判断是否主线战役不需要任何标志位
- 同桶页面：[TrainingField](../TrainingField) 与 [StoryModeManager](../StoryModeManager) 是本页最常被并排阅读的两页

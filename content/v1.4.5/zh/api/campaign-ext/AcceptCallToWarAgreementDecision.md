# AcceptCallToWarAgreementDecision

**命名空间：** `TaleWorlds.CampaignSystem.Election`  
**模块：** `TaleWorlds.CampaignSystem`  
**类型：** `public class AcceptCallToWarAgreementDecision : KingdomDecision`  
**基类：** `KingdomDecision`  
**源文件：** `TaleWorlds.CampaignSystem/Election/AcceptCallToWarAgreementDecision.cs`

## 概述

`AcceptCallToWarAgreementDecision` 是「联盟/参战」子系统在玩家王国一侧落地的**王国决策**。当一个与玩家王国结盟的王国向玩家发出参战号召（call to war）时，引擎会为玩家王国创建这条决策：氏族领袖提出，统治氏族（或统治者本人）定夺，其余氏族按各自立场贡献支持度，最终由 `ApplyChosenOutcome` 执行——同意则调用 `IAllianceCampaignBehavior.StartCallToWarAgreement` 正式参战并支付 `CallToWarCost` 金币，拒绝则调用 `DenyCallToWarAgreement` 礼貌回绝。

它继承自 `KingdomDecision`，因此完整走「王国决策」生命周期：提出 → 确定候选人（`DetermineInitialCandidates`）→ 确定抉择者（`DetermineChooser`）→ 各氏族计算支持度（`DetermineSupport`）→ 表决 → 应用结果（`ApplyChosenOutcome`）。mod 开发者一般**不需要手动构造**它——它由联盟行为在收到号召时自动加入 `Kingdom.UnresolvedDecisions`；但 mod 可以读取它的状态、监听它的结果，或在自己的决策中复用同一套模式。

## 心智模型

把这个类想成**一张摆在王国议会桌上的「是否参战」议案**，而不是一个服务类。它自己不做战争计算，只做三件事：

1. **记住议案的三个事实**——谁在号召（`CallingKingdom`）、打谁（`KingdomToCallToWarAgainst`）、要付多少钱（`CallToWarCost`）。这三个都是 `readonly`，构造后不可变，且都带 `[SaveableField]`，会随存档序列化。
2. **回答引擎在决策生命周期各阶段的问题**——`IsAllowed`（议案是否还成立）、`DetermineInitialCandidates`（有哪些选项：同意/拒绝）、`DetermineChooser`（谁拍板：统治氏族）、`DetermineSupport`（每个氏族倾向哪边）、`CanMakeDecision`（现在能不能表决，不能时给出原因）。
3. **在结果确定后执行副作用**——`ApplyChosenOutcome` 是唯一的「真正动手」点，通过 `AllianceCampaignBehavior` 这个延迟加载的网关调用联盟行为。

嵌套类 `AcceptCallToWarAgreementDecisionOutcome` 是议案的**选项载体**：它只有四个 `readonly` 字段（`ShouldAcceptCallToWar`、`Kingdom`、`CallingKingdom`、`KingdomToCallToWarAgainst`），自己不执行任何逻辑，只负责在决策界面显示「Yes / No」标题与描述。真正的动作永远发生在决策类一侧的 `ApplyChosenOutcome` 里。

`AutoGenerated*` 系列成员（`AutoGeneratedStaticCollectObjectsAcceptCallToWarAgreementDecision`、`AutoGeneratedInstanceCollectObjects`、`AutoGeneratedGetMemberValue*`）是引擎为存档序列化自动生成的辅助代码，**不是给 mod 用的 API**，mod 不应调用或依赖它们。

### 典型用法

- **观察/记录盟友的号召：** 遍历未决决策，命中后读取 `CallingKingdom`、`KingdomToCallToWarAgainst`、`CallToWarCost`，用于自己的 UI 或日志。
- **判断议案是否仍然有效：** 调用 `IsAllowed()`（联盟关系与战争状态都成立才返回 `true`），或 `CanMakeDecision(out TextObject reason)` 拿到人类可读的失效原因。
- **预判表决结果：** 用 `CalculateSupport(clan)` 或 `DetermineSupport(clan, outcome)` 看某个氏族的支持倾向；`GetQueriedDecisionOutcome` 返回「同意」选项，可用来定位默认推荐项。
- **在自己的决策里复用模式：** 参照它如何用嵌套 `DecisionOutcome` 子类 + `DetermineInitialCandidates` 产出两个对立选项，再在 `ApplyChosenOutcome` 里集中处理副作用。

### 坑

- **不要直接构造。** 构造函数需要 `proposerClan` 并立即调用 `Campaign.Current.Models.AllianceModel.GetCallToWarCost`，在非战役上下文（如编辑器、菜单）会拿到 null 模型。
- **`ApplyChosenOutcome` 只在表决完成后调用一次。** 想监听「玩家王国参战了」应该监听 `IAllianceCampaignBehavior` 触发的联盟事件，而不是轮询决策对象。
- **`CanMakeDecision` 的 `reason` 参数受 `includeReason` 控制。** `includeReason: false` 时 `reason` 为 `null`，不要无条件解引用。
- **`DetermineSupport` 对「拒绝」选项返回的是负分**（`0f - scoreOfJoiningWar`），比较支持度大小时注意符号。
- **`AutoGenerated*` 成员不要碰。** 它们是序列化基础设施，签名可能随引擎版本变化。

## 真实示例

以下示例展示 mod 如何在玩家王国的未决决策中发现参战号召，读取议案关键信息，并在表决完成后通过联盟事件感知结果：

```csharp
using System.Linq;
using TaleWorlds.CampaignSystem;
using TaleWorlds.CampaignSystem.CampaignBehaviors;
using TaleWorlds.CampaignSystem.Election;
using TaleWorlds.Localization;

public sealed class CallToWarDecisionTracker : CampaignBehaviorBase
{
    public override void RegisterEvents()
    {
        CampaignEvents.KingdomDecisionConcluded.AddNonSerializedListener(this, OnDecisionConcluded);
    }

    private void OnDecisionConcluded(KingdomDecision decision, DecisionOutcome chosenOutcome)
    {
        if (decision is not AcceptCallToWarAgreementDecision callToWar) return;
        var outcome = (AcceptCallToWarAgreementDecision.AcceptCallToWarAgreementDecisionOutcome)chosenOutcome;
        InformationManager.ShowInquiry(new InquiryData(
            "参战号召已表决",
            outcome.ShouldAcceptCallToWar
                ? $"已同意 {callToWar.CallingKingdom.Name} 的号召，向 {callToWar.KingdomToCallToWarAgainst.Name} 宣战。"
                : $"已拒绝 {callToWar.CallingKingdom.Name} 的参战号召。",
            true, false, "确定", "", null, null));
    }

    public override void SyncData(IDataStore dataStore) { }
}
```

mod 也可以在议案存续期间检查其状态，例如判断议案是否仍有效、某个氏族的支持倾向：

```csharp
KingdomDecision raw = Clan.PlayerClan.Kingdom.UnresolvedDecisions
    .FirstOrDefault(d => d is AcceptCallToWarAgreementDecision);
if (raw is AcceptCallToWarAgreementDecision callToWar)
{
    bool stillValid = callToWar.IsAllowed();
    TextObject reason;
    bool canDecide = callToWar.CanMakeDecision(out reason, includeReason: true);
    float playerClanSupport = callToWar.CalculateSupport(Clan.PlayerClan);
}
```

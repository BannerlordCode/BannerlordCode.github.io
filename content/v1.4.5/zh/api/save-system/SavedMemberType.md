# SavedMemberType

**Namespace:** `TaleWorlds.SaveSystem`
**Module:** `TaleWorlds.SaveSystem`
**Type:** `internal enum SavedMemberType`
**Base:** `System.Enum`
**File:** `TaleWorlds.SaveSystem/SavedMemberType.cs`

## 概述

存档里每一个「槽位」——类的一个字段、一个属性，或者容器里的一个元素——落盘时第一件事都是写一个字节，说明这个槽位里装的是什么形状的数据。这个字节就是 `SavedMemberType` 的序号。七个取值把「值怎么编码」分成七条互斥的路线：引用（Object）、容器引用（Container）、字符串（String）、元组（Tuple）、自定义结构体（CustomStruct）、枚举（Enum）、基础类型（BasicType）。判定发生在 [VariableSaveData](../VariableSaveData) 的 `InitializeData` 里（`TaleWorlds.SaveSystem.Save/VariableSaveData.cs:38-95`），写字节发生在同一类的 `SaveTo` 开头（`:94`）。它是 `internal`，mod 读不到源码里的这个名字，只能从行为上感受它。

## 心智模型

把它想成**集装箱上的货物分类标签**。同一条船，不同舱室对货物的固定方式不同：引用舱只放一个编号、字符串舱放字符串表编号、枚举舱连类型身份一起放、基础类型舱连类型身份加序列化字节一起放。由此推出四条边界：

1. **序号就是存档字节，顺序不可动。** `SaveTo` 的第一句是 `writer.WriteByte((byte)MemberType);`（`VariableSaveData.cs:94`），读侧 [VariableLoadData](../VariableLoadData) 按同一个序号分派。在枚举中间插一个成员，所有旧档的这一位就全错位——**不会有任何报错，只会读出一整片垃圾**。
2. **只有 Enum 和 BasicType 是自描述的。** 这两条分支在写值之前先写 `TypeDefinition.SaveId.WriteTo(writer)`（`:112`、`:117`），也就是把类型身份内联进槽位。其余五条只写值，读侧必须靠槽位所属的结构体定义才知道类型。**代价是：给一个字段换类型，前四条会静默错读，后两条会自我纠正。**
3. **`Tuple` 这个序号（3）是保留但未使用的槽位。** 全模块搜下来，写侧 `InitializeData` 从不产出 `Tuple`（它只有 Object/Container/String、Enum、BasicType、CustomStruct 五个分支，外加 null 分支给 Object），读侧 [VariableLoadData](../VariableLoadData) 也没有 `SavedMemberType.Tuple` 分支。**容易误读的一点**：`AutoGeneratedSaveManager` 里确实出现 `Tuple<bool, float>`，但那是 CLR 类型，被 [SaveableBasicTypeDefiner](../SaveableBasicTypeDefiner) 用 [CustomField](../CustomField) 登记成普通类定义（`:43`），走的是 **Object** 路线，跟序号 3 无关。
4. **`Value` 字段的含义随标签变。** 在基类里它统一是 `object`，但 Object/Container/CustomStruct 存的是 int 编号、String 存的是字符串本体（写的时候才换成字符串表 id）、Enum 存枚举值本体、BasicType 存值本体。读它必须先看 `MemberType`，否则会把一个编号当成值用。

## 如何使用

### 怎么拿到它

- **读侧唯一能碰到它的地方**是 [VariableLoadData](../VariableLoadData)：`SavedMemberType` 是它的一个属性，分派散在 `Read()` 与 `FillObject()` 两处（`VariableLoadData.cs:39/43/47/51/66/73` 与 `:87/95/103/108/124/128`）。
- **写侧由 [VariableSaveData](../VariableSaveData) 自己决定**，你只能通过选字段类型来间接选标签：`string` 字段 → String；有定义的类字段 → Object；`List<T>` / 字典字段 → Container；枚举字段 → Enum；基础类型（int、float、Vec3 等）字段 → BasicType；带定义的结构体字段 → CustomStruct。
- mod 侧要做的是**反推**：想让自己的字段走哪条路线，就声明成对应的 C# 类型。

### 最小可运行片段

```csharp
// 标签是 internal enum，mod 侧按数值语义理解它
// 0=Object 1=Container 2=String 3=Tuple(保留未用) 4=CustomStruct 5=Enum 6=BasicType

// 写法选择完全由字段的声明类型决定：
//   [SaveableField(1)] private int Count;          → BasicType（走 IntBasicTypeSerializer）
//   [SaveableField(2)] private string Label;       → String（进字符串表）
//   [SaveableField(3)] private Settlement Town;    → Object（写对象 id）
//   [SaveableField(4)] private List<int> Costs;    → Container（写容器 id）
//   [SaveableField(5)] private MyEnum Phase;       → Enum（写类型身份 + 值名字）

Debug.Print("BasicType 序号 = " + (int)SavedMemberType.BasicType, 0);   // 6
Debug.Print("Object 序号 = " + (int)SavedMemberType.Object, 0);         // 0
```

### 用它最容易踩的一条

**给已发布的存档字段换声明类型时，前四类标签会静默读错而不是报错。** 例如把 `[SaveableField(1)] private int Count;` 改成 `private string Count;`——标签从 BasicType（6）变成 String（2），槽位里原有的字节被当成字符串表编号去解释，`Context.GetStringWithId(id)` 拿到的要么是 null 要么是别人的字符串；整个过程没有异常，因为读侧的每个分支都「成功」返回了。**换字段类型必须同时换 `LocalSaveId`，或者提供 [IConflictResolver](../IConflictResolver) 做映射。**

| `Container` | `Container`（序号 1） | 容器引用。判定条件是 `TypeDefinition is ContainerDefinition`（`:44`），值是容器 id。`List<T>` / 字典 / `MBList<>` / 数组 / `Queue<T>` 都走这里。 |
| `String` | `String`（序号 2） | 字符串。判定条件是 `typeof(string) == memberType`（`:54`）——**按声明类型判，不按值判**。`Value` 存字符串本体，真正写盘时才 `Context.GetStringId((string)Value)` 换成字符串表编号（`:107`）。 |
| `Tuple` | `Tuple`（序号 3） | **保留槽位，当前版本不产出也不消费。** 写侧 `InitializeData` 无此分支，读侧 [VariableLoadData](../VariableLoadData) 也无此分支。`AutoGeneratedSaveManager` 里的 `Tuple<,>` 是 CLR 类型，走 Object 路线。 |
| `CustomStruct` | `CustomStruct`（序号 4） | 值类型结构体，值是**它自己在对象表里的 id**。有两条产出路径：定义存在且 `IsClassDefinition == false` 时由 [ElementSaveData](../ElementSaveData) 用元素下标当 id（`ElementSaveData.cs:24`），以及 `InitializeData` 最后的兜底分支（`:81`）。读侧在 `VariableLoadData.cs:73` / `:128` 处理。 |
| `Enum` | `Enum`（序号 5） | 枚举。判定条件是 `TypeDefinition is EnumDefinition`（`:69`）。**自描述**：先写类型身份（`:112`）再写值的字符串（`:113`）。所以枚举改名不会毁档，字节数随名字长度变。 |
| `BasicType` | `BasicType`（序号 6） | 基础类型（int / float / string 之外的标量与引擎向量）。判定条件是 `TypeDefinition is BasicTypeDefinition`（`:74`）。**自描述**：先写类型身份（`:117`），写之前还会 `TryGetTypeDefinition` 校验定义找得到、否则 `Debug.FailedAssert`（`:118-120`），再交给 `Serializer.Serialize`（`:122`）。 |

## 真实示例

七个分支的判定顺序就是优先级（`TaleWorlds.SaveSystem.Save/VariableSaveData.cs:42-82`）：

```csharp
if (TypeDefinition is ContainerDefinition)              { MemberType = SavedMemberType.Container; }
else if (typeof(string) == memberType)                  { MemberType = SavedMemberType.String; }
else if ((typeDefinition != null && typeDefinition.IsClassDefinition)
      || TypeDefinition is InterfaceDefinition
      || (TypeDefinition == null && memberType.IsInterface))
                                                     { MemberType = SavedMemberType.Object; }
else if (TypeDefinition is EnumDefinition)             { MemberType = SavedMemberType.Enum; }
else if (TypeDefinition is BasicTypeDefinition)        { MemberType = SavedMemberType.BasicType; }
else                                                  { MemberType = SavedMemberType.CustomStruct; }
```

写盘：只有 Enum 与 BasicType 先写类型身份（`VariableSaveData.cs:110-122`）

```csharp
else if (MemberType == SavedMemberType.Enum)
{
    TypeDefinition.SaveId.WriteTo(writer);      // 自描述：先身份
    writer.WriteString(Value.ToString());
}
else if (MemberType == SavedMemberType.BasicType)
{
    TypeDefinition.SaveId.WriteTo(writer);      // 自描述：先身份
    if (Context.DefinitionContext.TryGetTypeDefinition(TypeDefinition.SaveId) == null)
    {
        Debug.FailedAssert("Basic type definition cant be found: " + TypeDefinition.SaveId.GetStringId(), ..., "SaveTo", 132);
    }
    ((BasicTypeDefinition)TypeDefinition).Serializer.Serialize(writer, Value);
}
```

mod 视角的对照实验：

```csharp
// 同一份数据，三种声明类型 → 三条不同的槽位路线
// int    → BasicType(6)：1 字节标签 + 类型身份 + 4 字节值
// string → String(2)  ：1 字节标签 + 4 字节字符串表编号
// Settlement → Object(0)：1 字节标签 + 4 字节对象 id（null 写 -1）
Debug.Print("Enum 与 BasicType 是仅有的两条自描述路线", 0);
Debug.Print("其余五条的槽位类型靠所属结构体定义反推，SwapFieldType 会静默读错。", 0);
```

# 独立审查报告 · 模板与口径

> 本文件是 lead-9 每轮审查报告的**格式与判据**。
> 落盘文件名：`tools/_docs-review-<YYYY-MM-DD>-r<N>.md`（lead-9 独占前缀）。
> 定位：**只审查，不写正文**。发现问题写进报告，由 boss 转给写作线改。
> 审查者一动手，它就不再是独立审查。

---

## 一、进度口径（对外报数用这一套）

```
✅ 手写页数 / 手写行数      「25 页 / ~1030 行」
⛔ 不用 numstat 的总插入行   「7,557 行」会把 4 条线的工作量虚报 7 倍
```

因为 `git diff --numstat` 里混着 `nav-section-index.mjs` 写进 `_index.md` 的机械子页清单。
报告开头**必须**给出这个拆分：

```
加行总数 = 手写正文行数 + 机械清单行数 + tools/ 报告行数
```

## 二、七类检查（按危害从大到小）

| 编号 | 类| 必查/抽检 | 主判据 |
|---|---|---|---|
| ① | 编造的 API 用法 | **100%** | 符号存在性 |
| ② | 模板化 / 生成指纹 | **100%**（一个 grep） | 逐字对比 |
| ③ | 无据的「不存在」判断 | 抽检 | 阳性证据 |
| ④ | 链接解析 | 门禁 + 复核 | 目标是否存在 |
| ⑤ | 字符 / 行尾损坏 | 全量扫描 | 计数必须为 0 |
| ⑥ | 结构退化 | 抽检 5% | `deep_pass` |
| **⑥-b** | **内容实质性** | **抽 N 页逐字读** | **该类特有的细节** |

### ① 判据（boss #3319 + #3559 定，勿改）

**判据一：符号存在性（主判据）**

```
符号存在 + 行号完全相等        → 通过
符号存在 + 行号漂移 ≤ ±8 行    → drift，报出来并附真实内容
符号存在 + 行号漂移 > ±8 行    → drift+（超窗口），优先级提高
符号不存在                     → 🔴 编造，直接抓
```

**为什么以「符号存在性」为主判据**：漂移的符号都是真的，只查行号会误报它们；
**误报率一高这把尺会被当噪声关掉** —— 而本会话已经有过「一个检查静默什么都没做却输出通过」。

**判据二：引用点类型（boss #3559 补的第③条）**

一条引用指向的可能是 **声明 / 赋值 / 调用**，三者行号不同。
**工具必须先确定这一页指的是哪一种，否则「行号漂」这个分类本身没有意义。**

```
页面写：assigned in `SetObjects` at `MBAPI.cs:111`
  :79   internal static void SetObjects(...)                      ← 方法声明
  :111  IMBBannerlordConfig = GetObject<IMBBannerlordConfig>();   ← 赋值行
两个都对。页面指的是赋值行，工具锚在声明行 → 误报 drift +32。
```

⇒ 抽验样本时，除了核「符号在不在」，还要核**「这一页说的是哪一种」**。

**判据三：批量工具先验自身**

```
批量工具的输出必须先人工抽验 10 条样本，确认工具本身可信，才允许出结论。
```

（boss #3559 提为全队门禁，适用于所有线手上的每一把尺。）
理由见第六节自我证伪第 ⑥ 条 —— **工具比假设更危险：假设错了我会怀疑，
工具输出看起来合理我就会照报。**

### 已知工具坑位（写新工具前先看）

```
A 按文件名索引、没按模块索引
  bannerlord-1.4.5 树里 AssemblyInfo.cs 有 82 份同名 —— 必须按模块路径解析
B 锚点选取：不要取「引用前最近的反引号标识符」
  会把类型名（只在声明处出现）当成员锚点 → 一律误报 NOT within ±8
C 混淆声明行与赋值行 —— 见判据二
```

### ② 判据

不许下断言式结论。必须给出：
```
哪几页 的 哪几段 与 哪一页 雷同，逐字贴出来
```

### ⑥-b 判据（boss #3111 采纳为全队判据）

```
合格证明 = deep_pass  +  逐字读至少 N 页，确认新段落里确有【该类特有】的内容
```

**「该类特有」= file:行号 / 具体后果 / 具体调用点 / 跨文件对照。**
三样都没有 ⇒ 空话。

`deep_pass` 的含义是「没有已知的坏味道」，**不等于「有实质内容」**。
实例：六个空壳段 `## Dead members and traps` 表格行数 0，`_check_deep` 照样 deep_pass。

## 三、证据纪律（三条硬规则，违反即报告作废）

```
1. 「文件不存在」必须附全树 find 输出
   $ find <树> -name <文件名>
   不许只用 existsSync 拼一个路径就下结论。
   —— 理由：v1.4.5 树路径是 bannerlord-1.4.5/Bannerlord.Source/bin/<模块>/<命名空间>/…
      拼错一层就会把「路径错」误判成「页面编造」。本会话已因此产生过一次错误指控。

2. 「这个 API 不存在」必须给阳性证据
   v1.3.0 树只有 v1.5.3 的约 40%，「查不到」只说明这棵树没有。
   要说「不存在」，得给 file:行号 的阳性证明。

3. batch 结果与单点结果矛盾时，先怀疑调用方式
   实测两次：awk 语法错 → 命令没跑；node 批跑全 ERR → 得到 0/16 而单页 EXIT=0。
   断言用 exit status，绝不用「stdout 为空」当通过条件。
```

**选树的顺序**（每次核源码前先确认）：
```
v1.4.5 → bannerlord-1.4.5/Bannerlord.Source/bin/<模块>/<命名空间>/<File>.cs   ← 带 bin/ 与双层嵌套
v1.5.3 / v1.4.6 / v1.4.7 → bannerlord-<v>/<模块>/<File>.cs                      ← 单层
```
拿错树会导致 **19/19 全 FAIL**（实测）。

## 四、报告结构

```
# 文档独立审查报告 — <日期> 第 N 轮

## 0. 上一轮必修项的落地状态（逐条复查，不复查不算审）
## 1..N. 七类检查，每类给：发现数 / 证据（命令 + 输出）/ 正确的是什么

## 必修清单（转写作线）
## 本轮我推翻的自己的假设
## NOT VERIFIED（本轮没验的）
```

## 五、自我证伪（已定为报告必填段）

```
假设 → 量 → 不成立 → 公开推翻
```

**三次都是自己推翻自己的，这在本会话是头一份。** 记进来比守住假设值钱。

已发生的 5 次：
```
① 「public/ 构建过期，掩盖了死链」        → 证伪：0 条被掩盖（145,650 href 全量核过）
② 「v1.4.6 有 5 处 ../core-extra 新死链」 → 证伪：多线并行下的瞬时快照，非缺陷
③ 「IMBDelegate 引用了 3 个不存在的文件」  → 证伪：路径是我拼错的，全树 find 一击命中
④ 「v1.5.3 树核不出 AgentVictoryLogic 的 19 条断言」 → 证伪：树选错了，v1.4.5 全 PASS
⑤ 「门禁结构性看不见 214 处 _index 链接」 → 证伪：门禁剥掉 _index 后缀找 index.html，找的正是真实产物
```

**第 ⑤ 条的教训**：`find public -name "*_index*"` 证明「没有 _index 目录」，
**不等于**「门禁找不到文件」—— 两个不同的命题。
**提疑点可以，但必须标 NOT VERIFIED，且不能拿一个命题的证据下另一个命题的结论。**

## 六、多线并行时的采样纪律

```
1. 报告里记下采样时刻（改动文件数 + 时间戳）
   —— 否则会把中间态报成终态（见自我证伪 ②）
2. 「已消失」≠「不存在」，复查前先确认写作线是否刚改过
3. 门禁输出会过期：197 文件时跑出 dead=1，316 文件时跑出 dead=2
   —— 引用门禁数字必须同轮重跑，不许沿用上一轮的
```

## 七、给写作线的硬规则（boss 已批，勿再逐页派修）

```
【跨桶链接】叶子页里凡跨桶的 href，一律 ../../<桶名>/Foo 起步
           写完自查：把 href 里的桶名数一遍，出现两次就是错的
           —— 同一个错已出现 3 次，逐页派修只治已发现的，治不了下一批

【导航清单】✅ 允许脚本生成 _index.md 里的「子页清单」表
           ⛔ 禁止脚本生成任何类页（api/<桶>/<Class>.md）里的散文与成员表
           ⚠️ 机械清单必须能被 nav-verify 逐条验证解析到真实页面
           ⚠️ marker 块必须严格配对；块内只允许脚本的行，人工段一律移出块外
```

# 45 组同名跨桶页 — 身份二元判定

- **(a)** = 两个不同类型恰好同名（同名合法）
- **(b)** = 同一个类型被写了两页（重复页，内容缺陷）
- 本线**只判定、不改任何页面**。`content/` 一页未写，未 `git add`、未 `commit`。

## 0. 口径声明

**桶根定义（可执行）**：本线只取 `<bucket>/<Name>.md`，即 14 个桶目录下的**直接子文件**，**不含任何子目录**。
`content/v1.4.5/en/api/final/` 下另有 44 个子目录（`final/actions`、`final/campaignsystem-misc` 等），**不纳入**本线。

**分母**：桶根同名组共 **46** 组，其中 `_index` 组共 **14** 页（每桶一页的导航页），
`_index` 是导航页不是类页，**不参与判定** → 46 − 1 = **45** 组。
形状 = 43 组 2 页 + 1 组 3 页（MetaDataExtensions）+ 1 组 6 页（AutoGeneratedSaveManager）；
页数 43×2 + 3 + 6 = **95**。

**元数据标签在本树有 3 种变体：File: / Source: / Source path (1.4.5 authoritative):**
提取时必须逐页确认实际用的是哪一种，并把用的那一种记进表格。
实测分布：`File:` 79 页 / `Source:` 15 页 / `Source path (1.4.5 authoritative):` 1 页（`campaign-ext/CampaignEventReceiver.md`）。
只试前两种会漏掉这 1 页 → 判据 1 静默取空值 → 假 UNDETERMINED。

## 1. 口径偏离（照抄 boss 指定格式）

```
判据原样：Boss 逐字给四条
偏离 1：C1 raw → canon（理由：bin/ 前缀产生假阴性，方向会把 (b) 洗成 (a)）
偏离 2：判据 2 frontmatter → 正文粗体标签行（理由：frontmatter 内不存在该字段）
两处偏离的共同成因：Boss 未读过被测页面即写判据
```

**偏离 1 的影响面**：`canon` 与 `raw` 不同的对共 **11** 对，全部只差 `bin/` 方言前缀或
`Modules.Multiplayer/` 前缀，其中 **2** 对（`Team`、`CampaignBehaviorBase`）若按 raw 会被误判 (a)。
表里 `raw` 与 `canon` 两个值都记，差异在「依据」列注明。

## 2. 方法（含一条自检教训）

### C1 文件行
取 `**File:**` / `**Source:**` / `**Source path (1.4.5 authoritative):`` 首个反引号值。
同时记 **raw**（逐字）与 **canon**（归一 = `Namespace` + basename）。
方言：`bin/{Asm}/{Ns}/{F}.cs` ≡ `{Ns}/{F}.cs` ≡ `Modules.Multiplayer/{Asm}/{Ns}/{F}.cs`（同一 canon）。

### C2 类型身份
**frontmatter 里没有 type/namespace**（95 页 frontmatter 只有 `title` + `description`），
元数据在**正文粗体标签行**：`**Namespace:**` / `**Type:**` / `**Base:**`。
C2 比较的是**类型身份** = `Namespace` + `kind` + `名称`；
修饰符（`public`/`static`/`sealed`/`abstract`）、基类与接口列表、特性标注、行尾空白
都只是**声明细节**，不参与身份比较。
不这样归一会产生假冲突，实测 3 例：`Game`（一侧多 `([SaveableRootClass(5000)])`）、
`ItemObject`（`class` vs `sealed class`）、`ItemRoster`（接口列表详略不同 + 行尾空白）。

### C3 成员集合 —— 两种取法都报，两种都是代理指标
页面**没有机读成员表**，只有散文，所以 C3 是代理指标。取法 = 行内反引号标识符 ∪ md 表格首列，
正则 `^[A-Z][A-Za-z0-9_]*$`，去重。结构排除：围栏代码块、frontmatter、ATX 标题行、
**表格表头行**、以及**散文类目单元格**（首格去掉 `(...)` 后存在非 CamelCase token）。
实测排除散文单元格 **42 种 / 94 处**。

| 列 | 取法 |
|---|---|
| **宽松 J** | 上述全部接受 |
| **严格 J** | 再剔除 27 个"读起来像英文单词"的大写 token（`Name`/`Kingdom`/`State`/`Save`/`Entry`… 共 64 处） |

> **两种取法都属于「代理指标」不是「成员真集」**。页面没有机读成员表，两种取法都不是权威值，
> **它们的差就是噪声带**。下个会话要看的是**差有多大**，不是哪个数好看。
> 严格取法不作为判定依据，只用于标注噪声带宽度。

> **自检教训（本会话反复出现的同一类错：测的东西和你想测的不是一回事）**
> C3 第一版只抓行内反引号，得出 `campaign/Army.md` 成员数 **1**、`campaign-ext/Army.md` **113**。
> 那不是"成员差 112 个"，是**前者表格里成员名不带反引号**——测的是**排版风格**不是成员。
> 第二版改用"只出现在表格首列"来筛散文，又把真成员（`FinishArmyObjective`、`ToString`、
> `UpdateName`）判成散文——**同一个坑第二次**。
> 真正的根因不是"有几个噪声词"，是**不是每张表都是成员表**：`Deliberately disband` /
> `Fund cohesion` 那种是**散文类目表**。解法必须是结构判据，不是词表。

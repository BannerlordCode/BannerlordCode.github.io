## 概述

`QuestManager` 是战役任务系统的**总调度器**：它维护全部进行中的任务列表（`Quests`）和一张「任务 → 追踪对象」映射（`TrackedObjects`），驱动任务的超时判定与每小时/每日/每周 tick，并通过继承 `CampaignEventReceiver` 让任务有机会拦截英雄死亡、成为俘虏、结婚、装备变更、进入聚落等战役事件。它通过 `Campaign.Current.QuestManager` 暴露。

它的工作分三条线。**生命周期线**：任务开始时 `OnQuestStarted` 把任务加进列表，任务结束时 `OnQuestFinalized` 移除；加载时 `OnGameLoaded` 重建任务引用并清理没有对应 issue 的孤儿任务。**时间线**：`HourlyTick` 先扫一遍超时任务并逐个 `CompleteQuestWithTimeOut`，再对每个任务跑 `HourlyTickWithQuestManager`；`DailyTick` / `WeeklyTick` 同理。**拦截线**：`CanHeroDie` / `CanHeroMarry` / `CanMoveToSettlement` 等 `Can*` 方法让每个进行中的任务对「这个英雄能不能做这件事」投票，任一任务否决就阻止。

## 心智模型

**它是「任务列表 + 追踪映射 + 事件投票器」，不是「任务内容本身」。**

- **它管「哪些任务在跑」**：`Quests` 是进行中的任务总表；任务的具体内容（目标、对话、奖励）在 `QuestBase` 及其子类里。
- **它管「任务在追踪什么」**：`TrackedObjects` 是 `ITrackableCampaignObject → List<QuestBase>` 的反向映射——一个英雄、一个聚落、一个部队可以同时被多个任务追踪。
- **它管「任务什么时候超时」**：`HourlyTick` 里先收集 `QuestDueTime.IsPast` 的任务，再逐个超时结算；超时和正常完成走不同的结算路径。
- **它管「任务能不能拦截事件」**：`Can*` 系列方法遍历所有进行中的任务，把事件交给每个任务的 `OnHeroCanXxxInfoIsRequested` 钩子，任一任务把 `result` 置 false 就否决。

**为什么任务能拦截英雄死亡**：`CanHeroDie` 遍历 `Quests`，对每个任务调 `questBase.OnHeroCanDieInfoIsRequested(hero, causeOfDeath, ref result)`——任务可以保护关键 NPC 不死（例如「护送任务中目标不能死」）。这是任务系统影响战役世界的主要手段。

**一个常见误用**：直接 `new QuestManager()`。它由 `Campaign` 持有并注册进 `CampaignEventDispatcher`（`Campaign.cs:1892`），自己 new 的实例不在事件系统里，`Can*` 钩子不会被调用。

## 怎么用

### 怎么拿到

```csharp
QuestManager qm = Campaign.Current.QuestManager;
```

### 典型用法

```csharp
// 检查某个 NPC 是否有正在进行的任务可以接
bool canOffer = qm.IsQuestGiver(hero);

// 检查是否已有某类任务在跑（避免重复发放）
bool already = qm.IsThereActiveQuestWithType(typeof(MyQuest));

// 遍历所有进行中的任务
foreach (QuestBase quest in qm.Quests)
{
    if (quest.IsOngoing) { /* ... */ }
}

// 给任务注册一个追踪对象（任务目标英雄/聚落等）
qm.AddTrackedObjectForQuest(hero, myQuest);

// 查询某聚落是否有任务目标
bool inNotables = QuestManager.QuestExistInSettlementNotables(myQuest, settlement);
```

任务总表是 `Quests`（`QuestManager.cs:47`），追踪映射是 `TrackedObjects`（`QuestManager.cs:63`）。超时驱动在 `HourlyTick`（`QuestManager.cs:198`），加载重建在 `OnGameLoaded`（`QuestManager.cs:137`）。

### 坑

- **`IsThereActiveQuestWithType` 匹配子类**。它检查 `type == questBase.GetType() || questBase.GetType().IsSubclassOf(type)`——传基类会匹配所有子类任务。
- **`AddTrackedObjectForQuest` 重复添加会 FailedAssert**。同一对象同一任务重复注册会触发断言（Debug 构建下报错），注册前先检查 `TrackedObjects`。
- **`RemoveTrackedObjectForQuest` 会级联清理**。移除后如果该对象不再被任何任务追踪，会同时从 `VisualTrackerManager` 移除追踪标记。
- **`OnPlayerCharacterChanged` 会取消非特殊任务**。玩家角色更换时，所有 `!IsSpecialQuest` 的进行中任务会被 `CompleteQuestWithCancel` 取消——这是设计，不是 bug。
- **`QuestDebugMode` 是公开可写字段**。设为 true 后任务系统进入调试模式（具体表现取决于 `QuestBase` 子类），发布前记得关掉。
- **`PriorQuestName` 是静态字段**。它记录上一个任务的名字，用于对话系统衔接；多任务并发时可能被覆盖，不要依赖它做精确判定。

## 真实示例

```csharp
// 一个 CampaignBehavior：检查 NPC 是否有任务可接，有则显示追踪标记
public class QuestGiverHighlightBehavior : CampaignBehaviorBase
{
    public override void RegisterEvents()
    {
        CampaignEvents.HourlyTick.AddNonSerializedListener(this, this.OnHourlyTick);
    }

    private void OnHourlyTick()
    {
        QuestManager qm = Campaign.Current.QuestManager;
        foreach (Hero hero in Campaign.Current.AliveHeroes)
        {
            if (!qm.IsQuestGiver(hero)) continue;
            foreach (QuestBase quest in qm.GetQuestGiverQuests(hero))
            {
                foreach (var tracked in qm.GetAllTrackedObjectsOfAQuest(quest))
                {
                    // 对任务追踪对象做处理
                }
            }
        }
    }
}
```

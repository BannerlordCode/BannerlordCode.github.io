### 1.2 我的核验工具本身有 bug，101 条「发现」全部被我推翻

我写了个工具按「符号存在性 + ±8 行窗口」批量判定，输出：

```

```

看着像 101 条硬发现。**逐条复核后，101 条全部不成立。** 三个独立的工具缺陷：

**缺陷 A —— 按文件名索引，没按模块索引。**
```
$ find bannerlord-1.4.5 -name AssemblyInfo.cs | wc -l
82                                  ← 同名文件 82 份
```
页面写 `AssemblyInfo.cs:8-10` 指的是 `TaleWorlds.MountAndBlade/Properties/AssemblyInfo.cs`，
真值就是 8/9/10：
```
$ grep -n InternalsVisibleTo .../TaleWorlds.MountAndBlade/Properties/AssemblyInfo.cs
8:[assembly: InternalsVisibleTo("TaleWorlds.MountAndBlade.AutoGenerated")]
9:[assembly: InternalsVisibleTo("TaleWorlds.MountAndBlade.Multiplayer")]
10:[assembly: InternalsVisibleTo("TaleWorlds.Generator.Bannerlord")]
```
我的工具按目录顺序先撞上 `Newtonsoft.Json` 那份（11/12/13）→ 报 `delta=+3`。
**这一类占「发现」里最大的一块，全部是假的。**

**缺陷 B —— 锚点选取错误。** 工具取「引用前最近的被反引号包着的标识符」当锚点，
于是把类型名（`MBAnimation`、`IMBAnimation`）当成了成员锚点。
类型名在文件里只出现在声明处，引用点当然找不到它 → 一律误报 NOT within ±8。

**缺陷 C —— 混淆「声明在哪行」和「赋值在哪行」。**
```
页面（IMBBannerlordConfig.md:168）：
  assigned in `SetObjects` at `MBAPI.cs:111`
我的工具：
  锚点符号 = SetObjects，真实声明行 = 79 → 报 drift +32
真相：
  :108  IMBBannerlordChecker = GetObject<IMBBannerlordChecker>();     ← 页面写的正是这行 ✅
  :111  IMBBannerlordConfig   = GetObject<IMBBannerlordConfig>();     ← 页面写的正是这行 ✅
  :79   internal static void SetObjects(...)                          ← 方法声明
```
⇒ **页面说的「在 SetObjects 里赋值，位置是 111 行」，一字不差。我的工具锚在了方法声明上。**

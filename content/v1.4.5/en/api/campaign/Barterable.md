# Barterable

**Namespace:** `TaleWorlds.CampaignSystem.BarterSystem.Barterables`
**Module:** `TaleWorlds.CampaignSystem`
**Type:** `public abstract class Barterable`
**Base:** none (derives directly from object)
**Source:** `bin/TaleWorlds.CampaignSystem/TaleWorlds.CampaignSystem.BarterSystem.Barterables/Barterable.cs`

## Overview

`Barterable` is the abstract shape of **one item that can be put on the trade table**. Gold, goods, prisoners, fiefs — to [BarterData](../BarterData) they all have the same form: they know their original owner (`OriginalOwner` / `OriginalParty`), their unit price (`GetUnitValueForFaction`), the icon to draw (`GetVisualIdentifier`), and what to do when accepted (`Apply`). Derived classes fill those holes; the shared logic lives here.

In the architecture this type carries the **"polymorphic wrapper for heterogeneous trade lines"** slot. The trade screen has to show a pile of gold and a clay jar in the same list, and the UI cannot have one control per kind of good, so the shape is abstracted into a uniform `Name` / `GetVisualIdentifier` / `GetValueForFaction`.

Four intuitions to build first:

1. **It is "proposed", not "applied".** The constructor only records the owners, sets `CurrentAmount` to 1, and sets `Side` to `Left`. It touches no world state. The actual write happens inside `Apply()`, which the manager calls after the player confirms.
2. **`Side` is hard-wired to `Left` in the constructor.** That is `Barterable.BarterSide.Left`. The right-hand half is handled by the manager during assembly — **this base class exposes no public way to flip sides.** Seeing `Side` always return `Left` is not a bug.
3. **The `CurrentAmount` setter silently clamps to `MaxAmount`.** Write 100 in and you may read 1 back, because the base returns `MaxAmount => 1`. Selling several units of goods requires overriding `MaxAmount`.
4. **`SetIsOffered` cascades.** It sets itself and every entry in `_linkedBarterables` to the same value. Once a link exists, the two lines can never be offered independently.

## Mental Model

Think of it as **one slot on the trade table**.

- **The call order is always "construct, then Initialize, then Apply".** A barter behavior such as `ItemBarterBehavior` constructs a concrete subclass inside the `BarterData` callback and calls `args.AddBarterable<ItemBarterGroup>(barterable)`; that method in turn calls `barterable.Initialize(group, isContextDependent)` to write the group and context flag. `Apply()` only runs after the player confirms. **Skipping `Initialize` and calling `Apply` still compiles, but `Group` stays null**, and anything that looks lines up by group will miss it.
- **`GetValueForFaction` is `GetUnitValueForFaction` times `CurrentAmount`.** Pricing always goes through `IFaction`, because the same good is worth different amounts to different factions. Quote with `GetValueForFaction`; never multiply by `CurrentAmount` yourself.
- **`IsCompatible` defaults to true and `CheckBarterLink` defaults to a no-op.** Both are virtual hooks for link rules: the former decides whether two lines may coexist, the latter runs extra validation when a link is built.
- **Links are created with `AddBarterLink` and propagated with `SetIsOffered`.** The canonical case is "buying the armour also commits the scabbard". Building the link is one-shot; at runtime `SetIsOffered` synchronises visibility.
- **`Apply()` is pure abstract with no default.** It is the only member that really writes world state, and it must go through the official Actions.
- **`AutoGeneratedInstanceCollectObjects` is empty.** That means a barterable **does not enter the save** — the trade session itself is not persisted.

## How to use

**How to obtain it.** **It is abstract and inert on construction.** `public abstract class Barterable` writes no world state; a barterable only takes effect once it is registered into a `BarterData` group. Derive from it and register, or read the registered ones.

```csharp
// construct nothing on its own: register into a BarterData group instead
data.AddBarterable<MyModBarterable>();
// and read the effective set through the diplomacy model
```

**The most common pitfall.** **The constructor writes no world state.** `new`-ing a barterable does nothing except fill a few fields, so "construct it and it takes effect" is wrong.

## Examples

A minimal custom barterable trading renown for gold. `Apply` uses the real `GiveGoldAction.ApplyBetweenCharacters(Hero, Hero, int)` present in 1.4.5, and `GetVisualIdentifier` simply returns null, which is exactly what the official [GoldBarterable](../GoldBarterable), [FiefBarterable](../FiefBarterable), and [DeclareWarBarterable](../DeclareWarBarterable) do:

```csharp
using TaleWorlds.CampaignSystem;
using TaleWorlds.CampaignSystem.Actions;
using TaleWorlds.CampaignSystem.BarterSystem.Barterables;
using TaleWorlds.Core.ImageIdentifiers;
using TaleWorlds.Localization;

public class RenownBarterable : Barterable
{
    private readonly Hero _payer;
    private readonly Hero _receiver;
    private readonly int _renownToBuy;
    private readonly int _maxRenown;

    public RenownBarterable(Hero payer, Hero receiver, int renownToBuy, int maxRenown)
        : base(payer, payer.PartyBelongedTo)
    {
        _payer = payer;
        _receiver = receiver;
        _renownToBuy = renownToBuy;
        _maxRenown = maxRenown;
        this.MaxAmount = maxRenown;
        this.CurrentAmount = 0;
    }

    public override string StringID => "renown_barterable";

    public override int MaxAmount => _maxRenown;

    public override TextObject Name => new TextObject("{=myRenownBarter}Renown");

    public override int GetUnitValueForFaction(IFaction faction)
    {
        // Same shape as the official GoldBarterable: negative for our own side, positive for theirs
        if (faction == OriginalOwner?.Clan || faction == OriginalOwner?.MapFaction)
        {
            return -_renownToBuy;
        }

        if (faction == _receiver?.Clan || faction == _receiver?.MapFaction)
        {
            return _renownToBuy;
        }

        return 0;
    }

    public override ImageIdentifier GetVisualIdentifier()
    {
        return null;
    }

    public override void Apply()
    {
        if (_payer != null && _receiver != null)
        {
            GainRenownAction.Apply(_payer, CurrentAmount, doNotNotify: true);
        }
    }
}
```

> `GainRenownAction.ApplyInternal` is guarded by `if (gainedRenown > 0f)`, so a **negative renown value is silently ignored** by that Action. Spending renown requires `hero.Clan.AddRenown(-n)` or your own Action. That is a real 1.4.5 source boundary, not a typo.

Register the line on an in-flight trade and give it a linked partner:

```csharp
using TaleWorlds.CampaignSystem;
using TaleWorlds.CampaignSystem.BarterSystem;
using TaleWorlds.CampaignSystem.BarterSystem.Barterables;

public static void RegisterRenownLine(BarterData barterData, Hero offerer, Hero other)
{
    if (barterData == null || offerer == null || other == null)
    {
        return;
    }

    RenownBarterable renown = new RenownBarterable(offerer, other, 250, 500);
    barterData.AddBarterable<OtherBarterGroup>(renown);

    if (renown.Group == null)
    {
        Debug.Print("group not assigned, GetBarterGroups() does not contain OtherBarterGroup", 0);
        return;
    }

    renown.AddBarterLink(new RenownBarterable(other, offerer, 250, 500));
    renown.SetIsOffered(true);
    Debug.Print("offered lines = " + barterData.GetOfferedBarterables().Count, 0);
}
```

Quote for a faction through the total-value accessor instead of multiplying by hand:

```csharp
using TaleWorlds.CampaignSystem;

public static int QuoteForFaction(Barterable line, IFaction evaluating)
{
    if (line == null || evaluating == null)
    {
        return 0;
    }

    line.CurrentAmount = 1;
    return line.GetValueForFaction(evaluating);
}
```

Inspect a link's compatibility and group assignment; both are read points:

```csharp
using TaleWorlds.CampaignSystem;
using TaleWorlds.CampaignSystem.BarterSystem;
using TaleWorlds.CampaignSystem.BarterSystem.Barterables;

public static bool IsOnOffer(BarterData barterData, Barterable line)
{
    if (barterData == null || line == null)
    {
        return false;
    }

    bool grouped = barterData.GetBarterGroup<OtherBarterGroup>() != null;
    bool offered = line.IsOffered;
    Debug.Print("grouped=" + grouped + " offered=" + offered + " linked=" + line.LinkedBarterables.Count, 0);
    return offered;
}
```

## Risks and crash boundaries

- **The constructor writes no world state.** `new`-ing a barterable does nothing except fill a few fields. Any "construct it and it takes effect" style is wrong; the confirmed path runs `Apply()` inside the barter manager.
- **The `CurrentAmount` clamp is silent.** The setter does `if (_currentAmout > MaxAmount) _currentAmout = MaxAmount;`, so writing 100 reads back 1 without any notice. Override `MaxAmount` first if you need multiples.
- **`Group` depends on `Initialize`.** Constructing directly and bypassing `AddBarterable<T>` leaves `Group` null, and group-based lookups such as `BarterData.GetBarterGroup<T>()` will skip it.
- **`Side` always returns `Left`.** Fixed in the constructor with no public flip. Any code branching on `Side` deserves a look at how the caller works around it.
- **`AddBarterLink` is one-way and does not de-duplicate.** Call it a second time on the other side for a two-way link; calling it twice on the same side produces a duplicate and runs the cascade twice.
- **`CheckBarterLink` returns void and cannot refuse.** To block an incompatible pair, ask `IsCompatible` before building the link. The base `CheckBarterLink` is an empty body.
- **`GetEncyclopediaLink` returns an empty string, not null.** Use `string.IsNullOrEmpty`; a `== null` test is never true.
- **Does not enter the save.** `AutoGeneratedInstanceCollectObjects` is an empty implementation and the trade session is not persisted.
- **Abstract, but none of the official subclasses are `sealed`.** A mod can inherit one and change its semantics without breaking the build.

## Cross-Version Notes

`bannerlord-1.4.5/Bannerlord.Source/bin/TaleWorlds.CampaignSystem/TaleWorlds.CampaignSystem.BarterSystem.Barterables/Barterable.cs` is a 118-line original-source file and includes a nested `BarterSide` enum (`Left` / `Right`). Three things to check across versions: the capital-`D` spelling of `StringID` (neighbouring families have a lowercase-`d` `StringId`, and mixing them up does not compile), whether the clamp still lives inside the `CurrentAmount` setter, and whether `Side` is still pinned to `Left`. A change in any of the three silently shifts existing mod behaviour.

## Dependencies

- Dispatch and container: `AddBarterable<T>` on [BarterData](../BarterData) calls `Initialize`; `GetOfferedBarterables` reads `IsOffered`
- Group tag: [BarterGroup](../BarterGroup) is the type of the `Group` property, and its `AIDecisionWeight` decides whether the AI picks the line on its own
- Session and settlement: [BarterManager](../BarterManager) assembles the barterables, reads the valuations, and calls `Apply()` after the player confirms
- Owners: [Hero](../Hero) supplies `OriginalOwner` and the party side is [PartyBase](../PartyBase); either may be null
- Pricing context: `IFaction` (the interface family owned by [FactionManager](../FactionManager)) selects the branch inside `GetUnitValueForFaction`
- Icon and display: `ImageIdentifier` (a Core-layer abstract class with concrete subclasses such as `ItemImageIdentifier` and `BannerImageIdentifier`) and `TextObject` from Localization
- Bucket index: [campaign API section](../)

# ArmyCreationMapNotification

**Namespace:** `TaleWorlds.CampaignSystem.MapNotificationTypes`
**Module:** `TaleWorlds.CampaignSystem`
**Type:** `public class ArmyCreationMapNotification : InformationData`
**Base:** `InformationData`
**File:** `bin/TaleWorlds.CampaignSystem/TaleWorlds.CampaignSystem.MapNotificationTypes/ArmyCreationMapNotification.cs`

## 概述

`ArmyCreationMapNotification` 是地图左下角通知栏里那条「军团成立」的数据载体。它本身**不画任何东西**：继承 [InformationData](../../core-extra/InformationData)，把一份文本和一个 [Army](../Army) 引用装进去，剩下的全部交给 UI 层——`MapNotificationVM` 查表找到对应的 `ArmyCreationNotificationItemVM`，用 `Activator.CreateInstance(vmType, data)` 造出条目，再由条目自己订阅 `OnPartyJoinedArmyEvent` / `ArmyDispersed` / `OnClanChangedKingdomEvent`，在玩家真的入伙或军团解散时把自己移除。

唯一状态是 `[SaveableProperty(1)] public Army CreatedArmy { get; private set; }`。基类的 `DescriptionText` 通常由调用方从 [ArmyCreationLogEntry](../ArmyCreationLogEntry).GetEncyclopediaText() 借来——**同一条文本既进日志又进通知栏**。

## 心智模型

把它当成**一个纯 DTO + 一条反射契约**。三条链路按顺序发生，缺任何一环通知都不会出现在 UI 上：

1. **写入。** `Campaign.Current.CampaignInformationManager.NewMapNoticeAdded(data)`（`CampaignInformationManager.cs:100`）→ `AddInformationData` → `MBInformationManager.AddNotice`。这是唯一的官方入口。
2. **查表。** `MapNotificationVM.GetNotificationFromData(data)` 用 `data.GetType()` 精确查 `_itemConstructors` 字典。`ArmyCreationMapNotification` → `ArmyCreationNotificationItemVM` 的映射是**在 `MapNotificationVM` 的构造函数里硬写的**（`MapNotificationVM.cs:117`），不是基类推断的。**没在表里注册的类型会被静默丢弃**——`GetNotificationFromData` 返回 null，`AddMapNotification` 直接 return，不报错。
3. **自移除。** `ArmyCreationNotificationItemVM` 构造时订阅三个战役事件，任一命中就 `ExecuteRemove()`：玩家加入了这支军团、这支军团解散了、或者玩家的氏族换了王国。

最要紧的心智锚点是**「GameTime 无效」与「已注册」的区别**。本类型**不 override `IsValid()`**，所以基类默认返回 true，通知不会过期——即使创建它的那支军团半天后解散了，条目也是靠 VM 层的三个事件监听才消失的。这与 [AllianceOfferMapNotification](../AllianceOfferMapNotification) 那类带 `TriggerTime` 的通知完全不同：那种靠 `IsValid()` 定时淘汰，本类型靠事件。搞混这两条淘汰路径，就会写出「军团解散了通知还在」的 mod 逻辑。

第二个锚点是 **`CreatedArmy` 是活引用**。`[SaveableProperty(1)]` 存的是 `Army` 对象本身，不是 StringId。通知条目存活期间如果这个 `Army` 被解散，`CreatedArmy` 指向的仍是那个对象——VM 的 `GoToMapPosition(Army?.LeaderParty?.Position ?? MobileParty.MainParty.Position)` 用了 `?.` 兜底，正是因为 `LeaderParty` 可能已经为 null。

## 真实示例

官方唯一的构造形态，从 [DefaultLogsCampaignBehavior](../DefaultLogsCampaignBehavior).OnArmyCreated 照抄：

```csharp
ArmyCreationLogEntry armyCreationLogEntry = new ArmyCreationLogEntry(army);
LogEntry.AddLogEntry(armyCreationLogEntry);
if (army.LeaderParty.MapFaction == MobileParty.MainParty.MapFaction && army.LeaderParty != MobileParty.MainParty)
{
    Campaign.Current.CampaignInformationManager.NewMapNoticeAdded(
        new ArmyCreationMapNotification(army, armyCreationLogEntry.GetEncyclopediaText()));
}
```

做一条自定义文案的「军团成立」通知（mod 最常见的用法）：

```csharp
Army myArmy = MobileParty.MainParty.Army;
if (myArmy != null)
{
    TextObject custom = new TextObject("{=mykey}Your warband has gathered under {RULER.NAME}.");
    custom.SetTextVariable("RULER", Hero.MainHero.CharacterObject);
    Campaign.Current.CampaignInformationManager.NewMapNoticeAdded(new ArmyCreationMapNotification(myArmy, custom));
}
```

查当前是否已经存在一条未处理的军团成立通知（`InformationDataExists<T>` 是官方的存在性查询）：

```csharp
bool pending = Campaign.Current.CampaignInformationManager.InformationDataExists<ArmyCreationMapNotification>(null);
Debug.Print("pending army-created notices = " + pending, 0);
```

## 风险与边界

- **必须注册 VM，否则通知静默消失。** `MapNotificationVM` 用 `data.GetType()` 精确查表，未注册的类型走 `GetNotificationFromData` 返回 null 一路静默返回。mod 里自定义 `InformationData` 子类**必须**同时往 `_itemConstructors` 注册对应 VM，否则不报错也看不见。
- **`CreatedArmy` 可能已经失效。** 存的是活引用；军团解散后它仍指向那个对象。VM 侧用 `Army?.LeaderParty?.Position ?? MobileParty.MainParty.Position` 兜底，你自己读的时候不要假设 `LeaderParty` 非 null。
- **构造器会解引用。** `army` 为 null 时 `CreatedArmy` 直接是 null，没有参数校验，也没有 `Debug.FailedAssert`。
- **`IsValid()` 不 override，通知永不过期。** 基类默认返回 true。真正的清理由 VM 层的三个 `CampaignEvents` 监听完成；如果你在无头环境（不创建 VM）下发通知，它会一直留在 `CampaignInformationManager` 的 `_mapNotices` 里，读档时 `OnGameLoaded` 的 `RemoveAll(t => t == null || !t.IsValid())` 也清不掉它。
- **`TitleText` 每次访问都分配。** 别在循环里反复读。
- **存档。** `[SaveableProperty(1)]` + `AutoGeneratedInstanceCollectObjects` 收集 `CreatedArmy`；`SaveableCampaignTypeDefiner.cs` 与 `AutoGeneratedSaveManager` 负责 id 映射。给基类或本类加字段必须同步 SaveManager。
- **文本没有覆盖钩子。** 想换标题只能派生重写 `TitleText`，而派生类型又得重新注册 VM。
- **音效资源缺失是静默失败。** `SoundEventPath` 指向的事件名在资源包里不存在时只是没声音。

## 怎么用

### 怎么拿到它

**官方只有一个构造点，且它同时写了一条日志。** `DefaultLogsCampaignBehavior.cs:124` 把 `armyCreationLogEntry.GetEncyclopediaText()` 同时喂给 `LogEntry.AddLogEntry` 和本通知——**通知文案是从日志条目借来的，不是另写一份**。这决定了模特的正确姿势：先建 `ArmyCreationLogEntry`，再把它的百科文案转给通知，否则两处文字会各自漂移。

构造器本身极简：`ArmyCreationMapNotification(Army, TextObject)`（`:33`）只做 `base(description)`（`:35`）和 `CreatedArmy = createdArmy`（`:37`），**没有单参重载，也没有触发时间**。

消费侧是一条**精确类型查表**：`MapNotificationVM.GetNotificationFromData`（`MapNotificationVM.cs:193`）取 `data.GetType()`（`:195`）在 `_itemConstructors` 里查（`:197`），命中才 `Activator.CreateInstance`（`:199`）并挂 `OnRemove` / `OnFocus`（`:202`-`:203`）。本类型的注册在 `MapNotificationVM.cs:118`。

### 典型用法

它**不 override `IsValid()`**——基类返回 true，所以卡片永不过期，清理只靠玩家点「检视」时 VM 的 `_onInspect` 调 `ExecuteRemove()`。这意味着模组不能靠「发出去自然过期」来控制刷屏，得自己在发之前查一次存在性。

`CreatedArmy` 是 `SaveableProperty(1)` 的 `private set`（`:14`-`:15`），**运行时没有公开的改写入口**；而且 `AutoGeneratedInstanceCollectObjects`（`:22`）只收一个 `CreatedArmy`（`:25`），**没有 army 的内部成员**——读档后 `CreatedArmy` 是靠 army 自己的存档恢复的，不是靠这里。

想把「成立通知」和「解散通知」配对追踪，就靠两个 `SaveableProperty` 字段 + 事件，而不是靠文案：

```csharp
public static class ArmyNoticePairer
{
    public static void Report(Army army)
    {
        CampaignInformationManager info = Campaign.Current.CampaignInformationManager;
        bool created = info.InformationDataExists<ArmyCreationMapNotification>(null);
        bool dispersed = info.InformationDataExists<ArmyDispersionMapNotification>(null);
        Debug.Print("army=" + army.Name + " createdPending=" + created, 0);
        Debug.Print("dispersedPending=" + dispersed + " leaderParty=" + army.LeaderParty, 0);
    }
}
```

`SoundEventPath` 固定 `"event:/ui/notification/army_created"`（`:12`），`TitleText` 硬编码 `"{=6NWExCu6}Army Created"`（`:10`）——**都不是可注入字段，派生类要改只能 override。**

### 最容易踩的坑

**必须注册 VM，否则通知静默消失。** `MapNotificationVM` 用 `data.GetType()` 精确查表，未注册的类型走 `GetNotificationFromData` 返回 null 一路静默返回。mod 里自定义 `InformationData` 子类**必须**同时往 `_itemConstructors` 注册对应 VM，否则不报错也看不见。

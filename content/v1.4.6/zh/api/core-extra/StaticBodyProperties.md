# StaticBodyProperties

**Namespace:** `TaleWorlds.Core`
**Module:** `TaleWorlds.Core`
**Type:** `public struct StaticBodyProperties : ISerializableObject`
**Base:** `System.ValueType`（实现 `TaleWorlds.SaveSystem.ISerializableObject`）
**File:** `TaleWorlds.Core/StaticBodyProperties.cs`

## 概述

它是 [BodyProperties](../BodyProperties) 的另一半，也是角色「长什么样」的最终载体：**8 个 `ulong` 拼成 128 位指纹**，每一位对应一个脸型特征组的子项。[DynamicBodyProperties](../DynamicBodyProperties) 管年龄/体重/体型这种会变的量，这里管不会变的骨相与配色。

它实现 `ISerializableObject`，走存档系统的 `IReader.ReadULong()` / `IWriter.WriteULong()` 而**不是**属性层的 `[SaveableProperty]` 路径（虽然八个属性各自也挂了 `[SaveableProperty(1..8)]`）。`FromXmlNode` 是反方向：从 XML 的 `key` 属性读一个**恰好 128 个字符**的十六进制串，按 16 字符一段切成 8 个 `ulong`。

**这个类不做任何「解码」。** 128 位里的每一位代表什么特征、怎么组合出 mesh，完全在 native 侧（`MBAPI.IMBFaceGen` 一类的调用链）——`StaticBodyProperties` 只负责搬运、比较、序列化。你能对它做的判断只有相等与随机，**语义判断得靠 [FaceGen](../FaceGen) 那一侧**。

## 心智模型

三个典型用法：

1. **从 XML / 字符串读回**：`StaticBodyProperties.FromXmlNode(node, out props)`，或经 [BodyProperties](../BodyProperties).FromString 间接调用。**长度不是 128 就返回 false 并把 out 参数写成全 0**。
2. **构造**：`new StaticBodyProperties(k1, k2, …, k8)` —— 八个 `ulong` 位置参数。
3. **随机造一个**：`GetRandomStaticBodyProperties()`（测试/占位用，`DateTime.Now.Ticks` 做种子）。

因为它是值类型且没有引用字段，**拷贝、赋值、传参全部免费且安全**，可以放心当 `Dictionary` 的键——但**别用 `==`**，用 `Equals`，理由与 [DynamicBodyProperties](../DynamicBodyProperties) 完全一样：`operator ==` 的反编译形态里首项是自身调用。

**最坑的一条：`GetHashCode()` 只混入了 `KeyPart8` 的高 32 位。** 折叠循环第一段对 `KeyPart1`…`KeyPart8` 各取 `(uint)((uint)KeyPartN << 32)` 参与 FNV 式混合——`ulong` 左移 32 位后强制转 `uint` 拿到的是**高 32 位**；第二段只对 `KeyPart1`…`KeyPart7` 各取**低 32 位**继续混合，**`KeyPart8` 的低 32 位从头到尾没进过 hash**。所以两个仅在 `KeyPart8` 低 32 位不同的结构体 `Equals` 为 false（字段比较是全 8 项的），`GetHashCode` 却相同。当 `HashSet<StaticBodyProperties>` 或 `Dictionary` 的键时会先撞桶再走 `Equals` 判定——**结果正确，但冲突率异常高**，如果你的 key 主要靠 `KeyPart8` 区分，别把它当性能好的键类型。

第二条：**`Equals(object)` 就是 `base.Equals(obj)`。** 结构体的 `ValueType.Equals` 会逐字段反射比较，语义正确但**比手写版本慢一个数量级**。在热路径（每帧比对角色外观）里请改用 `Equals` 的结构体泛型重载——但**本类没有提供**，所以要么自己写 8 项比较，要么接受反射开销。

第三条：`FromXmlNode` 要求 `key` 属性**长度恰好 128**，否则直接失败。**长度 126 或 130 都会被拒**，不是「截断补零」。

第四条：`GetRandomStaticBodyProperties()` 用 `DateTime.Now.Ticks` 做种子，**同一 tick 内连调两次会得到完全相同的结果**。它不是密码学随机，别拿它生成玩家可区分的外观。

常见误用：把 `KeyPart1` 当「骨骼索引」之类的语义字段去猜；指望本类能解释 128 位里的特征；用 `==` 比较；把 `GetRandomStaticBodyProperties()` 当作可靠的随机源。

## 关键成员

### 八个特征段

| 成员 | 签名 | 作用 |
| --- | --- | --- |
| `KeyPart1` … `KeyPart8` | `public ulong KeyPartN { get; private set; }` | 8 个 64 位特征段，`[SaveableProperty(1)]` … `[SaveableProperty(8)]`，各占存档里的一个属性位。**`private set`，外部无法改**。语义在 native 侧，本类不解释。 |
| `.ctor` | `public StaticBodyProperties(ulong keyPart1, ulong keyPart2, ulong keyPart3, ulong keyPart4, ulong keyPart5, ulong keyPart6, ulong keyPart7, ulong keyPart8)` | 八参数位置构造。**无校验、无顺序检查**——参数顺序写反不会报错，只会造出一个长得完全不同的角色。 |

### 解析与构造

| 成员 | 签名 | 作用 |
| --- | --- | --- |
| `FromXmlNode` | `public static bool FromXmlNode(XmlNode node, out StaticBodyProperties staticBodyProperties)` | 读 `node.Attributes["key"]`。**长度 ≠ 128 → out 参数置 `default` 并返回 false**。长度对则按 16 字符一段 `ulong.TryParse`（`NumberStyles.AllowHexSpecifier`）切成 8 段。**`TryParse` 的失败被忽略**，所以非十六进制字符会静默变成 0。 |
| `GetRandomStaticBodyProperties` | `public static StaticBodyProperties GetRandomStaticBodyProperties()` | 每段用两次 `random.Next()` 拼满 64 位（`Next() << 32 + Next()`），种子取 `DateTime.Now.Ticks`。**同一 tick 内结果可重复。** |

### 相等与序列化

| 成员 | 签名 | 作用 |
| --- | --- | --- |
| `GetHashCode` | `public override int GetHashCode()` | 两段 FNV 式折叠：**`KeyPart1`…`KeyPart8` 各取高 32 位入第一段，`KeyPart1`…**`KeyPart7` 各取低 32 位入第二段**。`KeyPart8` 的低 32 位不参与。末尾再做 `num + (num<<13)` / `^ (num>>7)` / `+ (num<<3)` / `^ (num>>17)` / `+ (num<<5)` 的收尾混合。 |
| `Equals(object)` | `public override bool Equals(object obj)` | 直接 `return base.Equals(obj)`，即 `ValueType.Equals` 的逐字段反射比较。**语义正确但慢。** |

## 真实示例

从 XML 节点读回（先看返回 bool）：

```csharp
XmlNode node = doc.SelectSingleNode("//BodyProperties");
StaticBodyProperties props;

if (StaticBodyProperties.FromXmlNode(node, out props))
{
    Debug.Print("key1=" + props.KeyPart1 + " key8=" + props.KeyPart8, 0);
}
else
{
    Debug.Print("key attribute must be exactly 128 chars", 0);
}
```

手工构造一个并往返序列化：

```csharp
StaticBodyProperties props = new StaticBodyProperties(
    0x0000000000000001UL,
    0x0000000000000002UL,
    0x0000000000000003UL,
    0x0000000000000004UL,
    0x0000000000000005UL,
    0x0000000000000006UL,
    0x0000000000000007UL,
    0x0000000000000008UL);

ISerializableObject serializable = props;
Debug.Print("toString=" + props.ToString(), 0);
Debug.Print("weightBit=" + StaticBodyProperties.WeightKeyNo + " buildBit=" + StaticBodyProperties.BuildKeyNo, 0);
```

与 [DynamicBodyProperties](../DynamicBodyProperties) 组合成完整体型：

```csharp
StaticBodyProperties staticProps = StaticBodyProperties.GetRandomStaticBodyProperties();
BodyProperties body = new BodyProperties(new DynamicBodyProperties(28f, 0.5f, 0.6f), staticProps);

Debug.Print("age=" + body.Age + " weight=" + body.Weight, 0);
Debug.Print("static=" + body.StaticProperties.ToString(), 0);
```

比较两个指纹（用 `Equals`，别用 `==`）：

```csharp
StaticBodyProperties a = new StaticBodyProperties(1UL, 2UL, 3UL, 4UL, 5UL, 6UL, 7UL, 8UL);
StaticBodyProperties sameAsA = new StaticBodyProperties(1UL, 2UL, 3UL, 4UL, 5UL, 6UL, 7UL, 8UL);
StaticBodyProperties onlyKey8LowDiffers = new StaticBodyProperties(1UL, 2UL, 3UL, 4UL, 5UL, 6UL, 7UL, 0xDEADBEEFCAFEUL);

Debug.Print("a==a2 : " + a.Equals(sameAsA), 0);
Debug.Print("a==b  : " + a.Equals(onlyKey8LowDiffers), 0);
Debug.Print("hash collide (KeyPart8 低 32 位不进 hash): " + (a.GetHashCode() == onlyKey8LowDiffers.GetHashCode()), 0);
```

把 key 串反序列化回 [BodyProperties](../BodyProperties)：

```csharp
string keyValue = "<BodyProperties age=\"34\" weight=\"0.5\" build=\"0.5\" key=\"0000000000000001000000000000000200000000000000030000000000000004000000000000000500000000000000060000000000000070000000000000008\" />";

BodyProperties body;
if (BodyProperties.FromString(keyValue, out body))
{
    Debug.Print("age=" + body.Age + " key1=" + body.KeyPart1, 0);
}
```

## 风险与边界

- **8 个 `ulong` 位置参数，无顺序校验。** 参数写错一位就得到一个「合法但完全不同」的脸，编译器不报错。
- **`FromXmlNode` 要求 `key` 长度恰好 128。** 多一个少一个都失败并返回全 0。
- **`FromXmlNode` 忽略 `ulong.TryParse` 的失败。** 非十六进制字符静默变 0，**没有错误信号**。
- **`GetHashCode` 漏掉 `KeyPart8` 的低 32 位。** 大量键只差这一段时会严重撞桶——结果仍正确（`Equals` 会兜住），但哈希容器性能会塌。**这是源码里可确证的实现细节，不是推测。**
- **`Equals(object)` 走 `ValueType.Equals` 反射比较。** 每帧比对角色外观时开销明显。
- **`operator ==` 的反编译形态可疑**（首项自身调用），与 [DynamicBodyProperties](../DynamicBodyProperties) 同形。**行为未核实，用 `Equals`。**
- **`ISerializableObject` 的两个方法是显式接口实现。** 直接 `props.SerializeTo(writer)` 编译不过，必须 `(ISerializableObject)props`。
- **两个 `AutoGeneratedGetMemberValueKeyPartN` 是 `internal`。** 外部程序集看不到它们，别试图反射调用。
- **`GetRandomStaticBodyProperties` 同一 tick 内可重复。** 不是密码学随机源。
- **不做语义解码。** 想知道某一位代表什么特征，只能查 [FaceGen](../FaceGen) 那一侧的 native 调用；本类只有搬运与比较。
- **位偏移常量只有两个。** `WeightKeyNo = 59` / `BuildKeyNo = 60` 是唯一的语义锚点，其余 126 位在本类里没有名字。

## 跨版本提示

`bannerlord-1.3.15/TaleWorlds.Core/StaticBodyProperties.cs` 与 `bannerlord-1.4.6/TaleWorlds.Core/StaticBodyProperties.cs` 逐行比对，**public 表面完全一致**：20 条 public 成员（`KeyPart1`…`KeyPart8` 八个属性 + 构造器 + `FromXmlNode` / `GetRandomStaticBodyProperties` / `GetHashCode` / `Equals` / `operator ==` / `operator !=` / `ToString` / `AutoGeneratedStaticCollectObjectsStaticBodyProperties` 八个静态方法），`[SaveableProperty(1)]`…`[SaveableProperty(8)]` 编号与两个 `const int`（59 / 60）也没变。

**1.4.5 侧结论**：打开 `bannerlord-1.4.5/Bannerlord.Source/bin/TaleWorlds.Core/TaleWorlds.Core/StaticBodyProperties.cs`（233 行）与 `bannerlord-1.4.6/TaleWorlds.Core/StaticBodyProperties.cs`（275 行）逐成员比对 public/protected 表面。**三版 public/protected 表面完全一致（各 25 个成员，0 新增 / 0 移除 / 0 签名变化 / 0 可访问性变化）**。**并且 1.4.5 的原始源码同样解开了本段上文标记为无法判定的那一条**：该文件第 137–151 行的 `operator ==` 原始写法是 `if ((object)a == (object)b) { return true; }` 再 `if ((object)a == null || (object)b == null) { return false; }` 之后逐字段比 8 个 `KeyPartN` —— **首项是装箱引用比较，不是自身递归调用**。

**为什么这份源码之前被判为「不存在」**：`bannerlord-1.4.5/` 的 C# 源码在 `Bannerlord.Source/bin/` 下**双层嵌套** `bin/<Assembly>/<Assembly>/<Type>.cs`，而 `bin/` 的一层里没有任何 `.cs`（实测 `find bannerlord-1.4.5/Bannerlord.Source/bin -maxdepth 1 -name "*.cs"` 命中 0），只扫一层就会误判成无源码。**1.4.5 是原始源码形态**（file-scoped namespace、无 `// Token:` 注释），1.4.6 与 1.3.15 是反编译产物，所以两边的行数不可直接比大小。

## 依赖关系

- 宿主：[BodyProperties](../BodyProperties) 持有它作为 `StaticProperties`，并把 `KeyPart1`…`KeyPart8` 八个字段逐个转发
- 另一半：[DynamicBodyProperties](../DynamicBodyProperties) 管会变的年龄/体重/体型，与本类合成完整体型
- 解析方向：本类的 `FromXmlNode` 由 [BodyProperties](../BodyProperties).FromString / FromXmlNode 调用；写入方向是 `ISerializableObject.SerializeTo`，存档系统读
- 语义侧：[FaceGen](../FaceGen) 是解读这 128 位的地方，但它的具体解码实现跨到 native，本类不涉及
- JSON：[BodyPropertiesJsonConverter](../BodyPropertiesJsonConverter) 把组合后的 [BodyProperties](../BodyProperties) 写成 `{"_data": "<BodyProperties … key=\"128位十六进制\" />"}`，`ToString()` 产出的正是那个串

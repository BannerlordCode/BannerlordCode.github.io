# CampaignStoryMode

**Namespace:** `StoryMode`
**Module:** `StoryMode`
**Type:** `public class CampaignStoryMode : Campaign`
**Base:** `TaleWorlds.CampaignSystem.Campaign`
**File:** `Modules.StoryMode/StoryMode/StoryMode/CampaignStoryMode.cs`

## Overview

`Campaign` is the campaign layer's root object and the game picks one concrete subclass per game mode. This is the one Story Mode uses. Everything it adds is Story-Mode-specific scaffolding: an object type registration for `TrainingField`, a hook into the loading state machine that initialises the story mode's object set and then launches the main storyline, and one saveable property pointing at `StoryModeManager`.

What it does *not* do is worth stating plainly — it contains no behaviors, no models, and no settlement logic. Those are all registered by `StoryModeManager` and the module's `StoryModeGameModel`, not by this class. `CampaignStoryMode` is the campaign-shaped object that exists so the save system has something concrete to serialise and the loading pipeline has a place to hang its Story Mode steps.

## Mental Model

The base-class casts in the source are the key to reading this file. Every override begins with `((Campaign)this).Method(...)` rather than `base.Method(...)`. That is not a stylistic quirk — `Campaign` declares these members explicitly as interface implementations, and the 1.4.5 decompilation routes through the interface dispatch. What it means for you is that **`base` and `((Campaign)this)` behave identically here**; there is no hidden base logic you are bypassing.

Three extension points, in the order the game invokes them:

- **`BeforeRegisterTypes`** — one extra `objectManager.RegisterType<TrainingField>("TrainingField", "TrainingFields", 1u, true, false)`. The two string literals are the XML tag name and the plural save-group name; they must match what the item XMLs actually use, and they are not shared with any constant.
- **`DoLoadingForGameType`** — the meat. It calls the base first, capturing the `out GameTypeLoadingStates nextState`, then branches on `gameTypeLoadingState`:
  - `== 0` and `nextState != gameTypeLoadingState` → `StoryMode.InitializeStoryModeObjects()`.
  - `== 2` and `nextState != gameTypeLoadingState` → look up `Settlement.Find("tutorial_training_field")`; if found, take `Campaign.Current.MapSceneWrapper` and call `AddNewEntityToMapScene(stringId, position)`, which stamps the settlement's map entity into the scene so the tutorial field is visible/clickable.
  - `== 3` → `OnSessionLaunched()`, which forwards to `StoryMode.MainStoryLine.OnSessionLaunched()`.

  The `nextState != gameTypeLoadingState` guard appears on the first two branches and not the third. That asymmetry is the interesting part: it means the object-initialisation and map-entity steps are skipped if the base decided this is the final pass of that state, whereas the session launch always fires on state `3`. Both comparisons are against integer literals, not named `GameTypeLoadingStates` members, so the mapping is positional.
- **`AutoGeneratedInstanceCollectObjects`** — base, then `collectedObjects.Add(StoryMode)`. This is what puts the manager into the save graph.

The saveable property is `[SaveableProperty(9999)] public StoryModeManager StoryMode { get; private set; }`. The id `9999` is very high, which in Bannerlord's save ordering means the object is written near the end — necessary because `StoryModeManager` transitively references story objects that must be written first. The setter is `private`, so only the constructor assigns it.

The constructor is where `StoryMode = new StoryModeManager()` happens. That means **a `StoryModeManager` exists from construction**, before any loading state runs, and the property is never null. During save load it is repopulated through `AutoGeneratedGetMemberValueStoryMode`, which is the generated accessor the save system calls by reflection.

## Key Members

| Member | Signature | What it is for |
| --- | --- | --- |
| `StoryMode` | `[SaveableProperty(9999)] public StoryModeManager StoryMode { get; private set; }` | The single saveable member of the whole campaign object, and the handle mods should use to reach all Story Mode state. Assigned in the constructor and populated on load through the generated `AutoGeneratedGetMemberValueStoryMode` accessor. The high save id is deliberate — the manager references story objects that must serialise first. |
| `CampaignStoryMode` | `public CampaignStoryMode(CampaignGameMode gameMode) : base(gameMode)` | Builds the object and immediately creates the `StoryModeManager`. Because the manager is constructed here rather than lazily, it exists for the entire lifetime of the campaign object including before `DoLoadingForGameType` has run a single state. |
| `BeforeRegisterTypes` | `protected override void BeforeRegisterTypes(MBObjectManager objectManager)` | Adds one object type the base campaign does not know about: `RegisterType<TrainingField>("TrainingField", "TrainingFields", 1u, true, false)`. Anything reading `TrainingField` from XML or from a save depends on this line having run, which is why it is an override rather than something a mod can add later. |
| `DoLoadingForGameType` | `protected override void DoLoadingForGameType(GameTypeLoadingStates gameTypeLoadingState, out GameTypeLoadingStates nextState)` | The three Story Mode loading steps: initialise story objects on state `0`, add the `tutorial_training_field` map entity on state `2`, and launch the main storyline on state `3`. Both state checks are integer comparisons and the first two additionally require `nextState != gameTypeLoadingState`. Being `protected`, it can only be driven by the loading pipeline. |
| `AutoGeneratedInstanceCollectObjects` | `protected override void AutoGeneratedInstanceCollectObjects(List<object> collectedObjects)` | The save-graph hook. Calls the base implementation and then adds `StoryMode` to the collected list, which is what makes `StoryModeManager` — and everything it owns — actually persist. A campaign object that forgets this silently saves a world with no story state. |

## Real Example

Read the Story Mode manager from the live campaign and inspect its entry points:

```csharp
Campaign campaign = Campaign.Current;
if (campaign is CampaignStoryMode storyCampaign)
{
    StoryModeManager manager = storyCampaign.StoryMode;
    Debug.Print("main story line = " + manager.MainStoryLine, 0);
    Debug.Print("campaign type = " + campaign.GetType().Name, 0);
}
```

Add your own story objects during the same window Story Mode uses — the loading state `0` step is the only safe place for it:

```csharp
protected override void DoLoadingForGameType(GameTypeLoadingStates state, out GameTypeLoadingStates nextState)
{
    base.DoLoadingForGameType(state, out nextState);

    if ((int)state == 3)
    {
        StoryMode.MainStoryLine.OnSessionLaunched();
        Debug.Print("main story line launched", 0);
    }
}
```

Note what is **not** reachable from a mod: `StoryModeManager.InitializeStoryModeObjects()` is `internal` (`StoryModeManager.cs:65`), so the state-`0` step can only be driven by the loading pipeline, never by your own code.

Put a settlement's map entity into the scene the same way the tutorial training field is added:

```csharp
Settlement field = Settlement.Find("tutorial_training_field");
if (field != null)
{
    CampaignVec2 pos = field.Position;
    Campaign.Current.MapSceneWrapper.AddNewEntityToMapScene(field.StringId, pos);
}
```

Verify the story manager survives a save/load round trip by checking it is reachable after the load completes:

```csharp
CampaignEvents.OnGameLoadedEvent.AddNonSerializedListener(
    this,
    () =>
    {
        Campaign loaded = Campaign.Current;
        Debug.Print("story manager restored: " + (loaded is CampaignStoryMode story && story.StoryMode != null), 0);
    });
```

## Risks and Boundaries

- **Replacing `Campaign` is not incremental.** Game mode selects this class *instead of* the Sandbox campaign, so any mod that assumes Sandbox behaviours are present is wrong under Story Mode.
- **Two integer-literal state comparisons.** `gameTypeLoadingState == 0`, `== 2`, and `== 3` are compared against raw ints, not `GameTypeLoadingStates` members. They are positional and will silently misfire if the enum is reordered.
- **The `nextState != gameTypeLoadingState` guard is asymmetric.** It gates the object-init and map-entity steps but not the session launch, so a Story Mode that ends on state `3` launches its story while skipping the other two steps' final pass.
- **The `TrainingField` tag strings are hard-coded literals.** `"TrainingField"` and `"TrainingFields"` must match the shipped XML. A mod that re-registers the type with different strings will break the item group.
- **No `SyncData` override.** Serialization is entirely via `[SaveableProperty]` plus `AutoGeneratedInstanceCollectObjects`. Adding a new saveable member means adding the attribute *and* the collect call, in the generated style.
- **Save id `9999` is load-order-sensitive.** It assumes the objects `StoryModeManager` references are already written. Changing the id can produce a save that loads with a half-built manager.
- **`AutoGeneratedGetMemberValueStoryMode` and `AutoGeneratedStaticCollectObjectsCampaignStoryMode` are `internal static`** — they exist for the generated save system and are not part of the public surface.
- **No extension points for behaviors.** This class registers no campaign behaviors; everything beyond the four overrides belongs in `StoryModeManager` or in the module's game model.

## Cross-version note

The v1.4.5 file is 85 lines with exactly four overrides and one property. The `((Campaign)this)` base-routing rather than `base` syntax is an artefact of how `Campaign` declares its interface members and is a formatting-level difference, not a behavioural one.

## Dependencies

- Base: [Campaign](../campaign/Campaign) supplies the whole campaign layer and is the type this class replaces under Story Mode; it also owns `MapSceneWrapper` and the `IsLoading` flag.
- Owning state: [StoryModeManager](StoryModeManager) holds the story objects, `MainStoryLine`, and the initialisation this class drives.
- Registration: [MBObjectManager](MBObjectManager) is the `objectManager` that `RegisterType<TrainingField>` writes into.
- Loading pipeline: [GameTypeLoadingStates](../core-extra/GameTypeLoadingStates) is the enum being branched on, compared positionally.
- Map scene: [Settlement](../campaign/Settlement) is what `Settlement.Find("tutorial_training_field")` locates and whose `Position` / `StringId` feed `AddNewEntityToMapScene`.

# WeakenEmpireQuestBehaviorTypeDefiner

**Namespace:** StoryMode.Quests.SecondPhase
**Module:** StoryMode
**Type:** `public class WeakenEmpireQuestBehaviorTypeDefiner : SaveableTypeDefiner`
**Base:** SaveableTypeDefiner
**Source:** SecondPhase/WeakenEmpireQuestBehavior.cs

## 概述

与 `AssembleEmpireQuestBehaviorTypeDefiner` 结构完全相同的一个存档注册类，唯一区别是全局编号：这里是 **1005000**，类内编号同样是 1。它把 `WeakenEmpireQuestBehavior` 内嵌的 `WeakenEmpireQuest` 登记到存档序列化体系里，让这个第二阶段反帝国线任务的存档字段能被正确写入与读出。

## 心智模型

它属于 Bannerlord 存档系统的"类型表"层。整个机制分三级：模块在 `MBSubModuleBase.SaveableTypes` 里列出所有 definer；每个 definer 用构造参数声明一个**全局唯一 id**；`DefineClassTypes()` 再把该 definer 名下的每个嵌套类型映射到一个**类内 id**。存档文件里存的是数字，反序列化时按数字找回 CLR 类型，再反射调用类型生成的 `AutoGeneratedGetMemberValue*` / `AutoGeneratedInstanceCollectObjects`。

因此这类对象的生命周期与模块相同：常驻、无状态、不参与 gameplay 逻辑。第二阶段的两个 definer 用 1002000（帝国线）和 1005000（反帝国线）两个相隔 3000 的号段，第三阶段用 16000，教程后氏族重建用 4140000——**号段之间留了巨大空隙**，就是为了让后续版本能插入新 definer 而不冲突。

## 主要成员

- `WeakenEmpireQuestBehaviorTypeDefiner()`：无参构造，只调 `base(1005000)`。这是它唯一能配置的地方，也是唯一不该动的地方。
- `protected override void DefineClassTypes()`：`AddClassDefinition(typeof(WeakenEmpireQuestBehavior.WeakenEmpireQuest), 1, null)`，把内嵌任务类型挂到 id 1 上。

## 使用示例

```csharp
// 第二阶段反帝国线的存档注册：1005000 是全局号，1 是类内号
public class WeakenEmpireQuestBehaviorTypeDefiner : SaveableTypeDefiner
{
    public WeakenEmpireQuestBehaviorTypeDefiner() : base(1005000) { }

    protected override void DefineClassTypes()
    {
        base.AddClassDefinition(typeof(WeakenEmpireQuestBehavior.WeakenEmpireQuest), 1, null);
    }
}
```

## 风险与边界

两个数字都是公开的存档 ABI 契约，**改任何一个都会让所有旧存档无法加载**——报错是"未知类型"而不是静默错读，这一点比很多序列化系统安全。第三个参数（泛型版本号）留 `null` 是因为该任务没有泛型嵌套类型；如果 mod 给 `WeakenEmpireQuest` 加了泛型变体，需要在这里同步注册带版本号的条目。它没有 override `DefineEnumTypes`，因为 `WeakenEmpireQuest` 内部没有需要持久化的枚举（对比 `RebuildPlayerClanQuestBehaviorTypeDefiner`，那里同时定义了类和一个枚举）。作为 mod 作者要自己加 definer 时，**选号必须避开所有已占用值**，冲突时的表现通常是随机类型被错误映射，比缺号更难查。

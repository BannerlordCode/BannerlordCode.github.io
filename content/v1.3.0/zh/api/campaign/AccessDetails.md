# AccessDetails

**Namespace:** `TaleWorlds.CampaignSystem.ComponentInterfaces`
**Module:** `TaleWorlds.CampaignSystem`
**Type:** `public struct AccessDetails`
**Base:** 无（值类型，只隐式继承 `System.ValueType` → `System.Object`）
**File:** `TaleWorlds.CampaignSystem/ComponentInterfaces/SettlementAccessModel.cs`（`:123`，嵌套在 `SettlementAccessModel` 内）

## 概述

`AccessDetails` 是**一次城镇准入判定的完整结果包**。它是一个只有六个 `public` 字段的 `struct`——没有属性、没有方法、没有构造函数：

```csharp
public struct AccessDetails
{
    public SettlementAccessModel.AccessLevel AccessLevel;
    public SettlementAccessModel.AccessMethod AccessMethod;
    public SettlementAccessModel.AccessLimitationReason AccessLimitationReason;
    public SettlementAccessModel.LimitedAccessSolution LimitedAccessSolution;
    public SettlementAccessModel.PreliminaryActionObligation PreliminaryActionObligation;
    public SettlementAccessModel.PreliminaryActionType PreliminaryActionType;
}
```

六个字段分别是**三组**：`AccessLevel` + `AccessMethod` + `AccessLimitationReason` 回答「能不能进 / 怎么进 / 为什么不许进」，`LimitedAccessSolution` 回答「有限制时先做什么」，最后两个 `PreliminaryAction*` 回答「进场前需要完成的前置动作及其强制性」。

**你几乎从不 `new` 它。** 它只通过 `SettlementAccessModel` 三个抽象方法的 `out` 参数交到你手上：`CanMainHeroEnterSettlement(Settlement, out AccessDetails)`、`CanMainHeroEnterLordsHall(Settlement, out AccessDetails)`、`CanMainHeroEnterDungeon(Settlement, out AccessDetails)`。反过来，**要产出它就必须实现那个抽象类**——`DefaultSettlementAccessModel` 里的写法全是对象初始化器或逐字段赋值。

它是 `struct` 而不是 `class`，所以**复制是值复制**，没有引用同一性问题；但也因此**它不会为 null**，`default(AccessDetails)` 是合法的零值结构体，不是 null。

## 心智模型

把它当成**「判定回执」**，而不是配置对象——三个要点：

**第一，回执是一次性的，不持久。** 它不是 `MBObjectBase` 子类，没有 `StringId`、没有 `Id`、不会被 `MBObjectManager` 注册。`AutoGeneratedInstanceCollectObjects` 这类存档钩子在它身上根本不存在——[AccessLevel](../AccessLevel)、[AccessMethod](../AccessMethod)、[AccessLimitationReason](../AccessLimitationReason) 三个枚举同为 `int` 底层，不需要引用收集。**别试图把它存进存档。**

**第二，全零是一个自洽的「进不去且无方式」组合。** 六个枚举的第一个成员分别是 `NoAccess` / `None` / `None` / `None` / `None` / `None`，所以 `default(AccessDetails)` 天然等于「`AccessLevel.NoAccess` + 没有进入方式 + 没有限制理由」。官方大量分支以 `accessDetails = default(SettlementAccessModel.AccessDetails);` 开头，然后由私有方法覆写——**`DefaultSettlementAccessModel.CanMainHeroEnterDungeon` 与 `CanMainHeroEnterLordsHall` 都是这个形状**。忘记赋值的后果是**静默禁止进入**，不抛异常。

**第三，读它的顺序是有讲究的。** 先 `AccessLevel` 定大方向，只有落在 `LimitedAccess` 分支才读 `LimitedAccessSolution`，只有落在 `NoAccess` 分支才读 `AccessLimitationReason`。`AccessMethod` 在 `NoAccess` 分支上是残留值。`PreliminaryAction*` 两个字段**与准入判定无关**——它们描述的是「进场之后要做的第一批动作」，不要在准入分支里读它们。

**为什么是 struct 而不是 class。** 因为判定每次调用都产生一份，用完即弃；值类型避免了堆分配，也天然避免了「有人在别处改了这份结果」的问题。代价是**它完全可写**——六个字段都是 `public` 而非只读属性，任何拿到副本的代码都能改本地值而毫无阻力。官方正是靠这种可写性做「事后降级」：`CanMainHeroEnterKeepInternal` 在整条 if-else 链跑完后**直接改写字段**，把 `AccessLevel` 从 `LimitedAccess` 改成 `NoAccess`、`AccessLimitationReason` 改成 `LocationEmpty`。

## 关键成员

| 成员 | 签名 | 这个成员是做什么用的 |
| --- | --- | --- |
| `AccessLevel` | `public SettlementAccessModel.AccessLevel AccessLevel` | 裁决字段：三档 `NoAccess` / `LimitedAccess` / `FullAccess`。**其它五个字段都要在它的语境下解读。** 默认 0 即 `NoAccess`。 |
| `AccessMethod` | `public SettlementAccessModel.AccessMethod AccessMethod` | 手续字段：`None` / `Direct` / `ByRequest`。**必须与 `AccessLevel == FullAccess` 联判才有意义**——`NoAccess` 时它是残留值。默认 0 即 `None`。 |
| `AccessLimitationReason` | `public SettlementAccessModel.AccessLimitationReason AccessLimitationReason` | 解释字段：`LimitedAccess` 时说明「卡在哪一步」，`NoAccess` 时说明「为什么」。**同样出现在两种准入结果下，不能从中反推准入。** 默认 0 即 `None`。 |
| `LimitedAccessSolution` | `public SettlementAccessModel.LimitedAccessSolution LimitedAccessSolution` | `LimitedAccess` 分支专用：`None` / `Bribe` / `Disguise`。**在 `FullAccess` 与 `NoAccess` 下都是残留值**——`DefaultSettlementAccessModel` 填 `FullAccess` 时从不碰它。默认 0 即 `None`。 |
| `PreliminaryActionObligation` | `public SettlementAccessModel.PreliminaryActionObligation PreliminaryActionObligation` | 前置动作是否强制：`None` / `Optional`。**与准入无关**，描述进场后要先做的动作是「必须」还是「可选」。`CanMainHeroEnterVillage` 把它显式初始化为 `None`。默认 0 即 `None`。 |
| `PreliminaryActionType` | `public SettlementAccessModel.PreliminaryActionType PreliminaryActionType` | 前置动作类型：`None` / `FaceCharges`。**唯一有实际取值后果的动作类型**，同样与准入无关。`CanMainHeroEnterVillage` 显式初始化为 `None`。默认 0 即 `None`。 |

六个成员**全是 `public` 字段，不是属性**，没有 `readonly`、没有 setter 访问器修饰符——`struct` 的字段默认就是可写的。没有任何成员是方法或构造函数。

## 真实示例

通过 `out` 接收并分层解读（照抄 `DefaultSettlementAccessModel` 的判定结构）：

```csharp
SettlementAccessModel.AccessDetails details;
Campaign.Current.Models.SettlementAccessModel.CanMainHeroEnterSettlement(settlement, out details);

if (details.AccessLevel == SettlementAccessModel.AccessLevel.FullAccess
    && details.AccessMethod == SettlementAccessModel.AccessMethod.Direct)
{
    Debug.Print("enter freely", 0);
}
else if (details.AccessLevel == SettlementAccessModel.AccessLevel.LimitedAccess)
{
    if (details.LimitedAccessSolution == SettlementAccessModel.LimitedAccessSolution.Bribe)
    {
        Debug.Print("pay to enter", 0);
    }
    else if (details.LimitedAccessSolution == SettlementAccessModel.LimitedAccessSolution.Disguise)
    {
        Debug.Print("disguise to enter; reason = " + details.AccessLimitationReason, 0);
    }
}
else
{
    Debug.Print("blocked; reason = " + details.AccessLimitationReason, 0);
}
```

`out` 参数不需要先声明——C# 允许 `SettlementAccessModel.AccessDetails details;` 后直接作为 `out` 实参传入。若你写 `out var details` 也可以，编译器从形参类型推出。

作为 `SettlementAccessModel` 的派类产出它（照抄 `DefaultSettlementAccessModel.CanMainHeroEnterKeepInternal` 的中立分支形状）：

```csharp
public override void CanMainHeroEnterLordsHall(Settlement settlement, out AccessDetails accessDetails)
{
    accessDetails = default(AccessDetails);

    if (settlement.OwnerClan == Hero.MainHero.Clan)
    {
        accessDetails.AccessLevel = AccessLevel.FullAccess;
        accessDetails.AccessMethod = AccessMethod.Direct;
        accessDetails.AccessLimitationReason = AccessLimitationReason.None;
        accessDetails.LimitedAccessSolution = LimitedAccessSolution.None;
        accessDetails.PreliminaryActionObligation = PreliminaryActionObligation.None;
        accessDetails.PreliminaryActionType = PreliminaryActionType.None;
        return;
    }

    accessDetails.AccessLevel = AccessLevel.NoAccess;
    accessDetails.AccessMethod = AccessMethod.None;
    accessDetails.AccessLimitationReason = AccessLimitationReason.RelationshipWithOwner;
}
```

因为在派类内部写，所以六个枚举可以用短名（编译器优先解析嵌套类型）；在派类外部则应写全限定名 `SettlementAccessModel.AccessLevel.FullAccess`。

## 风险与边界

- **`struct`，不是 `class`。** 值复制语义，传给函数就是拷贝一份；反过来，`out` 参数会把整个结构体写回调用方的变量。**它永远不会为 null**，所以 `if (details == null)` 编译不过也不该写。
- **`default(AccessDetails)` 是「进不去」。** 六个字段全零，`AccessLevel == NoAccess`。**忘记赋值 = 静默禁止进入**，没有异常也没有断言。这是官方那段 `accessDetails = default(SettlementAccessModel.AccessDetails);` 开头代码的真实含义。
- **六个字段全可写，无保护。** 它们是 `public` 字段而非 `get`-only 属性。任何拿到副本的代码都能改本地值。官方正是靠这个做 `LocationEmpty` 事后降级——所以**你自己写的判定链之后，也必须考虑是否需要同样的后处理**。
- **不存档。** 不是 `MBObjectBase`，没有 `StringId`，不在 `MBObjectManager` 里，也没有 `AutoGeneratedInstanceCollectObjects`。想把它跨存档保留必须自己找别的容器。
- **嵌套类型。** 完整名 `SettlementAccessModel.AccessDetails`。在 `using TaleWorlds.CampaignSystem.ComponentInterfaces;` 之后可以写短名，但若同时 `using` 了别的同名类型就会歧义。
- **两个 `PreliminaryAction*` 与准入无关。** 它们描述进场后的前置动作。别在准入分支里读它们，也不要因为它们是 0 就以为「前置动作被跳过了」——0 就是 `None`，即没有前置动作。
- **字段之间没有不变式保护。** `AccessLevel == FullAccess` 而 `LimitedAccessSolution == Bribe` 这种自相矛盾的组合，编译器不拦、运行期也不拦，只会在下游联判时走进未定义分支。**填的时候成套填。**
- **只能在 `SettlementAccessModel` 的三个 `CanMainHeroEnterXxx` 里拿到它。** 另外三个 `CanMainHeroAccessLocation` / `CanMainHeroDoSettlementAction` / `IsRequestMeetingOptionAvailable` 返回的是 `out bool disableOption, out TextObject disabledText`，**不涉及 `AccessDetails`**。别拿它回答「能不能做 X」。

## 跨版本提示

`AccessDetails` 的六个字段在 `bannerlord-1.3.0/`、`bannerlord-1.3.15/`、`bannerlord-1.4.6/`、`bannerlord-1.4.7/`、`bannerlord-1.5.3/` 五棵树里**完全一致**：同样六个字段、同样顺序、同样全是 `public` 字段（无一个变成属性）、仍然是 `public struct`（没被改成 class）。跨 1.3 → 1.5 三个大版本零变化。

**变的是各个 `CanMainHeroEnterXxx` 实现里对字段的赋值组合。** `AccessLimitationReason` 在后续版本持续追加成员，相应的分支也变多；`PreliminaryAction*` 两个枚举也可能获得新值。但**结构体本身的形状是这份契约里最稳定的一环**。

对 mod 作者的实际含义：**只要你的 `SettlementAccessModel` 派类遵循「先 `default`，再成套赋值」的形状，跨版本几乎不需要改。** 唯一要盯的是你引用的具体枚举成员是否还在，以及 1.3.0 里那段 `LocationEmpty` 事后降级逻辑在后续版本是否被移到了别处。

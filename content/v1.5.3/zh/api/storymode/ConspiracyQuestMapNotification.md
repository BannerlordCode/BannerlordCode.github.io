# ConspiracyQuestMapNotification

**Namespace:** StoryMode
**Module:** StoryMode
**Type:** `public class ConspiracyQuestMapNotification : InformationData`
**Base:** `InformationData`（TaleWorlds.CampaignSystem）
**Source:** `bannerlord-1.5.3/StoryMode/ConspiracyQuestMapNotification.cs`

## 概述

这是主线阴谋阶段往地图信息流里塞的**一种可点击通知**：标题固定是 "Conspiracy Quest Available"，正文由调用方给一个 `TextObject`，并且额外携带一个 `QuestBase` 引用，这样 UI 能渲染出「当前追踪」的跳转。真正的内容（文字里嵌入哪些聚落链接、点了跳哪）都由传入的 `descriptionText` 决定，本类只负责标题与任务引用。

## 心智模型

`InformationData` 是地图通知的基类：把通知塞进 `Campaign.Current.CampaignInformationManager.NewMapNoticeAdded(...)` 就会出现在地图左下角的滚动信息流里。本类的使用点只有两个真实调用方：

1. `ConspiracyQuestBase.OnStartQuest()` —— 每个阴谋任务开局时发一条，正文用任务自己的 `SideNotificationText`。
2. `DisruptSupplyLinesConspiracyQuest` —— 劫商队事件发生时发一条，正文是**动态生成**的，带 `FROM_SETTLEMENT_LINK` / `TO_SETTLEMENT_LINK` 两个文本变量。

因为它带了一个 `[SaveableProperty(1)] QuestBase` 引用，且 `AutoGeneratedInstanceCollectObjects` 会把它加进对象图，所以**通知本身会进存档**——读档回来后地图上那条通知还在，任务引用也能解析。

**坑**：

1. **`SoundEventPath` 返回空字符串**，不是 null。意味这条通知**不发提示音**。
2. **标题是硬编码英文**：`"{=f3NvtzpE}Conspiracy Quest Available"`。所有阴谋通知标题都一样，无法区分是哪一条。
3. **同一个通知会被发多次**：`DisruptSupplyLinesConspiracyQuest` 在每次商队移动时都发一条，重复触发会在信息流里堆一串一模一样的条目——唯一区别是正文里的聚落名字。
4. **`ConspiracyQuest` 的 setter 是 private**：只能构造函数传入。想改引用只能造新的。
5. **任务没启动就发通知会留下坏引用**：如果 `ConspiracyQuest` 指向的任务被取消后立刻存档再读档，任务引用能否解析取决于存档系统；本类不做任何校验。

## 主要成员

- `public override TextObject TitleText { get; }`：**硬编码** `"{=f3NvtzpE}Conspiracy Quest Available"`。不可配置。
- `public override string SoundEventPath { get; }`：**恒为空字符串**。这条通知静音。
- `public QuestBase ConspiracyQuest { get; private set; }`：`[SaveableProperty(1)]`。指向触发这条通知的阴谋任务。存档类型表里 id 13（见 [SaveableStoryModeTypeDefiner](../SaveableStoryModeTypeDefiner)）。
- `ConspiracyQuestMapNotification(QuestBase conspiracyQuest, TextObject descriptionText)`：构造函数，`base(descriptionText)` 把正文交给 `InformationData`。正文里可以带 `{TO_SETTLEMENT_LINK}` 之类的文本变量。

## 使用示例

```csharp
// 1) 原生写法：阴谋任务开局时发一条（ConspiracyQuestBase.OnStartQuest）
public override void OnStartQuest()
{
    base.OnStartQuest();
    Campaign.Current.CampaignInformationManager.NewMapNoticeAdded(
        new ConspiracyQuestMapNotification(this, this.SideNotificationText));
    base.AddLog(this.StartMessageLogFromMentor, false);
}

// 2) 动态正文：劫商队事件（DisruptSupplyLinesConspiracyQuest 里的真实写法）
TextObject text = new TextObject(
    "{=SVcr0EJM}Caravan is moving on to {TO_SETTLEMENT_LINK} from {FROM_SETTLEMENT_LINK}.", null);
text.SetTextVariable("FROM_SETTLEMENT_LINK", settlement.EncyclopediaLinkWithName);
text.SetTextVariable("TO_SETTLEMENT_LINK", targetSettlement.EncyclopediaLinkWithName);
Campaign.Current.CampaignInformationManager.NewMapNoticeAdded(
    new ConspiracyQuestMapNotification(this, text));

// 3) 读回任务引用做跳转：把目标聚落挂成任务的追踪物
ConspiracyQuestMapNotification notice = ...;
QuestBase quest = notice.ConspiracyQuest;
if (quest != null && quest.IsOngoing)
{
    Settlement target = Settlement.Find("village_ES3_2");
    Campaign.Current.QuestManager.AddTrackedObjectForQuest(target, quest);
    // 注意签名是 (ITrackableCampaignObject, QuestBase) 两个参数，QuestBase 本身不是 ITrackableCampaignObject
}
```

## 风险与边界

- **会进存档**：`ConspiracyQuest` 是 `[SaveableProperty]`。通知对象存活时间可能跨过任务生命周期，读档后可能指向已结束的任务。做跳转前务必判 `quest.IsOngoing`。
- **重复通知会堆积**：每次事件都 new 一条，没有去重也没有上限。长时间战役里信息流会被同一类条目刷屏。
- **标题不可变**：所有阴谋通知标题一致，无法靠标题区分。想做不同的标题得自己派生 `InformationData`。
- **静音**：`SoundEventPath` 为空。指望这条通知伴随音效的 UI 逻辑要自己处理。
- **正文全靠调用方**：本类不校验 `descriptionText`。传 null 会让 `InformationData` 拿到空正文，UI 上表现为一条没有文字的条目。
- **`private set` + 构造函数注入**：通知发出后不能改指向的任务，只能新建。

# Noise and Non-Business Type Policy (v1.4.5)

“Noise” does not mean useless code. It means an implementation layer that should not be a daily modding entry point. These types must remain searchable and explainable, but they should not be expanded into a large API handbook that implies direct, stable calls.

## Mental model: inventory, policy, managed bridge

Treat these types as runtime wiring or generated output. They support object identity, saves, or platform features, while a mod normally enters through a higher-level managed contract. The documentation policy is: inventory -> one short policy page -> return to a stable `TaleWorlds.*` entry, rather than creating near-identical long pages for every generated type.

## Three categories of noise

### 1. AutoGenerated and serialization output

Names such as `AutoGenerated`, automatic collect methods, save definitions, and decompiler artifacts often belong here. The game build/save pipeline owns them; a mod normally should not `new` or rewrite them.

- To persist Behavior-owned state, start with `SyncData(IDataStore)` on [CampaignBehaviorBase](../../api/campaign/CampaignBehaviorBase).
- To understand save management and load boundaries, read [SaveManager](../../api/save-system/SaveManager).
- To declare a new saveable type or field, read [SaveableTypeDefiner](../../api/save-system/SaveableTypeDefiner), [SaveableFieldAttribute](../../api/save-system/SaveableFieldAttribute), and [SaveablePropertyAttribute](../../api/save-system/SaveablePropertyAttribute).

Do not treat generated collect methods as a custom save schema. Private SaveIds, generated type numbers, and load ordering are internal contracts; copying them can cause deserialization failures or silently lost data after an update.

### 2. Third-party and platform libraries

`System.*`, JSON libraries, and Steam/Epic assemblies may appear in inventory, but their semantics belong to their official SDKs. This site documents the Bannerlord lifecycle boundary: enter platform work through [MBSubModuleBase](../../api/core/MBSubModuleBase), pass text through [TextObject](../../api/localization/TextObject), and route UI through [ScreenManager](../../api/gui/ScreenManager) and [ViewModel](../../api/core-extra/ViewModel).

Do not mistake a third-party type in the inventory for a Bannerlord managed-API stability promise. Check module dependencies, platform mode, and version before consulting the vendor documentation.

### 3. Native, Provider, and `IMB*` engine bridges

`IMB*` interfaces, platform Providers, and native wrappers sit between managed code and the engine. Daily mods should prefer [Mission](../../api/mission/Mission), [Agent](../../api/mission/Agent), [GauntletLayer](../../api/engine/GauntletLayer), and other managed wrappers. Trace the Native bridge only when the managed layer genuinely lacks the capability and initialization/lifetime have been verified.

Direct P/Invoke into `TaleWorlds.Native.dll` bypasses function-pointer injection, reference counting, and version boundaries. It can fail at startup or when a scene ends. Read the [SandBox/StoryMode/Native reading policy](../sandbox-native-policy) first and separate engine failures from business-API failures.

## How to decide whether to deep-write

| Found type | Documentation treatment | Managed bridge |
|------------|-------------------------|----------------|
| Generated save collector | Inventory plus policy; do not invent usage | [SaveManager](../../api/save-system/SaveManager) |
| Third-party or platform Provider | Record dependency and mode; do not rewrite the vendor SDK | [MBSubModuleBase](../../api/core/MBSubModuleBase) |
| `IMB*` or Native wrapper | Record the bridge and version risk | [Engine API](../../api/engine/), [Mission](../../api/mission/Mission) |
| Type with a stable mod-facing entry point | Handwritten deep page or handwritten family entry | [Task-first entry map](../../api/) |

H6 still requires noise to be locatable, but a file existing does not mean a business type has met the deep-page contract. Coverage reports exclude declared noise from the R1 deep-writing denominator while retaining an inventory and policy page, so the types are not silently dropped.

## Risk boundaries

- Do not read Campaign or Native objects from `OnSubModuleLoad` before they exist.
- Do not treat decompiled AutoGenerated fields as a save schema that can be copied across versions.
- Do not store platform objects, Agents, or native handles in cross-scene Behavior state unless the owning contract guarantees their lifetime.
- Do not replace a required Model with `null`, or use a Native bridge to bypass an Action's event cascade.

# SDK Overview — assembly layering and reference map

## Mental model

Think of v1.4.7 as five blocks. **Each block can only see the block beneath it.** Your mod sits
on top, references an assembly to get one layer's entry points, and calls **downward**.

```text
storymode / sandbox        content: main-story quests, sandbox content, AI, board games
        ↓
campaign / campaign-ext    campaign: Campaign, Hero, Clan, behaviours, events, Actions, Models
        ↓
mission / mission-ext      battle: Mission, Agent, Formation, scene components
        ↓
gui / viewmodel            UI: ScreenBase, ScreenLayer, Gauntlet, ViewModel
        ↓
core / core-extra          foundation: module loading, event bus, collections, platform, diagnostics
```

> `ServiceDiscovery`.** Those are the platform layer (lobby, achievement backend, workshop), not mod
> API. The noise gate below exists precisely to keep those namespaces out of this documentation.

## Namespace → doc directory mapping

The docs are split by **subsystem**, not by assembly. Which directory a type lands in is decided
by four ordered rules (authoritative machine-readable copy: `tools/_dir-map-canonical.json`):

1. **Exclusion gate.** Namespace falls under one of 47 `excludeNamespaces` prefixes, or has a
   `CodeGenerator` / `AutoGenerated` segment → no page, counted separately.
2. **Longest prefix wins.** 37 `prefix → dir` rules; the longest match takes it.
3. **Entry-class override.** Seven exact, case-sensitive simple type names override the directory:
   `Mission`, `MissionState`, `MissionBehavior`, `Agent`, `Formation` → `mission`;
   `MBSubModuleBase`, `Module` → `core`. **This must run after step 2.**
4. **Fallback.** No match → `core-extra`, and the namespace is recorded in `unmapped`.

Step 3 is the one that bites. Skip it, or run it before step 2, and `mission/` and `core/` come
out as empty directories that 404 when you click them. So after every regeneration, assert that
every declared directory is non-empty.

**Same-directory name collisions** use `<NamespaceLeaf>__<TypeName>.md`, for example
`Campaign__IFaction.md`. One type gets exactly one path — the 1.4.5 tree had the same type name in
two directories **2,199 times**, and that duplication is precisely why clicking through it felt
like being sent somewhere unrelated with no way back.

## A type appearing in four places is normal

`Campaign` appears in the assembly `TaleWorlds.CampaignSystem`, in namespace
`TaleWorlds.CampaignSystem`, in doc directory `api/campaign/`, and in the assembly table above.
Each serves a different purpose: the assembly decides your compile reference, the namespace decides
your `using`, the directory decides the doc URL, and the table is just an index. Confusing the
first two is the most common compile error a new mod author hits.

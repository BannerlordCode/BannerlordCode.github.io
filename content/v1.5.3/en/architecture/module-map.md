# Module Map

> Three things per assembly: **what it is**, **where the docs put it**, and **whether you should care**.

## Why this page exists

`bannerlord-1.5.3/` has **68 `TaleWorlds.*` directories** at its root, but the documentation has only
**19 `api/` subdirectories**. The relationship is not one-to-one: a single assembly is split across
several buckets by responsibility, and a bucket can gather namespaces from several assemblies. Without
this table you will hunt for the same class in two places and find it in neither.

The mapping is not a judgement call. `tools/_dir-map-canonical.json` — 38 namespace rules plus an
entry-point rule set — is applied to the **real 621 namespaces** of 1.5.3 with **longest-prefix-wins**
matching, producing 19 buckets. (`boardgames` has a rule but matches zero namespaces, so it is an empty
bucket and no directory was created for it.)

### Assemblies that are not mod-facing

These exist in the source tree but are build-time generators, third-party libraries or launcher
components. **They are visible in the 1.5.3 source, but the running game does not let mods depend on
them.** They are listed so you are not confused when you meet them while reading source.

| Assembly | What it is |
|---|---|
| `TaleWorlds.GauntletUI.CodeGenerator` | Build-time prefab code generator |
| `TaleWorlds.MountAndBlade.GauntletUI.CodeGenerator` / `.AutoGenerated.0/.1` | Same, for battle UI |
| `TaleWorlds.MountAndBlade.SaveSystem.CodeGenerator` | Save-field code generator |
| `TaleWorlds.MountAndBlade.Launcher` / `.Launcher.Library` / `.Launcher.Steam` | Launcher |
| `TaleWorlds.MountAndBlade.SteamWorkshop` | Workshop CLI tool |
| `TaleWorlds.Starter.Library` | Mod development starter template |
| `TaleWorlds.MountAndBlade.DedicatedCustomServer.ClientHelper` | Dedicated server client helper |
| `GalaxyCSharp` | Scripting bridge |
| `Newtonsoft.Json` / `jose-jwt` / `Steamworks.NET` / `StbSharp` / `System.Management` / `System.Numerics.Vectors` | Third-party dependencies (plus reference assemblies `mscorlib` / `netstandard`) |
| `ManagedStarter` | Managed bootstrap entry point |

> **Source tree ≠ runtime reference.** `bannerlord-1.5.3/` also bundles the launcher, the code
> generators, third-party libraries and reference assemblies (`mscorlib` has 2 694 files, plus
> `netstandard`), 11 487 `.cs` in total. But when you compile a mod you reference the DLLs in the game
> install, not this source tree. So a third-party namespace that shows up under `core-extra` in the docs
> is **not** automatically part of the moddable API.

**Two traps worth memorizing**

1. `TaleWorlds.ObjectSystem` lands in [campaign-ext](../../api/campaign-ext/). There is **no**
   `objectsystem` directory.
2. `TaleWorlds.ScreenSystem` is merged into [gui](../../api/gui/). There is **no** `screensystem`
   directory.

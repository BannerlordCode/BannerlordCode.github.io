# TradeItemComponent

**Namespace:** `TaleWorlds.Core`
**Module:** `TaleWorlds.Core`
**Type:** `public class TradeItemComponent : ItemComponent`
**Base:** `TaleWorlds.Core.ItemComponent`
**File:** `TaleWorlds.Core/TradeItemComponent.cs`

## 概述

`TradeItemComponent` 是贸易品与食物在 [ItemObject](../ItemObject) 单槽上的行为插件，全部源码 54 行，只带一个数据成员：`MoraleBonus`（XML 属性 `morale_bonus`，代表「让队伍士兵开心」的那类商品）。它在整个组件体系里的地位特殊：**它是六个派生类里唯一一个能被官方 API 程序化挂上去的**——[ItemObject](../ItemObject) 的静态工厂 `InitializeTradeGood(...)` 的固定收尾动作就是 `item.ItemComponent = new TradeItemComponent(); item.AfterInitialized(); item.ItemFlags |= ItemFlags.Civilian;`。它同时也是 [ItemObject](../ItemObject) 的 `FoodComponent` 属性返回的类型（**属性名叫 `FoodComponent`，返回类型是 `TradeItemComponent`**），以及 XML 里 `<Trade>` 标签的落点。

## 心智模型

**记住三件事：官方工厂、绕过基类的 `Deserialize`、以及单槽覆盖。**

第一件是官方工厂。`ItemObject.InitializeTradeGood(item, name, meshName, category, value, weight, itemType, isFood)` 的顺序固定且不可跳步：`item.Initialize()` → 逐个填 `Name` / `MultiMeshName` / `ItemCategory` / `Value` / `Weight` / `ItemType` / `IsFood` → **`item.ItemComponent = new TradeItemComponent();`** → `item.AfterInitialized()` → `item.ItemFlags |= ItemFlags.Civilian` → `return item`（返回的是传入的那个实例本身）。**这是 mod 程序化造物品的唯一官方入口**，也是本组件在 1.4.6 唯一现实的挂载途径。食物的组件类型和贸易品**完全相同**——区别只体现在 `ItemObject.IsFood` 这个独立 bool 上。

第二件是**它的 `Deserialize` 绕过了基类**。实现是：

```csharp
public override void Deserialize(MBObjectManager objectManager, XmlNode node)
{
    this.Initialize();
    this.MoraleBonus = XmlHelper.ReadInt(node, "morale_bonus");
}
```

对比其余五个组件全部以 `base.Deserialize(objectManager, node)` 开头。后果有两个：`ItemModifierGroup` **不会被解析**（XML 上的 `modifier_group` 属性被静默忽略），以及**不依赖 `Game.Current`**——这是六个组件里唯一一个 `Deserialize` 不摸 `Game.Current` 的（[ArmorComponent](../ArmorComponent) / [HorseComponent](../HorseComponent) / [ItemComponent](../ItemComponent) 都要用它解析词缀组或 `SkeletonScale`）。所以贸易品在品质系统里永远是「无词缀」状态。

第三件是**单槽覆盖**。[ItemObject](../ItemObject) 的 `AddWeapon(WeaponComponentData, ItemModifierGroup)` 在 `this.WeaponComponent == null` 时执行 `this.ItemComponent = new WeaponComponent(this)`——**无条件覆盖已有的 `TradeItemComponent`**。所以「先 `InitializeTradeGood` 再 `AddWeapon`」这条常见写法会把贸易品组件连同它唯一的 `MoraleBonus` 一起丢掉。反过来，先 `AddWeapon` 再想补贸易品属性是做不到的，因为 `ItemComponent` 是 `private set`。

第四个心智锚点：`MoraleBonus` 是 **`private set`**。没有公开的写入路径，XML 之外拿不到非零值。想给贸易品设士气加成，只能改 XML。而且因为 `Deserialize` 不解析 `modifier_group`，这个 `MoraleBonus` 也不会被词缀加工——它就是最终值。

第五个是**两个构造器的语义完全不同**。`public TradeItemComponent()` 只把 `MoraleBonus` 置 0（这是给 `ItemObject` 工厂用的）；`public TradeItemComponent(TradeItemComponent a)` 复制 `MoraleBonus`。而 `GetCopy()` 是 `new TradeItemComponent(this)` ——**它是唯一一个真正完整的 `GetCopy()`**：数值拷了。相比之下 [ArmorComponent](../ArmorComponent) 漏拷 `IsNoSlim`，[HorseComponent](../HorseComponent) 只拷四个 int，[SaddleComponent](../SaddleComponent) 一个都不拷。但它**同样不拷 `ItemModifierGroup`**——所幸由于 `Deserialize` 绕过了基类，这个字段本来就是 null。

## 真实示例

用官方工厂造一件贸易品（**`MoraleBonus` 会是 0，因为工厂用的是无参构造器**）：

```csharp
ItemCategory myCategory = new ItemCategory("my_trade_category");
myCategory.InitializeObject(isTradeGood: true, baseDemand: 10, luxuryDemand: 2);

ItemObject tradeGood = new ItemObject();
ItemObject.InitializeTradeGood(
    tradeGood,
    new TextObject("{=my_trade_good}My Trade Good"),
    "my_trade_good_mesh",
    myCategory,
    value: 250,
    weight: 1.5f,
    itemType: ItemObject.ItemTypeEnum.Goods,
    isFood: false);

TradeItemComponent trade = tradeGood.ItemComponent as TradeItemComponent;
Debug.Print("component = " + tradeGood.ItemComponent.GetType().Name, 0);
Debug.Print("morale bonus = " + trade.MoraleBonus, 0);
Debug.Print("is civilian = " + tradeGood.IsCivilian, 0);
```

读一件食物的士气加成（**注意 `FoodComponent` 返回的是 `TradeItemComponent` 类型**）：

```csharp
ItemObject food = hero.BattleEquipment.GetEquipmentFromSlot(EquipmentIndex.Body).Item;
if (food != null && food.HasFoodComponent)
{
    TradeItemComponent foodComponent = food.FoodComponent;
    Debug.Print("morale bonus = " + foodComponent.MoraleBonus, 0);
    Debug.Print("is food = " + food.IsFood, 0);
}
```

演示单槽覆盖——这是本类型最容易踩的坑：

```csharp
ItemCategory hybridCategory = new ItemCategory("my_hybrid_category");
hybridCategory.InitializeObject(isTradeGood: true, baseDemand: 10);

ItemObject hybrid = new ItemObject();
ItemObject.InitializeTradeGood(
    hybrid,
    new TextObject("{=hybrid}Hybrid"),
    "hybrid_mesh",
    hybridCategory,
    value: 300,
    weight: 2f,
    itemType: ItemObject.ItemTypeEnum.Goods,
    isFood: false);

Debug.Print("before AddWeapon: " + hybrid.ItemComponent.GetType().Name, 0);

hybrid.AddWeapon(new WeaponComponentData(hybrid, WeaponClass.OneHanded, WeaponFlags.None), hybrid.ItemModifierGroup);

Debug.Print("after  AddWeapon: " + hybrid.ItemComponent.GetType().Name, 0);
Debug.Print("morale bonus survived? " + (hybrid.ItemComponent is TradeItemComponent), 0);
```

从 XML 装配（**`modifier_group` 会被忽略**）：

```csharp
// 物品 XML：<Item id="my_good" ...>
//   <ItemComponent>
//     <Trade morale_bonus="12" modifier_group="my_group" />
//   </ItemComponent>
// </Item>
// 注意 modifier_group="my_group" 会被 TradeItemComponent.Deserialize 静默忽略。
ItemObject loaded = MBObjectManager.Instance.GetObject<ItemObject>("my_good");
if (loaded != null && loaded.HasFoodComponent)
{
    Debug.Print("morale = " + loaded.FoodComponent.MoraleBonus, 0);
    Debug.Print("modifier group = " + loaded.FoodComponent.ItemModifierGroup, 0);
}
```

自定义带更多数据的贸易品组件（**记得调 `base.Deserialize`**）：

```csharp
public class MyTradeComponent : ItemComponent
{
    public int MoraleBonus { get; private set; }

    public int TradeTier { get; private set; }

    public override ItemComponent GetCopy()
    {
        MyTradeComponent copy = new MyTradeComponent();
        copy.Item = this.Item;
        copy.ItemModifierGroup = this.ItemModifierGroup;
        copy.MoraleBonus = this.MoraleBonus;
        copy.TradeTier = this.TradeTier;
        return copy;
    }

    public override void Deserialize(MBObjectManager objectManager, XmlNode node)
    {
        base.Deserialize(objectManager, node);
        XmlAttribute morale = node.Attributes["morale_bonus"];
        XmlAttribute tier = node.Attributes["trade_tier"];
        this.MoraleBonus = morale != null ? int.Parse(morale.Value) : 0;
        this.TradeTier = tier != null ? int.Parse(tier.Value) : 1;
    }

    // IncidentEffect 是「事件效果描述对象」：构造它不会立即生效。
    // 源码里没有公开的 Apply/Execute 成员，效果如何落到队伍上由上层事件系统决定。
    public IncidentEffect BuildMoraleEffect()
    {
        return IncidentEffect.MoraleChange((float)this.MoraleBonus);
    }
}
```

## 风险与边界

- **`Deserialize` 不调 `base.Deserialize`。** XML 上的 `modifier_group` 属性被静默忽略，`ItemModifierGroup` 恒为 null。**贸易品不进品质词缀系统。** 自定义派生类务必反过来——始终 `base.Deserialize` 优先。
- **`Item` 恒为 null。** 两个构造器都不写 `base.Item`，`ItemObject` 挂载时也不回填。**要拿宿主物品请从 [ItemObject](../ItemObject) 侧拿。**
- **占用单槽，`AddWeapon` 会无声覆盖它。** `ItemObject.AddWeapon` 在 `WeaponComponent == null` 时 `new WeaponComponent(this)` 直接覆盖 `ItemComponent`。**「先 InitializeTradeGood 再 AddWeapon」会丢掉 `MoraleBonus`。**
- **`MoraleBonus` 是 `private set`，XML 之外无法写入。** `InitializeTradeGood` 用的是无参构造器，恒为 0。
- **`Deserialize` 依赖 `XmlHelper.ReadInt(node, "morale_bonus")`，`node` 为 null 时 NRE。** 手写调用必须自己保证节点。
- **不受品质词缀加工。** 即使外部硬把 `ItemModifierGroup` 塞进来（`protected set`，需派生类），`MoraleBonus` 也不会被 `ItemModifier.Modify*` 处理——没有这样的调用路径。
- **食物与贸易品共用同一类型。** `ItemObject.FoodComponent` 的名字是 Food，类型是 `TradeItemComponent`；区分靠 `ItemObject.IsFood` 这个独立 bool，不是组件类型。
- **`<Food>` XML 标签已废弃。** `ItemObject.Deserialize` 的 `<Food>` 分支触发 `Debug.FailedAssert("FoodComponent tag has been converted to TradeComponent. Use Trade xml node type", ...)` 并把组件置 null。**写 `<Food>` 等于该物品没有组件。**
- **不 `sealed`，可继承。** 但继承它并不能解决挂载问题——只有 `<Trade>` 标签和 `InitializeTradeGood` 能装它。
- **不进存档。**

## 跨版本提示

`bannerlord-1.3.15/` 与 `bannerlord-1.4.6/` 的 `TaleWorlds.Core/TradeItemComponent.cs` 公开表面**完全一致**（6 个公开成员：1 个属性、2 个构造器、`GetCopy`、`Deserialize`、`AutoGeneratedInstanceCollectObjects`）。

**1.4.5 侧结论**：打开 `bannerlord-1.4.5/Bannerlord.Source/bin/TaleWorlds.Core/TaleWorlds.Core/TradeItemComponent.cs`（42 行）与 `bannerlord-1.4.6/TaleWorlds.Core/TradeItemComponent.cs`（54 行）逐成员比对 public/protected 表面。**三版 public/protected 表面完全一致（各 5 个成员，0 新增 / 0 移除 / 0 签名变化 / 0 可访问性变化）**。1.4.5 是 42 行、1.4.6 是 54 行。

**为什么这份源码之前被判为「不存在」**：`bannerlord-1.4.5/` 的 C# 源码在 `Bannerlord.Source/bin/` 下**双层嵌套** `bin/<Assembly>/<Assembly>/<Type>.cs`，而 `bin/` 的一层里没有任何 `.cs`（实测 `find bannerlord-1.4.5/Bannerlord.Source/bin -maxdepth 1 -name "*.cs"` 命中 0），只扫一层就会误判成无源码。**1.4.5 是原始源码形态**（file-scoped namespace、无 `// Token:` 注释），1.4.6 与 1.3.15 是反编译产物，所以两边的行数不可直接比大小。

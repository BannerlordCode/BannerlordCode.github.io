## v1.3.0 → v1.3.15

v1.3.0 is the early 1.3 baseline. It still ships the full `SandBox` and `StoryMode` source folders plus their UI/view layers. v1.3.15 reorganizes the engine into many small, focused assemblies.

### What disappears from the source bundle

- `SandBox`, `SandBox.GauntletUI`, `SandBox.View`, `SandBox.ViewModelCollection`
- `StoryMode`, `StoryMode.GauntletUI`, `StoryMode.View`, `StoryMode.ViewModelCollection`
- `TaleWorlds.GauntletUI.TooltipExtensions`
- `TaleWorlds.MountAndBlade.GauntletUI`
- `TaleWorlds.MountAndBlade.View`

These gameplay and view layers are either merged into the main `TaleWorlds.*` assemblies or shipped with the game build rather than as separate source modules.

### Major new areas in v1.3.15

- **SaveSystem**: `TaleWorlds.SaveSystem` becomes a top-level assembly, and `TaleWorlds.MountAndBlade.SaveSystem.CodeGenerator` appears.
- **Platform services**: `TaleWorlds.PlatformService` plus Steam/Epic/GOG providers, plus `TaleWorlds.PlayerServices`.
- **Networking**: `TaleWorlds.Network`, `TaleWorlds.Diamond` and its access providers, `TaleWorlds.MountAndBlade.Diamond`, `TaleWorlds.ServiceDiscovery.Client`.
- **Object and screen infrastructure**: `TaleWorlds.ObjectSystem`, `TaleWorlds.ScreenSystem`, `TaleWorlds.NavigationSystem`, `TaleWorlds.ModuleManager`.
- **Engine helpers**: `TaleWorlds.DotNet` and `.AutoGenerated`, `TaleWorlds.Engine.AutoGenerated`, `TaleWorlds.MountAndBlade.AutoGenerated`, `TaleWorlds.MountAndBlade.Helpers`.
- **Launcher and workshop**: `TaleWorlds.MountAndBlade.Launcher` and its Steam/Library sub-assemblies, plus `TaleWorlds.MountAndBlade.SteamWorkshop`.
- **New UI widgets/collections**: `TaleWorlds.MountAndBlade.GauntletUI.Widgets`, `TaleWorlds.MountAndBlade.ViewModelCollection`, `TaleWorlds.TwoDimension` and `.Standalone`.

### Impact on mods

1. **References change**: if you use save types, add `TaleWorlds.SaveSystem.dll`.
2. **Gameplay source moves**: old `SandBox`/`StoryMode` class references now live under `TaleWorlds.CampaignSystem` or `TaleWorlds.MountAndBlade` namespaces.
3. **Lifecycle stays the same**: `MBSubModuleBase` hooks remain compatible.

## v1.3.15 → v1.4.5

### New or separated modules

- `TaleWorlds.CampaignSystem.FastMode` — campaign fast/batch mode
- `TaleWorlds.CampaignSystem.ViewModelCollection.BirthAndDeath` — birth and death VMs
- `TaleWorlds.MountAndBlade.CustomBattle` — custom battle logic
- `TaleWorlds.MountAndBlade.DedicatedCustomServer.ClientHelper`
- `TaleWorlds.MountAndBlade.GauntletUI` — M&B Gauntlet as a standalone module
- `TaleWorlds.MountAndBlade.GauntletUI.AutoGenerated.0` / `.1`
- `TaleWorlds.MountAndBlade.Multiplayer` and its GauntletUI/View/ViewModelCollection assemblies
- `TaleWorlds.MountAndBlade.Platform.PC`
- `TaleWorlds.MountAndBlade.View`
- `Modules.SandBox` and `Modules.StoryMode` gameplay source

### Removed modules

- `TaleWorlds.MountAndBlade.GauntletUI.CodeGenerator`
- `TaleWorlds.MountAndBlade.Launcher` (`.Library` and `.Steam` remain)
- `TaleWorlds.MountAndBlade.SaveSystem.CodeGenerator`
- `TaleWorlds.MountAndBlade.SteamWorkshop`

## Migration checklist

### v1.3.0 → v1.3.15

- [ ] Add the `TaleWorlds.SaveSystem` assembly reference.
- [ ] Move old `MBSaveLoad` calls to `SaveManager`.
- [ ] Check references to `TaleWorlds.ObjectSystem`, `TaleWorlds.ScreenSystem`, `TaleWorlds.ModuleManager`.
- [ ] Update any direct `SandBox`/`StoryMode` namespace paths to `TaleWorlds.CampaignSystem` or `TaleWorlds.MountAndBlade`.

### v1.3.15 → v1.4.5

- [ ] Verify Multiplayer/Gauntlet/View assembly paths in your `.csproj`.
- [ ] Update `MobileParty` party-role code, `Clan.CommanderLimit`, and `Kingdom.HasCalledToWar` usage.
- [ ] Reference `Modules.SandBox`/`Modules.StoryMode` source if you need gameplay internals.
- [ ] Keep `[SaveableField]` IDs unique when you add new fields.

---

## Migration advice

- **New mods**: start on v1.3.15. It has the most complete source and the most stable documented API.
- **Targeting v1.4.5**: expect assembly path changes around multiplayer and UI, and review the breaking class list above.
- **Save compatibility**: `.sav` files are generally **not** interchangeable across major versions; state it clearly in your mod description.

## Overview

`IMBBannerlordTableauManager` is the managed-to-native seam for the **character tableau system** — the machinery that renders a posed, lit character into an offscreen scene so the game can show it as a portrait, a menu backdrop, or a codex entry. The file is 17 lines with three `[EngineMethod]` bindings: `request_character_tableau_render` (`IMBBannerlordTableauManager.cs:10`), `initialize_character_tableau_render_system` (`IMBBannerlordTableauManager.cs:13`) and `get_number_of_pending_tableau_requests` (`IMBBannerlordTableauManager.cs:16`).

What makes this bridge different from the others in this bucket is that **the traffic runs both ways**. Managed asks native to render, and native calls back into managed — the return trip is the `[MBCallback(null, false)]` methods `RegisterCharacterTableauScene` and `RequestCharacterTableauSetup` on the wrapper (`BannerlordTableauManager.cs:49-53`, `:43-47`). The bridge itself only covers the outbound half; the inbound half is ordinary managed methods marked by attribute, not interface members. The wrapper is [`BannerlordTableauManager`](../../mission-ext/BannerlordTableauManager), a `public static class` (`BannerlordTableauManager.cs:5`).

## Mental Model

### What it is / which layer

- It is an **asynchronous rendering queue**, not a draw call. `RequestCharacterTableauRender` enqueues work; `GetNumberOfPendingTableauRequests` is how you learn it has not finished; the actual completion arrives later as the `RequestCharacterTableauSetup` callback (`BannerlordTableauManager.cs:43-47`). Reading `RequestCharacterTableauRender` as "draw now" is the single biggest misreading available on this page.
- The system is **pooled**. The wrapper holds `private static Scene[] _tableauCharacterScenes = new Scene[5]` (`BannerlordTableauManager.cs:9`) and exposes it as `public static Scene[] TableauCharacterScenes` (`BannerlordTableauManager.cs:15`), which native fills through `RegisterCharacterTableauScene` indexed by `type` (`BannerlordTableauManager.cs:50-52`). Five slots, indexed by tableau type — so the tableau *type* is a slot number, not a category enum you can invent values for.
- The initialization is **idempotent on the managed side**. `BannerlordTableauManager.InitializeCharacterTableauRenderSystem()` checks `_isTableauRenderSystemInitialized` and only then calls native, setting the flag afterwards (`BannerlordTableauManager.cs:29-36`). Native is called at most once per session unless `ClearManager()` resets the flag (`BannerlordTableauManager.cs:22-27`).

### The consequence that matters

**Requesting a tableau does not produce a tableau, and nothing tells you it succeeded.** `GetNumberOfPendingTableauRequests()` (`IMBBannerlordTableauManager.cs:16`) is the only progress signal, and it counts pending work rather than reporting per-request success. The per-request outcome reaches managed through `RequestCallback` — a `public static RequestCharacterTableauSetupDelegate` field on the wrapper (`BannerlordTableauManager.cs:13`), assigned by whoever owns the request, invoked from the `[MBCallback]` at `BannerlordTableauManager.cs:44-46`. That callback **dereferences `RequestCallback` without a null check** (`BannerlordTableauManager.cs:46`), so if the system is running but nobody set `RequestCallback`, native's callback throws a `NullReferenceException` on the engine's callback thread.

## How to use

**How to obtain it.** You cannot reference the interface — it is `internal` (`IMBBannerlordTableauManager.cs:8`), the `MBAPI` field is `internal static` (`MBAPI.cs:64`), and `TaleWorlds.MountAndBlade` grants `InternalsVisibleTo` only to `TaleWorlds.MountAndBlade.AutoGenerated`, `TaleWorlds.MountAndBlade.Multiplayer` and `TaleWorlds.Generator.Bannerlord` (`TaleWorlds.MountAndBlade/Properties/AssemblyInfo.cs:8-10`).

The door out is [`BannerlordTableauManager`](../../mission-ext/BannerlordTableauManager), `public static class` at `BannerlordTableauManager.cs:5`, which forwards all three members (`:19`, `:33`, `:40`) and, more importantly, exposes the callback hook you are actually meant to use.

**A typical use.** Request a tableau and handle the completion callback, which is the pattern the wrapper was built for:

```csharp
using TaleWorlds.Engine;
using TaleWorlds.MountAndBlade;

public static class MyModTableau
{
    public static void Request(GameEntity poseEntity, Camera camera)
    {
        // Initialize first: the wrapper guards this so native is called at most
        // once per session (BannerlordTableauManager.cs:29-36).
        BannerlordTableauManager.InitializeCharacterTableauRenderSystem();

        // The callback is invoked from native via the [MBCallback] method at
        // BannerlordTableauManager.cs:44-46, and that method dereferences
        // RequestCallback with no null check — so it MUST be assigned first or
        // the callback thread throws.
        BannerlordTableauManager.RequestCallback = (int characterCodeId, Scene scene, GameEntity entity) =>
        {
            // Your scene is ready here. Grab a slot before using it: native fills
            // TableauCharacterScenes[type] through RegisterCharacterTableauScene
            // (BannerlordTableauManager.cs:50-52), and the array has 5 entries.
            Debug.Print("tableau " + characterCodeId + " ready", 0);
        };

        BannerlordTableauManager.RequestCharacterTableauRender(
            characterCodeId: 0,
            path: "MyMod_Character",
            poseEntity: poseEntity,
            cameraObject: camera,
            tableauType: 0);
    }

    public static bool IsBusy()
    {
        // The only progress signal on this bridge.
        return BannerlordTableauManager.GetNumberOfPendingTableauRequests() > 0;
    }
}
```

**What to watch out for.** Set `RequestCallback` **before** requesting, always. `RequestCharacterTableauSetup` calls `RequestCallback(...)` unguarded (`BannerlordTableauManager.cs:46`), and it is invoked on native's callback path, not yours — so a `NullReferenceException` there will not surface at your request site and will not be catchable around the request call. Second, do not treat the return of `RequestCharacterTableauRender` as confirmation: it is `void` (`IMBBannerlordTableauManager.cs:10`) and the work is queued. Third, `TableauCharacterScenes` is a fixed 5-element array indexed by `tableauType` (`BannerlordTableauManager.cs:9`, `:15`, `:52`), so a `tableauType` of 5 or more writes out of bounds.

## Examples

Request a tableau and use the pooled scene slot on completion — the full round trip:

```csharp
using TaleWorlds.Engine;
using TaleWorlds.MountAndBlade;

public static class MyModTableau
{
    // Five slots exist (BannerlordTableauManager.cs:9); 0..4 are the valid types.
    private const int TableauType = 0;

    public static void Request(GameEntity poseEntity, Camera camera, int characterCodeId)
    {
        BannerlordTableauManager.InitializeCharacterTableauRenderSystem();

        // MUST precede the request: the callback dereferences this with no null
        // check (BannerlordTableauManager.cs:46).
        BannerlordTableauManager.RequestCallback = (int codeId, Scene scene, GameEntity entity) =>
        {
            Scene[] slots = BannerlordTableauManager.TableauCharacterScenes;
            if (TableauType < slots.Length && slots[TableauType] != null)
            {
                Debug.Print("slot " + TableauType + " scene ready for " + codeId, 0);
            }
        };

        BannerlordTableauManager.RequestCharacterTableauRender(
            characterCodeId, "MyMod_Character", poseEntity, camera, TableauType);
    }
}
```

Poll for idle instead of guessing a fixed delay — the honest way to sequence follow-up work:

```csharp
using TaleWorlds.Core;
using TaleWorlds.MountAndBlade;

public class TableauWatcher : MissionLogic
{
    private bool _requested;

    public override void OnMissionTick(float dt)
    {
        base.OnMissionTick(dt);

        if (!_requested)
        {
            _requested = true;
            return;
        }

        // GetNumberOfPendingTableauRequests is an aggregate count, not a per-request
        // status (IMBBannerlordTableauManager.cs:16), so "0" means the whole queue
        // is empty — not that any particular request succeeded.

        {
            Debug.Print("tableau queue drained", 0);
        }
    }
}
```

## Risks and crash boundaries

- **A mod cannot name the interface.** `internal interface` (`IMBBannerlordTableauManager.cs:8`) plus `internal static MBAPI` field (`MBAPI.cs:64`) plus `InternalsVisibleTo` limited to three TaleWorlds assemblies (`TaleWorlds.MountAndBlade/Properties/AssemblyInfo.cs:8-10`). Compile-time failure.
- **The callback will throw if you did not set it.** `RequestCharacterTableauSetup` invokes `RequestCallback(characterCodeId, scene, poseEntity)` with no null guard (`BannerlordTableauManager.cs:46`), on native's callback path. A missing callback is a `NullReferenceException` raised somewhere other than your request site, so it cannot be caught by wrapping `RequestCharacterTableauRender`.
- **`tableauType` is an unchecked array index.** `RegisterCharacterTableauScene` writes `TableauCharacterScenes[type] = scene` (`BannerlordTableauManager.cs:52`) into an array allocated with 5 elements (`BannerlordTableauManager.cs:9`). Nothing in the bridge validates the value, so a type of 5 or more is an out-of-bounds write on the callback thread.
- **Asynchronous, with no per-request confirmation.** `RequestCharacterTableauRender` is `void` (`IMBBannerlordTableauManager.cs:10`) and the work is queued. The only aggregate signal is `GetNumberOfPendingTableauRequests()` (`IMBBannerlordTableauManager.cs:16`); a request that was never serviced leaves no individually observable trace.
- **The scene array is shared, static and managed.** `TableauCharacterScenes` is a public static array (`BannerlordTableauManager.cs:15`) over a static backing field (`BannerlordTableauManager.cs:9`). Two systems using the same `tableauType` overwrite each other's slot.
- **`ClearManager()` is one-way until re-initialised.** It nulls the array and resets the flag (`BannerlordTableauManager.cs:24-26`), so a subsequent native registration for that type will fault on the null array. Re-initialise before expecting callbacks again.
- **Not a save participant.** No `[Serializable]`, no state; tableau renders are presentation and are never persisted.

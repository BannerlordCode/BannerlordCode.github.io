# AllianceCampaignBehavior

**Namespace:** `TaleWorlds.CampaignSystem.CampaignBehaviors`
**Module:** `TaleWorlds.CampaignSystem`
**Type:** `public class AllianceCampaignBehavior : CampaignBehaviorBase, IAllianceCampaignBehavior`
**Base:** `CampaignBehaviorBase`
**File:** `bin/TaleWorlds.CampaignSystem/TaleWorlds.CampaignSystem.CampaignBehaviors/AllianceCampaignBehavior.cs`

## 概述

`AllianceCampaignBehavior` 是**王国同盟与宣战号召的唯一权威状态持有者**。它内部只有两张表——`_alliances`（`List<Alliance>`）与 `_callToWarAgreements`（`List<CallToWarAgreement>`）——两者都通过 `SyncData` 进存档。除此之外它还负责：到期检查（日结）、宣战/宣和的连带惩罚、灭国清理、以及给玩家发通知或建决议。

它是 `IAllianceCampaignBehavior` 接口的实现，[AcceptCallToWarAgreementDecision](../AcceptCallToWarAgreementDecision) 通过 `Campaign.Current.GetCampaignBehavior<IAllianceCampaignBehavior>()` 拿到它并调 `StartCallToWarAgreement` / `DenyCallToWarAgreement`。

## 心智模型

把它当成**「外交账本 + 到期清算器」**。四条必须记住的规则：

1. **`Kingdom.IsAllyWith` 不查这张表。** 本类型的 `IsAllyWithKingdom(kingdom1, kingdom2)` 是**独立的一套判定**：先挡 null / 同一家 / 任一方 `IsEliminated`，再 `TryGetAlliance` 查 `_alliances`。**别把 `Kingdom.IsAllyWith` 和本方法混为一谈**——[AcceptCallToWarAgreementDecision](../AcceptCallToWarAgreementDecision).CanMakeDecision 用的是 `base.Kingdom.IsAllyWith(CallingKingdom)`，而 `HasCalledToWar` 用的是 `calledKingdom.IsAllyWith(callingKingdom)`。

2. **两层的到期机制互相独立。** `DailyTickClan` 对**每个氏族**调用，但只对**执政氏族**做事：先 `clan.Aggressiveness -= 1f`，然后 `clan.Kingdom.RulingClan != clan` 就 return。之后它遍历 `kingdom.AlliedKingdoms`，倒序清理：先逐个检查 `CallToWarAgreement.EndTime.IsPast` 调 `EndCallToWarAgreement`，再检查 `Alliance.EndTime.IsPast` 调 `EndAlliance`。**两个 `EndTime` 是各自独立的时钟，宣战到期不会顺带解除同盟。**

3. **`StartCallToWarAgreement` 会真的宣战。** 它不只是记账：末尾调 `DeclareWarAction.ApplyByCallToWarAgreement(calledKingdom, kingdomToCallToWarAgainst)`。同时按 `isPlayerPaying` 决定钱从谁钱包出：`isPlayerPaying ? Hero.MainHero.ChangeHeroGold(-cost) : callingKingdom.CallToWarWallet -= cost`，然后 `calledKingdom.CallToWarWallet += cost`。**它前置检查 `IsAllyWithKingdom && !calledKingdom.IsAtWarWith(...)`，不满足则整段静默跳过。**

4. **`ApplyBrokenAlliancePenalty` 有一个玩家/AI 分叉。** 硬编码常量 `BreakingAllianceRelationPenalty = -100`，但施加对象是 `detail == DeclareWarAction.DeclareWarDetail.CausedByPlayerHostility ? Hero.MainHero : kingdom.Leader`——**因玩家敌对行为而撕毁同盟时，扣的是玩家的关系；否则扣的是王国领袖的。** 这意味着同一个 `detail` 值会改变受害者。

## 真实示例

查询两个王国是否为盟友，并拿到过期时间（用本行为而不是 `Kingdom.IsAllyWith`）：

```csharp
AllianceCampaignBehavior behavior = Campaign.Current.GetCampaignBehavior<AllianceCampaignBehavior>();
Kingdom mine = Clan.PlayerClan.Kingdom;
Kingdom theirs = Kingdom.All.Find((Kingdom k) => k.StringId == "empire");
bool allied = behavior.IsAllyWithKingdom(mine, theirs);
Debug.Print("allied = " + allied + " end date = " + behavior.GetAllianceEndDate(mine, theirs).ToDays, 0);
```

列出某个盟友号召我们去打的全部目标国（用反查接口确认战争来源）：

```csharp
List<Kingdom> targets = behavior.GetKingdomsToCallToWarAgainst(theirs, mine);
foreach (Kingdom target in targets)
{
    Kingdom caller;
    bool byCallToWar = behavior.IsAtWarByCallToWarAgreement(mine, target, out caller);
    Debug.Print("at war with " + target.Name + " because of " + (caller == null ? "direct" : caller.Name), 0);
}
```

在 mod 里主动建立同盟（**注意它会自动为每个交战国创建宣战号召决议**）：

```csharp
Kingdom partner = Kingdom.All.Find((Kingdom k) => k.StringId == "vlandia");
if (partner != null && !behavior.IsAllyWithKingdom(Clan.PlayerClan.Kingdom, partner))
{
    behavior.StartAlliance(Clan.PlayerClan.Kingdom, partner);
    Debug.Print("allied with " + partner.Name + ", wars carried: " + behavior.GetKingdomsToCallToWarAgainst(Clan.PlayerClan.Kingdom, partner).Count, 0);
}
```

## 风险与边界

- **`StartCallToWarAgreement` 前置失败是静默的。** `IsAllyWithKingdom(...) && !calledKingdom.IsAtWarWith(...)` 不成立时**整段 return，不抛异常、不记账、不宣战**。调用方必须自己先判。
- **`StartCallToWarAgreement` 会真的宣战。** 末尾 `DeclareWarAction.ApplyByCallToWarAgreement(calledKingdom, kingdomToCallToWarAgainst)` —— **想「只记账不宣战」做不到，必须另找路径。**
- **`IsAllyWithKingdom` 挡已灭国。** 任一方 `IsEliminated` 即 false，即便 `_alliances` 里还有记录。**`OnKingdomDestroyed` 也只清 `_alliances`，`_callToWarAgreements` 靠这个判据自然失效。**
- **`IsAtWarByCallToWarAgreement` 的 `out` 可能为 null。** 未命中时显式置 null。**不解判空就 `.Name` 会 NRE。**
- **`StartAlliance` 有副作用链。** 建盟会遍历双方**每一个交战王国**并自动 `AddDecision(ProposeCallToWarAgreementDecision)`。**mod 里手动建盟可能一次生成 dozens 条决议。**
- **`StartAlliance` 里有一段冗余代码。** 同一段 `if (stanceWith.GetDailyTributeToPay(proposerKingdom) != 0) stanceWith.SetDailyTributePaid(proposerKingdom, 0, 0);` **写了两遍**，第二次必然不成立（第一次已清零）。无害但不要照抄。
- **`DenyCallToWarAgreement` 不写表。** 它只施加 `-50` 关系惩罚（`DenyingCallToWarRelationPenalty`）。**拒绝后 `_callToWarAgreements` 里不会有记录**，想查「谁被拒绝过」没有数据来源。
- **三个关系惩罚/奖励是硬编码 const。** `BreakingAllianceRelationPenalty = -100`、`DenyingCallToWarRelationPenalty = -50`、`AcceptingCallToWarRelationBonus = +10`。**改不了，除非改行为本身。**
- **`ApplyBrokenAlliancePenalty` 的受害者随 `detail` 变。** `detail == CausedByPlayerHostility ? Hero.MainHero : kingdom.Leader` —— **同一个撕盟事件，扣的关系可能落在玩家身上也可能落在领袖身上。**
- **`DailyTickClan` 每个氏族每天调一次，但只有执政氏族做事。** `clan.Aggressiveness -= 1f` 对所有氏族生效，之后 `clan.Kingdom.RulingClan != clan` 就 return。**性能上这是全树最重的日结之一**（对每个王国遍历盟友与全部号召）。
- **`OnGameLoadFinished` 是版本迁移补丁。** 只在 `MBSaveLoad.IsUpdatingGameVersion && LastLoadedGameVersion < v1.4.0.110693` 时执行，**正常读当前存档永不触发**。
- **两张表都进存档。** `_alliances` 与 `_callToWarAgreements` 通过 `SyncData` 同步，嵌套的 `Kingdom` 引用由各自的 `AutoGeneratedInstanceCollectObjects` 收集。**改表结构必须同步 `AutoGeneratedSaveManager`。**

## Mental Model

Think of it as **the engine room behind the mission**, with the control room being `Mission`. `Mission` is what a mod holds: `Mission.Current` (`Mission.cs:1044`), a `Scene` (`:1087`), teams, and behaviours. `IMBMission` is the machinery `Mission` drives, and every call needs the mission's native pointer because that pointer *is* the identifier — there is no other way to say which battle you mean.

The mental model that matters most is that **`IMBMission` reports physics and geometry, it does not interpret them.** `RayCastForClosestAgent` (`:85`) returns an `Agent` and an `out float collisionDistance` — a fact about the world. Whether that hit is a valid target, whether the shooter should fire, whether the shot is blocked by a friendly: none of that is here. Similarly `IsPositionInsideBoundaries` (`:106`) answers a geometric yes/no that is **independent of whether anything is allowed to be there**.

Two boundaries follow. First, **`out` parameters are how this bridge returns multiplicity.** `RayCastForClosestAgentsLimbs` (`:88`) returns the agent *and* an `out sbyte boneIndex`; `GetAgentCountAroundPosition` (`:262`) writes both ally and enemy counts through two `ref int` parameters. Reading only the return value silently discards half the answer.

Second, **the proximity-map search is a cursor protocol, not a collection.** `ProximityMapBeginSearch` (`:319`) returns a `ProximityMapSearchStructInternal` that you pass by `ref` to `ProximityMapFindNext` (`:322`) repeatedly. It mutates in place, so **you must keep passing the same struct**; copying it or re-beginning mid-loop loses your position.

## How to use

**How to obtain it.** Use `Mission`. The interface is `internal` (`IMBMission.cs:10`) behind `internal static IMBMission IMBMission;` (`MBAPI.cs:24`), and `TaleWorlds.MountAndBlade/Properties/AssemblyInfo.cs:8-10` grants `InternalsVisibleTo` only to `TaleWorlds.MountAndBlade.AutoGenerated`, `TaleWorlds.MountAndBlade.Multiplayer` and `TaleWorlds.Generator.Bannerlord`.

**A typical use.** A mod that finds the nearest enemy to a point — the single most common thing this bridge is for — goes through `Mission`, which forwards to `GetClosestEnemy` at `Mission.cs:2160-2163`:

```csharp
using TaleWorlds.Library;
using TaleWorlds.MountAndBlade;

Mission mission = Mission.Current;
Vec3 origin = mission.Scene.GetLastFinalRenderCameraPosition;

Agent nearest = mission.GetClosestEnemyAgent(mission.PlayerTeam, origin, 50f);
if (nearest != null)
{
    Debug.Print("nearest enemy is agent " + nearest.Index + " at " + nearest.Position, 0);
}
```

Ray-cast to find what is in front of a point, taking the limb index too:

```csharp
using TaleWorlds.Library;
using TaleWorlds.MountAndBlade;

Mission mission = Mission.Current;
Vec3 from = mission.Scene.GetLastFinalRenderCameraPosition;
Vec3 to = from + new Vec3(0f, 0f, 10f);

float collisionDistance = 0f;
sbyte boneIndex = 0;
Agent hit = mission.RayCastForClosestAgentsLimbs(from, to, -1, 0.1f, out collisionDistance, out boneIndex);
Debug.Print("hit agent " + (hit != null ? hit.Index : -1) + " at " + collisionDistance + " on bone " + boneIndex, 0);
```

**What to watch out for.** Treating a `null` return from the ray-casts and proximity helpers as "nothing there" without checking the distance. `RayCastForClosestAgent` (`:85`) returns an `Agent` **or null**, and `ProximityMapFindNext` (`:322`) signals exhaustion by leaving the retrieved count at zero rather than by an exception. The consequence is that a mod which uses the returned agent without checking `collisionDistance` acts on the nearest body even when the ray stopped far short of it, which reads in-game as an agent reacting through a wall.

## Examples

Find the nearest enemy to a point, handling the null case:

```csharp
using TaleWorlds.Library;
using TaleWorlds.MountAndBlade;

Mission mission = Mission.Current;
Vec3 origin = mission.Scene.GetLastFinalRenderCameraPosition;

Agent nearest = mission.GetClosestEnemyAgent(mission.PlayerTeam, origin, 50f);
if (nearest == null)
{
    Debug.Print("no enemy within 50m", 0);
    return;
}
Debug.Print("nearest enemy is agent " + nearest.Index + " at " + nearest.Position, 0);
```

Ray-cast and read the distance so you can tell a real hit from a far one:

```csharp
using TaleWorlds.Library;
using TaleWorlds.MountAndBlade;

Mission mission = Mission.Current;
Vec3 from = mission.Scene.GetLastFinalRenderCameraPosition;
Vec3 to = from + new Vec3(0f, 0f, 10f);

float collisionDistance = 0f;
sbyte boneIndex = 0;
Agent hit = mission.RayCastForClosestAgentsLimbs(from, to, -1, 0.1f, out collisionDistance, out boneIndex);
if (hit != null && collisionDistance <= 10f)
{
    Debug.Print("hit agent " + hit.Index + " on bone " + boneIndex, 0);
}
```

Walk the proximity map as a cursor, keeping the same struct:

```csharp
using TaleWorlds.Library;
using TaleWorlds.MountAndBlade;

Mission mission = Mission.Current;
Vec3 camera = mission.Scene.GetLastFinalRenderCameraPosition;
Vec2 centre = new Vec2(camera.x, camera.z);

if (AgentProximityMap.CanSearchRadius(25f))
{
    AgentProximityMap.ProximityMapSearchStruct search =
        AgentProximityMap.BeginSearch(mission, centre, 25f);
    while (search.LastFoundAgent != null)
    {
        Debug.Print("nearby agent " + search.LastFoundAgent.Index
            + " team " + search.LastFoundAgent.Team, 0);
        AgentProximityMap.FindNext(mission, ref search);
    }
}
```

Tune the corpse budget, which is the cheapest performance lever in a long battle:

```csharp
using TaleWorlds.MountAndBlade;

Mission.Current.SetOverrideCorpseCount(40);
Mission.Current.SetMissionCorpseFadeOutTimeInSeconds(6f);
Debug.Print("corpse budget applied", 0);
```

## Risks and crash boundaries

- **A mod assembly cannot call this interface.** `internal interface IMBMission` (`IMBMission.cs:10`), `internal static` field (`MBAPI.cs:24`), `InternalsVisibleTo` limited to three TaleWorlds assemblies (`TaleWorlds.MountAndBlade/Properties/AssemblyInfo.cs:8-10`).
- **The mission pointer is the identity.** Almost every member takes `UIntPtr missionPointer` first. A stale pointer after mission teardown is the classic crash here — `FinalizeMission` (`:70`) and `ClearScene` (`:64`) invalidate the handle without nulling anything you hold.
- **Several members return `null` rather than failing.** `GetClosestEnemy` / `GetClosestAlly` (`:250`, `:253`) and `FindAgentWithIndex` (`:265`) return `Agent`, and the managed forwarder returns `null` when there is no match (`Mission.cs:2155-2157`). **Dereferecing unconditionally is a crash; a modest radius guarantees the null.**
- **Answers arrive through `out` and `ref`, not the return value.** `RayCastForClosestAgentsLimbs` (`:88`) carries the limb in an `out sbyte`; `GetAgentCountAroundPosition` (`:262`) returns **`void`** and writes two counts through `ref int`. Ignoring them discards half the answer.
- **`sbyte` bone indices.** (`:88`, `:91`) Values over 127 arrive negative, indistinguishable from "no bone".
- **`AddMissile` has seventeen parameters** (`:121`) including a `bool isPrediction`. **Firing the prediction missile alongside the real one** shows the player two shots; the flag exists precisely so you do not.
- **Unchecked enum casts.** `GetCombatType` / `SetCombatType` (`:79`, `:82`) round-trip through `(MissionCombatType)` and `(int)` with no validation (`Mission.cs:1173`, `:1177`).
- **Reading the wrong Fps member.** `IMBMission.GetAverageFps` (`:75`) is a rolling average; [`IMBTestRun.GetFPS`](../IMBTestRun) (`:11`) is one sample. Comparing them is meaningless.
- **The proximity cursor mutates in place.** `ProximityMapFindNext` (`:322`) takes the search struct by `ref`, and the public wrapper `AgentProximityMap.FindNext(Mission, ref ProximityMapSearchStruct)` (`AgentProximityMap.cs:89`) does the same. **Copying it, or calling `BeginSearch` again mid-loop, resets your position** — the loop restarts instead of advancing. Termination is `search.LastFoundAgent == null` (`:18`), not an exception.
- **`StartRecording` takes no mission pointer** (`:223`) while the file members do — recordings are identified by **path**, so two missions writing the same file name collide.
- **No `Mission` member returns the live camera.** `set_camera_frame` / `get_camera_frame` (`:55`, `:58`) act on the mission, but the camera handle a mod would project through is injected elsewhere — see the note on [`IMBWindowManager`](../IMBWindowManager).
- **Not a save participant.** No `[Serializable]`; the battle is reconstructed from the mission record.

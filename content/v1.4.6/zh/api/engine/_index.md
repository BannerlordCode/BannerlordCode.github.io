# engine 桶：引擎胶水、场景实体与 Gauntlet 渲染层

这个桶覆盖 `bannerlord-1.4.6/TaleWorlds.Engine/`（顶层 175 个 `.cs`，另有 `.AutoGenerated`）及其子命名空间 `TaleWorlds.Engine.GauntletUI`（11）、`TaleWorlds.Engine.InputSystem`、`TaleWorlds.Engine.Options`、`TaleWorlds.Engine.Screens`，外加按前缀规则落进来的 `TaleWorlds.Diamond`（72）。它是 C# 与原生 Bannerlord 引擎之间的胶水层：场景与实体、相机、声音、贴图与字体资源、引擎选项、以及把 Gauntlet 界面真正画出来的渲染实现。

**两处容易走错的地方。** 一是 `TaleWorlds.Engine.GauntletUI` 归本桶，而 `TaleWorlds.GauntletUI` 归 [gui](../gui/) 桶——前缀最长命中决定归属，两者名字只差 `Engine.` 一段。二是 `TaleWorlds.Engine.InputSystem`（引擎侧输入，本桶）与 `TaleWorlds.InputSystem`（玩家按键与输入上下文，`system` 桶，尚未撰写）是两个不同的命名空间。

## 已手写的类页（1 张）

- [GauntletLayer](./GauntletLayer) — `TaleWorlds.Engine.GauntletUI` 里的 `ScreenLayer` 实现：加载 prefab movie、绑定 ViewModel、参与命中测试与手柄导航。自定义界面时经 `ScreenBase.AddLayer` 挂上去的就是它这一类。

## 尚未撰写的部分

下列类型在 1.4.6 源码里存在（命名空间已逐个核对），但**还没有类页**：

| 命名空间 | 待写类型 | mod 什么时候需要 |
| --- | --- | --- |
| `TaleWorlds.Engine` | `Scene`、`Camera`、`ICamera`、`GameEntity`、`IGameEntity`、`GameEntityComponent`、`PhysicsShape`、`SoundManager`、`Decal`、`EngineManaged`、`EngineScreenManager` | 手动创建 / 查询场景实体、切换相机、控制播放的音效；读取引擎状态 |
| `TaleWorlds.Engine.GauntletUI` | `GauntletMovieIdentifier`、`UIResourceManager`、`EngineTexture`、`UIConfig`、`TwoDimensionEnginePlatform`、`TwoDimensionEngineResourceContext` | 构造 movie 标识加载 prefab、预载贴图、配置 UI 缩放与二维绘制平台 |
| `TaleWorlds.Engine.InputSystem` | `EngineInputManager`、`CheatsHotKeyCategory`、`DebugHotKeyCategory` | 读取引擎侧输入状态与调试热键 |
| `TaleWorlds.Engine.Options` | `NativeOptions`、`IOptionData` | 注册或读取引擎原生选项 |
| `TaleWorlds.Engine.Screens` | `SceneLayer` | 在场景上叠加渲染层 |
| `TaleWorlds.Diamond` | 整个命名空间（72 个 `.cs`，联机传输层）尚无类页 | 做联机功能时才需要，mod 作者基本用不到 |

## 与邻桶的分工

- [gui](../gui/) — 屏幕栈与控件树在本桶之外的 gui 侧；[ScreenManager](../gui/ScreenManager) 决定何时推屏，[GauntletLayer](./GauntletLayer) 决定怎么画。
- [mission](../mission/) 与 [campaign](../campaign/) — 场景与实体这两个桶都在用：战斗里的投射物与攻城器械、地图上的天气与实体，都是引擎实体。
- [core-extra](../core-extra/) — `Game` / `GameStateManager` 等托管侧生命周期入口在本桶之上。

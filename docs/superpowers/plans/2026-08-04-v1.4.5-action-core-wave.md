# v1.4.5 Core Action Handwritten Wave Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Each task is a bilingual handwritten documentation rewrite followed by an independent review.

**Goal:** Replace four remaining high-value v1.4.5 campaign Action stubs with source-backed bilingual pages that teach safe world mutation, event cascades, real object acquisition, and lifecycle boundaries.

**Architecture:** Rewrite the existing `campaign-ext` leaf URLs in place. Each Action page is a task-oriented contract, not a method catalogue: explain what `Apply` changes, which reason/detail overload owns the behavior, what the caller must validate, which events and downstream Actions fire, and what direct field mutation would skip.

**Tech Stack:** Markdown, Zola clean routes, Bannerlord 1.4.5 C# source and call sites, Node.js handwritten-policy and documentation gates.

## Global Constraints

- All business-class body prose is handwritten from source and call sites; signatures are evidence only.
- Do not invoke retired body generators, stub writers, signature-to-prose tools, or bulk mutators.
- Preserve existing bilingual URLs and write Chinese/English pages with the same safety model.
- Every page needs a mental model, when/when-not guidance, real acquisition path, Action/detail semantics, dependency/event graph, real C# example, risk/version notes, and Parent/Sibling/Related navigation.
- Explain validation and lifecycle ownership before calling `Apply`; do not teach direct field writes as an Action replacement.
- All links are relative and must pass `BROKEN_LINKS=0`; every pair must classify as `deep_pass`.
- Do not reset, clean, stash, checkout, commit, or discard unrelated dirty-worktree changes.

# 架构总览

> **架构不是零件清单，是一张交通图。** 本页只回答一个问题：你想做的事该从哪一页开始读，读完之后往哪走。所有架构页都可以独立阅读，彼此之间有双向链接。

## 一句话地图

```
bannerlord-1.4.6/<模块目录>/            你要改的代码在这里
        │  71 个玩法模块，目录名 = 程序集名
        ▼
SDK 分层（sdk-overview）                先判断这层对象活多久、依赖谁
        │  Foundation / Campaign / Mission / UI / Save
        ▼
模块地图（module-map）                  再判断哪个目录负责这件事
        │
        ▼
API 分区 /api/<模块 slug>/             最后才查具体类
        │
        ▼
版本差异（version-delta）               只有要迁移时才回头看
```

**90% 的 mod 只和中间三层打交道**：模块入口（`MBSubModuleBase`）→ 战役/战斗行为 → 存档。

## 三页分工

| 文档 | 回答的问题 | 什么时候读 |
| --- | --- | --- |
| [SDK 分层概览](./sdk-overview) | 这段代码属于哪一层？依赖方向是什么？入口类是哪个？ | 每个新 mod 的第一页 |
| [模块地图](./module-map) | 1.4.6 有哪些模块目录，各自负责什么，mod 什么时候会碰到它？ | 知道要做什么之后 |
| [版本差异](./version-delta) | 1.4.6 相对 1.4.5 / 1.3.15 多了什么、少了什么？ | 需要同时支持旧版本时 |

## 推荐阅读顺序

1. [SDK 分层概览](./sdk-overview) — 建立层次感，确认目标层。
2. [模块地图](./module-map) — 把层次落到 1.4.6 的具体目录名。
3. [版本差异](./version-delta) — 确认你依赖的 API 在目标版本里都在。
4. 进 API 分区查类型页。

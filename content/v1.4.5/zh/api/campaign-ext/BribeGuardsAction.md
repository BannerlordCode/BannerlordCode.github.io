# BribeGuardsAction

**Namespace:** `TaleWorlds.CampaignSystem.Actions`  
**Module:** `TaleWorlds.CampaignSystem`  
**Type:** `public static class BribeGuardsAction`  
**Base:** 无（静态类）  
**源文件路径：** `TaleWorlds.CampaignSystem/Actions/BribeGuardsAction.cs`

## 概述

`BribeGuardsAction` 是战役中的一个**静态 Action**，唯一公开入口是 `Apply(Settlement settlement, int gold)`。它把一笔金币从主角（`Hero.MainHero`）转出，并把这笔钱累加到目标据点的 `BribePaid` 字段上。

贿赂的目的不是“立刻放人”或“直接逃狱”，而是**抬高据点已付贿赂的累计值**：游戏在判定主角能否进入地牢/领主厅时，会用 `BribeCalculationModel.GetBribeToEnterDungeon(settlement)` 计算“还差多少”，而该值等于 `MathF.Max(基础贿赂值 - settlement.BribePaid, 0)`。也就是说，每调用一次 `Apply`，就把剩余所需贿赂往下压一截，直到降到 0，对应的菜单选项才会解锁。

> 注意：源码里**只有一个**公开的 `Apply(Settlement, int)` 重载，没有返回值，也没有“贿赂原因 / 成功失败”这类参数。一些自动生成桩里暗示的多重载、返回 `bool`、改犯罪值或改逃脱几率等说法，在 1.3.15 / 1.4.5 源码中均**不存在**——下面所有效果都来自真实实现。

## 一句话职责

把主角的金币付给某个据点，抬高其 `BribePaid` 累计值，从而逐步降低进入该据点地牢/领主厅所需的剩余贿赂。

## 心智模型

把它想成**“往据点的贿赂计数里存钱”**，而不是“执行一次逃脱”或“改一次状态标志”：

- 它是一个无状态的静态入口，本身不持有任何数据；真正的状态落在两处：`Hero.MainHero.Gold`（付款方余额）和 `settlement.BribePaid`（据点累计贿赂，会随存档持久化）。
- 调用发生在**战役逻辑层**（Campaign Action）。典型的调用方是 `PlayerTownVisitCampaignBehavior` 里的贿赂菜单项（`town_keep_bribe`），或你自己的 Issue/任务/对话行为在玩家处于“受限访问（LimitedAccess）”据点时触发。
- **何时用**：想让玩家通过花钱解锁进入地牢（探监/救囚）或领主厅的权限，且当前 `BribeCalculationModel` 判定还差一笔钱时。
- **何时不要用**：不要在 `Mission`（战斗/场景）里调用；不要在读档/序列化（`SyncData`）阶段调用；不要为了“直接改一个据点的访问标志”而调用它——它只累加 `BribePaid`，真正的访问解锁由 `SettlementAccessModel` + `BribeCalculationModel` + 菜单条件共同决定。需要改关系/金库/归属时，应使用对应的 `*Action.Apply`（见下方依赖图），不要直接写 `settlement.BribePaid` 字段或 `Hero.MainHero.Gold`。

## 依赖图

- **上游（谁会调用它）**
  - [PlayerTownVisitCampaignBehavior](../PlayerTownVisitCampaignBehavior/)：在城镇/城堡的“贿赂守卫”菜单代价（`town_keep_bribe`）里调用，是游戏原生的调用方。
  - 你自己的 Issue / 任务 / ConversationBehavior：当玩家停留在某个据点且 `SettlementAccessModel` 返回 `LimitedAccessSolution.Bribe` 时，可主动调用。
- **下游（它改了什么）**
  - [Settlement](../../campaign/Settlement/) 的 `BribePaid` 属性：每次 `Apply` 都 `+= gold`，是**持久化字段**（见存档点），且不会被本 Action 重置。
  - [Hero](../../campaign/Hero/) / `Hero.MainHero.Gold`：通过 [GiveGoldAction](../GiveGoldAction/) 扣减主角金币（收款方为 `null`，金币从世界消失，不进任何人的账）。
  - [SkillLevelingManager](../SkillLevelingManager/)：按 `gold/1000` 的概率调用 `OnBribeGiven(gold)`，给主角相关技能加经验。
- **相关 Models / Behaviors / Actions**
  - [BribeCalculationModel](../BribeCalculationModel/) 与 [DefaultBribeCalculationModel](../DefaultBribeCalculationModel/)：`GetBribeToEnterDungeon` / `GetBribeToEnterLordsHall` 返回 `MathF.Max(基础值 - settlement.BribePaid, 0)`，是 `BribePaid` 的实际消费者。
  - [GiveGoldAction](../GiveGoldAction/)：本 Action 通过它完成扣款与 `OnHeroOrPartyTradedGold` 事件广播。
  - 同类状态变更入口：改关系用 [ChangeRelationAction](../ChangeRelationAction/)，改归属用 [ChangeOwnerOfSettlementAction](../ChangeOwnerOfSettlementAction/)，占领用 [ClaimSettlementAction](../ClaimSettlementAction/)，入驻用 [ChangeGovernorAction](../ChangeGovernorAction/)，村庄状态用 [ChangeVillageStateAction](../ChangeVillageStateAction/)，影响力用 [ChangeClanInfluenceAction](../ChangeClanInfluenceAction/)，王国用 [ChangeKingdomAction](../ChangeKingdomAction/)——都不要绕过对应 Action 直接写字段。
- **存档点**
  - `Settlement.BribePaid` 由自动存档系统序列化（见 `AutoGeneratedSaveManager` 中的成员注册）。贿赂进度会跨会话保留，一次没付够下次继续累加。
- **世界访问入口**
  - [Campaign](../../campaign/Campaign/) 提供 `Campaign.Current.Models.BribeCalculationModel` 与 `Campaign.Current.Models.SettlementAccessModel`；据点通过 [Settlement](../../campaign/Settlement/) / [MobileParty](../../campaign/MobileParty/) 获取。

## 风险（崩溃 / 坏档）

- **必须在战役期间调用**。仅在 `Campaign.Current` 已初始化、且 `Hero.MainHero` 非空时安全。在 `Mission` 内、读档（序列化/`SyncData`）过程中、或战役尚未启动的阶段调用，会因为 `ApplyBetweenCharacters(Hero.MainHero, null, gold)` 解引用 `Hero.MainHero` 而空引用崩溃。
- **`settlement` 不能为 null**。实现里直接 `settlement.BribePaid += gold`；传 null 会抛 `NullReferenceException`。务必先取得一个真实据点（`Settlement.CurrentSettlement` 或查询所得），并判空。
- **金币不足不会抛异常，但也没有效果**。扣款走 `GiveGoldAction`，内部用 `MathF.Min(Hero.MainHero.Gold, gold)` 把金额夹到主角实际持有量——钱不够时只付“现有的”，不会变负、不会报错。调用方若想确保达到解锁阈值，应先用 `BribeCalculationModel.GetBribeToEnterDungeon(settlement)` 取“还差多少”，再判断 `Hero.MainHero.Gold` 是否够。
- **会级联事件**。扣款会广播 `OnHeroOrPartyTradedGold`；按概率触发 `SkillLevelingManager.OnBribeGiven`。其他监听金币交易或技能经验的 mod/Behavior 都会响应，注意副作用叠加。
- **`BribePaid` 只增不减、随存档持久**。本 Action 从不把 `BribePaid` 清零；一旦累计到满足阈值，地牢/领主厅访问即永久解锁（直到该据点数据被其它逻辑改写）。不要把一次“付过但没解锁”的调用误判为失败。
- 不要在 `SyncData` 或任何存档读写回调里调用（详见 [崩溃与存档边界](../../../architecture/crash-boundaries/)）。

## 成员说明

### `public static void Apply(Settlement settlement, int gold)`

唯一的公开入口（内部转调私有的 `ApplyInternal`）。

- **用途**：把 `gold` 金币贿赂给 `settlement` 的守卫。
- **副作用（仅当 `gold > 0` 时执行）**：
  1. 以 `MBRandom.RandomFloat < (float)gold / 1000f` 的概率调用 `SkillLevelingManager.OnBribeGiven(gold)`——给主角加贿赂相关技能经验；概率随金额线性上升（约 1000 金≈必触发，500 金≈50%，100 金≈10%）。
  2. 调用 `GiveGoldAction.ApplyBetweenCharacters(Hero.MainHero, null, gold)`（1.4.5 的 3 参版本 `disableNotification` 默认为 `false`，与 1.3.x 的 4 参 `false` 等价）：从主角扣款，收款方为 `null`，金币从世界消失；同时广播 `OnHeroOrPartyTradedGold`。
  3. `settlement.BribePaid += gold`：抬高据点累计贿赂。
- **何时调用**：在玩家处于某据点且 `SettlementAccessModel.CanMainHeroEnterDungeon` 给出 `LimitedAccess` + `LimitedAccessSolution.Bribe` 时；或你自己实现的 Issue/任务代价里，按“还差多少”调用。

```csharp
// 真实调用（与 GuardsCampaignBehavior 同源）：在受限访问据点、剩余所需贿赂足够时调用
Settlement settlement = Settlement.CurrentSettlement;
if (settlement != null)
{
    int stillNeeded = Campaign.Current.Models.BribeCalculationModel.GetBribeToEnterDungeon(settlement);
    if (stillNeeded > 0 && Hero.MainHero.Gold >= stillNeeded)
        BribeGuardsAction.Apply(settlement, stillNeeded); // 抬高 settlement.BribePaid，累积到阈值后解锁
}
```

> 没有 `Apply` 的其它重载，也没有返回 `bool` / `BribeReason` 枚举等成员。`ApplyInternal` 是私有实现细节，mod 不应直接调用。

## 真实示例

### 示例 1：在“受限访问”据点按剩余所需金额贿赂（菜单/对话上下文）

真实获取路径：玩家正停留的据点用 `Settlement.CurrentSettlement`；金币来源是 `Hero.MainHero.Gold`；剩余所需金额来自 `Campaign.Current.Models.BribeCalculationModel`。

```csharp
using TaleWorlds.CampaignSystem;
using TaleWorlds.CampaignSystem.Actions;
using TaleWorlds.CampaignSystem.Settlements;

// 放在 GameMenu 代价（如 "town_keep_bribe"）或 ConversationBehavior 的 consequence 里
Settlement settlement = Settlement.CurrentSettlement;
if (settlement != null)
{
    int stillNeeded = Campaign.Current.Models.BribeCalculationModel.GetBribeToEnterDungeon(settlement);
    if (stillNeeded > 0 && Hero.MainHero.Gold >= stillNeeded)
    {
        // 抬高 settlement.BribePaid；累积到阈值后，进入地牢菜单项自动解锁
        BribeGuardsAction.Apply(settlement, stillNeeded);
    }
}
```

### 示例 2：从任务/Issue 行为对一个具体据点累计贿赂

真实获取路径：用 `Settlement.Find(stringId)` 取确定据点（这里以 `town_ESHORTA` 为例，实际换成你的目标据点 ID），或 `MobileParty.MainParty.CurrentSettlement` 取玩家当前所在据点；金币来自 `Hero.MainHero.Gold`。

```csharp
using TaleWorlds.CampaignSystem;
using TaleWorlds.CampaignSystem.Actions;

// 在 Issue/Quest 的 ApplyConsequence 或某 CampaignBehavior 的每日 tick 中
Settlement target = Settlement.Find("town_ESHORTA"); // 也可用 MobileParty.MainParty.CurrentSettlement
if (target != null && Hero.MainHero.Gold >= 200)
{
    // 累计支付 200 金；BribePaid 会跨会话保留，下次可继续累加直到解锁
    BribeGuardsAction.Apply(target, 200);
}
```

## 跨版本提示

- **1.3.0 / 1.3.15**：内部调用为 `GiveGoldAction.ApplyBetweenCharacters(Hero.MainHero, null, gold, false)`（4 参，`disableNotification = false`）。
- **1.4.5**：改为 3 参 `GiveGoldAction.ApplyBetweenCharacters(Hero.MainHero, null, gold)`，`disableNotification` 默认 `false`，**行为完全一致**。
- 三个版本公开的 `Apply(Settlement, int)` 签名与三项真实副作用（概率技能经验、扣主角金币、累加 `BribePaid`）均一致。

# AnchorPoint

**Namespace:** `TaleWorlds.CampaignSystem.Naval`
**Module:** `TaleWorlds.CampaignSystem`
**Type:** `public class AnchorPoint : IInteractablePoint, ITrackableCampaignObject, ITrackableBase`
**Base:** `IInteractablePoint`
**File:** `bin/TaleWorlds.CampaignSystem/TaleWorlds.CampaignSystem.Naval/AnchorPoint.cs`

## 概述

`AnchorPoint` 是「一支舰队的锚点」——玩家或 AI 用它表示**船队当前停在哪里 / 正在开往哪里**。它是 [MobileParty](../MobileParty) 上的一个字段（`MobileParty.Anchor`，构造时 `Anchor = new AnchorPoint(this)`），实现了三个接口：`IInteractablePoint`（地图上可点击的交互点）、`ITrackableCampaignObject`（提供旗帜与位置供小地图跟踪）、`ITrackableBase`（提供显示名）。

四个存档字段里三个是坐标或时间（`Position` / `TargetPosition` / `ArrivalTime`），一个是历史值（`_lastUsedDisembarkPosition`）。**`Owner` 是唯一没有存档标记的引用字段**，读档后靠 `InitializeOnLoad(MobileParty owner)` 重新绑定。

## 心智模型

把它当成**「一支船的当前停位 + 目的位 + 到达时钟 + 上次下船点」四元组**。核心心智模型是**双位置语义**：

- **`Position` = 现在的锚点**（船队实际所在）。
- **`TargetPosition` = 目的地锚点**（开往中的目标）。
- **`ArrivalTime` = 到达时钟**。`IsMovingToPoint` 完全由它推导：`ArrivalTime != CampaignTime.Zero && !ArrivalTime.IsPast`。**注意 `ArrivalTime` 是 `CampaignTime.Zero` 表示「不在航行中」，而不是「已到达」**——这是一个用零值当哨兵的设计。

`CallFleet(Settlement settlement)` 是唯一的业务入口，它把这四元组串起来：

```csharp
CampaignTime fleetTravelTimeToSettlement = Campaign.Current.Models.PartyTransitionModel.GetFleetTravelTimeToSettlement(Owner, settlement);
if (fleetTravelTimeToSettlement == CampaignTime.Zero)
{
    SetSettlement(settlement);
    return;
}
ResetPosition();
TargetPosition = settlement.PortPosition;
ArrivalTime = CampaignTime.Now + fleetTravelTimeToSettlement;
```

**同城镇呼舰队是瞬移（`SetSettlement` 立即落位），跨城镇才设航程。** `HourlyTick()` 每小时检查 `ArrivalTime.IsPast`，命中就 `SetPosition(TargetPosition)` 并给主玩家弹一条绿色信息。

第二个心智锚点是 **`_lastUsedDisembarkPosition` 与 `Position` 是两回事**。`SetSettlement(settlement)` 会同时做 `SetPosition(settlement.PortPosition)` 和 `SetLastUsedDisembarkPosition(settlement.GatePosition)`——**锚点在港口，交互点在城门**。而 `GetInteractionPosition()` 返回的是**停泊位**（`_lastUsedDisembarkPosition`），不是 `Position`。搞混这两者，遭遇判定半径就会算错。

第三个锚点是 **`Owner` 没有存档标记**。`AutoGeneratedInstanceCollectObjects` 只收集三个 `CampaignVec2` 与一个 `CampaignTime`，**不收集 `Owner`**。所以读档后必须由外部调 `InitializeOnLoad(owner)` 把 `MobileParty.Anchor` 重新绑上，否则 `Owner` 为 null，`CallFleet` / `HourlyTick` / `GetBanners` 全崩。

## 真实示例

呼舰队去另一个港口（走完整航程路径）：

```csharp
MobileParty fleet = MobileParty.MainParty;
Settlement target = Settlement.Find("Caes_Imperium");
if (fleet.Anchor != null && target != null)
{
    fleet.Anchor.CallFleet(target);
    Debug.Print("target=" + fleet.Anchor.TargetPosition + " arrival=" + fleet.Anchor.ArrivalTime, 0);
    Debug.Print("moving? " + fleet.Anchor.IsMovingToPoint, 0);
}
```

判断锚点当前停在哪个港口附近（用 `IsAtSettlement` 而不是自己算距离）：

```csharp
MobileParty fleet = MobileParty.MainParty;
foreach (Settlement settlement in Settlement.All)
{
    if (fleet.Anchor.IsAtSettlement(settlement))
    {
        Debug.Print("anchored at " + settlement.Name + " interaction pos=" + fleet.Anchor.GetLastUsedDisembarkPosition(), 0);
    }
}
```

手动移动锚点并确认跟踪注册（`SetPosition` 会顺带处理 `VisualTrackerManager`）：

```csharp
MobileParty fleet = MobileParty.MainParty;
CampaignVec2 spot = new CampaignVec2(new Vec2(1200f, -300f), isOnLand: false);
fleet.Anchor.SetPosition(spot);
Debug.Print("valid=" + fleet.Anchor.IsValid + " tracked=" + Campaign.Current.VisualTrackerManager.CheckTracked(fleet.Anchor), 0);
```

## 风险与边界

- **`Owner` 不进存档。** `AutoGeneratedInstanceCollectObjects` 只收三个 `CampaignVec2` 和一个 `CampaignTime`。**读档后必须由外部调 `InitializeOnLoad(owner)`**，否则 `CallFleet` / `HourlyTick` / `GetBanners` / `Name` 全部 NRE。
- **`IsReady` 恒为 `true`。** 硬编码常量，不做任何检查。**拿它当「可以交互」的判据会在锚点无效时给出错误结论**——真正的判据是 `CanPartyInteract` 的三个条件。
- **`CanPartyInteract` 要求三个条件同时成立。** `mobileParty.IsMainParty && IsValid && !IsDisabled`，再加距离判定 `mobileParty.Position.Distance(GetInteractionPosition(mobileParty)) < Campaign.Current.Models.EncounterModel.NeededMaximumLandDistanceForEncounteringMobileParty`。**只有主玩家能交互**，AI 船队点不动。
- **`GetInteractionPosition` 在 `IsValid` 为假时返回 `CampaignVec2.Invalid`。** 而 `CanPartyInteract` 的距离判定在它之后——**`IsValid` 为假时短路在前，所以不会拿 Invalid 算距离**；但外部自己调 `GetInteractionPosition` 时必须先判 `IsValid`。
- **`Position` 与 `_lastUsedDisembarkPosition` 语义不同。** 前者是船在港口的位置，后者是玩家下船的城门位置。`SetSettlement` 同时写两者，但**两者可以不同**（港口与城门本来就不是一个点）。
- **`HourlyTick` 是 `internal`。** mod 调不到。**航行结算的粒度是一小时**——`ArrivalTime` 已过但还没 tick 到，锚点会短暂停在原地。
- **`SetPosition` 只对主玩家注册跟踪。** `if (!Owner.IsMainParty) return;` 之后才处理 `VisualTrackerManager`——**AI 船队的锚点从不注册跟踪**。
- **存档字段序号不连续。** `_lastUsedDisembarkPosition` 是 4，`IsDisabled` 是 5，中间没有 6 之前的其它字段。**新增字段从 6 往后，且必须同步 `AutoGeneratedSaveManager` 的 `AutoGeneratedGetMemberValue*` 注册。**
- **`CheckPositionsForMapChangeAndUpdateIfNeeded()` 会改 `Position`。** 地图切换后若锚点落在非海军地形上，它会被强制挪到最近的可达海面点（`FindReachablePointAroundPosition(..., 8f, 1f)`）。**这个方法会静默改变你的坐标。**
- **`OnPartyInteraction` 会改 `MobileParty` 的三个字段。** 它清 `mobileParty.Ai.AiBehaviorInteractable`、写 `TargetPosition` / `MoveTargetPoint`、调 `SetSailAtPosition`。**它是对移动队状态机的写入，不是只读查询。**

## 怎么用

### 怎么拿到它

**永远不要自己 `new AnchorPoint`。** 全树只有两处构造，都在 `MobileParty` 内部：`:1878` 是 `MobileParty` 构造时的 `Anchor = new AnchorPoint(this)`，`:2258` 是读 1.3.0 之前的旧存档时的补建（条件是 `MBSaveLoad.LastLoadedGameVersion.IsOlderThan(ApplicationVersion.FromString("v1.3.0"))`，`:2255`）。**除了这两处，任何地方都不该出现第三个。**

你要拿的是 `MobileParty.Anchor`——它属于某一个队伍，不属于地图或战役。mod 唯一被支持的接管方式是 `MobileParty.SetAnchor(AnchorPoint anchor)`（`:3053`）：它把 `Anchor` 赋过去，**并立刻调 `Anchor.InitializeOnLoad(this)`（`:3056`）**。这一步是必需的，不是可选的——`InitializeOnLoad`（`AnchorPoint.cs:157`）只做一件事：把 `Owner` 补上（`:159`）。

`Owner` 不进存档。`AutoGeneratedInstanceCollectObjects`（`:68`）只收三个 `CampaignVec2`（`:70`-`:72`）和一个 `CampaignTime`（`:73`），**没有 `Owner`**。所以读档路径靠 `MobileParty.PreAfterLoad()` 里的 `Anchor?.InitializeOnLoad(this)`（`:2267`）补回归属。

### 典型用法

调度的 tick 由队伍驱动：`MobileParty` 的逐小时逻辑末尾无条件调 `Anchor.HourlyTick()`（`:2445`），而 `AnchorPoint.HourlyTick()` 是 `internal`（`AnchorPoint.cs:198`）——**它只判 `ArrivalTime != CampaignTime.Zero && ArrivalTime.IsPast`（`:200`），成立就 `SetPosition(TargetPosition)`（`:202`）并给主队弹一条绿字信息（`:205`）**。也就是说「舰队什么时候真正到位」取决于队伍还在活动状态。

`IsValid` 只看 `Position.IsValid()`（`:47`），而新构造的锚点 `Position = CampaignVec2.Invalid`（`:117`）——**刚建出来时它是无效的**。想在接管一个自定义锚点后确认状态，直接读这几个派生属性：

```csharp
public static class AnchorHandoverProbe
{
    public static void Report(MobileParty fleet)
    {
        AnchorPoint anchor = fleet.Anchor;
        Debug.Print("owner=" + (anchor != null && anchor.Owner != null ? anchor.Owner.Name.ToString() : "<null>"), 0);
        Debug.Print("valid=" + anchor.IsValid + " moving=" + anchor.IsMovingToPoint + " disabled=" + anchor.IsDisabled, 0);
        Debug.Print("arrival=" + anchor.ArrivalTime + " target=" + anchor.TargetPosition, 0);
    }
}
```

`CallFleet` 有一条短路要先知道（`:103`-`:108`）：`PartyTransitionModel.GetFleetTravelTimeToSettlement` 返回 `CampaignTime.Zero` 时，它**不走航程**，直接 `SetSettlement(settlement)` 就 return。`SetSettlement` 会把 `Position` 设成 `settlement.PortPosition`、把 `_lastUsedDisembarkPosition` 设成 `settlement.GatePosition`（`:153`-`:154`）——**这两个值一个是港口一个是城门，不要混。**

想彻底清空一个锚点，用 `ResetPosition()`（`:255`）而不是 `SetPosition`：它内部走 `SetPosition(new CampaignVec2(Vec2.Invalid, isOnLand: false))`（`:257`），而 `SetPosition` 会顺手 `ResetMoveTarget()`（`:133`）并处理 `VisualTrackerManager` 的注册/反注册（`:138`-`:148`）。

### 最容易踩的坑

**`Owner` 不进存档。** `AutoGeneratedInstanceCollectObjects` 只收三个 `CampaignVec2` 和一个 `CampaignTime`。**读档后必须由外部调 `InitializeOnLoad(owner)`**，否则 `CallFleet` / `HourlyTick` / `GetBanners` / `Name` 全部 NRE。

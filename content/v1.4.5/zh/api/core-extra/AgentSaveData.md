# AgentSaveData

**Base:** 无

## 概述

`AgentSaveData` 是**存档层面的一个 agent 身份快照**：它要回答的是「存档里要恢复一批 agent 时，我需要记住每个 agent 的哪四样东西」——角色 StringId、出生位置的 [MatrixFrame](../MatrixFrame)、生成点的 tag 数组、以及决定外观的随机种子。四个字段全部带 `[SaveableField(n)]` 特性，序号 1 到 4，**这个序号是存档格式的一部分，不能改**。

它承担的是**「可序列化的最小 agent 描述」**这一环，位于 campaign 存档层而不是 mission 运行时。它的形状值得注意：这是一个 **C# 12 主构造函数结构体**（`public struct AgentSaveData(string characterStringId, ...)`，源码第 7 行），四个字段里有三个是 `readonly`、只有 `SpawnFrame` 可写——因为出生位置是唯一需要在存档恢复后被修正的量（通过 `UpdateSpawnFrame`）。

## 心智模型

把它当成**「存档里的一条 agent 名册」**，而不是一个活着的 agent 描述。它不参与战斗、不进 mission、不持有任何游戏对象引用——它只有四样纯粹的数据，其中唯一的引用类型 `string[]` 也只是 tag 字符串数组。**判断该不该用它，问一句：这个信息需要在游戏退出后重新读回来吗？** 需要，就用；不需要，用 [AgentData](../AgentData) 就够了。

**这个类型最需要理解的一点是「它是半自动生成的」。** `AgentSaveData.cs:26-53` 里有五个名字以 `AutoGenerated` 开头的成员：`AutoGeneratedStaticCollectObjectsAgentSaveData`、`AutoGeneratedInstanceCollectObjects`、`AutoGeneratedGetMemberValueCharacterStringId`、`AutoGeneratedGetMemberValueSpawnFrame`、`AutoGeneratedGetMemberValueAgentSpawnPointTags`、`AutoGeneratedGetMemberValueAgentSeed`。它们**不是代码生成器写的，而是手写在源码里的**——`TaleWorlds.Core/AutoGeneratedSaveManager.cs:150-155` 直接把这五个方法作为委托注册给存档系统：

（这段是源码引用，不是本文的示例。）**所以四个 `SaveableField` 的序号与这四个 `AutoGeneratedGetMemberValueXxx` 是一一对应的硬绑定。** 你给结构体加第五个字段，就必须同时补一个 `AutoGeneratedGetMemberValueXxx` 并在 `AutoGeneratedSaveManager` 里多注册一行——**只加字段不加回调，存档会静默丢掉这个字段**。

由此推出三条实操结论。第一，**`UpdateSpawnFrame` 是唯一可写的路径，而且是 mutating 的**：`SpawnFrame` 虽然不是 `readonly`，但结构体本身是值语义，`UpdateSpawnFrame` 修改的是副本，除非你重新赋回去。第二，**`AutoGeneratedInstanceCollectObjects` 只收集一个引用**：`AgentSpawnPointTags`。`CharacterStringId`、`SpawnFrame`、`AgentSeed` 都是值类型或内嵌结构，**不需要**进引用表——这是理解为什么 `collectedObjects.Add(...)` 只有一行的钥匙。第三，**在 1.4.5 的托管源码里，这个类型既没有构造调用方也没有读取方**（详见风险小节），这决定了它对你能做什么的实际约束。

## 真实示例

这个类型的真实形状——注意结构体是值语义，`UpdateSpawnFrame` 需要重新赋值：

```csharp
MatrixFrame spawnFrame = new MatrixFrame(Mat3.Identity, new Vec3(120f, -340f, 0f, 1f));

AgentSaveData entry = new AgentSaveData(
    "empire_villager_female",
    spawnFrame,
    new string[] { "spawn_point_01", "spawn_point_02" },
    MBRandom.RandomInt(0, 99999));

// CharacterStringId is a plain string, not an object reference -- that is why
// AutoGeneratedInstanceCollectObjects only collects AgentSpawnPointTags.
Debug.Print("id = " + entry.CharacterStringId, 0);
Debug.Print("seed = " + entry.AgentSeed, 0);
Debug.Print("tags = " + entry.AgentSpawnPointTags.Length, 0);
```

`UpdateSpawnFrame` 的值语义陷阱——这是本页最实用的一段：

```csharp
AgentSaveData before = new AgentSaveData(
    "empire_villager_female", MatrixFrame.Identity, new string[0], 12345);

// Mutating a method on a struct changes a copy, not the original.
before.UpdateSpawnFrame(new MatrixFrame(Mat3.Identity, new Vec3(5f, 6f, 0f, 1f)));

// before still holds MatrixFrame.Identity here -- you must write it back.
before = new AgentSaveData(
    before.CharacterStringId,
    new MatrixFrame(Mat3.Identity, new Vec3(5f, 6f, 0f, 1f)),
    before.AgentSpawnPointTags,
    before.AgentSeed);

Debug.Print("seed survived the rewrite = " + before.AgentSeed, 0);
```

## 风险与边界

- **在 1.4.5 托管源码里没有生产者和消费者。** `new AgentSaveData(` 全树命中 0 次；`AgentSaveData` 的所有引用都落在它自己、`AutoGeneratedSaveManager` 与 `SaveableCoreTypeDefiner` 三处。**因此 mod 无法从托管侧触发游戏走这条流程。** 判断填充 `List<AgentSaveData>` 的代码在哪——**做不到**，仅凭这份托管源码无法判定它是在 native 侧、被运行时反射创建，还是已被重构移除。能确定的只有类型号 1012、容器类型、以及被 `AutoGeneratedSaveManager` 遍历的事实。
- **结构体 + mutating 方法 = 静默丢失。** `UpdateSpawnFrame` 改的是副本。这是整个类型最常见的错误来源，且**编译期与运行期都没有任何提示**。
- **`SaveableField` 序号是存档格式的一部分。** 序号 1–4 与四个 `AutoGeneratedGetMemberValueXxx` 一一对应（`AutoGeneratedSaveManager.cs:152-155` 用 `new MemberTypeId(1, 1)` 到 `(1, 4)` 绑定）。**改序号会让旧存档读错位。**
- **加字段必须配齐三处。** 新的 `[SaveableField(5)]` 需要同时补一个 `AutoGeneratedGetMemberValueXxx` 并在 `AutoGeneratedSaveManager` 里加一行 `GetFieldDefinitionWithId(new MemberTypeId(1, 5)).InitializeForAutoGeneration(...)`。**只加字段会让存档静默丢掉它**——这是 `AutoGenerated*` 成员手写而非生成带来的直接代价。
- **只有数组进引用表。** `AutoGeneratedInstanceCollectObjects` 只 `Add(AgentSpawnPointTags)`。如果你把某个值类型字段改成引用类型（比如把 `AgentSeed` 换成包装类），**必须同步加进这个方法**，否则序列化器不会正确追踪它。
- **三个字段是 `readonly`，一个是可写的。** 这不是随意设计：`SpawnFrame` 是唯一需要在读档后被修正的量（战斗重开时出生点会变），其余三个读档后原样恢复。
- **`CharacterStringId` 是字符串不是引用。** 读档时游戏需要自己 `MBObjectManager.GetObject<BasicCharacterObject>(CharacterStringId)` 把字符串换回对象。**改存档里的角色定义（换 StringId）会让旧存档找不到角色。**
- **`AgentSeed` 决定外观复现。** 同一个 `AgentSeed` 必须复算出同一张脸与同一套装备。**如果你改了 `BodyProperties` 的生成算法而没动 `AgentSeed`，旧存档读出来的外观会和原本不同**（不会崩，但会变）。
- **注册号 1012 与容器是全局共享的。** `SaveableCoreTypeDefiner.cs:58/119` 是全局唯一的定义，**不能为自定义用途重复注册同一个类型号。**
- **`AutoGenerated*` 成员不是 mod 的 API。** 三个 `GetMemberValueXxx` 是 `internal`，外部程序集根本调不到；两个 `CollectObjects` 是 `public` 但只为存档框架服务。**用它们实现自己的序列化是自找麻烦。**

## 怎么用

### 怎么拿到它

`public struct AgentSaveData(string characterStringId, MatrixFrame spawnFrame, string[] agentSpawnPointTags, int agentSeed)`——**C# 12 主构造函数，声明在 `TaleWorlds.Core/AgentSaveData.cs:7`**，四个参数按顺序对应四个 `SaveableField`。**但 1.4.5 托管源码里它没有任何生产者**（`new AgentSaveData(` 全树 0 命中），所以你拿不到游戏填好的实例；要么自己 `new`，要么照它的形状注册自己的存档类型。

### 典型用法

上面「真实示例」两段都在构造侧：一段是字段形状，一段是 `UpdateSpawnFrame` 的值语义陷阱。缺的是**读档那一侧**——`CharacterStringId` 是字符串不是对象引用，解析是你自己的事：

```csharp
public static class MyCheckpointReader
{
    // 读档侧：CharacterStringId 只是 StringId，必须自己解析回对象
    public static bool TryResolve(AgentSaveData data, out BasicCharacterObject character)
    {
        character = MBObjectManager.Instance.GetObject<BasicCharacterObject>(data.CharacterStringId);
        if (character == null)
        {
            // 引用的角色必须存在于你正在加载的那个模块里，否则复现时拿到 null
            MBDebug.Print("[MyMod] 存档里的 " + data.CharacterStringId + " 不在当前模块");
            return false;
        }
        return true;
    }
}
```

与上面「真实示例」的差别：那里全程在**写**——造结构体、改 `SpawnFrame`、并演示「改了副本要重新赋值」；这里一行写都没有，只有一句解析和一句判空。之所以必须单独处理，是因为存档系统只存 `StringId`，`AutoGeneratedInstanceCollectObjects` 收的是 `AgentSpawnPointTags` 那个数组引用，**角色对象本身从来不被存**。

### 最容易踩的坑

## 跨版本提示

`AgentSaveData.cs` 在 1.4.5 是 55 行，是原始源码形态（file-scoped namespace、无 `// Token:` 注释、无 `// <auto-generated/>` 标记——**这恰恰证明这些 `AutoGenerated*` 成员是手写的**，因为真自动生成的代码会带标记头）。1.3.x / 1.4.6 的对应文件是反编译产物，会多出反编译器生成的 `Equals` / `GetHashCode` / `ToString` 等样板。**跨版本迁移时值得核对三件事**：类型注册号 1012 是否稳定（它是存档格式的一部分，改了旧存档全废）；四个 `SaveableField` 的序号与顺序是否稳定；以及——**最值得关注的**——1.4.5 这个「已注册、未接线」的状态是否在后续版本发生了变化。如果后续版本出现了 `new AgentSaveData(` 的调用方，那说明生产者被补回来了；反之若这个类型在某个版本从 `SaveableCoreTypeDefiner` 里消失，说明整条机制被移除了。**本页不猜这个，只提示你去核对。**

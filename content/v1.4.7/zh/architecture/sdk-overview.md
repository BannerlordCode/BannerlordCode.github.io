# SDK 总览 — 程序集分层与引用地图

## 心智模型

把 v1.4.7 想成五块积木，**每一块只能看到它下面的块**。你写的模组代码坐在最上面，
通过引用程序集拿到某一层的入口，然后**向下调用**。

```text
storymode / sandbox        内容层：主线任务、沙盒内容、AI、棋盘游戏
        ↓
campaign / campaign-ext    战役层：Campaign、Hero、Clan、行为、事件、Action、Model
        ↓
mission / mission-ext      战斗层：Mission、Agent、Formation、场景组件
        ↓
gui / viewmodel            界面层：ScreenBase、ScreenLayer、Gauntlet、ViewModel
        ↓
core / core-extra          基础层：Module 加载、事件总线、集合、平台、诊断
```

## 命名空间 → 文档目录的映射规则

文档不按程序集分目录，按**子系统**分。一个类型落在哪个目录，由四条规则按顺序决定
（权威机器可读版本是 `tools/_dir-map-canonical.json`）：

1. 排除闸门：命名空间落在 47 条 `excludeNamespaces` 前缀之下，或含有 `CodeGenerator` /
   `AutoGenerated` 段 → 不出页面，单独计数。
2. 最长前缀优先：37 条 `prefix → dir` 规则，取最长命中。
3. 入口类覆盖：7 个精确区分大小写的简单类型名直接改写目标目录
   （`Mission`、`MissionState`、`MissionBehavior`、`Agent`、`Formation` → `mission`；
   `MBSubModuleBase`、`Module` → `core`）。**这一步必须在第 2 步之后跑。**
4. 兜底：都没命中就进 `core-extra`，并记进 `unmapped`。

第 3 步是容易踩坑的地方：跳过它或者放到第 2 步之前，`mission/` 和 `core/` 会变成空目录，
点进去就是 404。所以每次重新生成之后都要断言"每个声明的目录都非空"。

**同一目录内重名怎么办？** 用 `<命名空间尾段>__<类型名>.md`，例如 `Campaign__IFaction.md`。
同一个类型只允许存在一个路径 —— 1.4.5 树里同一个类型出现在两个目录共 2,199 次，
那正是"点进去发现是别的地方、然后回不来"的根源。

## 一个类型在四个地方出现，是正常的

`Campaign` 同时出现在：程序集 `TaleWorlds.CampaignSystem`、命名空间
`TaleWorlds.CampaignSystem`、文档目录 `api/campaign/`、本页的程序集表里。
这四者各司其职：程序集决定编译引用，命名空间决定 `using`，目录决定文档 URL，本表只是索引。
搞混前两者是新手最常见的编译错误来源。

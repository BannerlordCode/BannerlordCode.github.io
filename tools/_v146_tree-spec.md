## 1. 路径与命名规则

| 规则 | 内容 |
| --- | --- |
| 叶子页路径 | `content/v1.4.6/{zh,en}/api/<module-slug>/<TypeSlug>.md` |
| 模块 slug | 去掉开头的 `TaleWorlds.`，转小写，其余点改连字符 |
| 泛型 | 泛型参数个数 N → `<Name>__<N>`（`IMbEvent<T1,T2>` → `IMbEvent__2`） |
| 同名冲突 | 同一 module-slug 内，命名空间等于模块目录名的类型保留裸名；其余加 `__<命名空间后缀>`（点改连字符） |
| 嵌套类型 | 不单独建页，作为 `nested` 行进入外层类型的「主要成员」表 |
| 泛型重复源文件 | 反编译器把不同 arity 拆成 `X.2.cs`/`X.3.cs`，已按 arity 视为不同类型 |

示例：`TaleWorlds.Core` → `core`；`TaleWorlds.Core.ViewModelCollection` → `core-viewmodelcollection`；`TaleWorlds.Engine.GauntletUI` → `engine-gauntletui`；`TaleWorlds.GauntletUI` → `gauntletui`；`TaleWorlds.MountAndBlade.GauntletUI.Widgets` → `mountandblade-gauntletui-widgets`；`SandBox` → `sandbox`；`StoryMode` → `storymode`。

> 1.4.6 的 slug 与 1.4.5 树的分区名**不同**（1.4.5 用 `core-extra` / `save-system` / `mission-ext` 这类人为分组名）。跨版本链接不要假设 slug 相同。

## 5. 链接写法（本树实测）

| 位置 | 目标 | 写法 |
| --- | --- | --- |
| 叶子页（路由 `zh/api/<slug>/<Type>/`） | 同模块类型 | `../<Type>` |
| 叶子页 | 本模块 `_index.md` | `../` |
| 叶子页 | api 落地页 `zh/api/` | `../../` |
| 叶子页 | 版本首页 `zh/` | `../../../` |
| 叶子页 | 跨模块类型 | `../../<slug>/<Type>` |
| 模块 `_index.md`（路由 `zh/api/<slug>/`） | api 落地页 | `../` |
| 模块 `_index.md` | 版本首页 | `../../` |
| api 落地页（路由 `zh/api/`） | 版本首页 | `../` |
| api 落地页 | 架构页 | `../architecture/…` |

关键点：**叶子页路由自带尾斜杠，所以同级叶子页必须写 `../X`，不能写 `X` 或 `./X`；也不要带 `.md` 后缀。** 生成器只对「本次会写出的文件 ∪ 磁盘上已存在的文件」发链接，所以本树不会自己制造断链。

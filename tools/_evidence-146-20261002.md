## 5. 方法论（本轮沉淀，全部有实例）

### 5.1 手抄机器可读表必然漂移
我在简报里手抄了 `tools/_dir-map-canonical.json` 的映射表，artifact 三次迭代后我的副本落后两轮，导致三轮错误广播（`TextObject` 桶、`rules=38` 实为 36、引用已删除的 `Engine.GauntletUI → gui` 规则）。**简报只放指针，不放转述。**

### 5.2 检查器与被检查者不得共用同一套错误的世界模型
worker-10 的 nav-checker 报 `OWNED_LINKS_BROKEN=0`，我复跑它 EXIT=0 就采信了 —— **它和我都用「把审计根当 URL 根」的解析**，于是互相印证。19 组「跨版本弹层少一层」的 C2 就是这样产生的，**而它根本不存在**（`zh/_index.md` 的 `../../versions/` 本来就对）。差点把对的改成错的。
**通则：验收时检查器与被检查对象必须使用不同解析实现。**
本次靠**独立第二实现**（完整站点 route、含版本段、从 `content/` 根解析）挡住。两套口径的差值（cross-version 一套 20、另一套 0）本身就是最强的对账信号 —— **跨口径差值是免费的对账信号，不要只报其中一个数字。**

### 5.3 纯文本路径陈述是断链审计的盲区
16 张类页页脚写「父级：campaign API 目录导览位于版本根 `../../../`」—— 是纯文本不是链接，**断链审计永远发现不了**，而且内容是错的。已修正为真链接 `](../)`。**新增门禁需求：类页页脚需人工核对，不能只跑链接审计。**

### 5.4 「报出一切都是错的」看起来像发现，不像 bug
我通过 shell heredoc 写检查脚本，`new RegExp('\\b'+id+'\\b')` 被折叠成 `'\b'`（JS 里是**退格符**），于是 25 个散文页的 1,457 个标识符全部被报成「未命中」，包括 `Campaign`、`Hero`、`SaveManager`。**根因是我的检查器没有阳性对照** —— 共享 `anti-fabrication.mjs` 有（`positive control: 6/6 found`），所以它在本会话里每次都能自证。
**通则：任何新检测器必须先证明它能找到已知存在的东西，否则它的「找不到」没有意义**（本次修正版已内置阳性对照，不通过则 exit 2 拒绝出结论）。

### 5.5 worker 反对派单是最后一道真值检查
本会话四次破坏性事故里，有三次起点是派单里的转述失真。三次被 worker 拦下：

| worker | 拒绝了什么 | 依据 |
| --- | --- | --- |
| worker-28 | 我说桶索引同桶叶子写 `../Game`；我说语言根 = `../../../` | artifact `linkRules`：`bucketIndexToLeaf: "./<Name>"`；语言根 2 层、版本根 3 层 |
| worker-29 | 同上，独立从 `linkRules` 复核 | 同上 |
| worker-30 | 门禁 PASS 不足以证明散文类型名可信 | 自写反查脚本抓出 `EncyclopediaVM` |

**通则：worker 发现派单与权威 artifact 冲突时，应按 artifact 执行并回报冲突，而不是按派单执行。派单者是转述者，artifact 是真值。worker 是这条链上唯一还在读原始真值的环节。**

### 5.6 反虚构门禁只扫代码块
`anti-fabrication.mjs` 只扫 ` ```csharp ` 内的标识符；桶索引、待写清单、架构页这类散文型页面没有代码块，**门禁在那里完全盲**。已补 `_v146_prose_name_check.mjs` 单独覆盖，**两者分别记录、不可互相代替**。

### 5.7 派单里的具体数字必须是派单者亲自核实过的
本会话同类错误三条：文件数（我说 8 个实为 7 个）、从配置抽出的值（把 `entryPointDirs._why` 散文当桶名）、转述 worker 首报（把「1.4.5 无 C# 源码」当事实广播三轮；worker-20 自己跑通后发现 1.4.5 源码在 `Bannerlord.Source/bin/`，于是那 16 页的跨版本段是真比对）。
**通则：派单者与被派单者不得共用同一套未经核实的假设。**

## Mental Model

Think of it as **the ground floor of the map**, as opposed to the battle upstairs. Nothing here knows what an `Agent` is. Its subject matter is terrain: where a party can stand, how the ground sounds under hooves, what colour a region tints to, and where the map's mouse pointer is. If your mod is reasoning about soldiers, this interface is the wrong floor — that is [`IMBMission`](../IMBMission) and [`IMBAgent`](../IMBAgent).

The boundary worth naming is that **the navmesh members report, they do not move.** `GetAccessiblePointNearPosition` (`:10`) and `GetNearestFaceCenterPositionForPosition` (`:13`) both take an optional `int[] excludedFaceIds` plus a count, and return a `Vec3` / `Vec2` rather than a success flag. There is no member here that accepts a destination and starts travel. So a mod using this bridge to place or route something must do the movement itself, using the point this bridge validates.

The second boundary is a naming trap that costs real debugging time. **`set_political_color` is exposed as `MBMapScene.GetGlobalIlluminationOfString`** (`MBMapScene.cs:82-85`):

```csharp
public static void GetGlobalIlluminationOfString(Scene mapScene, string value)
{
    MBAPI.IMBMapScene.SetPoliticalColor(mapScene.Pointer, value);
}
```

A method that begins with `Get` **writes**. Anyone tracing `GetGlobalIlluminationOfString` by name will conclude it is a read and miss the only call to `set_political_color` in the module entirely.

## How to use

**How to obtain it.** `public static class MBMapScene` (`MBMapScene.cs:7`) is public and needs no detour. The interface is `internal` (`IMBMapScene.cs:8`) behind `internal static IMBMapScene IMBMapScene;` (`MBAPI.cs:60`), and `TaleWorlds.MountAndBlade/Properties/AssemblyInfo.cs:8-10` grants `InternalsVisibleTo` only to `TaleWorlds.MountAndBlade.AutoGenerated`, `TaleWorlds.MountAndBlade.Multiplayer` and `TaleWorlds.Generator.Bannerlord`.

**A typical use.** A mod that needs a point a party can actually stand on asks the map scene to validate the spot, excluding the faces it already rejected:

```csharp
using TaleWorlds.Library;
using TaleWorlds.Engine;
using TaleWorlds.MountAndBlade;

Scene mapScene = mapSceneParameter;
int[] excludedFaces = new int[] { 0, 0, 0, 0 };
Vec2 spot = MBMapScene.GetNearestFaceCenterForPosition(mapScene, new Vec2(120f, 80f), false, excludedFaces);
Debug.Print("nearest walkable point = " + spot, 0);
```

**What to watch out for.** Reading the wrapper name instead of the native symbol. `MBMapScene.GetGlobalIlluminationOfString` (`MBMapScene.cs:82`) sounds like a read and is a write — it calls `MBAPI.IMBMapScene.SetPoliticalColor` (`:84`). The consequence is that a mod hunting for "the political colour getter" never finds one, concludes the value is write-only, and then builds UI that re-tints a region every frame instead of reading it. Search the interface for `set_political_color` (`IMBMapScene.cs:36`), not the wrapper for the managed name.

## Examples

Find a standable point, excluding faces you have already rejected:

```csharp
using TaleWorlds.Library;
using TaleWorlds.Engine;
using TaleWorlds.MountAndBlade;

Scene mapScene = mapSceneParameter;
int[] excludedFaces = new int[] { 0, 0, 0, 0 };
Vec2 spot = MBMapScene.GetNearestFaceCenterForPosition(mapScene, new Vec2(120f, 80f), false, excludedFaces);
Debug.Print("nearest walkable point = " + spot, 0);
```

Prefer the path-aware query when connectivity matters more than distance:

```csharp
using TaleWorlds.Library;
using TaleWorlds.Engine;
using TaleWorlds.MountAndBlade;

Scene mapScene = mapSceneParameter;
PathFaceRecord start = new PathFaceRecord(0, 0, 0);
int[] excludedFaces = new int[4];
Vec2 reachable = MBMapScene.GetNearestFaceCenterForPositionWithPath(mapScene, start, false, 50f, excludedFaces);
Debug.Print("reachable within 50m = " + reachable, 0);
```

Query the terrain index-map resolution before reading the map itself, since the read has no length parameter:

```csharp
using TaleWorlds.Engine;
using TaleWorlds.MountAndBlade;

Scene mapScene = mapSceneParameter;
int width = 0, height = 0;
MBMapScene.GetBattleSceneIndexMapResolution(mapScene, ref width, ref height);
Debug.Print("index map is " + width + "x" + height, 0);
```

Read and write the season factor, remembering it is scene state only:

```csharp
using TaleWorlds.Engine;
using TaleWorlds.MountAndBlade;

Scene mapScene = mapSceneParameter;
MBMapScene.SetSeasonTimeFactor(mapScene, 0.5f);
Debug.Print("season factor now = " + MBMapScene.GetSeasonTimeFactor(mapScene), 0);
```

## Risks and crash boundaries

- **A mod assembly cannot call this interface.** `internal interface IMBMapScene` (`IMBMapScene.cs:8`), `internal static` field (`MBAPI.cs:60`), `InternalsVisibleTo` limited to three TaleWorlds assemblies (`TaleWorlds.MountAndBlade/Properties/AssemblyInfo.cs:8-10`).
- **This is the campaign map, not the battlefield.** No member mentions an agent, team or mission. Reaching for it during a battle is the wrong floor entirely.
- **The wrapper name of `SetPoliticalColor` begins with `Get`.** `MBMapScene.cs:82-85` — `GetGlobalIlluminationOfString` writes. **Tracing by managed name hides the only write site**, and no read-back member exists on this interface.
- **Two bulk reads are unguarded.** `GetBattleSceneIndexMap(byte[] indexData)` (`IMBMapScene.cs:49`) and `GetColorGradeGridData(byte[] snowData, string)` (`:43`) take **no length parameter**. **Undersizing the buffer is a native overrun.** Query `GetBattleSceneIndexMapResolution` (`:45`) first.
- **Navmesh queries report no success.** Both `GetAccessiblePointNearPosition` (`:10`) and the two face-centre members (`:13`, `:16`) return a point and nothing else. **A point beyond your search radius is indistinguishable from one inside it.**
- **The excluded-face count is passed separately from the array.** (`:13`, `:16`) A mismatched pair makes native read the wrong span of your array.
- **`TickVisuals` substitutes a fixed 1024-entry buffer.** `MBMapScene.cs:11` declares `private static UIntPtr[] _tickedMapMeshesCachedArray = new UIntPtr[1024]`, and `:68` converts your `Mesh[]` through it — so the native mesh count is derived from that buffer, not from your call.
- **The mouse members are the map scene's own cursor,** not the OS or window cursor, and `SendMouseKeyEvent` (`IMBMapScene.cs:64`) **injects** an event rather than reporting one.
- **`terrainType` is an untyped `int`** on both `TickStepSound` (`:25`) and `TickAmbientSounds` (`:28`); a wrong value selects a wrong sound rather than failing.
- **Scene state does not persist.** `SetSeasonTimeFactor` (`:55`) and `SetTerrainDynamicParams` (`:52`) write scene-local state the campaign side owns.
- **Not a save participant.** No `[Serializable]`, no sync surface.

# storymode：官方故事模式（`StoryMode*`）

> **覆盖状态：本桶 0 张类页。**
> 核心结论先给：**和 [sandbox](../sandbox) 一样，这是官方玩法的实现代码，不是 mod 的 API 面**；但它比 sandbox 多一个例外——`StoryModeEvents` 是本桶里 mod 真正常用的入口。本页是导览，页面上出现的类型名全部是纯文本，**没有任何一个指向尚未撰写的类页**。

## 这个桶在源码里对应什么

归属规则只有一条前缀 `StoryMode` → `storymode`，前缀匹配。`bannerlord-1.4.6/` 下的 5 个相关目录与实测规模：

| 源码目录 | `.cs` 文件数 | 里面是什么 |
| --- | --- | --- |
| `StoryMode/` | 89 | 故事模式战役的实现：主线任务、阴谋任务、教学阶段、事件、战斗奖励模型 |
| `StoryMode.GauntletUI/` | 74 | 故事模式的 Gauntlet 部件与预制体 |
| `StoryMode.View/` | 8 | 故事模式专属的官方界面 |
| `StoryMode.ViewModelCollection/` | 5 | 故事模式专属的界面数据类 |
| `StoryMode.GauntletUI.AutoGenerated/` | 7 | prefab 生成物，权威排除清单按 `AutoGenerated` 后缀排除 |
| **合计** | **183** | |

在这个范围里以 `StoryMode` 开头的命名空间有 **14** 个，命名空间级类型声明数 **174**。

**口径定义**：`.cs 文件数` = `find <目录> -name '*.cs' | wc -l`；`命名空间级类型声明数` = 命名空间以该前缀开头的文件里，缩进恰好一个制表符的类型 / 委托声明行数，**不含嵌套类型**。

`StoryMode.GauntletUI.AutoGenerated/` 被权威排除清单排除，不生成任何页面——你在 [模块地图](../../architecture/module-map) 里看不到它，但它在磁盘上、grep 时会出现，**这是预期行为**。

## 和 sandbox 桶的关系

两个桶是**同构**的：都通过「一条前缀规则收拢一个官方玩法程序集」形成，都装的是官方内容实现，都不适合按类平铺。区别在内容：

- [sandbox](../sandbox) 装的是**沙盒战役**——遭遇、竞技场、地下城、城镇经营这类「可重复的日常玩法」
- storymode 装的是**故事模式战役**——主线、阴谋、教学阶段这类「一次性推进的叙事内容」

规模上本桶比 sandbox 小一个量级（183 对 1196 个文件），因为故事模式的内容更集中：主线任务和阴谋任务是有限的几十个，不是几百个遭遇。

**一个必须说清的差异**：sandbox 的两个 `AutoGenerated` 目录占了它 1196 个文件里的 627 个（一半以上），而 storymode 的生成物目录只有 7 个文件，全桶带双下划线命名特征的 `.cs` 只有 5 个。

```bash
find bannerlord-1.4.6/StoryMode* -name '*__*.cs' | wc -l   # → 5
```

**所以「storymode 的绝大多数文件是生成物」这个说法对 storymode 不成立**——那是 sandbox 的情况。storymode 的内容是手写的官方实现。

如果你的 mod 是战役玩法类（加遭遇、加城镇收益），两个桶你都要看一眼，因为它们的行为会挂在同一张战役图上。

## 读源码：可复跑的查法

在工作区根目录执行：

```bash
ls -d bannerlord-1.4.6/StoryMode*

grep -rhoE '^namespace StoryMode[A-Za-z0-9_.]*' bannerlord-1.4.6/StoryMode* --include='*.cs' | sort -u

# 「故事模式挂了哪些战役行为」——本桶最该读的那个问题
grep -rln 'CampaignBehaviorBase' bannerlord-1.4.6/StoryMode --include='*.cs' | head -30

# 从模块入口读起
grep -n 'class StoryModeSubModule' bannerlord-1.4.6/StoryMode/StoryModeSubModule.cs

# 本桶唯一对 mod 真正有用的入口：事件总线
grep -vE '^\s*//' bannerlord-1.4.6/StoryMode/StoryModeEvents.cs | head -60
```

## 什么时候会碰到它

三种关系，按重要性：

1. **插入点关系。** 和 sandbox 完全一样：你的行为会和故事模式自带的一批行为一起被加进战役。要挂行为本身写 [campaign](../campaign) 的 `CampaignBehaviorBase` + 战役启动流程；要知道你在跟谁抢位置，读本桶。
2. **事件监听（唯一的真实入口）。** `StoryModeEvents` 是一个继承 `CampaignEventReceiver` 的事件总线，暴露了一组事件静态属性。已核实的成员包括 `OnMainStoryLineSideChosenEvent`（载荷类型是 `MainStoryLine`），以及 `RemoveListeners` 里清理的那批：`OnStoryModeTutorialEndedEvent`、`OnStealthTutorialActivatedEvent`、`OnBannerPieceCollectedEvent`、`OnConspiracyActivatedEvent`、`OnTravelToVillageTutorialQuestStartedEvent`。**想做「主线选了哪一边」「某个阴谋被激活」这类反应的 mod，就订阅这里。** 这是本桶最值得先写一页的类型。它是 `StoryModeManager` 上的一个属性，所以它非空才有事件可用。
3. **教学阶段参考。** 故事模式带了一整套内置教学：入口是 `TutorialPhase`（文件 `StoryMode/StoryModePhases/TutorialPhase.cs`），由 `TutorialPhaseCampaignBehavior` 驱动，具体关卡是 `FindHideoutTutorialQuest` / `TalkToTheHeadmanTutorialQuest` / `RecruitTroopsTutorialQuest` 一族教程任务。做新手引导 mod 时参考这一套；否则完全不用碰。

**心智模型**：把 `StoryMode` 想成「官方发布的第二个大 mod」——它和你的 mod 做同样的事（挂行为、加任务、注册模型、接管界面），只是它是官方的、随游戏一起装的。所以读它的正确姿势是**对照**，不是继承。

**边界**：同 sandbox——**不要继承 `StoryModeQuestBase` 或故事模式的行为类**。它们没有兼容承诺。要挂钩子，用 [campaign](../campaign) 的稳定基类。

## 三处源码纠错

1. **`CampaignStoryMode` 是 `Campaign` 的子类。** `StoryMode/CampaignStoryMode.cs` 里写的是 `public class CampaignStoryMode : Campaign`，构造器接一个 `CampaignGameMode`。这解释了为什么故事模式 mod 能像普通战役 mod 一样挂行为——运行时你手上的 `Campaign.Current` 就是它。这也意味着写普通战役 mod 时**必须**同时考虑两种 campaign 实现。
2. **`DelayedAction` 和 `OppositionData` 不属于 `TaleWorlds.MountAndBlade`。** 它们的真实归属是：`DelayedAction` 在 `StoryMode/Missions/TrainingFieldMissionController.cs`（命名空间 `StoryMode.Missions`），`OppositionData` 在 `StoryMode/Quests/ThirdPhase/DefeatTheConspiracyQuestBehavior.cs`（命名空间 `StoryMode.Quests.ThirdPhase`）。按前缀规则这两个**文件**都落在本桶，而不是 [mission-ext](../mission-ext)。写它们时不要建到 mission-ext 去。
3. **但这两个都是嵌套类型，不是命名空间层级。** `DelayedAction` 是 `TrainingFieldMissionController` 内部的一个 `readonly struct`，`OppositionData` 是 `DefeatTheConspiracyQuestBehavior` 内部的一个 `internal class`。它们不会出现在本桶的「命名空间级类型声明」统计里——这是**正确行为**，不是漏数。

## 按用途分组的代表性类型（非链接，全部核实，未撰写类页）

下面每个名字都用 `grep -rw` 在 `bannerlord-1.4.6/StoryMode*` 下核实过。**这是按用途挑的代表性索引，不是待补清单，它们全部没有类页。**

模块入口与全局状态：

- `StoryModeSubModule` — 故事模式的模块入口，**想知道「故事模式挂了哪些战役行为派生类」就从这里读起**
- `StoryModeGauntletUISubModule` — 故事模式界面子模块（在 `StoryMode.GauntletUI/` 下，不在 `StoryMode/` 下）
- `CampaignStoryMode` — 继承 `Campaign` 的战役实现，见上面的纠错
- `StoryModeManager` — 故事模式的全局状态持有者；它上面的 `StoryModeEvents` 属性是事件总线的实际载体
- `StoryModeData` — 故事模式的数据容器

事件与任务基类：

- `StoryModeEvents` — **本桶最值得写一页的类型**，见上文。类型声明是 `public class StoryModeEvents : CampaignEventReceiver`。它有一个静态属性 `Instance`，内部先取 `StoryModeManager.Current`，**取不到就返回 `null`**——所以订阅事件前务必判空，否则你会在非故事模式战役里拿到一个空引用。
- `StoryModeQuestBase` — 故事模式任务基类（只读参考，不要继承）
- `ConspiracyQuestBase` — 阴谋线任务基类
- `MainStoryLine` / `MainStorylineCampaignBehavior` — 主线与它的战役行为；`MainStoryLine` 同时是主线选择事件的载荷类型

教学阶段：

- `TutorialPhase` / `TutorialPhaseCampaignBehavior` — 教学阶段与它的战役行为；做引导类 mod 的入口
- `TutorialQuestPhase` / `TutorialObjective` — 单个教学任务阶段与目标
- `FirstPhaseCampaignBehavior` / `SecondPhaseCampaignBehavior` / `ThirdPhaseCampaignBehavior` — 故事模式三个阶段各自的行为，示范了「按阶段切换行为」怎么写

计算模型（故事模式对基础模型的覆盖）：

- `StoryModeBattleRewardModel` — 战斗奖励的计算模型；想改故事模式下的战利品，从这里看
- `StoryModeCharacterCreationCampaignBehavior` — 角色创建相关的战役行为
- `StoryModeBanditSpawnCampaignBehavior` / `StoryModeNotableSpawnModel` — 刷 bandit 与重要人物生成
- `StoryModePartySizeLimitModel` / `StoryModePartyWageModel` — 队伍人数上限与薪资
- `StoryModeHeroDeathProbabilityCalculationModel` — 英雄死亡概率

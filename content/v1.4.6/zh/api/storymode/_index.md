# storymode：官方故事模式（`StoryMode*`）

> **本桶当前没有任何已撰写页面。** 核心结论先给：**和 [sandbox](../sandbox) 一样，这是官方玩法的实现代码，不是 mod 的 API 面**；但它比 sandbox 多一个例外——`StoryModeEvents` 是本桶里 mod 真正常用的入口。

## 这个桶对应源码里的什么

权威映射只有一条规则：`StoryMode` → `storymode`，前缀匹配。`bannerlord-1.4.6/` 下相关目录：

| 源码目录 | 里面是什么 |
| --- | --- |
| `StoryMode/` | 故事模式战役的实现：主线任务、阴谋任务、教学阶段、事件、战斗奖励模型 |
| `StoryMode.ViewModelCollection/` | 故事模式专属的界面数据类 |
| `StoryMode.View/` | 故事模式专属的界面 |
| `StoryMode.GauntletUI/` | 故事模式的 Gauntlet 部件与预制体 |
| `StoryMode.GauntletUI.AutoGenerated` | prefab 生成物，噪声清单排除 |

按声明抓到的类型名共 **194 个**（实测）。这个数字比 [sandbox](../sandbox) 的 1273 小得多，因为故事模式的内容更集中——主线任务和阴谋任务是有限的几十个，不是几百个遭遇。

## 和 sandbox 桶的关系

两个桶是**同构**的：都通过「一条前缀规则收拢一个官方玩法程序集」形成，都装的是官方内容实现，都不适合按类平铺。区别在内容：

- [sandbox](../sandbox) 装的是**沙盒战役**——遭遇、竞技场、地下城、城镇经营这类「可重复的日常玩法」
- storymode 装的是**故事模式战役**——主线、阴谋、教学阶段这类「一次性推进的叙事内容」

如果你的 mod 是战役玩法类（加遭遇、加城镇收益），两个桶你都要看一眼，因为它们的行为会挂在同一张战役图上。

## mod 什么时候会碰到它

三种关系，按重要性：

1. **插入点关系。** 和 sandbox 完全一样：你的行为会和故事模式自带的几百个行为一起被加进战役。要挂行为本身写 [campaign](../campaign) 的 `CampaignBehaviorBase` + `CampaignGameStarter`；要知道你在跟谁抢位置，读本桶。
2. **事件监听（唯一的真实入口）。** `StoryModeEvents` 是一个继承 `CampaignEventReceiver` 的事件总线，暴露了一组 `IMbEvent<T>` 静态属性。已核实的成员包括 `OnMainStoryLineSideChosenEvent`（`IMbEvent<MainStoryLineSide>`），以及 `RemoveListeners` 里清理的那批：`OnStoryModeTutorialEndedEvent`、`OnStealthTutorialActivatedEvent`、`OnBannerPieceCollectedEvent`、`OnConspiracyActivatedEvent`、`OnTravelToVillageTutorialQuestStartedEvent`。**想做「主线选了哪一边」「某个阴谋被激活」这类反应的 mod，就订阅这里。** 这是本桶最值得先写一页的类型。
3. **教学阶段参考。** 故事模式带了一整套内置教学（`TutorialPhase` 及其大量 `*Tutorial` / `*Step1Tutorial` 类）。做新手引导 mod 时参考这一套；否则完全不用碰。

**心智模型**：把 `StoryMode` 想成「官方发布的第二个大 mod」——它和你的 mod 做同样的事（挂行为、加任务、注册模型、接管界面），只是它是官方的、随游戏一起装的。所以读它的正确姿势是对照，不是继承。

**边界**：同 sandbox——**不要继承 `StoryModeQuestBase` 或故事模式的行为类**。它们没有兼容承诺。要挂钩子，用 [campaign](../campaign) 的稳定基类。

## 两处源码纠错

1. **`CampaignStoryMode` 是 `Campaign` 的子类。** `StoryMode/CampaignStoryMode.cs` 里写的是 `public class CampaignStoryMode : Campaign`，构造器接一个 `CampaignGameMode`。这解释了为什么故事模式 mod 能像普通战役 mod 一样挂行为——运行时你手上的 `Campaign.Current` 就是它。这也意味着写普通战役 mod 时**必须**同时考虑两种 campaign 实现。
2. **`DelayedAction` 和 `OppositionData` 不属于 `TaleWorlds.MountAndBlade`。** 1.4.5 的文档把它们和 `AgentNavigator`、`MapAudioManager` 一起归进一个语义混杂的 `gameplay/` 桶，看起来像战斗层类型。1.4.6 源码里它们的真实归属是：`DelayedAction` 在 `StoryMode.Missions`（`StoryMode/Missions/TrainingFieldMissionController.cs` 里使用），`OppositionData` 在 `StoryMode.Quests.ThirdPhase`。按前缀规则**两者都落在本桶**，不是 [mission-ext](../mission-ext)。写这两个类时不要建到 mission-ext 去。

## 待写清单（节选，17 条已核实类型）

下面每个名字都在 `bannerlord-1.4.6/StoryMode/` 核实过。**这是节选**——本桶 194 个类型，194 张类页没有意义。挑的是 mod 真会打开看的。

模块入口与全局状态：

- `StoryModeSubModule` — 故事模式的 `MBSubModuleBase` 子类，**想知道「故事模式挂了哪些 CampaignBehavior」就从这里读起**
- `StoryModeGauntletUISubModule` — 故事模式界面子模块
- `CampaignStoryMode` — 继承 `Campaign` 的战役实现，见上面的纠错
- `StoryModeManager` — 故事模式的全局状态持有者；`StoryModeEvents.Instance` 就是从 `StoryModeManager.Current.StoryModeEvents` 取的，所以它非空才有事件可用
- `StoryModeData` — 故事模式的数据容器

事件与任务基类：

- `StoryModeEvents` — **本桶最值得写一页的类型**，见上文
- `StoryModeQuestBase` — 故事模式任务基类（只读参考，不要继承）
- `ConspiracyQuestBase` — 阴谋线任务基类
- `MainStoryLine` / `MainStorylineCampaignBehavior` — 主线与它的战役行为；`MainStoryLine` 同时是 `OnMainStoryLineSideChosenEvent` 的事件载荷类型

教学阶段：

- `TutorialPhase` / `TutorialPhaseCampaignBehavior` — 教学阶段与它的战役行为；做引导类 mod 的入口
- `TutorialQuestPhase` / `TutorialObjective` — 单个教学任务阶段与目标
- `FirstPhaseCampaignBehavior` / `SecondPhaseCampaignBehavior` / `ThirdPhaseCampaignBehavior` — 故事模式三个阶段各自的行为，示范了「按阶段切换行为」怎么写

计算模型（故事模式对基础模型的覆盖）：

- `StoryModeBattleRewardModel` — 战斗奖励的计算模型；想改故事模式下的战利品，从这里看
- `StoryModeCharacterCreationCampaignBehavior` — 角色创建相关的战役行为
- `StoryModeBanditSpawnCampaignBehavior` / `StoryModeNotableSpawnModel` — 刷 bandit 与重要人物生成
- `StoryModePartySizeLimitModel` / `StoryModePartyWageModel` — 队伍人数上限与薪资
- `StoryModeHeroDeathProbabilityCalculationModel` — 英雄死亡概率

**没有页面**。写的时候建议以「一个问题」为主线（例如「怎么在主线分支做选择时插一脚」，答案落在 `StoryModeEvents` 上），或者给 `StoryModeSubModule` 写一篇「故事模式挂了哪些行为」的解剖，而不是 194 张单类页。

## 为什么现在还没有页面

1.4.6 的手写覆盖按 **mod 实际使用频率** 排序。本桶排在后段，理由与 [sandbox](../sandbox) 相同：**没有可继承的稳定基类**（该继承的都在 [campaign](../campaign) 和 [mission](../mission) 桶里写好了），内容是官方实现。

两个桶的真实价值都是**一次性通读**（「故事模式到底挂了哪些东西」），而不是**反复查单类**。这决定了它们该写成专题页而不是类页，排在手写队列后段是对的。

**这一页不是占位符**——归属规则、与 sandbox 的同构关系、`StoryModeEvents` 的已核实成员、`CampaignStoryMode` 的继承关系、以及 `DelayedAction` / `OppositionData` 的归属纠错，都是从源码来的。

> 节 schema：本页采用 7 节（按出现顺序）：概述 / 心智模型 / 怎么用 / 关键成员 / 真实示例 / 参见 / 导航

## 概述

`PartyComponent` 是 `MobileParty` 的**类型组件**（type component）。`MobileParty` 负责「一支部队在地图上怎么移动」——位置、路径、士气、工资、名册；`PartyComponent` 负责回答「这支部队是什么」——它是什么类型的队伍、谁拥有它、它叫什么名字、它的家乡定居点在哪、它默认挂谁的旗帜、它的工资上限是多少、它能不能走海路。这两块职责在源码里是分开的两个类，`MobileParty` 本身只保留通用机械，所有与「队伍身份」有关的语义都被推到 `PartyComponent` 的派生类里。

**持有关系是双向的，但生命周期是单向的。** `MobileParty` 内部持有 `_partyComponent` 字段，并通过 `PartyComponent` 属性暴露给外部；反过来，`PartyComponent` 也持有一个 `MobileParty` 属性（`PartyComponent.cs:21`）。这个反向引用**不是**构造函数注入的，而是由框架在创建或切换组件时回填：`MobileParty.CreateParty(stringId, component)` 与 `MobileParty.SetPartyComponent(...)` 会依次调用组件的 `Create` / `Initialize`（`PartyComponent.cs:116`、`PartyComponent.cs:123`），替换或销毁旧组件时调用 `Finish`（`PartyComponent.cs:130`）。换句话说：**队伍持有组件并主导其生命周期，组件反向引用队伍以访问 `Party`、`MemberRoster`、`ActualClan` 等运行时状态**。这正是 `Create` / `Initialize` / `Finish` 都是 `internal` 的原因——它们是框架的调用口，不是给 mod 直接调用的。

因为组件要能被存档，类上有一个 `protected virtual void AutoGeneratedInstanceCollectObjects(List<object> collectedObjects)`（`PartyComponent.cs:14`），派生类的存档字段会通过这套自动生成的对象收集机制被序列化。基类里还声明了一个公开委托 `OnPartyComponentCreatedDelegate(MobileParty mobileParty)`（`PartyComponent.cs:195`），作为创建队伍时的扩展点；在当前 `TaleWorlds.CampaignSystem` 里没有内建的订阅方，它主要留给外部模块。

## 心智模型

**组件是「队伍的身份与策略插件」，不是数据容器。** 它把一类队伍的游戏规则集中到一处：命名（`Name`）、归属（`PartyOwner`、`Leader`）、家园（`HomeSettlement`）、旗帜（`Banner` / `GetDefaultComponentBanner`）、工资上限（`WagePaymentLimit` / `SetWagePaymentLimit`）、海陆能力（`CanHaveNavalNavigationCapability` / `CanHaveLandNavigationCapability`）、敌对行为（`AvoidHostileActions`）。`MobileParty` 不需要知道「商队该怎么命名」，它只需要拿到 `PartyComponent` 然后问它。

**识别机制是类型判断，不是注册表。** 源码里没有一个「组件工厂注册中心」。`MobileParty` 通过 `UpdatePartyComponentFlags()` 用一连串 `is` 判断把组件类型翻译成缓存标志位（`IsLordParty` / `IsCaravan` / `IsBandit` / `IsGarrison` / `IsVillager` / `IsMilitia` / `IsPatrolParty` / `IsCustomParty`），并给每种类型配了一个 `as` 转换的便捷属性（`VillagerPartyComponent`、`CaravanPartyComponent`、`WarPartyComponent`、`BanditPartyComponent`、`PatrolPartyComponent`、`LordPartyComponent`、`GarrisonPartyComponent`）。**推论**：mod 自定义的组件子类不会被自动识别成任何内置种类——那些标志位只认内置的具体类型。唯一的例外是 `WarPartyComponent`：它的 `OnInitialize` / `OnFinalize` 会把自己注册/注销到所属家族（`Clan.OnWarPartyAdded` / `OnWarPartyRemoved`），因此任何继承它的队伍都会自动进入家族的战争队伍列表。

**一个组件实例只属于一支队伍。** `MobileParty` 属性有 `private set`，且 `SetPartyComponent` 在替换时会对旧组件调用 `Finish` 再对新的调用 `Initialize`。不要在多个 `MobileParty` 之间共享同一个组件实例。

**抽象 vs 默认实现的边界很清晰**：必须实现的是 `PartyOwner`（`PartyComponent.cs:35`）、`Name`（`PartyComponent.cs:39`）、`HomeSettlement`（`PartyComponent.cs:43`）、`GetDefaultComponentBanner`（`PartyComponent.cs:92`）；其余带默认实现，例如 `AvoidHostileActions` 默认 `false`（`PartyComponent.cs:47`）、`Leader` 默认 `null`（`PartyComponent.cs:73`）、`CanHaveLandNavigationCapability` 默认 `true`（`PartyComponent.cs:107`）、`WagePaymentLimit` 默认读 `Campaign.Current.Models.PartyWageModel.MaxWagePaymentLimit`（`PartyComponent.cs:57`）。

## 怎么用

### 怎么拿到

最直接的方式是 `MobileParty.PartyComponent`；如果已知类型，用 `MobileParty` 上对应的强类型属性做 `as` 转换更省事：

```csharp
// 通用入口
PartyComponent component = MobileParty.MainParty.PartyComponent;
Hero owner = component.PartyOwner;
TextObject displayName = component.Name;
Settlement home = component.HomeSettlement;

// 已知种类时用强类型属性（内部就是 as 转换，拿不到会返回 null）
CaravanPartyComponent caravan = MobileParty.MainParty.CaravanPartyComponent;
if (caravan != null)
{
    Settlement spawn = caravan.HomeSettlement;
}

// 遍历全战役的部队并按类型筛选
foreach (MobileParty party in Campaign.Current.MobileParties)
{
    if (party.PartyComponent is LordPartyComponent lord)
    {
        Hero lordOwner = lord.PartyOwner;
    }
}
```

注意 `WarPartyComponent` 是领主队与匪徒队的共同抽象父类，用 `party.WarPartyComponent != null` 可以一次覆盖「有家族归属的战争队伍」这一类。

### 典型用法

读取组件的身份信息是只读操作，可以随时做；**创建队伍**则应该走各派生类提供的静态工厂（它们内部会调用 `MobileParty.CreateParty`），不要自己 `new` 一个 `MobileParty`：

```csharp
// 领主队伍（由 LordPartyComponent 的静态工厂创建，内部 new 好组件再交给 CreateParty）
MobileParty lordParty = LordPartyComponent.CreateLordParty(
    "my_lord_party", someHero, position, 1.0f, someSettlement, someHero);

// 商队
MobileParty caravan = CaravanPartyComponent.CreateCaravanParty(
    someHero, spawnSettlement, partyTemplate, isInitialSpawn: false);

// 驻军
MobileParty garrison = GarrisonPartyComponent.CreateGarrisonParty("garrison_1", someSettlement);
```

**改变已有队伍的类型**用派生类的 `ConvertPartyTo...` 系列（内部走 `SetPartyComponent`），或者直接调用 `SetPartyComponent`：

```csharp
// 把一支普通队伍转成匪徒队
BanditPartyComponent.ConvertPartyToBanditParty(mobileParty, clan, hideout, isBossParty: false);

// 通用切换：旧组件会被 Finish，新组件会被 Create/Initialize
mobileParty.SetPartyComponent(new GarrisonPartyComponent(settlement, new GarrisonPartyComponent.InitializationArgs()));
```

**换队长**统一走基类的 `ChangePartyLeader`（`PartyComponent.cs:156`），它会在内部调用派生类覆写的 `OnChangePartyLeader`（`PartyComponent.cs:182`），并在队长真正变化时抛出 `CampaignEventDispatcher.OnPartyLeaderChanged`：

```csharp
mobileParty.PartyComponent.ChangePartyLeader(newLeader);
```

### 坑

- **`ChangePartyLeader` 会校验新队长是否已在名册里**。如果 `newLeader` 不是该队伍 `MemberRoster` 的成员，源码会 `Debug.FailedAssert` 并**直接返回、不换人**。换队长前先把角色加进名册。
- **基类的 `SetWagePaymentLimit` 会断言失败**（`PartyComponent.cs:66`）。默认实现只做 `Debug.FailedAssert("Invalid set wage payment limit function usage!")`。只有覆写了它的派生类（如领主队、驻军）才真正支持设置工资上限。
- **`Party` 与 `Banner` 是转发属性，依赖已回填的 `MobileParty`**。它们分别返回 `MobileParty.Party`（`PartyComponent.cs:25`）和 `MobileParty.Banner`（`PartyComponent.cs:83`）。在 `Create` / `Initialize` 之前访问会空引用——不要自己 `new` 完组件就立刻读这些。
- **不要绕过 `MobileParty.CreateParty` / `SetPartyComponent`**。只有这两条路径会调用 `Create` / `Initialize` 并触发 `UpdatePartyComponentFlags()`；手动给 `_partyComponent` 赋值不会更新 `IsCaravan` 等缓存标志。
- **`ClearCachedName`（`PartyComponent.cs:151`）默认是空实现**，名字变了但派生类没覆写它时，缓存不会失效。
- **自定义子类不会被内置标志位识别**。`UpdatePartyComponentFlags()` 只对内置类型做 `is` 判断，所以你的组件在 `party.IsCaravan` 之类查询里永远是 `false`，判断时请用自己的类型或 `is YourComponent`。

## 真实示例

**示例一：自建一类队伍。** 继承 `PartyComponent`，实现四个抽象成员，再提供一个静态工厂把组件交给 `MobileParty.CreateParty`。这就是源码里所有内置队伍遵循的同一套模式。

```csharp
using System.Collections.Generic;
using TaleWorlds.CampaignSystem;
using TaleWorlds.CampaignSystem.Party;
using TaleWorlds.CampaignSystem.Party.PartyComponents;
using TaleWorlds.CampaignSystem.Settlements;
using TaleWorlds.Core;
using TaleWorlds.Localization;

// 自建「自由兵团」队伍类型。若要挂靠家族、随家族旗帜，请改为继承 WarPartyComponent。
public class FreeCompanyComponent : PartyComponent
{
    private Hero _owner;
    private Settlement _home;
    private TextObject _name;

    public FreeCompanyComponent(Hero owner, Settlement home, TextObject name)
    {
        _owner = owner;
        _home = home;
        _name = name;
    }

    // 4 个抽象成员：不实现就编译不过
    public override Hero PartyOwner => _owner;
    public override TextObject Name => _name;
    public override Settlement HomeSettlement => _home;
    public override Banner GetDefaultComponentBanner() => _owner.Clan?.Banner;

    // 有默认实现的虚方法按需覆写
    public override bool AvoidHostileActions => false;
    public override Hero Leader => _owner;

    // 存档字段登记
    protected override void AutoGeneratedInstanceCollectObjects(List<object> collectedObjects)
    {
        base.AutoGeneratedInstanceCollectObjects(collectedObjects);
    }

    // 静态工厂：唯一正确的创建入口
    public static MobileParty Create(string stringId, Hero owner, Settlement home)
    {
        return MobileParty.CreateParty(stringId,
            new FreeCompanyComponent(owner, home, new TextObject("{=free_company}自由兵团")));
    }
}
```

**示例二：把已有队伍转成自定义类型。** 组件是可以中途替换的，旧组件会收到 `Finish`，新组件会收到 `Create` / `Initialize`：

```csharp
// 转换：复用已有的 SetPartyComponent 路径
mobileParty.SetPartyComponent(new FreeCompanyComponent(hero, settlement, new TextObject("自由兵团")));

// 之后的读取
PartyComponent c = mobileParty.PartyComponent;
if (c is FreeCompanyComponent freeCompany)
{
    Settlement home = freeCompany.HomeSettlement;
    Hero owner = freeCompany.PartyOwner;
}
```

**示例三：按类型读取全战役队伍。** 组件是判断队伍语义的稳定入口，比读 `IsXxx` 缓存标志更能覆盖自定义类型：

```csharp
foreach (MobileParty party in Campaign.Current.MobileParties)
{
    PartyComponent comp = party.PartyComponent;
    if (comp == null) continue;

    // 战争队伍统一挂在家族下
    if (comp is WarPartyComponent war)
    {
        Clan clan = war.Clan;
    }

    // 驻军支持设置工资上限，其它类型覆写前会断言失败
    if (comp is GarrisonPartyComponent)
    {
        comp.SetWagePaymentLimit(500);
    }
}
```

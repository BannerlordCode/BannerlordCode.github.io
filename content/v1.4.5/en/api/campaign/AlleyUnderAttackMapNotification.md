# AlleyUnderAttackMapNotification

**Namespace:** `TaleWorlds.CampaignSystem.MapNotificationTypes`
**Module:** `TaleWorlds.CampaignSystem`
**Type:** `public class AlleyUnderAttackMapNotification : InformationData`
**Base:** `InformationData`
**File:** `bin/TaleWorlds.CampaignSystem/TaleWorlds.CampaignSystem.MapNotificationTypes/AlleyUnderAttackMapNotification.cs`

## Overview

`AlleyUnderAttackMapNotification` is the map notice for "your alley is being raided". It is the leanest shape in this bucket: **one `Alley` reference plus a piece of text**, plus two hard-coded overrides (`TitleText` = `"{=emQQbbO9}Alley under attack!"`, `SoundEventPath` = `"event:/ui/notification/war_declared"`).

It is a pair with [AlleyLeaderDiedMapNotification](../AlleyLeaderDiedMapNotification): same domain, same single `Alley` field, **no expiry clock in either**. The UI behaviour differs though — this one's VM disappears when the player **enters that settlement**, while the leader-died one pops an inquiry box with a "learn more" button.

## Mental Model

Read it as **a temporary signpost pointing at one town**. Three things to know:

1. **It has no construction site.** In the whole 1.4.5 tree, `new AlleyUnderAttackMapNotification(` returns **0 hits** (positive control: `new AllianceOfferMapNotification(` returns 1 at `AllianceCampaignBehavior.cs:187`, so the probe itself works). The type is referenced in exactly three places — `SaveableCampaignTypeDefiner.cs:255`, `AutoGeneratedSaveManager.cs:1609` and `MapNotificationVM.cs:123` — **one save registration, one UI mapping, and zero business construction sites.**

   That means **a mod has to construct it itself.** Nothing in the shipped `TaleWorlds.CampaignSystem` assembly ever raises it.

2. **The clearing condition is "the player walked into the town", not "the fight ended".** `AlleyUnderAttackMapNotificationItemVM` (`Bannerlord.Source/bin/TaleWorlds.CampaignSystem.ViewModelCollection/TaleWorlds.CampaignSystem.ViewModelCollection.Map.MapNotificationTypes/AlleyUnderAttackMapNotificationItemVM.cs:16`) calls `CampaignEvents.SettlementEntered.AddNonSerializedListener(this, OnSettlementEnter)` in its constructor; `OnSettlementEnter` tests `party != null && party.IsMainParty && settlement == _alley.Settlement`, then `RemoveListeners(this)` and `ExecuteRemove()`. **The moment the main party sets foot in that settlement the notice is gone, whether or not the raid is over.**

3. **This type does not override `IsValid()`.** The base returns true, so the load-time `RemoveAll(t => t == null || !t.IsValid())` **cannot clear it**. The event listener above is its only self-cleaning route.

The second anchor is that **`Alley` is a live reference and the VM dereferences two hops**. `AlleyUnderAttackMapNotificationItemVM._onInspect` runs `GoToMapPosition(_alley.Settlement.Position)` — `_alley` then `.Settlement`, with no null check at either hop. A null `Alley` crashes when the player clicks inspect. Because `Alley` itself gets `Settlement` re-bound on load (see [Alley](../Alley)), both hops are safe in a normal save.

## Examples

Raise an alley-under-attack notice by hand (1.4.5 never does, so this is the only way):

```csharp
Alley playerAlley = Settlement.Find("Epicrotea").Alleys.First((Alley a) => a.State == AreaState.OccupiedByPlayer);
if (playerAlley != null)
{
    TextObject note = new TextObject("{=mykey5}Attackers have hit your alley in {TOWN}.");
    note.SetTextVariable("TOWN", playerAlley.Settlement.Name);
    Campaign.Current.CampaignInformationManager.NewMapNoticeAdded(new AlleyUnderAttackMapNotification(playerAlley, note));
    Debug.Print("notified for alley " + playerAlley.Tag + " in " + playerAlley.Settlement.Name, 0);
}
```

Sweep every settlement of a kingdom for owned alleys, guarding against a null `Settlement` on orphaned alleys:

```csharp
foreach (Settlement settlement in Kingdom.All[0].Settlements)
{
    foreach (Alley alley in settlement.Alleys)
    {
        if (alley.Owner != null && alley.Settlement != null && alley.State != AreaState.Empty)
        {
            Debug.Print(settlement.Name + " / " + alley.Tag + " state=" + alley.State, 0);
        }
    }
}
```

Ask whether an alley-under-attack notice is still pending:

```csharp
bool pending = Campaign.Current.CampaignInformationManager.InformationDataExists<AlleyUnderAttackMapNotification>(null);
Debug.Print("pending alley-under-attack notices = " + pending, 0);
```

## Risks and crash boundaries

- **No official construction site exists in 1.4.5.** `new AlleyUnderAttackMapNotification(` is 0 hits tree-wide (positive control: `new AllianceOfferMapNotification(` is 1 hit at `AllianceCampaignBehavior.cs:187`). It is referenced only by the save registration and the UI mapping. **Only a mod can raise it — do not assume the game posts it under some condition.**
- **The notice never expires on its own.** `IsValid()` is not overridden, so the base returns true and the load-time sweep cannot remove it. The sole self-cleaning path is the VM's `SettlementEntered` listener — **entering the town removes it even while the raid is still running.**
- **The VM dereferences two hops with no null check.** `_onInspect` runs `GoToMapPosition(_alley.Settlement.Position)`. A null `Alley` NREs on inspect; so does an orphaned alley whose `Settlement` is null.
- **`OnSettlementEnter` requires `party != null`.** If that event ever arrives with a null party, the notice does not clear and lingers in the map corner.
- **The VM must be registered.** The mapping is a hard-written table entry at `MapNotificationVM.cs:123`; an unregistered `InformationData` subclass is discarded without an error.
- **`TitleText` allocates per access.** Do not read it in a hot loop.
- **The sound is shared with war declarations.** `event:/ui/notification/war_declared` is a common event name, so an audio mod touching it affects every war-declared prompt.
- **The `SaveableProperty` id is 10.** Identical to [Alley](../Alley)'s `_owner` but numbered per type — do not reason across types.
- **Serialization.** `AutoGeneratedSaveManager.cs:1609` registers `AutoGeneratedStaticCollectObjectsAlleyUnderAttackMapNotification` and line 1611 registers `AutoGeneratedGetMemberValueAlley`. Adding a field means updating both plus `SaveableCampaignTypeDefiner.cs:255`.

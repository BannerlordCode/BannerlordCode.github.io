# AlleyUnderAttackMapNotification

**Namespace:** `TaleWorlds.CampaignSystem.MapNotificationTypes`
**Module:** `TaleWorlds.CampaignSystem`
**Type:** `public class AlleyUnderAttackMapNotification : InformationData`
**Base:** `InformationData`
**File:** `bin/TaleWorlds.CampaignSystem/TaleWorlds.CampaignSystem.MapNotificationTypes/AlleyUnderAttackMapNotification.cs`

## 概述

`AlleyUnderAttackMapNotification` 是「你的暗巷正在被攻打」那条地图通知。结构是本桶里最简的一档：**一个 `Alley` 引用 + 一段文本**，加上两个硬编码的 override（`TitleText` = `"{=emQQbbO9}Alley under attack!"`，`SoundEventPath` = `"event:/ui/notification/war_declared"`）。

它与 [AlleyLeaderDiedMapNotification](../AlleyLeaderDiedMapNotification) 是一对：**同样是暗巷告警、同样只有一个 `Alley` 字段、同样没有存档时钟**，但两者的 UI 行为不同——本类型的 VM 在玩家**走进该城镇**时自动消失，另一条则弹一个带「了解更多」按钮的询问框。

## 心智模型

把它当成**「一个指向具体城镇的临时路标」**。理解三件事就够：

1. **它没有构造点。** 1.4.5 全树 `new AlleyUnderAttackMapNotification(` 命中 **0**（阳性对照：同目录下的 `new AllianceOfferMapNotification(` 在 `AllianceCampaignBehavior.cs:187` 命中 1，说明探针本身有效）。它只在 `SaveableCampaignTypeDefiner.cs:255`、`AutoGeneratedSaveManager.cs:1609` 与 `MapNotificationVM.cs:123` 三处被引用——**存档注册与 UI 映射各一处，零个业务构造点**。

   这意味着：**要发出这条通知，mod 必须自己 `new` 它。** 官方战役系统（`TaleWorlds.CampaignSystem` 程序集里）从来不发。

2. **清除条件是「玩家进城」，不是「战斗结束」。** `AlleyUnderAttackMapNotificationItemVM`（`Bannerlord.Source/bin/TaleWorlds.CampaignSystem.ViewModelCollection/TaleWorlds.CampaignSystem.ViewModelCollection.Map.MapNotificationTypes/AlleyUnderAttackMapNotificationItemVM.cs:16`）在构造器里 `CampaignEvents.SettlementEntered.AddNonSerializedListener(this, OnSettlementEnter)`；`OnSettlementEnter` 判 `party != null && party.IsMainParty && settlement == _alley.Settlement` 后 `RemoveListeners(this)` + `ExecuteRemove()`。**只要玩家本部踏进那个城镇，不管袭击是否已经结束，通知就没了。**

3. **本类型不 override `IsValid()`。** 基类恒返回 true，所以读档时的 `RemoveAll(t => t == null || !t.IsValid())` **清不掉它**。它唯一的自清理路径就是上面那个事件。

第二个心智锚点是 **`Alley` 是活引用，而 VM 会解引用两层**。`AlleyUnderAttackMapNotificationItemVM._onInspect` 调 `GoToMapPosition(_alley.Settlement.Position)`——**先 `_alley` 再 `.Settlement`**，两跳都没有判空。传 null 的 `Alley` 会让玩家点「检视」时崩。而 `Alley` 本身已被读档时的 `Initialize` 重新绑定过 `Settlement`（见 [Alley](../Alley)），所以正常存档里这两跳是安全的。

## 真实示例

mod 里手动发一条暗巷遇袭通知（官方 1.4.5 不发，所以这里只能自己构造）：

```csharp
Alley playerAlley = Settlement.Find("Epicrotea").Alleys.First((Alley a) => a.State == AreaState.OccupiedByPlayer);
if (playerAlley != null)
{
    TextObject note = new TextObject("{=mykey5}Attackers have hit your alley in {TOWN}.");
    note.SetTextVariable("TOWN", playerAlley.Settlement.Name);
    Campaign.Current.CampaignInformationManager.NewMapNoticeAdded(new AlleyUnderAttackMapNotification(playerAlley, note));
    Debug.Print("notified for alley " + playerAlley.Tag + " in " + playerAlley.Settlement.Name, 0);
}
```

遍历所有城镇的暗巷，找出「有主人但可能有风险」的那些（判空 `Settlement` 以防存档孤儿）：

```csharp
foreach (Settlement settlement in Kingdom.All[0].Settlements)
{
    foreach (Alley alley in settlement.Alleys)
    {
        if (alley.Owner != null && alley.Settlement != null && !alley.State.Equals(AreaState.Empty))
        {
            Debug.Print(settlement.Name + " / " + alley.Tag + " state=" + alley.State, 0);
        }
    }
}
```

确认当前是否已有未处理的遇袭通知：

```csharp
bool pending = Campaign.Current.CampaignInformationManager.InformationDataExists<AlleyUnderAttackMapNotification>(null);
Debug.Print("pending alley-under-attack notices = " + pending, 0);
```

## 风险与边界

- **官方 1.4.5 没有任何构造点。** `new AlleyUnderAttackMapNotification(` 全树 0 命中（阳性对照 `new AllianceOfferMapNotification(` 在 `AllianceCampaignBehavior.cs:187` 命中 1）。它只被存档注册与 UI 映射引用。**要发它只能 mod 自己 `new`——别以为「游戏在某个条件下会自动发」。**
- **通知不自己过期。** 不 override `IsValid()`，基类恒 true。读档时的 `RemoveAll(t => t == null || !t.IsValid())` 清不掉它。唯一的自清理是 VM 的 `SettlementEntered` 监听——**玩家进城即消失，哪怕袭击还在继续。**
- **VM 会解引用两层且无判空。** `_onInspect` 走 `GoToMapPosition(_alley.Settlement.Position)`。传 null 的 `Alley` 会让玩家点检视时 NRE；`Alley.Settlement` 为 null 的孤儿暗巷同样。
- **`SettlementEntered` 判定要求 `party != null`。** 若该事件在某些路径上 party 为 null（`OnSettlementEnter` 的第一个参数），通知不会消失，只会更久地留在地图角落。
- **必须注册 VM。** 映射是 `MapNotificationVM.cs:123` 的硬写表项；自定义 `InformationData` 子类没登记会被静默丢弃。
- **`TitleText` 每次访问都分配。** 别在循环里反复读。
- **音效与宣战共用。** `event:/ui/notification/war_declared` 是共享事件名，做音效 mod 时会影响所有宣战类提示。
- **`SaveableProperty` id 是 10。** 与 [Alley](../Alley) 的 `_owner` 同号但不同类型——存档编号按类型独立，不要跨类型推断。
- **存档。** `AutoGeneratedSaveManager.cs:1609` 注册 `AutoGeneratedStaticCollectObjectsAlleyUnderAttackMapNotification`，`:1611` 注册 `AutoGeneratedGetMemberValueAlley`。加字段必须同步这两处与 `SaveableCampaignTypeDefiner.cs:255`。

## 怎么用

### 怎么拿到它

**它没有官方构造点，你只能自己 `new`。** 全树 `new AlleyUnderAttackMapNotification(` 命中 0（阳性对照：`new AllianceOfferMapNotification(` 在 `AllianceCampaignBehavior.cs:187` 命中 1，证明这个探针有效）。它只出现在两处：`MapNotificationVM.cs:123` 的 VM 注册，以及存档侧。

唯一的构造器是 `AlleyUnderAttackMapNotification(Alley, TextObject)`（`:34`），**没有单参重载**——构造器只做两件事：`base(description)`（`:35`）和 `Alley = alley`（`:37`）。没有触发时间、没有有效期。

### 典型用法

因为它不 override `IsValid()`，卡片**永不过期**：基类返回 true，而清理完全靠玩家点「检视」时 VM 的 `_onInspect` 调 `ExecuteRemove()`。无人值守场景（自动测试、后台批量存档）下发通知会永久堆积。

注册这一侧是 `MapNotificationVM.cs:123` 的 `_itemConstructors.Add(typeof(AlleyUnderAttackMapNotification), typeof(AlleyUnderAttackMapNotificationItemVM))`；`GetNotificationFromData`（`MapNotificationVM.cs:193`）用 `data.GetType()` 精确查表（`:195`/`:197`），命中才 `Activator.CreateInstance`（`:199`），**未命中返回 null，上游 `:178` 判空静默 return**。

所以这个类型的全部正确用法就是「造出来 + 立刻发出去」两条语句，别指望它自己过期帮你收拾：

```csharp
public static class AlleyUnderAttackEmitter
{
    public static void Emit(Alley alley)
    {
        TextObject note = new TextObject("{=aL0AlleyChk}Your alley {TAG} in {TOWN} was attacked.");
        note.SetTextVariable("TAG", alley.Tag);
        note.SetTextVariable("TOWN", alley.Settlement.Name);
        AlleyUnderAttackMapNotification notice = new AlleyUnderAttackMapNotification(alley, note);
        Campaign.Current.CampaignInformationManager.NewMapNoticeAdded(notice);
        Debug.Print("emitted, valid=" + notice.IsValid() + " (base always true)", 0);
    }
}
```

`Alley` 字段是 `SaveableProperty(10)`（`:11`-`:12`）——**id 跳到 10，1 到 9 已被旧版本占用**。你派生新通知类型时不要从 1 开始顺次排，先查同族已用的 id。

`SoundEventPath` 固定为 `"event:/ui/notification/war_declared"`（`:16`），`TitleText` 是硬编码的 `"{=emQQbbO9}Alley under attack!"`（`:14`）——**两者都不可覆写为实例字段，派生类要改只能 override**。

# CharacterObject

**Namespace:** `TaleWorlds.CampaignSystem`
**Module:** `TaleWorlds.CampaignSystem`
**Type:** `public sealed class CharacterObject : BasicCharacterObject, ICharacterData`
**Source:** `TaleWorlds.CampaignSystem/CharacterObject.cs`

## 概述

`CharacterObject` 是战役与战斗两层共用的**人物模板**。它继承 [BasicCharacterObject](../../core-extra/BasicCharacterObject)（那一层放体型、种族、名字、默认技能），在战役这一层补上四样东西：XML 里的职业与特质、模板化的升级链（`UpgradeTargets`）、战役侧的派生数据（tier、工资、conformity），以及一个可选的 `HeroObject` 指针。

`sealed`。1.4.6 的声明就是 `public sealed class CharacterObject : BasicCharacterObject, ICharacterData`，类里 `virtual` 与 `abstract` 的出现次数都是 0，唯一那个 `protected` 成员是 `protected override void AutoGeneratedInstanceCollectObjects(List<object>)`——覆盖基类的虚成员，sealed 之下拿不到任何派生收益。因此**没有可继承的扩展点**。想扩展只能用基类 `BasicCharacterObject` 的路线，或者走 [CampaignBehaviorBase](../CampaignBehaviorBase) 挂逻辑。

一个实例有两种身份，由 `HeroObject` 是否为 null 决定。**有** `HeroObject` 的是「给某个领主用的专属模板」，**没有**的是通用兵种模板（`IsRegular`）。这个分叉贯穿几乎所有成员：`HitPoints`、`Level`、`Age`、`Equipment`、`GetSkillValue`、`GetTraitLevel`、`GetPerkValue`、`Occupation`、`TroopWage` 都会在 `IsHero` 为真时转发到 `HeroObject`，否则走自己的字段。

## 心智模型

**读取路径有三条，优先级从高到低。** 一是 `CharacterObject.Find("villager_hunter")`，它只做一件事：`MBObjectManager.Instance.GetObject<CharacterObject>(idString)`，找不到返回 null，**没有 `Invalid` 哨兵值**。二是 `CharacterObject.FindFirst(predicate)` / `FindAll(predicate)`，两者都建立在 `CharacterObject.All` 之上。三是 `CharacterObject.All`，它就是 `Campaign.Current.Characters` 的转发——**战役没建立时转发本身就会抛**，主菜单阶段、读档界面里调这三个静态入口都是错的。

**转发规则是最需要记住的一条。** `IsHero` 的实现是 `this._heroObject != null`。一旦为真，下面这些全部改道：

- `HitPoints` 从 `MaxHitPoints()`（模板值）切成 `HeroObject.HitPoints`（活体值）
- `Level` 从基类模板等级切成 `HeroObject.Level`
- `Equipment` 从 `base.Equipment` 切成 `HeroObject.BattleEquipment`
- `GetSkillValue` / `GetTraitLevel` / `GetPerkValue` / `Age` / `RandomBattleEquipment` 同样改道

`GetPerkValue` 的转发是 `return this.IsHero && this.HeroObject.GetPerkValue(perk);`——**非英雄模板恒为 false**，不是「没解锁」，是压根不查。

**派生数据的计算时机**。`Tier` 不是字段，是 `Campaign.Current.Models.CharacterStatsModel.GetTier(this)` 现算的。`MaxHitPoints()` 同样是现算，走 `CharacterStatsModel.MaxHitpoints(this, false).ResultNumber`。要拿带解释的版本读 `MaxHitPointsExplanation`（第二个参数传 true 会带上 tooltip 文案）。`TroopWage` 在英雄模板上直接写成 `2 + Level * 2`，不查模型。

**`CreateFrom` 是复制模板的入口，但它复制的是「半份」。** 它用 `MBObjectManager.Instance.CreateObject<CharacterObject>()` 建新对象，然后把 `_originCharacter`、`_occupation`、`_persona`、特质容器、三件装备模板、`HiddenInEncyclopedia` 搬过去，最后调 `FillFrom(character)`。注意它**不搬** `UpgradeTargets` 和 `UpgradeRequiresItemFromCategory`——副本的升级链要自己填。副本的 `IsOriginalCharacter` 会变成 false（因为 `_originCharacter` 非 null）。

**真正的风险集中在 `IsOriginalCharacter` 这个反向判断上。** 它的实现是 `return this._originCharacter == null;`——**它问的是「我是不是没有来源」，不是「我是不是原始模板」**。`CreateFrom` 出来的东西和它的来源模板读出来都是 false。唯一为真的是那批由 `Deserialize` 直接构造、`_originCharacter` 停留在 null 的条目。想沿升级链往上回溯，用 `OriginalCharacter`，别用 `IsOriginalCharacter`。

**升级链的读法**。`UpgradeTargets` 是 `CharacterObject[]`，**长度可以为零**（默认初始化就是 `new CharacterObject[0]`）。`GetUpgradeXpCost(party, index)` 与 `GetUpgradeGoldCost(party, index)` 内部都会访问 `this.UpgradeTargets[index]`，`index` 越界或链为空时直接抛——没有边界检查。

## 真实示例

扫一遍战役里所有「远程但不下马」的模板，把 id、tier 与血量上限打出来。模板扫描走 `All`，不要用 `Find`，因为要遍历全部：

```csharp
public class TemplateAudit : CampaignBehaviorBase
{
    private readonly List<string> _report = new List<string>();

    public override void RegisterEvents()
    {
        CampaignEvents.DailyTickClanEvent += OnDailyTickClan;
    }

    public override void SyncData(IDataStore dataStore)
    {
        dataStore.SyncData("templateAuditReport", ref _report);
    }

    private void OnDailyTickClan(Clan clan)
    {
        if (clan == null)
        {
            return;
        }

        MBReadOnlyList<CharacterObject> templates = CharacterObject.All;
        for (int i = 0; i < templates.Count; i++)
        {
            CharacterObject template = templates[i];
            if (template.IsHero || !template.IsRanged || template.IsMounted)
            {
                continue;
            }

            _report.Add(template.StringId
                + " tier=" + template.Tier
                + " hp=" + template.MaxHitPoints()
                + " formation=" + template.GetFormationClass());
        }

        Debug.Print(_report.Count + " ranged foot templates in campaign", 0);
    }
}
```

单个模板的攻防与升级链读取。`Find` 未命中返回 null，必须判空；`UpgradeTargets` 长度为 0 时不要去索引它：

```csharp
CharacterObject template = CharacterObject.Find("villager_hunter");
if (template == null || template.IsHero)
{
    return;
}

template.GetSimulationAttackPower(out float attackPoints, out float defencePoints);
Debug.Print(template.StringId + " atk=" + attackPoints + " def=" + defencePoints, 0);

CharacterObject[] upgrades = template.UpgradeTargets;
for (int i = 0; i < upgrades.Length; i++)
{
    Debug.Print("upgrade[" + i + "]=" + upgrades[i].StringId
        + " reqCategory=" + template.UpgradeRequiresItemFromCategory, 0);
}
```

给某个领主造一份专属模板。注意 `CreateFrom` 不搬升级链，副本要用 `InitializeHeroCharacterOnAfterLoad` 之外的路径自己接：

```csharp
CharacterObject baseTemplate = CharacterObject.Find("villager_hunter");
if (baseTemplate != null)
{
    CharacterObject personalTemplate = CharacterObject.CreateFrom(baseTemplate);
    Debug.Print("copy of " + baseTemplate.StringId
        + " -> " + personalTemplate.StringId
        + " isOriginal=" + personalTemplate.IsOriginalCharacter
        + " origin=" + personalTemplate.OriginalCharacter, 0);
}
```

## 风险与边界

- **sealed，没有继承点**：1.4.6 声明为 `public sealed class`，类内零 `virtual`、零 `abstract`；唯一的 `protected` 成员是 `AutoGeneratedInstanceCollectObjects` 的 override，那是基类要求的实现而非扩展点。想换行为只能走 [CampaignBehaviorBase](../CampaignBehaviorBase) 与 `IDataStore`。
- **`Find` / `FindFirst` 未命中返回 null**：本类没有 `Invalid` 哨兵值，和 [Hero](../Hero) 一样。判空是硬要求。
- **`All` 会转发到 `Campaign.Current`**：战役未建立时这三个静态入口直接抛异常，不要在主菜单逻辑里调。
- **`IsOriginalCharacter` 名字有误导性**：它是 `_originCharacter == null`，不是「官方原始模板」。`CreateFrom` 的产物与它的来源读出来都是 false。
- **`HeroObject` 的 setter 是 internal**：mod 代码能读不能写。绑定关系由 `Deserialize` 与 `InitializeHeroCharacterOnAfterLoad` 维护。
- **`GetPerkValue` 对非英雄模板恒 false**：整个表达式是 `IsHero && ...`，短路掉了后半段。想看兵种的天赋，只能看特质（`GetTraitLevel`）。
- **`ClearAttributes` 对非英雄模板是空操作**：`if (this.IsHero)` 里面只有一行调用，没有 else 分支。
- **升级链没有边界检查**：`GetUpgradeGoldCost` 直接 `UpgradeTargets[index]`，链长 0 或 index 越界会抛。默认 `UpgradeTargets` 就是空数组。
- **`MaxHitPoints` 是方法不是属性**：写 `template.MaxHitPoints` 拿到的是方法组不是数值，容易在 lambda 里绑定出预期外的结果。
- **`GetFormationClass` 与 `Tier` 不是一回事**：前者读装备槽，后者查统计模型。用 `Tier` 推阵型会在跨兵种升级时出错。
- **数值成员全部现算**：`Tier`、`MaxHitPoints()`、`TroopWage`、`ConformityNeededToRecruitPrisoner` 每次访问都过一遍 `Campaign.Current.Models`。在每帧回调里反复读会有实打实的开销，先取到局部变量。
- **`CreateFrom` 是浅拷贝的一半**：`_characterTraits` 用 `new PropertyOwner<TraitObject>(character._characterTraits)` 复制，但 `UpgradeTargets` 与 `UpgradeRequiresItemFromCategory` 完全不搬。

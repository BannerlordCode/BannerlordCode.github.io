# campaign 桶：战役世界的数据与运行时

这个桶对应 `bannerlord-1.4.6/TaleWorlds.CampaignSystem/` 的**顶层命名空间** `TaleWorlds.CampaignSystem` 及其未被更长前缀规则截走的子命名空间（`.Settlements`、`.Party`、`.GameState`、`.Siege`、`.MapEvents`、`.GameMenus` 等）。源码目录顶层就有 135 个 `.cs`，加上这些子目录是战役层里体量最大的一块。mod 作者碰到它通常只有三个理由：读战役世界状态（领主、家族、王国、部队、聚落）、挂一段随战役存活的逻辑、或者在事件里改点什么。

**先搞清楚这个桶的另一半在哪儿。** `TaleWorlds.CampaignSystem` 的七个子命名空间被权威映射 `tools/_dir-map-canonical.json` 单独截走，落在 [campaign-ext](../campaign-ext/)：`.CampaignBehaviors`、`.ComponentInterfaces`、`.GameComponents`、`.Conversation`、`.Issues`、`.SandBox`、`.PartyBasedVisitables`。一句话分法：**本桶是战役的数据与运行时，campaign-ext 是战役的扩展契约与官方实现**——`CampaignBehaviorBase` 在这里，而 `CampaignBehaviorManager`、各 `*Model` 接口与 `Default*Model` 实现全在那边。命名空间 → 桶的完整规则见 [模块地图](../../architecture/module-map)。

## 已手写的类页（7 张）

- [Campaign](./Campaign) — 一局战役的运行时根对象：`Campaign.Current` 单例持有全部管理器、行为列表与实体集合，mod 从它拿到「这局游戏的一切」，也是时间控制与自定义组件挂载的入口。
- [CampaignGameStarter](./CampaignGameStarter) — 战役启动期的装配总线：mod 在 `OnGameStart` 里向它注册 Behavior、GameModel 与菜单，不经过它注册的行为 `Campaign` 根本看不到。
- [CampaignBehaviorBase](./CampaignBehaviorBase) — 战役逻辑的官方扩展点基类：订阅事件的代码写进 `RegisterEvents`，私有状态写进 `SyncData`。
- [CampaignEvents](./CampaignEvents) — 全局事件总线：数百个抛出方法与静态事件属性，覆盖 tick、会话、领主、家族、王国、部队、聚落、攻城、任务与菜单，替代「每 tick 遍历全表」的老写法。
- [IDataStore](./IDataStore) — Behavior 私有字段的存/读档通道：用 key 对齐存档字段，`IsSaving` / `IsLoading` 告诉你当前该读还是该写。
- [Hero](./Hero) — 领主实体：`CharacterStates` 状态机、属性与技能、家族与队伍、财富与关系，附带一整套可否决查询（`IsAllowed*` 系列）。
- [Settlement](./Settlement) — 定居点实体：城镇 / 城堡 / 村庄 / 据点的统一容器，承载驻军、围城侧、街区、库存与估值。

## 尚未撰写的部分

下面这些类型在 1.4.6 源码里确实存在（已按命名空间逐个核对过），但**本桶还没有它们的类页**，点不开。按命名空间分组列出，作为待写清单：

| 命名空间 | 待写类型 | mod 什么时候需要 |
| --- | --- | --- |
| `TaleWorlds.CampaignSystem` | `CharacterObject`、`Clan`、`Kingdom`、`Army`、`GameModels`、`CampaignEventReceiver`、`ICampaignBehavior` | 读家族与王国状态；替换计算模型（`GameModels`）时拿接口；自己实现 Behavior 时看它要满足什么 |
| `.Party`（含 `.PartyComponents`） | `MobileParty`、`PartyBase`、`PartyComponent`、`CustomPartyComponent`、`PartyTemplateObject`、`PartyScreenLogic` | 操作地图上的队伍；给队伍挂自定义组件；做队伍编成界面 |
| `.Settlements`（含 `.Buildings` / `.Locations` / `.Workshops`） | `Town`、`Village`、`Hideout`、`Alley`、`Fief`、`SettlementComponent`、`SettlementArea`、`RetirementSettlementComponent`、`ItemData`、`IMarketData`、`ISpottable`、`Building`、`BuildingType`、`Location`、`LocationComplex`、`Workshop`、`WorkshopType` | 城镇经济与建筑等级；给聚落挂组件；自定义市场数据与工作坊 |
| `.GameState` | `MapState`、`MapStateData`、`ClanState`、`KingdomState`、`CharacterDeveloperState`、`CraftingState`、`PartyState`、`QuestsState`、`InventoryState` | 想改「打开某个界面时游戏处于什么状态」时；自定义菜单需要的状态 |
| `.Siege` | `SiegeEvent`、`SiegeEventManager`、`PlayerSiege`、`BesiegerCamp`、`SiegeStrategy`、`DefaultSiegeStrategies`、`ISiegeEventSide` | 改攻城规则与胜负判定；给围城事件挂钩子 |
| `.MapEvents` | `MapEvent`、`MapEventSide` | 地图上遭遇战的触发与参与方 |
| `.GameMenus` | `GameMenu` | 自定义游戏菜单项 |

**一个归属歧义要说明白**：`AutoGeneratedSaveManager` 在 1.4.6 里不是一个类型，而是每个模块各有一份同名类——`TaleWorlds.CampaignSystem`、`TaleWorlds.ObjectSystem`、`TaleWorlds.MountAndBlade` 下各有一个。它不属于任何一个桶的独占清单，用的时候按你的 mod 所在的模块选，别直接照抄别处文档里的命名空间。

## 与邻桶的分工

- [campaign-ext](../campaign-ext/) — 行为管理器、各类 `*Model` 接口与默认实现、对话与议题系统，以及 `TaleWorlds.ObjectSystem` 的对象注册表。本桶的实体都从那边的 `MBObjectBase` 派生。
- [mission](../mission/) — 战役地图之外的那一场战斗。两侧靠 `CampaignEvents` 的任务开始 / 结束事件搭桥。
- [save-system](../save-system/) — `IDataStore` 的实际执行方，Behavior 私有字段最终由它落盘。

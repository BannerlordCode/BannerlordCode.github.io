# AllianceCampaignBehavior

**Namespace:** `TaleWorlds.CampaignSystem.CampaignBehaviors`
**Module:** `TaleWorlds.CampaignSystem`
**Type:** `public class AllianceCampaignBehavior : CampaignBehaviorBase, IAllianceCampaignBehavior`
**Base:** `CampaignBehaviorBase`
**File:** `bin/TaleWorlds.CampaignSystem/TaleWorlds.CampaignSystem.CampaignBehaviors/AllianceCampaignBehavior.cs`

## Overview

`AllianceCampaignBehavior` is the **sole authoritative state holder for realm alliances and call-to-war agreements**. Internally it has just two tables — `_alliances` (`List<Alliance>`) and `_callToWarAgreements` (`List<CallToWarAgreement>`) — both serialized through `SyncData`. On top of them it owns expiry checks (daily), the knock-on penalties for declaring war or peace, kingdom-destruction cleanup, and posting notifications or building decisions for the player.

It is the implementation behind `IAllianceCampaignBehavior`; [AcceptCallToWarAgreementDecision](../AcceptCallToWarAgreementDecision) obtains it through `Campaign.Current.GetCampaignBehavior<IAllianceCampaignBehavior>()` and calls `StartCallToWarAgreement` / `DenyCallToWarAgreement`.

## Mental Model

Read it as **a diplomacy ledger plus an expiry liquidator**. Four rules:

1. **`Kingdom.IsAllyWith` does not consult this table.** The type's own `IsAllyWithKingdom(kingdom1, kingdom2)` is an **independent judgement**: it rejects null / identical realms / any side `IsEliminated`, then `TryGetAlliance` against `_alliances`. **Do not conflate it with `Kingdom.IsAllyWith`** — [AcceptCallToWarAgreementDecision](../AcceptCallToWarAgreementDecision).CanMakeDecision uses `base.Kingdom.IsAllyWith(CallingKingdom)`, while `HasCalledToWar` uses `calledKingdom.IsAllyWith(callingKingdom)`.

2. **The two expiry clocks are independent.** `DailyTickClan` runs **per clan** but only does work for the **ruling clan**: first `clan.Aggressiveness -= 1f`, then `if (clan.Kingdom.RulingClan != clan) return;`. It then walks `kingdom.AlliedKingdoms` in reverse, first expiring `CallToWarAgreement.EndTime` via `EndCallToWarAgreement`, then expiring `Alliance.EndTime` via `EndAlliance`. **The two `EndTime` values are separate clocks; an expiring call to war does not dissolve the alliance.**

3. **`StartCallToWarAgreement` really declares war.** It is not bookkeeping: it ends by calling `DeclareWarAction.ApplyByCallToWarAgreement(calledKingdom, kingdomToCallToWarAgainst)`. Money moves per `isPlayerPaying`: `isPlayerPaying ? Hero.MainHero.ChangeHeroGold(-callToWarCost) : callingKingdom.CallToWarWallet -= callToWarCost`, then `calledKingdom.CallToWarWallet += callToWarCost`. **It is gated on `IsAllyWithKingdom && !calledKingdom.IsAtWarWith(...)` and silently skips everything when that fails.**

4. **`ApplyBrokenAlliancePenalty` branches on who is at fault.** The hard-coded constant is `BreakingAllianceRelationPenalty = -100`, but the recipient is `detail == DeclareWarAction.DeclareWarDetail.CausedByPlayerHostility ? Hero.MainHero : kingdom.Leader` — **a rupture caused by player hostility costs the player's relation; otherwise it costs the realm leader's.** The same `detail` value therefore changes the victim.

## How to use

**How to obtain it.** **Do not construct it.** It is a `CampaignBehaviorBase : IAllianceCampaignBehavior` added at campaign start; reach the live one with `Campaign.Current.GetCampaignBehavior<AllianceCampaignBehavior>()`.

```csharp
AllianceCampaignBehavior alliance = Campaign.Current.GetCampaignBehavior<AllianceCampaignBehavior>();
Kingdom mine  = Clan.PlayerClan.Kingdom;
Kingdom theirs = Kingdom.All.Find(k => k.StringId == "empire");
Debug.Print("allied = " + alliance.IsAllyWithKingdom(mine, theirs), 0);
```

**The most common pitfall.** **A failed precondition in `StartCallToWarAgreement` is silent.** When the alliance/peace check fails it returns without throwing, recording, or logging.

| `EndAlliance` | `public void EndAlliance(Kingdom kingdom1, Kingdom kingdom2)` | Dissolves the alliance; called by `DailyTickClan` on expiry, by a player decision, or by `OnKingdomDestroyed`. |
| `StartCallToWarAgreement` | `public void StartCallToWarAgreement(Kingdom callingKingdom, Kingdom calledKingdom, Kingdom kingdomToCallToWarAgainst, int callToWarCost, bool isPlayerPaying = false)` | The accept-the-call flow. | `HasCalledToWar` | `public bool HasCalledToWar(Kingdom callingKingdom, Kingdom calledKingdom)` | "Has A ever called B?" It additionally requires `calledKingdom.IsAllyWith(callingKingdom)` — **only allies can have a call-to-war record at all.** |
| `IsAtWarByCallToWarAgreement` | `public bool IsAtWarByCallToWarAgreement(Kingdom calledKingdom, Kingdom kingdomToCallToWarAgainst, out Kingdom callingKingdom)` | The reverse lookup: "is B at war with C because of A's call?", returning A through the `out`. It returns true on a hit; **on a miss `callingKingdom` is explicitly null, so callers must null-check.** |
| `GetKingdomsToCallToWarAgainst` | `public List<Kingdom> GetKingdomsToCallToWarAgainst(Kingdom callingKingdom, Kingdom calledKingdom)` | Lists every target A called B to attack. | `DenyCallToWarAgreement` | `public void DenyCallToWarAgreement(Kingdom callingKingdom, Kingdom calledKingdom)` | Refusing the call. **It does exactly one thing: call `ApplyDenyingCallToWarOfferPenalty` (a hard-coded `-50` relation penalty). It writes no table.** |
| `OnGameLoadFinished` | `private void OnGameLoadFinished()` | Version-compatibility hook: when `MBSaveLoad.IsUpdatingGameVersion` and the old version predates `v1.4.0.110693`, it pushes each `CallToWarAgreement.EndTime` back onto its alliance through `UpdateAllianceEndTime`. **A data-migration patch introduced with 1.4.0 and merely retained in 1.4.5.** |
| `OnKingdomDestroyed` | `private void OnKingdomDestroyed(Kingdom kingdom)` | Walks `_alliances` and calls `EndAlliance` for every record touching the destroyed realm. **Note it clears only `_alliances`, not `_callToWarAgreements`** — the latter are neutralised by the `IsEliminated` check inside `HasCalledToWar`. |

## Examples

Ask whether two realms are allied and when it lapses — using this behavior rather than `Kingdom.IsAllyWith`:

```csharp
AllianceCampaignBehavior behavior = Campaign.Current.GetCampaignBehavior<AllianceCampaignBehavior>();
Kingdom mine = Clan.PlayerClan.Kingdom;
Kingdom theirs = Kingdom.All.Find((Kingdom k) => k.StringId == "empire");
bool allied = behavior.IsAllyWithKingdom(mine, theirs);
Debug.Print("allied = " + allied + " end date = " + behavior.GetAllianceEndDate(mine, theirs).ToDays, 0);
```

List every target an ally called you to attack, and identify which wars came from a call:

```csharp
List<Kingdom> targets = behavior.GetKingdomsToCallToWarAgainst(theirs, mine);
foreach (Kingdom target in targets)
{
    Kingdom caller;
    bool byCallToWar = behavior.IsAtWarByCallToWarAgreement(mine, target, out caller);
    Debug.Print("at war with " + target.Name + " because of " + (caller == null ? "direct" : caller.Name), 0);
}
```

Form an alliance from a mod — minding that it auto-creates a call-to-war decision per wartime kingdom:

```csharp
Kingdom partner = Kingdom.All.Find((Kingdom k) => k.StringId == "vlandia");
if (partner != null && !behavior.IsAllyWithKingdom(Clan.PlayerClan.Kingdom, partner))
{
    behavior.StartAlliance(Clan.PlayerClan.Kingdom, partner);
    Debug.Print("allied with " + partner.Name + ", wars carried: " + behavior.GetKingdomsToCallToWarAgainst(Clan.PlayerClan.Kingdom, partner).Count, 0);
}
```

## Risks and crash boundaries

- **A failed precondition in `StartCallToWarAgreement` is silent.** When `IsAllyWithKingdom(...) && !calledKingdom.IsAtWarWith(...)` is false it **returns without throwing, recording, or declaring war**. Callers must test first.
- **`StartCallToWarAgreement` really declares war.** It ends in `DeclareWarAction.ApplyByCallToWarAgreement(calledKingdom, kingdomToCallToWarAgainst)` — **"record without declaring" is not reachable through this method.**
- **`IsAllyWithKingdom` blocks eliminated realms.** Either side reporting `IsEliminated` yields false even while a record persists in `_alliances`. **`OnKingdomDestroyed` also clears only `_alliances`; `_callToWarAgreements` is neutralised through this check.**
- **`IsAtWarByCallToWarAgreement`'s `out` can be null.** It explicitly assigns null on a miss. **Calling `.Name` on it without a guard NREs.**
- **`StartAlliance` has a side-effect chain.** Creating an alliance walks **every wartime kingdom of both sides** and calls `AddDecision(ProposeCallToWarAgreementDecision)` for each. **A mod creating an alliance by hand can generate dozens of decisions in one call.**
- **`StartAlliance` contains redundant code.** The same `if (stanceWith.GetDailyTributeToPay(proposerKingdom) != 0) stanceWith.SetDailyTributePaid(proposerKingdom, 0, 0);` block appears **twice**; the second pass can never fire because the first already zeroed it. Harmless, but do not copy it.
- **`DenyCallToWarAgreement` writes no table.** It only applies the `-50` relation penalty (`DenyingCallToWarRelationPenalty`). **After a refusal there is no record in `_callToWarAgreements`, so "who refused me" has no data source.**
- **Three relation penalties are hard-coded constants.** `BreakingAllianceRelationPenalty = -100`, `DenyingCallToWarRelationPenalty = -50`, `AcceptingCallToWarRelationBonus = +10`. **You cannot change them short of editing the behavior.**
- **`ApplyBrokenAlliancePenalty`'s victim depends on `detail`.** `detail == CausedByPlayerHostility ? Hero.MainHero : kingdom.Leader` — **the same rupture event can debit the player or the realm leader depending on the flag.**
- **`DailyTickClan` runs once per clan but only acts for the ruling clan.** `clan.Aggressiveness -= 1f` applies to all; after `clan.Kingdom.RulingClan != clan` it returns. **Performance-wise this is one of the heavier daily ticks in the tree**, iterating every realm's allies and all of their call records.
- **`OnGameLoadFinished` is a version-migration patch.** It only runs when `MBSaveLoad.IsUpdatingGameVersion && LastLoadedGameVersion < v1.4.0.110693`, **so a normal load of a current save never touches it.**
- **Both tables are serialized.** `_alliances` and `_callToWarAgreements` go through `SyncData`, with nested `Kingdom` references collected by each record's `AutoGeneratedInstanceCollectObjects`. **Changing the record shape means updating `AutoGeneratedSaveManager` too.**

## Cross-Version Notes

`bannerlord-1.4.5/Bannerlord.Source/bin/TaleWorlds.CampaignSystem/TaleWorlds.CampaignSystem.CampaignBehaviors/AllianceCampaignBehavior.cs` is 764 lines with **19 public methods** (`RegisterEvents` / `SyncData` plus 17 business methods), alongside the public nested `AllianceCampaignBehaviorTypeDefiner` and the internal `Alliance` / `CallToWarAgreement` record classes.

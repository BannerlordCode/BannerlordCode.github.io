## Overview

`IMBAnimation` is the managed-to-native bridge for the **clip database**: the table holding every animation clip the game knows, keyed both by numeric index and by id string. It is 80 lines, `internal`, and carries `[ScriptingInterfaceBase]` at `IMBAnimation.cs:5`, the marker the engine's loader reads before binding the C# side to the native implementation. Its 23 members each bind a named native symbol through `[EngineMethod("...", false, null, false)]` — `get_index_with_id` at `:11`, `get_animation_duration` at `:32`, `get_action_code_with_name` at `:65`, and so on.

Two distinct keying schemes coexist here, and confusing them is the source of most confusion here. `GetIndexWithID` (`:12`) resolves an **animation id** to a clip index; `GetActionCodeWithName` (`:66`) resolves an **action code name** such as `act.notched_debug_sword_idle` to a *different* numbering — the action-code table, counted by `GetNumActionCodes()` (`:72`). `GetNumAnimations()` (`:75`) counts a third space. The engine keeps all three apart.

Managed consumers are the public wrapper struct `MBAnimation` (a straight pass-through — `MBAnimation.cs:38` returns `MBAPI.IMBAnimation.GetActionType(actionIndex.Index)`), the wrapper `MBActionSet` (`MBActionSet.cs:92`-`:138` routes six members through here), and `ActionIndexCache` (`ActionIndexCache.cs:462`).

## Mental Model

Picture a **film archive with two catalogues in the same building**. One catalogue is indexed by film title (`get_index_with_id`), the other by the scene number an actor calls out (`get_action_code_with_name`). Asking the archive "how long is film 17" and asking it "how long is action 17" are different questions that can return different clips, because the numbers live in separate catalogues. `GetNumAnimations` counts one, `GetNumActionCodes` counts the other; they are not interchangeable bounds.

The consequence is that a numeric index taken from one catalogue and spent in the other is **not a crash** — it is a valid-looking number that silently returns the metadata of an unrelated clip. You get a plausible duration, a plausible blend period, no exception. That is the boundary worth internalising: this bridge has no type-level way to tell you which catalogue an `int` came from, so the discipline has to be yours.

The one place the wrappers *do* defend is the empty-string input. `MBAnimation.GetAnimationIndexWithName` checks `if (string.IsNullOrEmpty(animationName)) { return -1; }` (`MBAnimation.cs:31-34`) and `GetActionCodeWithName` returns `ActionIndexCache.act_none.Index` for an empty name (`MBAnimation.cs:125-128`). The pass-through accessors do not.

## How to use

**How to obtain it.** Not directly. The interface is `internal` (`IMBAnimation.cs:6`), its holder is `internal static IMBAnimation IMBAnimation;` on `MBAPI` (`MBAPI.cs:16`), and the assembly grants `InternalsVisibleTo` only to `TaleWorlds.MountAndBlade.AutoGenerated`, `TaleWorlds.MountAndBlade.Multiplayer` and `TaleWorlds.Generator.Bannerlord` (`TaleWorlds.MountAndBlade/Properties/AssemblyInfo.cs:8-10`). Go through the public `MBAnimation` struct, which is the wrapper the engine itself uses.

**A typical use.** A mod that wants to know how long a named clip runs and whether it blends into another, using the string overloads that a modder can actually reach:

```csharp
using TaleWorlds.MountAndBlade;

float seconds = MBAnimation.GetAnimationDuration("act.notched_debug_sword_idle");
float blendIn = MBAnimation.GetAnimationBlendInPeriod("act.notched_debug_sword_idle");
ActionIndexCache continuesInto = MBAnimation.GetAnimationBlendsWithActionIndex("act.notched_debug_sword_idle");
Debug.Print("clip runs " + seconds + "s, blend-in " + blendIn + "s, continues into " + continuesInto.GetName(), 0);
```

Prefetch a clip during a loading screen so the first agent that plays it does not stall, then count both catalogues to see the shape of the registry:

```csharp
using TaleWorlds.MountAndBlade;

Debug.Print("action codes = " + MBAnimation.GetNumActionCodes() + ", clips = " + MBAnimation.GetNumAnimations(), 0);
if (MBAnimation.IsAnyAnimationLoadingFromDisk())
{
    Debug.Print("clips still streaming in from disk", 0);
}
MBActionSet soldier = MBActionSet.GetActionSet("human_soldier");
MBAnimation.PrefetchAnimationClip(soldier, ActionIndexCache.Create("act.notched_debug_sword_idle"));
```

**What to watch out for.** The single most common mistake is passing an empty or misspelled name into one of the **string overloads of the pass-through accessors** — `GetAnimationDuration(string)` at `MBAnimation.cs:52`, `GetAnimationParameter1(string)` at `:63`, `GetAnimationDisplacementAtProgress(string, float)` at `:113`. Unlike `GetAnimationIndexWithName` and `GetActionCodeWithName`, these do **not** test for an empty string; they call `GetIndexWithID(name)` and spend the result immediately. The consequence is a duration or displacement read at an index that names no clip, returning a meaningless number that flows straight into whatever timing logic you wrote.

## Examples

Prove the two catalogues really are separate before you spend a numeric index:

```csharp
using TaleWorlds.MountAndBlade;

Debug.Print("action codes = " + MBAnimation.GetNumActionCodes(), 0);
Debug.Print("clips       = " + MBAnimation.GetNumAnimations(), 0);

// act.* resolves in the ACTION catalogue, not the clip catalogue
int actionCode = MBAnimation.GetActionCodeWithName("act.notched_debug_sword_idle");
Debug.Print("action code = " + actionCode, 0);
```

Look up a clip by its animation id, then confirm the round trip before relying on it:

```csharp
using TaleWorlds.MountAndBlade;

int clipIndex = MBAnimation.GetAnimationIndexWithName("act.notched_debug_sword_idle");
if (clipIndex >= 0)
{
    Debug.Print("clip " + clipIndex + " lasts " + MBAnimation.GetAnimationDuration(clipIndex) + "s", 0);
    Debug.Print("blends from action code " + MBAnimation.GetAnimationBlendsWithActionIndex(clipIndex), 0);
}
```

Resolve the action-set index to a real clip index with the catalogue bridge before reading per-skeleton metadata:

```csharp
using TaleWorlds.MountAndBlade;

MBActionSet actionSet = MBActionSet.GetActionSet("human_soldier");
if (!actionSet.IsValid)
{
    return;
}
ActionIndexCache action = ActionIndexCache.Create("act.notched_debug_sword_idle");
if (!MBActionSet.CheckActionAnimationClipExists(actionSet, in action))
{
    Debug.Print("this action set does not carry that clip", 0);
    return;
}
Vec3 rootMotion = MBActionSet.GetActionDisplacementVector(actionSet, in action);
Debug.Print("root motion " + rootMotion, 0);
```

## Risks and crash boundaries

- **A mod assembly cannot call this interface.** `internal` interface, `internal static MBAPI` field (`MBAPI.cs:16`), and `InternalsVisibleTo` limited to three TaleWorlds assemblies (`TaleWorlds.MountAndBlade/Properties/AssemblyInfo.cs:8-10`).
- **There is no exception channel and no catalogue tag.** Every index is a bare `int`. An index from `GetNumActionCodes` space spent in `GetNumAnimations` space returns real data about the wrong clip with no diagnostic.
- **The string pass-through overloads do not validate.** `MBAnimation.GetAnimationDuration(string)` (`MBAnimation.cs:52`), `GetAnimationParameter1/2/3(string)` (`:63`, `:74`, `:85`), `GetAnimationBlendInPeriod(string)` (`:91`) and `GetAnimationDisplacementAtProgress(string, float)` (`:113`) call `GetIndexWithID` directly. Only `GetAnimationIndexWithName` (`:31`) and `GetActionCodeWithName` (`:125`) test for an empty name.
- **`GetAnimationFlags` is unreachable from `MBAnimation`.** Only `MBActionSet.GetActionAnimationFlags` forwards it (`MBActionSet.cs:95`).
- **Four-argument `true` flags matter.** `AnimationIndexOfActionCode` (`:23`), `GetActionType` (`:29`), `GetAnimationDisplacementAtProgress` (`:62`) pass `true` in the fourth `EngineMethod` slot, marking them for a different marshalling path than the `false`-flagged members.
- **`GetDisplacementVector` and `GetActionAnimationDuration` need the action-set number.** Calling them with a clip index is a type error at compile time but a silent semantic error if you swap arguments for the same-sized `int` overloads that do exist.
- **Streaming is asynchronous.** Metadata read before `PrefetchAnimationClip` completes reflects the unloaded state; `IsAnyAnimationLoadingFromDisk` is the only signal that tells you so.
- **Not a save participant.** No `[Serializable]`, no sync surface.

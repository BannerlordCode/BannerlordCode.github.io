# AssembleEmpireQuestBehaviorTypeDefiner

**Namespace:** StoryMode.Quests.SecondPhase
**Module:** StoryMode
**Type:** `public class AssembleEmpireQuestBehaviorTypeDefiner : SaveableTypeDefiner`
**Base:** SaveableTypeDefiner
**Source:** SecondPhase/AssembleEmpireQuestBehavior.cs

## 概述

一个只有十几行的存档基础设施类，作用是把 `AssembleEmpireQuestBehavior` 内嵌的那个 `AssembleEmpireQuest` 登记到 Bannerlord 的存档序列化系统里。没有它，`AssembleEmpireQuest` 这个嵌套在行为类内部的类型就无法被写入或读出——存档系统需要每个可持久化类型都有一个显式的数字编号。

## 心智模型

Bannerlord 的存档不是反射式的，而是**由开发者手写 `SaveableTypeDefiner` 显式声明"哪个 CLR 类型对应哪个数字 id"**。这些 definer 由模块的 `MBSubModuleBase.SaveableTypes` 属性聚合，存档系统在保存/读取时按数字 id 匹配并反射调用类型里的 `AutoGeneratedGetMemberValue<字段名>` 与 `AutoGeneratedInstanceCollectObjects` 系列方法。

因此这类对象的生命周期是"整个模块生命周期"——它在游戏启动时被反射实例化一次，之后常驻。构造器里的 `base(1002000)` 就是它在这个全局表里的**主键**，`DefineClassTypes()` 里的 `AddClassDefinition(typeof(...), 1, null)` 是它**子表里的第二级 id**。

坑：这个类的两个数字都是**公开的存档 ABI 契约**。改 `1002000` 或改类内 id `1`，所有旧存档都会在加载时报"未知类型"而不是静默失败——好的一面是不会数据损坏，坏的一面是 mod 作者根本改不得。三个第二阶段/第三阶段的 definer 用的是完全不同的编号区间（1002000 / 1005000 / 16000），这说明每个剧情行为都各自划了一块号。

## 主要成员

- `AssembleEmpireQuestBehaviorTypeDefiner()`：无参构造，只调 `base(1002000)` 设定全局类型 id。这是唯一能修改"注册信息"的地方——但它同时也是最不该改的地方。
- `protected override void DefineClassTypes()`：调基类实现后，执行 `AddClassDefinition(typeof(AssembleEmpireQuestBehavior.AssembleEmpireQuest), 1, null)`。第二个参数是类内序号，第三个参数是可选的泛型版本号（这里为 `null`）。

## 使用示例

```csharp
// 存档类型定义器：全局 id 1002000，子表 id 1
public class AssembleEmpireQuestBehaviorTypeDefiner : SaveableTypeDefiner
{
    public AssembleEmpireQuestBehaviorTypeDefiner() : base(1002000)
    {
    }

    protected override void DefineClassTypes()
    {
        base.AddClassDefinition(typeof(AssembleEmpireQuestBehavior.AssembleEmpireQuest), 1, null);
    }
}
```

## 风险与边界

它没有任何运行时逻辑，因此**"删掉这个类"是唯一真正致命的改动**——旧存档里的 `AssembleEmpireQuest` 会变成无法解析的类型，加载直接失败。反过来，它的两个数字**永远不要动**：这两个常量是 Bannerlord 官方与所有第三方存档共享的命名空间。如果你的 mod 也定义了 `SaveableTypeDefiner`，必须选一个没人用过的全局 id，否则运行时会因为 id 冲突而出现难以定位的加载错误。它没有 `DefineEnumTypes` 调用，因为 `AssembleEmpireQuest` 里没有需要存档的枚举；对比 `RebuildPlayerClanQuestBehaviorTypeDefiner` 就同时定义了类和枚举，可以看出这是按需添加的。

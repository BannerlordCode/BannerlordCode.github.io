# v1.4.7 tree spec — which namespace lands in which `api/` bucket

**Scope.** This file explains the directory taxonomy for the new `content/v1.4.7/{zh,en}/api/**`
tree. It is a *human-readable* companion, not a second source of truth.

> **Authority.** `tools/_dir-map-canonical.json` (Boss-owned, 37 rules) is the authoritative
> machine-readable artifact. `tools/_v147_treespec.json` is a derived projection of it.
> `tools/_v147-dirprojection.json` is the measured result of simulating the resolution over the real
> `bannerlord-1.4.7` source. If this markdown and the canonical JSON ever disagree, **the canonical
> JSON wins** and this file is a bug. Do not add rules here.

---

## 1. Why the legacy 1.4.5 tree cannot be copied

From `tools/_dir-map-canonical.json`:

| Measurement | Value |
| --- | --- |
| Type names duplicated across two or more buckets | **2,199** |
| Namespaces split across buckets | **171 of 513** |
| Examples | `ScreenBase` → `campaign-ext` \| `gui`; `ScreenLayer` → `campaign-ext` \| `gui`; `MBObjectBase` → `campaign-ext` \| `core`; every `TaleWorlds.CampaignSystem` type → `campaign` \| `campaign-ext` |

Legacy page counts therefore say nothing about which bucket a namespace belongs to — counting
1.4.5 pages puts `TaleWorlds.InputSystem` and `TaleWorlds.DotNet` in `campaign-ext`. The taxonomy is
fixed by the subsystem table, not by page counts.

## 2. THE NORMALIZATION ALGORITHM (normative, 4 steps, in order)

A type's bucket is **not** a namespace-prefix lookup. It is four ordered steps. The full rationale,
the empirical evidence, and the failure modes are in `tools/_v147_nav-spec.md` §1.5; the short form:

| Step | Operation | Source |
| --- | --- | --- |
| **1** | **Hard skip** — namespace under an `excludeNamespaces` prefix (37 entries) or containing an `excludeSuffixes` segment (`CodeGenerator`, `AutoGenerated`). No page; counted separately. | `excludeNamespaces`, `excludeSuffixes` |
| **2** | **Longest-prefix-wins** over `rules[]`. Not first-match. | `rules[]` (37) |
| **3** | **Override by lowercased SIMPLE TYPE NAME.** `typeName.ToLower()` in `entryPointDirs[dir]` → that `dir` wins over step 2. **Runs after step 2.** | `entryPointDirs` |
| **4** | `defaultDir` = `core-extra`, and record the namespace in `unmapped`. | `defaultDir` |

**Step 3 is load-bearing and its failure is invisible in the rule text.** Applying it before step 2,
or skipping it, empties `mission/` and `core/` — the only symptom is that `api/mission/` and
`api/core/` 404. Verify empirically, do not trust the table.

### 2.1 Step 3 matches EXACT, case-sensitive simple type names — and only 7 of them

`entryPointDirs` is now a **flat map**, not a bucket→list map. Verified top-level keys: exactly 7
entries, all single-word camelCase.

| Simple type name | → bucket | Source namespace | What step 2 would have chosen |
| --- | --- | --- | --- |
| `Mission` | `mission` | `TaleWorlds.MountAndBlade` | `mission-ext` |
| `MissionState` | `mission` | `TaleWorlds.MountAndBlade` | `mission-ext` |
| `MissionBehavior` | `mission` | `TaleWorlds.MountAndBlade` | `mission-ext` |
| `Agent` | `mission` | `TaleWorlds.MountAndBlade` | `mission-ext` |
| `Formation` | `mission` | `TaleWorlds.MountAndBlade` | `mission-ext` |
| `MBSubModuleBase` | `core` | `TaleWorlds.MountAndBlade` | `mission-ext` |
| `Module` | `core` | `TaleWorlds.MountAndBlade` | `mission-ext` |

Every earlier pin was deleted as either a no-op or contradicting 1.4.5 precedent (`Hero`, `Campaign`,
`Game`, `ScreenManager`, `SaveManager`, `ViewModel`, `TextObject`, `MBDebug`, `GameModels`,
`GauntletLayer` — all already land where the pin wanted them, so the pin changed nothing).

**Matching is exact and case-sensitive.** A lowercased or substring match would wrongly capture
`MissionBehaviorDefinition`, `AgentState`, `Formation`, etc. into `mission/`.

**`ModuleManager` does not exist.** The artifact records `_noModuleManager`: a full-tree scan of
1.4.5 (8,583 `.cs`), 1.4.6, 1.4.7 and 1.5.3 found **zero** declarations of a type named
`ModuleManager`, and 1.4.5 has no `ModuleManager.md`. The `modulemanager/` bucket holds the *other*
8 types of `TaleWorlds.ModuleManager` (`DependedModule`, `Extensions`,
`IPlatformModuleExtension`, `ModuleCategory`, `ModuleHelper`, `ModuleInfo`, `ModuleType`,
`SubModuleInfo`). **Never synthesise a `ModuleManager` page or route.**

### 2.2 Source typo namespaces are excluded, not mapped

`sourceTypoNamespaces`: `Sandbox`, `Sandobx.GauntletUI.Missions`, `Storymode.Missions`,
`Sandbox.View.GameStates`. Ruling: **EXCLUDE** — mapping them to `sandbox`/`storymode` would invent
a namespace rule the source does not support. They are listed so the affected types are accounted
for rather than silently dropped.

### 2.3 Measured result of running the 4 steps over `bannerlord-1.4.7`

Independent simulation over 11,387 `.cs` files (separate from `tools/_v147_inventory.json`, used as
a cross-check): 12,148 unique top-level types → 4,382 dropped by the namespace gate, 30 by the suffix
gate, 7,736 live. **The authoritative page counts are the inventory's**, reproduced in §2.4.

## 4. Conflict adjudication

Rule 1 (R1) = reuse the existing 1.4.5 `api/` dir name. Rule 2 (R2) = genuinely new domains get a
lowercase module slug. Every place both could apply:

| Namespace | R2 would say | R1 says | **Winner** | Why |
| --- | --- | --- | --- | --- |
| `TaleWorlds.ObjectSystem` | `objectsystem` | 1.4.5 `api/campaign-ext/` already holds `MBObjectBase.md`, `MBObjectManager.md`, `MbObjectXmlInformation.md` (verified on disk) | **`campaign-ext`** | Keeps the object-identity types next to the campaign extension points that consume them. A new bucket would strand `MBObjectBase` away from `CampaignBehaviorBase`. |
| `TaleWorlds.Library` | `library` | 1.4.5 `api/core-extra/` already holds 536 pages incl. `ApplicationPlatform.md`, `ApplicationVersion.md`, `AssemblyLoader.md`, `AmbientInformation.md` | **`core-extra`** | Platform/runtime primitives; 1.4.5 already grouped them with `TaleWorlds.Core`. |
| `TaleWorlds.TwoDimension` | `twodimension` | 1.4.5 `api/gui/` holds the whole `Brush*` family (`Brush.md`, `BrushAnimation.md`, `BrushFactory.md`, `BrushLayer.md`, …) | **`gui`** | It *is* the 2D render layer Gauntlet draws through; splitting it breaks the read order screen → layer → brush. |
| `TaleWorlds.InputSystem` | `inputsystem` | 1.4.5 `api/system/` already holds it (`EmptyInputManager.md` verified on disk) | **`system`** | Existing URL; input plumbing sits with the `*Helper` types that consume it. |
| `TaleWorlds.ScreenSystem` | `screensystem` | 1.4.5 `api/gui/ScreenManager.md` exists in **both** `zh/` and `en/` (verified on disk) | **`gui`** | **Reversed** from an earlier note. A second bucket would break 1.4.5 ↔ 1.4.7 cross-version URL matching, which is exactly what `data/relkey_map.json` exists to preserve. Rule 1 wins. |
| `TaleWorlds.ActivitySystem` | `activitysystem` | no 1.4.5 dir | **`activitysystem`** | Genuinely new. 7 `.cs`, 6 live types: `Activity`, `ActivityManager`, `ActivityOutcome`, `ActivityTransition`, `TestActivityService`, +1. |
| `TaleWorlds.AchievementSystem` | `achievementsystem` | no 1.4.5 dir | **`achievementsystem`** | Genuinely new. 5 `.cs`, 4 live types: `Achievement`, `AchievementManager`, `TestAchievementService`, +1. |
| `TaleWorlds.ModuleManager` | `modulemanager` | no 1.4.5 dir | **`modulemanager`** | Genuinely new as a bucket: 9 types (`ModuleInfo`, `SubModuleInfo`, `ModuleCategory`, `ModuleType`, `SubModuleTags`, `Extensions`, `ModuleHelper`, +2). |
| `TaleWorlds.Network` | `network` | no 1.4.5 dir | **`network`** | Genuinely new: 38 live types (`NetworkMessage`, `MessageId`, `MessageInfo`, `MessageContractHandlerManager`, `ConnectionState`, `RESTClient`, …). Distinct from `TaleWorlds.MountAndBlade.Network` (multiplayer), caught by the longer prefix. |
| `TaleWorlds.NavigationSystem` | `navigationsystem` | no 1.4.5 dir | **`core-extra`** | **Cancelled.** No rule matches it and the only file in `bannerlord-1.4.7/TaleWorlds.NavigationSystem/` is an assembly-attribute stub with zero public types. The 1.4.5 tree has no `navigationsystem` dir either, so `core-extra` **is** the parity. |
| `SandBox*` + `StoryMode*` | `gameplay` | 1.4.5 `api/gameplay/` has 19 pages | **no `gameplay`** | **Two separate buckets now.** The 1.4.5 bucket is semantically mixed (holds `SandBox`/`StoryMode.*` types *and* bare `TaleWorlds.MountAndBlade` types like `AgentNavigator`, `MapAudioManager`, `OppositionData`, `DelayedAction`, `NameplateSize`), so no namespace rule can reproduce it. Do not invent a bucket to make the numbers line up. |

### 4.1 The collision rule that replaces 1.4.5's duplicate-bucket habit

> `If two namespaces mapping to the SAME dir export the same simple type name, the page file is
> <NamespaceLeaf>__<TypeName>.md (e.g. Campaign__IFaction.md). Never write two files for one type.`

Optional but recorded because 1.4.5 already uses this shape:
`campaign-ext/HideoutBattleEndState__StoryMode_Quests_TutorialPhase.md`.

## 5. Two places that look like bugs and are not

### 5.1 `TaleWorlds.Engine.GauntletUI` → `engine`, `TaleWorlds.GauntletUI` → `gui`

| Namespace | Bucket | Why |
| --- | --- | --- |
| `TaleWorlds.GauntletUI` (no `Engine` segment) | `gui` | 63 pages in 1.4.5 `gui/`. |
| `TaleWorlds.Engine.GauntletUI` | `engine` | 1.3.15 and 1.4.5 both keep the whole namespace in `engine/`. |

There is deliberately **no** `TaleWorlds.Engine.GauntletUI → gui` rule. The one type that would be
stranded, `GauntletLayer`, is pinned by `entryPointDirs.engine = ["gauntletlayer"]`. Verified against
source: `GauntletLayer` is declared in `TaleWorlds.Engine.GauntletUI`, and **no `GauntletLayer.md`
exists in any 1.4.5 `gui/` or `campaign-ext/` directory** — 1.4.5 `engine/` is where it lives.

### 5.2 `mission/` (3 types) and `core/` (2 types) beside huge siblings

Designed. Those five types were moved out of the bulk buckets by the step-3 override, so each still
has exactly one path. See `tools/_v147_nav-spec.md` §6.2 for the required index-page shape.

## 7. Parity gaps — imported from the artifact

The rows below are **imported verbatim** from `tools/_dir-map-canonical.json` → `parityGaps[]`
(4 objects, 73 pages total). They are greppable by `id` back to the artifact, and mirrored into
`tools/_v147_treespec.json` → `parityGaps`. The prose below each row is analysis; the facts are the
artifact's.

### 7.1 `no-gameplay-bucket` — 19 pages break

- **Breaks:** `1.4.5/gameplay/` (19 pages) → **no 1.4.7 counterpart**.
- **Artifact reason:** *"The 1.4.5 gameplay/ bucket is semantically mixed: it holds SandBox(4),
  StoryMode.\*(4) and bare TaleWorlds.MountAndBlade types (AgentNavigator, MapAudioManager,
  OppositionData, DelayedAction, NameplateSize, ...). No namespace rule can reproduce it."*
- **Decision:** *"accept the 19-URL break; do not invent a bucket to make numbers line up."*
- **Why acceptable:** a namespace→bucket map cannot express "these five specific classes, because I
  hand-picked them". Reproducing `gameplay/` would require a type-name allowlist, which is the
  1.4.5 anti-pattern the canonical map exists to kill. The 19 classes are still documented — in
  `sandbox/`, `storymode/` or `mission-ext/`, wherever their namespace actually points. Only the
  cross-version URL alignment is lost, and `data/relkey_map.json` degrades to a version-home link
  for those 19 pages.

### 7.2 `mission-bulk-to-mission-ext` — 52 pages move

- **Breaks:** 52 of 1.4.5's 78 `mission/` pages → `mission-ext/`.
- **Artifact reason:** *"That is a hand-picked modder entry list no namespace rule can reproduce;
  faking parity would mean shredding the ~850-page mission-ext bucket and hand-maintaining a list."*
- **Decision:** *"accept; mission/ stays a small intentional entry-class carve-out with bidirectional
  links to ../mission-ext/"*
- **Why acceptable:** `mission/` keeps the five classes a mod author actually subclasses —
  `Mission`, `MissionState`, `MissionBehavior`, `Agent`, `Formation`. Everything else that was filed
  there by hand (`ActionIndexCache`, `AutoGeneratedSaveManager`, `BannerTextureCreator`,
  `AgentHelper`, `GenericMissionObjective`, …) is a `TaleWorlds.MountAndBlade` type and now sits
  with its 1,669 siblings, where prefix search works. The bidirectional link on the bucket index
  page is what keeps the smaller bucket findable.

### 7.3 `game-to-core-extra` — 1 page moves

- **Breaks:** `1.4.5/core/Game.md` → `core-extra/Game.md`.
- **Artifact reason:** *"Game is namespace TaleWorlds.Core, which the prefix rules route to
  core-extra. 1.4.5 happens to keep a copy in core/ (and a duplicate in core-extra/)."*
- **Decision:** *"accept the 1-URL move; namespace consistency beats copying a legacy duplicate."*
- **Why acceptable:** this is the *same* duplicate the canonical map set out to remove. 1.4.5 shipped
  `Game` twice; 1.4.5 ships it once.

### 7.4 `missionstate-to-mission` — 1 URL breaks

- **Breaks:** `1.4.5 mission-ext/MissionState.md` (+ its `campaign-ext/` duplicate) →
  `mission/MissionState.md`.
- **Artifact reason:** *"1.4.5 has MissionState duplicated in campaign-ext/ and mission-ext/ and no
  mission/ copy. The entryPointDirs carve-out groups it with Mission/Agent/Formation for modders."*
- **Decision:** *"accept the 1-URL break for modder-facing grouping."*
- **Why acceptable:** verified on disk — 1.4.5 really does have it in two places and nowhere else.
  Moving it into the mod-entry bucket removes one of the two duplicate URLs that `legacyDuplicationEvidence`
  is trying to retire, and puts it next to `Mission` and `MissionState`'s real collaborators.

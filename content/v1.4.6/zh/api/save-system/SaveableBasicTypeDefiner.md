## 概述

这是存档系统的**内置基础定义器**：一个具体的、非抽象的 `SaveableTypeDefiner` 子类，构造时把自己的号段定在 `30000`。它不处理任何游戏业务类型，只做一件事——把「所有 mod 都会用到的语言级类型」一次性登记好，这样各个模块的 definer 就不用重复声明 `List<int>` 这种东西。

它注册的内容按六个覆写方法分成六类：

- **基础类型**（`DefineBasicTypes`）：21 个标量/值类型，`int` 编号 1 一直到 `string` 编号 21，每个都配了一个专用序列化器（`IntBasicTypeSerializer`、`StringSerializer` 等）。
- **类类型**（`DefineClassTypes`）：`object` = 0、`Tuple<,>` = 100、`PriorityQueue<,>` = 103、`MBReadOnlyDictionary<,>` = 105、`GenericComparer<>` = 106。后三个用 `AddClassDefinitionWithCustomFields` 显式声明了私有字段名，因为它们的字段是编译器/框架生成的、没法标 `[SaveableField]`。
- **结构体类型**（`DefineStructTypes`）：`Nullable<>` = 101、`KeyValuePair<,>` = 102、`ValueTuple<,>` = 107，同样是自定义字段版。
- **泛型结构体闭合**（`DefineGenericStructDefinitions`）：`KeyValuePair<string,string>` 等 6 个具体闭合类型。
- **泛型类闭合**（`DefineGenericClassDefinitions`）：`Tuple<string,int>`、`Tuple<bool,float>`、`GenericComparer<int>`、`GenericComparer<float>`。
- **容器**（`DefineContainerDefinitions`）：21 个基础类型的 `List<T>` / `Queue<T>` / `T[]`，加上 `List<KeyValuePair<...>>`、`List<Tuple<bool,float>>` 和 7 个 `Dictionary<,>` 组合。

一个值得注意的事实：**这个类在全树里没有任何显式引用**。它只出现在自己的文件里——引擎靠 `DefinitionContext.CollectTypes` 扫描程序集、`Activator.CreateInstance` 无参实例化来发现它，属于「自动被发现」的 definer。

## 心智模型

把它想成**存档类型表的地基**，而且是一块「只在启动时浇一次」的地基：

1. **它是 `saveBaseId = 30000` 的普通 definer。** 所有 `Add*` 里的编号都是相对号，最终全局编号是 `30000 + n`——`int` 实际是 30001、`string` 是 30021。所以你在自己的 definer 里写 `AddBasicTypeDefinition(typeof(MyId), 1, ...)` 用的是另一个号段，不会和它撞。
2. **「阶段」比「类」更重要。** 六个覆写方法对应 `FillWithCurrentTypes()` 的六个阶段（基础 → 类 → 结构体 → 泛型结构体 → 泛型类 → 容器）。引擎是「所有 definer 走完基础阶段，再全体进类阶段」，而不是「这个 definer 一口气走完」。泛型闭合必须排在容器之前，否则 `List<KeyValuePair<string,int>>` 的元素类型还没有定义。
3. **泛型是「两段式」。** `KeyValuePair<,>` 这类开放泛型先登记**定义**（`DefineStructTypes`），再用 `ConstructGenericStructDefinition` 登记**具体的闭合类型**（`DefineGenericStructDefinitions`）。容器又只能声明闭合类型（`typeof(List<int>)`），所以三层缺一不可：开放定义 → 闭合泛型 → 容器。
4. **自定义字段是给「改不动的类型」用的。** `Tuple<,>` 的字段是 `m_Item1`/`m_Item2`，`PriorityQueue<,>` 的是 `_baseHeap`。这些名字直接写死在注册表里，等于承认「存档格式跟着 BCL 的私有字段名走」。这也是跨版本最脆弱的地方。

## 怎么用

### 怎么拿到

你**不 new 它**，也**不要继承它**。它是引擎自动实例化的内置 definer。你只会间接使用它登记的结果：

```csharp
// 你自己的 definer 里，可以直接依赖 List<int> / Dictionary<string,int> 已经登记好了
public class MyModTypeDefiner : SaveableTypeDefiner
{
    public MyModTypeDefiner() : base(31000) { }

    protected override void DefineClassTypes()
    {
        // 字段类型是 List<int>，容器定义由 SaveableBasicTypeDefiner 提供，这里不用重复声明
        base.AddClassDefinition(typeof(MyLedger), 1, null);
    }
}
```

想确认某类是否已被登记，用上下文查询（编号是绝对号，`int` = 30001）：

```csharp
// 形状同 SandBox/Sandbox/AutoGeneratedSaveManager.cs:17 的用法
TypeDefinition typeDefinition =
    (TypeDefinition)definitionContext.TryGetTypeDefinition(new TypeSaveId(30001));
```

### 典型用法

当你的类型**不是**语言级基础类型，但你想让它像 `int` 一样按一个基本值落盘时，你要自己写基础类型定义——参考它的做法：

```csharp
// 官方范例：SaveableBasicTypeDefiner 自己的 DefineBasicTypes（节选）
protected internal override void DefineBasicTypes()
{
    base.AddBasicTypeDefinition(typeof(int), 1, new IntBasicTypeSerializer());
    base.AddBasicTypeDefinition(typeof(uint), 2, new UintBasicTypeSerializer());
    // ...
    base.AddBasicTypeDefinition(typeof(string), 21, new StringSerializer());
}

// mod 侧：把一个自定 id 结构体压成 ulong 存
public class MyModTypeDefiner : SaveableTypeDefiner
{
    public MyModTypeDefiner() : base(31000) { }

    protected override void DefineBasicTypes()
    {
        base.AddBasicTypeDefinition(typeof(MyModId), 1, new MyModIdBasicTypeSerializer());
    }
}
```

`TaleWorlds.ObjectSystem` 就是这么处理 `MBGUID` 的——它不走本类，而是在自己的 definer 里加一条基础类型定义。

### 坑

- **不要试图改它、继承它。** 它的号段 30000 是引擎占用的；再写一个 base(30000) 的 definer 会在 `Dictionary.Add` 上抛重复定义异常。
- **它登记的容器是「白名单」，不是「任意泛型」。** 只有源码里逐行列出的那些闭合类型可用。`List<MyLedger>` 不会被自动支持，你必须在自己的 `DefineContainerDefinitions` 里 `ConstructContainerDefinition(typeof(List<MyLedger>))`。
- **`Dictionary<,>` 只登记了 7 个组合**，而且 `List<T>` 只覆盖 21 个基础类型。常见误判是以为「泛型容器自动可用」。
- **自定义字段名是硬编码的 BCL 私有字段。** `Tuple<,>` 依赖 `m_Item1`/`m_Item2`、`PriorityQueue<,>` 依赖 `_baseHeap`。这些名字一旦在运行时版本间变化，旧档就读不回来——这是它最脆弱的假设。
- **`DefineContainerDefinitions` 用 `ConstructContainerDefinition`，重复时只打 `Debug.FailedAssert`**，不像 `Add*` 那样抛异常。所以重复声明容器会「静默地不正确」，排查时容易被忽略。

## 真实示例

三个阶段怎么配合，看这三行就够了——开放泛型 → 闭合泛型 → 容器：

```csharp
// ① 开放泛型定义（DefineStructTypes 内）
base.AddStructDefinitionWithCustomFields(typeof(KeyValuePair<,>), 102,
    new Tuple<string, short>[]
    {
        new Tuple<string, short>("key", 1),
        new Tuple<string, short>("value", 2)
    }, null);

// ② 闭合具体类型（DefineGenericStructDefinitions 内）
base.ConstructGenericStructDefinition(typeof(KeyValuePair<string, int>));

// ③ 容器里用它（DefineContainerDefinitions 内）
base.ConstructContainerDefinition(typeof(List<KeyValuePair<string, int>>));
```

基础类型注册的实际写法（编号是相对号，全局要加 30000）：

```csharp
protected internal override void DefineBasicTypes()
{
    base.AddBasicTypeDefinition(typeof(int), 1, new IntBasicTypeSerializer());
    base.AddBasicTypeDefinition(typeof(Vec3), 13, new Vec3BasicTypeSerializer());
    base.AddBasicTypeDefinition(typeof(string), 21, new StringSerializer());
}
```

mod 侧补一个自定义容器，把「白名单」扩到自己需要的类型：

```csharp
public class MyModTypeDefiner : SaveableTypeDefiner
{
    public MyModTypeDefiner() : base(31000) { }

    protected override void DefineContainerDefinitions()
    {
        base.ConstructContainerDefinition(typeof(List<MyLedgerRow>));
        base.ConstructContainerDefinition(typeof(Dictionary<string, MyLedgerRow>));
    }
}
```

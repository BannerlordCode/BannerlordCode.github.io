# SaveableStoryModeTypeDefiner

**Namespace:** StoryMode
**Module:** StoryMode
**Type:** `public class SaveableStoryModeTypeDefiner : SaveableTypeDefiner`
**Base:** `SaveableTypeDefiner`（TaleWorlds.SaveSystem）
**Source:** `bannerlord-1.5.3/StoryMode/SaveableStoryModeTypeDefiner.cs`

## 概述

Bannerlord 的存档是按**类型 id** 而不是按类名序列化的。`SaveableTypeDefiner` 就是那张「类型名 ↔ 数字」表，每个模块一份。这个类只负责 StoryMode 模块这一份：35 个类定义、5 个枚举定义、4 个容器定义。它是**纯声明**的——没有运行时逻辑，全部在 `Define*` 方法里以字面量形式列出。

## 心智模型

它继承 `SaveableTypeDefiner`，构造函数 `: base(320000)` 里的 **320000 是模块命名空间**，决定这个模块能用的 id 区间。`DefineClassTypes()` 里出现的数字就是模块内的类型序号，`DefineEnumTypes()` 同理，`DefineContainerDefinitions()` 则声明「哪些泛型容器需要参与序列化」。

基类上这些方法的修饰符是 `protected internal virtual`，所以**只能覆写、不能从外部调用**——引擎在建立存档上下文时会自行实例化并逐个调用。

它的生命周期是纯启动期：`SaveManager` 在建立存档上下文时遍历所有已加载模块的 definer，把它们的定义合并进全局表。之后读写档就只认数字。**所以任何一次读档，主线对象能不能恢复，完全取决于这里的 id 还在不在原位。**

id 的排布明显分两个时代：

- 早期小 id（1–18）：`CampaignStoryMode`、`StoryModeManager`、`MainStoryLine`、`TrainingField`、四个阶段、以及三个阴谋任务——这些从 1.x 就在。
- 大 id（580001–3780001）：所有具体的教学/主线任务类，每个三位到七位数，显然是后续版本追加时随手挑的。

**坑**：**id 一旦发布就冻结**。把某个类型的 id 改成别的、或者把两个类型对调，1.5.3 之前存档的主线进度就全乱——不是报错，是静默读出错误的阶段状态。追加新类型时只能挑一个没用过的数。

另外注意 `DisruptSupplyLinesConspiracyQuest` 用了 **17**，而 `DestroyRaidersConspiracyQuest` 是 15、`ConspiracyBaseOfOperationsDiscoveredConspiracyQuest` 是 14——**16 被跳过了**。不要以为 16 是「被删掉的类型」。

## 怎么用

### 怎么拿到它

`public class SaveableStoryModeTypeDefiner : SaveableTypeDefiner` 声明在 `bannerlord-1.5.3/StoryMode/SaveableStoryModeTypeDefiner.cs:17`，全文 108 行。

**引擎实例化它，你不要 new。** `SaveableTypeDefiner` 由模块加载器扫描并构造，构造函数唯一的动作是 `: base(320000)`（`:20`→`:21`）——这个数字是**模块的存档 id 区间基数**，整个 StoryMode 模块的类型 id 都从这个区间往外排。

六个 override 里有三个是空实现：`DefineStructTypes()`（`:64`）、`DefineInterfaceTypes()`（`:79`）、`DefineRootClassTypes()`（`:84`）、`DefineGenericClassDefinitions()`（`:89`）、`DefineGenericStructDefinitions()`（`:94`）。**只有 `DefineClassTypes`（`:26`）、`DefineEnumTypes`（`:69`）、`DefineContainerDefinitions`（`:99`）填了东西。**

`DefineClassTypes`（`:26`）共 33 条 `AddClassDefinition`，编号分两套：

| 编号段 | 条数 | 例子 | 行 |
| --- | --- | --- | --- |
| `1`–`18`（`base(320000)` 派生的连续号） | 18 | `CampaignStoryMode`=1、`StoryModeManager`=2、`MainStoryLine`=3、`TrainingField`=4、`VillagersInNeed`=18 | `:28`–`:60` |
| `580001`–`695001`（每个任务自带号段） | 15 | `SupportKingdomQuest`=680001、`ArzagosBannerPieceQuest`=681001、`FindHideoutTutorialQuest`=686001、`ConspiracyProgressQuest`=695001 | `:44`–`:59` |

注意 `1`–`18` 这段**跳过了 16**（`:43` 直接从 15 到 17）——16 号位空缺。

`DefineEnumTypes`（`:69`）五条：`MainStoryLineSide`=2001、`TutorialQuestPhase`=2002、三个同名不同类的 `HideoutBattleEndState`（`FindHideoutTutorialQuest`=686010、`IstianasBannerPieceQuest`=687010、`ArzagosBannerPieceQuest`=681010）。

`DefineContainerDefinitions`（`:99`）为 [TrainingField](../TrainingField) 声明了三种容器：`List<TrainingField>`、`Dictionary<string, TrainingField>`、`Dictionary<MBGUID, TrainingField>`（`:101`→`:103`）。

### 典型用法

```csharp
// 不要 new。只在需要确认「某个类型有没有存档定义」时查询：
// 存档系统读到未登记的类型会直接抛 SaveableTypeNotFoundException

// 复现 DefineClassTypes 的登记结果：这些类型在存档里能往返
Type[] saveable = new[]
{
    typeof(CampaignStoryMode),                 // id 1
    typeof(StoryModeManager),                  // id 2
    typeof(MainStoryLine),                     // id 3
    typeof(TrainingField),                     // id 4
    typeof(ThirdPhase),                       // id 11
    typeof(VillagersInNeed),                   // id 18
};
Debug.Print("已登记类型数=" + saveable.Length);

// 关键洞察：三个同名 HideoutBattleEndState 各有自己的枚举 id
// 681010 = ArzagosBannerPieceQuest 的
// 687010 = IstianasBannerPieceQuest 的
// 686010 = FindHideoutTutorialQuest 的
Debug.Print("三份同名字面量，互不通用");

// 存档往返验证：存一个带 MainStoryLine 的战役再读回
// 若 MainStoryLine(3) 未登记，读档会在 AutoGeneratedStaticCollectObjects 处失败
MainStoryLine line = StoryModeManager.Current.MainStoryLine;
Debug.Print("MainStoryLine 已登记，读档安全；ThirdPhase=" + (line.ThirdPhase != null));
```

### 最容易踩的坑

你在 mod 里新建一个 `QuestBase` 子类（比如自己写的主线任务），**不加 `AddClassDefinition` 它就存不进档**。症状是存档能写、读回来任务对象变 null 或存档系统抛异常——因为存档系统只认识 `DefineClassTypes`（`:26`）里那 33 个类型。另外本类的 id 基数是 `320000`（`:21`），它与另外三个行为专用的 `SaveableTypeDefiner`（`AssembleEmpireQuestBehaviorTypeDefiner` 的 `1002000`、`WeakenEmpireQuestBehaviorTypeDefiner` 的 `1005000`、`DefeatTheConspiracyQuestBehaviorTypeDefiner` 的 `16000`、`RebuildPlayerClanQuestBehaviorTypeDefiner` 的 `4140000`）**分散在不同号段**——各自是独立的 id 空间，不要以为整个模块的 id 都从 320000 起。

## 主要成员

- `SaveableStoryModeTypeDefiner()`：唯一构造函数，`base(320000)` 固定模块 id 区间。引擎自动实例化，不要自己 new。
- `protected override void DefineClassTypes()`：35 条 `AddClassDefinition`。按功能分组：
  - 基础设施（1–5）：`CampaignStoryMode` 1、`StoryModeManager` 2、`MainStoryLine` 3、`TrainingField` 4、`TrainingFieldEncounter` 5。
  - 教学（6–8）：`PurchaseItemTutorialQuestTask` 6、`RecruitTroopTutorialQuestTask` 7、`TutorialPhase` 8。
  - 阶段（9–11）：`FirstPhase` 9、`SecondPhase` 10、`ThirdPhase` 11。
  - 阴谋（12–17）：`ConspiracyQuestBase` 12、`ConspiracyQuestMapNotification` 13、`ConspiracyBaseOfOperationsDiscoveredConspiracyQuest` 14、`DestroyRaidersConspiracyQuest` 15、`DisruptSupplyLinesConspiracyQuest` 17。
  - 任务（18 与 580001–3780001）：`VillagersInNeed` 18，以及 `CreateKingdomQuest` 580001、`ArzagosBannerPieceQuest` 681001、`SupportKingdomQuest` 680001 等一长串。
- `protected override void DefineEnumTypes()`：5 条 `AddEnumDefinition`：`MainStoryLineSide` 2001、`TutorialQuestPhase` 2002，以及三个嵌套枚举 `FindHideoutTutorialQuest.HideoutBattleEndState` 686010、`IstianasBannerPieceQuest.HideoutBattleEndState` 687010、`ArzagosBannerPieceQuest.HideoutBattleEndState` 681010。
- `protected override void DefineContainerDefinitions()`：4 条 `ConstructContainerDefinition`：`List<TrainingField>`、`Dictionary<string, TrainingField>`、`Dictionary<MBGUID, TrainingField>`、`Dictionary<int, CampaignTime>`。练武场的三种索引形态和阴谋时间表都在这里。
- 其余覆写（`DefineStructTypes` / `DefineInterfaceTypes` / `DefineRootClassTypes` / `DefineGenericClassDefinitions` / `DefineGenericStructDefinitions`）**全部为空**。StoryMode 没有结构体、没有接口实现、没有泛型可序列化类型。

## 使用示例

```csharp
// 1) 调试存档：确认主线状态真的能被序列化回来（要同时满足三件事，见下方风险段）
CampaignStoryMode campaign = Game.Current.GameType as CampaignStoryMode;
MainStoryLine line = campaign.StoryMode.MainStoryLine;
Debug.Print(line.SecondPhase.ConspiracyStrength);   // [SaveableProperty(5)]，读档后仍在

// 2) 想给自己的存档类型也拿一个 id 区间：继承 SaveableTypeDefiner，换一个 saveBaseId
public class SaveableMyModTypeDefiner : SaveableTypeDefiner
{
    public SaveableMyModTypeDefiner()
        : base(330000)          // 不能和 StoryMode 的 320000 撞区
    {
    }

    protected internal override void DefineClassTypes()
    {
        AddClassDefinition(typeof(MyStoryProgress), 1, null);
    }

    protected internal override void DefineEnumTypes()
    {
        AddEnumDefinition(typeof(MyStoryProgressSide), 2001, null);
    }
}

// 3) 容器必须单独登记：泛型容器不在这张类表里，得走 DefineContainerDefinitions
protected internal override void DefineContainerDefinitions()
{
    ConstructContainerDefinition(typeof(List<MyStoryProgress>));
}
```

## 风险与边界

- **id 是永久契约**。改号等于让老存档读出错误的主线阶段，且不会有任何报错——阶段对象字段错位往往要到游戏逻辑跑偏时才被发现。
- **跳号不是错误**：`16` 缺失、`6/7` 是教学任务而非阶段，编号顺序和逻辑顺序不一致。只能照抄，不能重排。
- **只登记类型，不登记成员**：字段能不能存靠各类型的 `[SaveableField]` / `[SaveableProperty]` 标注，靠 `AutoGeneratedInstanceCollectObjects` 建立引用图。两套机制缺一不可，改字段时两边都要动。
- **容器定义是独立维度**：`Dictionary<int, CampaignTime>` 在容器表里，其它任何地方用到的泛型容器若没登记，读档时会被当成不可序列化直接丢。
- **泛型/接口/结构体三张表全空**：如果你给 StoryMode 引入接口多态字段，存档系统没有类型线索，必须改成具体类字段。

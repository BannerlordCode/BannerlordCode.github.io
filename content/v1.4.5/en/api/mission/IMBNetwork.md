## Mental Model

Think of it as **the postal counter at the back of the network**, with two distinct services on one counter. One service is a **broadcast**: everything you write between `begin_broadcast_module_event` and `end_broadcast_module_event` goes out to the session. The other is a **serialised value channel**: `write_int_to_packet`, `write_string_to_packet` and friends, with matching `read_*` calls that each take a `ref CompressionInfo.*` carrying back-compression state.

The rule that follows is the one you must respect to write anything that works: **a value written on the server must be read with the matching `read_*` on the client, in the same order, with the same compression descriptor.** The `CompressionInfo.Integer`, `.UnsignedInteger`, `.LongInteger`, `.UnsignedLongInteger` and `.Float` types are *per-value* delta descriptors (`IMBNetwork.cs:69`, `:72`, `:75`, `:78`, `:81`), not per-channel. They are threaded by `ref` so each read learns from the last one. Read the same stream in a different order and the deltas are applied to the wrong values — and nothing throws, because each individual `read` succeeded.

The second boundary is that **`EndBroadcastModuleEvent` has no matching "begin needs an argument" contract — it has three.** `(int broadcastFlags, int targetPlayer, bool isReliable)` (`:57`). The managed wrapper supplies the flags and turns an absent target into `-1` (`GameNetwork.cs:954`: `int targetPlayer2 = targetPlayer?.Index ?? (-1);`). So `-1` means broadcast-to-all, not "peer minus one".

## How to use

**How to obtain it.** Use `GameNetwork`. The interface is `internal` (`IMBNetwork.cs:6`) behind `internal static IMBNetwork IMBNetwork;` (`MBAPI.cs:30`), and `TaleWorlds.MountAndBlade/Properties/AssemblyInfo.cs:8-10` grants `InternalsVisibleTo` only to `TaleWorlds.MountAndBlade.AutoGenerated`, `TaleWorlds.MountAndBlade.Multiplayer` and `TaleWorlds.Generator.Bannerlord`.

**A typical use.** A mod that sends a one-off notice to the whole session wraps its payload in the balanced broadcast pair:

```csharp
using TaleWorlds.MountAndBlade;

GameNetwork.BeginBroadcastModuleEvent();
GameNetwork.WriteMessage(new MyModBroadcastMessage(payload));
GameNetwork.EndBroadcastModuleEvent(GameNetwork.EventBroadcastFlags.AddToMissionRecord);
Debug.Print("broadcast closed", 0);
```

**What to watch out for.** Assuming a `false` from `MultiplayerDisabled` or `IsDedicatedServer` tells you anything. **Neither bridge member is called.** `GameNetwork` hardcodes both as compile-time constants: `public static bool IsDedicatedServer => false;` (`GameNetwork.cs:353`) and `public static bool MultiplayerDisabled => false;` (`:355`). The consequence is that on this build path the properties are literally `false` regardless of the native answer — a mod that gates a dedicated-server code path on `GameNetwork.IsDedicatedServer` compiles, runs, and takes the wrong branch every time.

## Risks and crash boundaries

- **A mod assembly cannot call this interface.** `internal interface IMBNetwork` (`IMBNetwork.cs:6`), `internal static` field (`MBAPI.cs:30`), `InternalsVisibleTo` limited to three TaleWorlds assemblies (`TaleWorlds.MountAndBlade/Properties/AssemblyInfo.cs:8-10`).
- **Two members are dead on this path.** `GetMultiplayerDisabled` (`:8`) and `IsDedicatedServer` (`:11`) are never called; `GameNetwork.cs:353` and `:355` hardcode `false`. **Any dedicated-server branch gated on them is dead code that compiles cleanly.**
- **Read and write order must match exactly.** The `CompressionInfo.*` descriptors are threaded by `ref` per type (`:68`-`:99`) and carry delta state between successive calls. **Reordering applies deltas to the wrong values, and every individual read still returns `true`.**
- **The string channel does not follow the same shape.** `WriteStringToPacket(string value)` (`:107`) takes no descriptor and `ReadStringFromPacket(ref bool bufferReadValid)` (`:84`) uses a plain validity flag — a different contract from the numeric pairs.
- **Unbalanced framing corrupts the stream.** `BeginBroadcastModuleEvent` (`:53`) takes nothing while `EndBroadcastModuleEvent` (`:57`) takes three, so a mismatched close is not detectable by argument count. The same applies to the client pair (`:62`, `:65`).
- **`-1` is the broadcast-to-all sentinel.** `GameNetwork.cs:954` substitutes it for an absent target. Passing `-1` deliberately is broadcast; it is not a peer index.
- **Bulk reads are capacity-aware and can overrun.** `ReadByteArrayFromPacket` takes `bufferCapacity` (`:105`) and returns the count written; an undersized buffer overruns.
- **Tick rate and frame rate are independent.** `SetServerTickRate` (`:113`) and `SetServerFrameRate` (`:137`) are different dials, both taking `double`.
- **`GetAveragePacketLossRatio` is a ratio** (`:122`), not the per-peer percent on [`IMBPeer`](../IMBPeer) (`:39`). Do not multiply by 100.
- **`PrepareNewUdpSession` has no public caller.** Its only managed call site is `private static` (`GameNetwork.cs:743`, invoked at `:809`).
- **Not a save participant.** Session state; it is rebuilt when a mission loads.

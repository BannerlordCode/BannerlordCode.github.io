# 模块地图 / Module Map

> 一次给你三件事：**这个程序集是什么**、**它被归到哪个桶**、**你要不要关心它**。
> 分层心智模型见 [SDK 分层概览](../sdk-overview)；本页是查表用的。

## 为什么需要这张表

`bannerlord-1.5.3/` 根目录下有 **68 个 `TaleWorlds.*` 目录**，而文档侧的桶有 **19 个**。
两者不是一对一：一个程序集会被按职责拆进多个桶，一个桶也会聚起来自多个程序集。
不先讲清这条对应关系，你在两边找同一个类都会扑空。

对应关系不是拍脑袋定的：`tools/_dir-map-canonical.json` 的 **36 条命名空间规则 + 8 条
`entryPointDirs` 门面规则**，按「排除命名空间 → 前缀最长优先 → `entryPointDirs` 按类型名精确匹配 →
`defaultDir`」的顺序作用在 1.5.3 源码真实的 **621 个命名空间声明**上，得到 19 个桶
（`boardgames` 规则存在但无命名空间命中，故为空桶，未建目录）。一个类型只对应一个页面路径。

> **「归到哪个桶」≠「有页面」。** 19 个桶目前只有 8 个桶里各有一两篇手写类型页，
> 桶索引页（`api/<桶>/_index.md`）**尚未撰写**，所以站内没有任何链接指向桶目录。
> 每桶的已撰写 / 未撰写实况见本页末尾「各桶的文档覆盖实况」。

### 不面向 mod 的程序集

这些在源码树里存在，但它们要么是构建期代码生成器，要么是第三方/启动器组件。**它们在 1.5.3 源码里可见，
但游戏运行时不让 mod 依赖**。列出来是为了让你在源码树里看到它们时不困惑。

| 程序集 | 是什么 |
|---|---|
| `TaleWorlds.GauntletUI.CodeGenerator` / `.PrefabSystem` | 构建期 prefab 代码生成器与元数据 |
| `TaleWorlds.MountAndBlade.GauntletUI.CodeGenerator` / `.AutoGenerated.0/.1` | 同上，战斗界面部分 |
| `TaleWorlds.MountAndBlade.SaveSystem.CodeGenerator` | 存档字段代码生成器 |
| `TaleWorlds.MountAndBlade.Launcher` / `.Launcher.Library` / `.Launcher.Steam` | 启动器 |
| `TaleWorlds.MountAndBlade.SteamWorkshop` | 创意工坊 CLI 工具 |
| `TaleWorlds.Starter.Library` | 模组开发启动模板 |
| `TaleWorlds.MountAndBlade.DedicatedCustomServer.ClientHelper` | 专用服务器客户端辅助 |
| `TaleWorlds.ServiceDiscovery.Client` / `TaleWorlds.PSAI` / `TaleWorlds.PlatformService.*` / `TaleWorlds.PlayerServices` | 平台服务发现与在线服务胶水 |
| `GalaxyCSharp` | 脚本引擎桥 |
| `Newtonsoft.Json` / `jose-jwt` / `Steamworks.NET` / `StbSharp` / `System.Management` / `System.Numerics.Vectors` | 第三方依赖（含参考程序集 `mscorlib` 2 694 个文件、`netstandard`） |
| `ManagedStarter` | 托管层启动入口 |

> **关键区别：源码树 ≠ 运行时可引用。** `bannerlord-1.5.3/` 把启动器、代码生成器、第三方库和
> 参考程序集（`mscorlib`、`netstandard`）都收进来了。
> 但你编译 mod 时引用的是游戏安装目录下的 DLL，不是这棵源码树。
> 所以上表里「文档桶」为 `core-extra` 的那些第三方命名空间，
> **不等于**它们是 mod 的可用 API —— 它们在分桶时被噪声规则排除，落到 `defaultDir` 只是兜底。

**两个容易踩的坑**

1. `TaleWorlds.ObjectSystem` 落在 `campaign-ext`，**没有** `objectsystem` 桶。
2. `TaleWorlds.ScreenSystem` 并入 `gui`，**没有** `screensystem` 桶。

**第三个坑（1.5.3 才有的）**：`TaleWorlds.Diamond` 不在 `network` 桶，而在 `engine` 桶；
`TaleWorlds.Network` 自己独占 `network` 桶。两者名字相近，归属却不同。

噪声与非业务类型政策（v1.3.15）

噪声与非业务类型政策

「噪声」指不应作为精写 API 文档逐类展开的类型。它们不是没用，而是 mod 日常不该直接依赖、且桥回托管 API 即可。本页给出判定标准与回桥清单。

心智模型

噪声类型像「地基里的钢筋」：支撑整套系统，但 mod 开发者站在地板上工作，不需要逐根读懂。文档策略是「清单 + 短总则 + 回桥」，而不是假装成业务 API 深写（那会误导读者以为该直接调用）。

噪声的三类

1. AutoGenerated（自动生成）

  • 来源：*AutoGenerated.cs、MBGUID、AutoGeneratedSaveManager、序列化桩等由工具生成的类型。
  • mod 何时碰到：几乎不会直接 new；你只通过 [SaveableField] 标注自己的字段，生成器管序列化。
  • 回桥：自定义存档见 存档系统 与 SaveManager。

2. 第三方 / 平台库

  • 来源：Newtonsoft.Json、Steamworks（Steam API）、System.*、Epic 在线服务等。
  • mod 何时碰到：需要读写 JSON、调平台服务时；但这些有官方文档，不必本站重写。
  • 回桥：平台接入经 MBSubModuleBase 与官方 SDK；JSON 用 Newtonsoft 官方文档。

3. 平台 Provider / 引擎桥

  • 来源：IMB* 原生接口、各平台输入/渲染 provider。
  • mod 何时碰到：基本不直接碰；UI 走 Gauntlet，输入走引擎封装。
  • 回桥：GauntletLayer · engine 模块 · 原生互操作

判定规则（写文档时用）

  • 命名含 AutoGenerated / Provider / 明显第三方命名空间 → 噪声。
  • 类型只为序列化或平台桥接、无 mod 可调用业务语义 → 噪声。
  • 噪声进「清单 + 短总则页」，不写假长文，也不静默消失（H6 要求可定位）。

## 5. 🔴 三条盲区各自的 fail-closed 规则

### 规则 ① 链接可解析性

**盲区**：`classifyPage` 只数依赖节链接的**个数**（≥2），从不验证能否解析；
`anti-fabrication` 只扫 ```` ```csharp ```` 块。死链一路绿灯。

**规则**（`tools/_check_links_exist.mjs`）：

| 输入状态 | 退出码 | 实测输出 |
|---|---|---|
| 干净 | 0 | — |
| 发现死链 | 1 | `dead=186 / hrefs=140207 (0.13%)` |
| `--root` 指向不存在目录 | **2** | `UNREADABLE_ROOT: ... not a readable directory.` |
| 遍历到 0 个 `.md` | **2** | `EMPTY_UNIVERSE: 0 .md pages found under ...` |
| 读不到文件（`readFileSync` 失败） | **2** | `read_errors : 1` → `RESULT: FAIL-CLOSED` |

**接线前这把尺对上述三种坏输入返回 0 并打印 `RESULT: PASS`。** 那就是本轮要消灭的形态。

**读失败构造方式**（记录在此以便复核）：用 PowerShell `Set-Acl` 加
`FileSystemAccessRule($env:USERNAME,'Read','Deny')`。
`icacls //deny` 的参数被 MSYS 路径转换吃掉两次；自环符号链接在本机 `EPERM` 不可行
（Windows 未开开发者模式）。两次探针失败后换了构造路径，
**而不是把「构造不出来」写成「测不了」**。

### 规则 ② XML 语料缺失

**盲区**：`bannerlord-*` 六棵源码树的 `.xml` 全部 = 0
（1.3.0 / 1.3.15 / 1.4.5 / 1.4.6 / 1.4.7 / 1.5.3，加 `native-1.2.9` / `native-1.4.5` 亦为 0）。
`.cs` 分别 4,596 / 5,208 / 8,583 / 11,385 / 11,387 / 11,487。
**所以「字符串 id 断言不可验证」这条盲区的适用范围是全站六个版本，不是局部。**

**根判据（第一版错的，已按裁定换掉）**：
第一版问「这个版本的 XML 语料能不能验证字符串 id 断言」——
**那个问题的答案永远是「不能」，所以这根轴会恒定返回 1。**

**现行判据**：**页面上写了字符串 id 断言时，有没有把它显式标注为不可验证。**
这个问题的答案会随标注推进而变化：今天红，明天能绿，**而绿了是真的绿**。
`.xml = 0` 不再是判定输入，而是**标注义务的理由**，被打印出来。

| 状态 | 退出码 |
|---|---|
| 该标注的都标注了 | 0 |
| 有断言但未标注 | 1 |
| 源码根不存在 / 读不到 | 2（`UNMEASURED`） |

**阳性对照两个方向都有**（缺任一方向的校准不算校准）：
- 有断言 + 有标注 → `OK(0)`，0/2
- 有断言 + 无标注 → `FINDINGS(1)`，2/4
- 防过度报：语料有 `.xml` → 义务解除 → `OK(0)`

### 规则 ③ declare-site 假阴性

**盲区**：对泛型方法 / 接口成员 / BCL-Linq / 类型自身四类一律报「无声明者」，
实际是 **UNSUPPORTED**（这把尺看不见，不是东西不存在）。

**规则**：四类返回 `UNSUPPORTED`，每条附**判别依据的原文片段**，
且这些条目**不计入**「无声明者」分子。

| 类 | 真实命中（content/ 全站） |
|---|---|
| `TYPE_SELF` | 20,876 |
| `GENERIC_METHOD` | 3,968 |
| `INTERFACE_MEMBER` | 2,700 |
| `BCL_MEMBER` | 970 |

**「全判 UNSUPPORTED」这种无信息分类器被显式挡住**：
selftest 断言 3 个普通成员位必须留在 `CANDIDATE`。

⚠️ **`Agent.AgentVisualsData` 在 `content/` 实测 0 命中。**
按「没搜到 ≠ 不存在」，读作**「这一类在 content/ 里没出现」**，不是「这一类不存在」。
阳性对照用 fixture 语料（真写了 `interface IDataStore` / `struct AgentVisualsData` 两个 `.cs`），

### 为什么它与本轮第一个盲区同源

第一个盲区是：`tools/_check_links_exist.mjs` 存在于仓库、9/9 selftest 通过、**但不在 CI 里**。

而核盘时若只看「文件在不在」「跑没跑过」，两种情况都显示正常。

### 判据

**验接线是否真的接上，判据是 `git log -S "<关键串>" -- <file>` 返回非空，
不是「文件存在」，也不是「我本地跑过了」。**

**「本 commit 之前该接线只存在于工作区」** —— 否则下一个读 `git log` 的人

让读者当一个论证读，而不是两条规则。**第六条未被修改。**

## 11. 条件冲突时按「目的」裁决，不按「先写」

本会话发生了一次真实冲突，worker-18 把它挑明而没有埋掉：

```
条件 2 的目的 = 抓【意料之外的语义变化】
  那 7 行 = DEAD-LINK COUNTS 显示块，明写、不改任何判定、cmp 证实其余 5,579 字节逐字节相同
```

## 14. 一条我自己写进规范、且已经进了库的坏判据

**`grep -c "^-[^-]"` 会静默少算 markdown 的删除行。**

```
$ git diff -U0 -- content/v1.4.5/en/api/campaign-ext/AIState.md | grep -c "^-[^-]"
0                                  ← 错的
$ git diff -U0 -- <同上> | grep "^-" | grep -v "^---" | wc -l
3                                  ← 与 numstat 3/3 一致
```
**原因**：markdown 列表项被删掉后，diff 行以 `-- ` 开头（`-` 标记 + 内容自己的 `-`），第二个字符也是 `-`，被 `[^-]` 挡掉。

**worker-22 实测：13 个纯文件 numstat = 57 删，该命令报 4 —— 少算 93%。任何含列表的文档桶都会中招，而本仓库 39,000+ 页全是 markdown。**

**我自己的两个文件按正确写法重验**：
```
tools/_LINK-GATE-20261003.md   numstat 110/0   literal 0   corrected 0
tools/_INTEGRATION-GATES.md   （已入库，无 diff）
```
**结论没变，但是「碰巧对」不是「方法对」。** 如果那两个文件里有列表被改，我同样会漏算而不知道。

> **修正写法**：`git diff -U0 -- <f> | grep "^-" | grep -v "^---" | wc -l`

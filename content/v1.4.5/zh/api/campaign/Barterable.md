# Barterable

**Namespace:** `TaleWorlds.CampaignSystem.BarterSystem.Barterables`
**Module:** `TaleWorlds.CampaignSystem`
**Type:** `public abstract class Barterable`
**Base:** 无（直接继承 object）
**Source:** `bin/TaleWorlds.CampaignSystem/TaleWorlds.CampaignSystem.BarterSystem.Barterables/Barterable.cs`

## 概述

`Barterable` 是以物易物系统里**一件可被摆上交易台的货**的抽象形态。金币、物品、囚犯、领地——在 [BarterData](../BarterData) 眼里全是同一个形状：知道原始归属方（`OriginalOwner` / `OriginalParty`）、知道单价（`GetUnitValueForFaction`）、知道画什么图标（`GetVisualIdentifier`）、知道自己被接受了要做什么（`Apply`）。派生类只填这几个洞，共用逻辑全在这里。

它在体系里承担的是**「异质交易项的多态包装」**这一环。因为交易屏幕要在同一个列表里同时显示金币和一个陶罐，UI 侧不可能为每种货物写一套控件，所以抽象出统一的 `Name` / `GetVisualIdentifier` / `GetValueForFaction`。

四个必须先建立的直觉：

1. **它是「待确认」而不是「已生效」。** 构造器只记录归属方、把 `CurrentAmount` 设为 1、把 `Side` 设为 `Left`，不碰任何世界状态。真正的写入发生在 [BarterManager](../BarterManager) 在玩家确认后调用的 `Apply()` 里。
2. **`Side` 在构造器里写死为 `Left`。** 这是 `Barterable.BarterSide.Left`。右侧（对方能收的那一半）由管理器在组装时通过别的机制处理——**这个基类自身没有换边的公开 API**。看到 `Side` 永远是 `Left` 不是 bug。
3. **`CurrentAmount` 的 setter 会自动截断到 `MaxAmount`。** 写 100 进、读出来可能只有 1，因为基类 `MaxAmount => 1`。要卖多份物品必须 override `MaxAmount`。
4. **`SetIsOffered` 是级联的。** 它会把自己和 `_linkedBarterables` 里所有条目一起设成同一个值。所以联动条目一旦建立，双方的「是否被提供」永远同步，无法独立控制。

## 心智模型

把它当成**「交易台上的一个格位」**就对了。

- **典型调用顺序永远是「先 new → 再 Initialize → 最后 Apply」。** barter 行为（如 `ItemBarterBehavior`）在 `BarterData` 回调里 `new` 一个具体子类，然后 `args.AddBarterable<ItemBarterGroup>(barterable)`；后者内部调 `barterable.Initialize(group, isContextDependent)` 把分组和上下文标记写进去。交易确认后管理器才调 `Apply()`。**跳过 `Initialize` 就 `Apply` 能跑，但 `Group` 会是 null**，任何按分组找条目的逻辑都会漏掉它。
- **`GetValueForFaction` 是 `GetUnitValueForFaction` 乘 `CurrentAmount`。** 计价永远按派系走（`IFaction`），因为同一个物品对不同派系的估值不同。你要报价就用 `GetValueForFaction`，不要自己乘 `CurrentAmount`。
- **`IsCompatible` 默认返回 true，`CheckBarterLink` 默认是空实现。** 这两个都是给你做联动规则用的虚方法：前者决定「这两条能不能同时出现在交易里」，后者在建链时被调用做额外校验。
- **联动用 `AddBarterLink` 建，级联用 `SetIsOffered` 触发。** 典型场景是「买下装备的同时必须买下它的刀鞘」。建链是一次性的，运行期由 `SetIsOffered` 同步可见性。
- **`Apply()` 是纯抽象的，没有默认实现。** 它是唯一真正写世界状态的成员，必须走官方 Action，不要直接改数值。
- **`AutoGeneratedInstanceCollectObjects` 是空的。** 这意味着 barterable **不进存档**——交易会话本身不持久化。

## 真实示例

写一个最小可用的自定义 barterable（声望换金币）。`Apply` 用的是 1.4.5 里真实存在的 `GiveGoldAction.ApplyBetweenCharacters(Hero, Hero, int)`，`GetVisualIdentifier` 直接返回 null——官方 [GoldBarterable](../GoldBarterable)、[FiefBarterable](../FiefBarterable)、[DeclareWarBarterable](../DeclareWarBarterable) 都是这么做的：

```csharp
using TaleWorlds.CampaignSystem;
using TaleWorlds.CampaignSystem.Actions;
using TaleWorlds.CampaignSystem.BarterSystem.Barterables;
using TaleWorlds.Core.ImageIdentifiers;
using TaleWorlds.Localization;

public class RenownBarterable : Barterable
{
    private readonly Hero _payer;
    private readonly Hero _receiver;
    private readonly int _renownToBuy;
    private readonly int _maxRenown;

    public RenownBarterable(Hero payer, Hero receiver, int renownToBuy, int maxRenown)
        : base(payer, payer.PartyBelongedTo)
    {
        _payer = payer;
        _receiver = receiver;
        _renownToBuy = renownToBuy;
        _maxRenown = maxRenown;
        this.MaxAmount = maxRenown;
        this.CurrentAmount = 0;
    }

    public override string StringID => "renown_barterable";

    public override int MaxAmount => _maxRenown;

    public override TextObject Name => new TextObject("{=myRenownBarter}Renown");

    public override int GetUnitValueForFaction(IFaction faction)
    {
        // 官方 GoldBarterable 的形状：对自己一方是负价，对对方是正价
        if (faction == OriginalOwner?.Clan || faction == OriginalOwner?.MapFaction)
        {
            return -_renownToBuy;
        }

        if (faction == _receiver?.Clan || faction == _receiver?.MapFaction)
        {
            return _renownToBuy;
        }

        return 0;
    }

    public override ImageIdentifier GetVisualIdentifier()
    {
        return null;
    }

    public override void Apply()
    {
        if (_payer != null && _receiver != null)
        {
            GainRenownAction.Apply(_payer, CurrentAmount, doNotNotify: true);
        }
    }
}
```

> `GainRenownAction` 的 `ApplyInternal` 里有 `if (gainedRenown > 0f)` 的守卫，**负声望走这个 Action 会被静默忽略**。要「花费声望」必须直接走 `hero.Clan.AddRenown(-n)` 或自建 Action——这是 1.4.5 源码的真实边界，不是笔误。

把它挂进一笔交易，并给它建一条联动关系：

```csharp
using TaleWorlds.CampaignSystem;
using TaleWorlds.CampaignSystem.BarterSystem;
using TaleWorlds.CampaignSystem.BarterSystem.Barterables;

public static void RegisterRenownLine(BarterData barterData, Hero offerer, Hero other)
{
    if (barterData == null || offerer == null || other == null)
    {
        return;
    }

    RenownBarterable renown = new RenownBarterable(offerer, offerer.PartyBelongedTo, 250);
    barterData.AddBarterable<OtherBarterGroup>(renown);

    if (renown.Group == null)
    {
        Debug.Print("group not assigned, GetBarterGroups() does not contain OtherBarterGroup", 0);
        return;
    }

    renown.AddBarterLink(new RenownBarterable(other, other.PartyBelongedTo, 250));
    renown.SetIsOffered(true);
    Debug.Print("offered lines = " + barterData.GetOfferedBarterables().Count, 0);
}
```

按派系报价，读总价而不是自己乘数量：

```csharp
using TaleWorlds.CampaignSystem;

public static int QuoteForFaction(Barterable line, IFaction evaluating)
{
    if (line == null || evaluating == null)
    {
        return 0;
    }

    line.CurrentAmount = 1;
    return line.GetValueForFaction(evaluating);
}
```

检查一条联动的兼容性与分组归属（`IsCompatible` 与 `Group` 都是读点）：

```csharp
using TaleWorlds.CampaignSystem;
using TaleWorlds.CampaignSystem.BarterSystem;
using TaleWorlds.CampaignSystem.BarterSystem.Barterables;

public static bool IsOnOffer(BarterData barterData, Barterable line)
{
    if (barterData == null || line == null)
    {
        return false;
    }

    bool grouped = barterData.GetBarterGroup<OtherBarterGroup>() != null;
    bool offered = line.IsOffered;
    Debug.Print("grouped=" + grouped + " offered=" + offered + " linked=" + line.LinkedBarterables.Count, 0);
    return offered;
}
```

## 风险与边界

- **构造器不写世界状态。** `new` 一个 barterable 什么都不会发生，只填了几个字段。任何「new 完就生效」的写法都是错的，必须走 [BarterManager](../BarterManager) 的确认流程调 `Apply()`。
- **`CurrentAmount` 的截断是静默的。** setter 里 `if (_currentAmout > MaxAmount) _currentAmout = MaxAmount;`，写 100 读回 1 且无任何提示。要多份必须先 override `MaxAmount`。
- **`Group` 依赖 `Initialize`。** 直接 `new` 而不经 `AddBarterable<T>`，`Group` 就是 null；`BarterData.GetBarterGroup<T>()` 之类的按组查找会漏掉它。
- **`Side` 永远返回 `Left`。** 构造器写死且无公开换边入口。依赖 `Side` 做左右区分的代码要确认调用方是怎么绕过去的。
- **`AddBarterLink` 是单向且不去重。** 需要双向就自己再调一次对侧；重复调用会产生重复项，而 `SetIsOffered` 会把级联跑两遍。
- **`CheckBarterLink` 返回 void，不能拒绝建链。** 想阻止不兼容的两条共存，得在调用前先问 `IsCompatible`。基类的 `CheckBarterLink` 是空实现。
- **`GetEncyclopediaLink` 默认返回空串不是 null。** 判空要用 `string.IsNullOrEmpty`，直接 `== null` 永远不成立。
- **不进存档。** `AutoGeneratedInstanceCollectObjects` 是空实现，交易会话本身不持久化。
- **抽象类但六个官方子类都不 `sealed`。** mod 可以继承并改变语义而不破坏编译。

## 跨版本提示

`bannerlord-1.4.5/Bannerlord.Source/bin/TaleWorlds.CampaignSystem/TaleWorlds.CampaignSystem.BarterSystem.Barterables/Barterable.cs` 是 118 行原始源码，含一个 `BarterSide` 嵌套枚举（`Left` / `Right`）。跨版本比对时注意三点：`StringID` 的大写 D 拼写（不同族类里有 `StringId` 小写 d 的版本，别混）、`CurrentAmount` 的截断逻辑是否仍在 setter 里、以及 `Side` 是否仍写死 `Left`。这三点任何一处改动都会让现有 mod 静默行为漂移。

## 依赖关系

- 分派与容器：[BarterData](../BarterData) 的 `AddBarterable<T>` 调 `Initialize`，`GetOfferedBarterables` 读 `IsOffered`
- 分组标签：[BarterGroup](../BarterGroup) 是 `Group` 属性的类型，`AIDecisionWeight` 决定 AI 是否主动选这条
- 会话与结算：[BarterManager](../BarterManager) 组装 barterable、读取估值、并在玩家确认后调 `Apply()`
- 归属方：[Hero](../Hero) 提供 `OriginalOwner`，队伍侧是 [PartyBase](../PartyBase)；双方都可能为 null
- 计价上下文：`IFaction`（[FactionManager](../FactionManager) 所属的接口族）决定 `GetUnitValueForFaction` 的分支
- 图标与显示：`ImageIdentifier` 与 `TextObject` 来自 Core / Localization 层
- 桶首页：[campaign API 分区](../)

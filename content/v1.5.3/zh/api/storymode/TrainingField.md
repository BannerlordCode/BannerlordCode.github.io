# TrainingField

**Namespace:** StoryMode
**Module:** StoryMode
**Type:** `public class TrainingField : SettlementComponent`
**Base:** `SettlementComponent`（TaleWorlds.CampaignSystem.Settlements）
**Source:** `bannerlord-1.5.3/StoryMode/TrainingField.cs`

## 概述

`Settlement` 本身没有「这是个练武场」的概念——它的类型由 `SettlementComponent` 决定。`TrainingField` 就是主线教学那个 `tutorial_training_field` 聚落所挂的组件类型，它自己只有两块额外能力：从聚落 XML 的三个自定义属性里读出背景网格/裁剪位置/等待网格；以及让 `MapFaction` 返回 null（因为练武场不参与任何地图派系判定）。

## 心智模型

它的类型能被识别，**完全依赖 `CampaignStoryMode.BeforeRegisterTypes` 里的那行注册**：

```csharp
objectManager.RegisterType<TrainingField>("TrainingField", "TrainingFields", 1U, true, false);
```

没有这行，XML 里的 `tutorial_training_field` 反序列化时 MBObjectManager 不认识这个组件类型，加载直接失败。这行代码在 `StoryMode` 模块自己的 [CampaignStoryMode](../CampaignStoryMode) 里——所以**依赖链是硬编码在主线模块的**。

识别之后，[StoryMode.Extensions 命名空间的扩展方法](../Extensions) 提供两个便捷入口：`settlement.IsTrainingField()` 和 `settlement.TrainingField()`。真正的使用方是 `StoryModeCombatXpModel` 和 `StoryModeGenericXpModel`——它们在算经验时先问一句「现在是不是在练武场」，是就返回 0 经验。

**三个 XML 属性**是本类唯一的自定义数据来源：

| 属性 | 写入的基类字段 |
| --- | --- |
| `background_crop_position` | `BackgroundCropPosition`（float） |
| `background_mesh` | `BackgroundMeshName`（string） |
| `wait_mesh` | `WaitMeshName`（string） |

它们被 `TrainingFieldCampaignBehavior` 的菜单初始化处理器读取，用来给练武场菜单画正确的背景。

**坑**：

1. **`float.Parse` 用当前区域设置**：`Deserialize` 里 `float.Parse(node.Attributes["background_crop_position"].Value)` 没有指定 `CultureInfo.InvariantCulture`。**在用逗号作小数点的区域设置下，XML 里写 `1.5` 会抛异常**。这是本类最容易踩的国际化坑。
2. **`MapFaction` 返回 null 有副作用**：任何问「这个聚落属于哪个派系」的代码在练武场上会拿到 null。相关方必须判空，否则练武场里的逻辑会崩。
3. **`Deserialize` 不是属性映射，是手写解析**：往 `SettlementComponent` 基类加新 XML 属性时，本类**不会**自动读到，必须手写。
4. **没有自定义成员**：类里除了两个 override 什么都没有。想区分「教学练武场」和别的练武场，只能靠 `Settlement.StringId`。
5. **`RegisterType` 的 `1U` 是保存 id**。改它等于改存档格式。

## 主要成员

- `public override IFaction MapFaction { get; }`：**恒返回 null**。练武场不属于任何派系。
- `public override void Deserialize(MBObjectManager objectManager, XmlNode node)`：调 `base.Deserialize` 后，手工读三个 XML 属性。缺哪个属性就跳过（逐个 null 判断）。
- `internal static void AutoGeneratedStaticCollectObjectsTrainingField(object o, List<object> collectedObjects)`：自动生成的存档静态钩子。**不要手写调用**。
- `protected override void AutoGeneratedInstanceCollectObjects(List<object> collectedObjects)`：只调 `base`，本类没有需要进存档的对象引用。

## 使用示例

```csharp
// 1) 判断当前聚落是不是练武场（需要 using StoryMode.Extensions）
if (Settlement.CurrentSettlement != null && Settlement.CurrentSettlement.IsTrainingField())
{
    return new ExplainedNumber(0f, false, null);   // 练武场里不给经验
}

// 2) 取组件本体读它的网格配置（StoryModeCombatXpModel / StoryModeGenericXpModel 用的就是这个）
TrainingField field = Settlement.Find("tutorial_training_field").TrainingField();
if (field != null)
{
    Debug.Print("等待网格：" + field.WaitMeshName);
}

// 3) 给菜单画背景（TrainingFieldCampaignBehavior 里的真实写法）
[GameMenuInitializationHandler("training_field_menu")]
private static void OnMenuInit(MenuCallbackArgs args)
{
    TrainingField trainingField = Settlement.Find("tutorial_training_field").TrainingField();
    if (trainingField != null)
    {
        args.MenuContext.SetBackgroundMeshName(trainingField.WaitMeshName);
    }
}

// 4) 自己注册一种新的 SettlementComponent：漏了 RegisterType 就会读档失败
protected override void BeforeRegisterTypes(MBObjectManager objectManager)
{
    base.BeforeRegisterTypes(objectManager);
    objectManager.RegisterType<TrainingField>("TrainingField", "TrainingFields", 1U, true, false);
}
```

## 风险与边界

- **区域设置敏感的解析**：`float.Parse` 未指定不变文化。带小数点的 `background_crop_position` 在某些区域设置下会抛 `FormatException`。写 mod 改 XML 时用整数或确认区域设置。
- **`MapFaction` 为 null 的连锁影响**：任何遍历聚落问派系的代码都要判 null，否则在练武场场景里崩。
- **依赖注册顺序**：类型没在 `BeforeRegisterTypes` 登记 → 读档时反序列化失败，且是整个战役加载失败级别的问题。
- **`1U` 是存档 id**：改它等于改存档格式，老存档的练武场会解析不出组件。
- **`Deserialize` 手写、不自动扩展**：基类新增 XML 属性时本类不会跟进。
- **只识别类型不识别具体实例**：`IsTrainingField()` 对所有练武场聚落都为 true。要区分特定练武场得自己比 `StringId`。

# AlleyLeaderDiedMapNotification

**Namespace:** `TaleWorlds.CampaignSystem.MapNotificationTypes`
**Module:** `TaleWorlds.CampaignSystem`
**Type:** `public class AlleyLeaderDiedMapNotification : InformationData`
**Base:** `InformationData`
**File:** `bin/TaleWorlds.CampaignSystem/TaleWorlds.CampaignSystem.MapNotificationTypes/AlleyLeaderDiedMapNotification.cs`

## 概述

`AlleyLeaderDiedMapNotification` 是「你有条暗巷失去首领（或人手不足）」那条地图通知。数据面极简——`[SaveableProperty(10)] public Alley Alley` + 一段文本 + 两个硬编码 override（`TitleText` = `"{=6QoSHiWC}An alley without a leader"`，`SoundEventPath` = `"event:/ui/notification/death"`）。

**真正的内容在 VM 里，不在本类型里。** `AlleyLeaderDiedMapNotificationItemVM` 的 `_onInspect` 指向 `CreateAlleyLeaderDiedPopUp`，它构造一段说明文本、把 `Campaign.Current.Models.AlleyModel.DestroyAlleyAfterDaysWhenLeaderIsDeath.ToDays` 填进 `{DAYS}` 变量、再 `InformationManager.ShowInquiry` 弹出一个带「了解更多 / 关闭」双按钮的框。「了解更多」走 `NavigationHandler.OpenClan(_alley)` 跳氏族界面并 `ExecuteRemove()`；「关闭」只执行 `base.ExecuteRemove`。

## 心智模型

把它当成**「一个带倒计时的最后通牒入口」**——数据本身不带倒计时，倒计时由 `AlleyModel.DestroyAlleyAfterDaysWhenLeaderIsDeath` 在 UI 层现算。三条链路：

1. **它同样没有官方构造点。** 全树 `new AlleyLeaderDiedMapNotification(` 命中 **0**（阳性对照：`new AllianceOfferMapNotification(` 在 `AllianceCampaignBehavior.cs:187` 命中 1）。引用只有 `SaveableCampaignTypeDefiner.cs:254`、`AutoGeneratedSaveManager.cs:1605`、`MapNotificationVM.cs:122` 三处。**与 [AlleyUnderAttackMapNotification](../AlleyUnderAttackMapNotification) 一样，mod 必须自己 `new`。**

2. **它的自清理与「事件」无关，与「玩家点了按钮」有关。** `AlleyLeaderDiedMapNotificationItemVM` 的构造器**不订阅任何 `CampaignEvents`**——对比 `AlleyUnderAttackMapNotificationItemVM` 订阅 `SettlementEntered`。它只在 `OnFinalize`/按钮回调里 `ExecuteRemove()`。**所以它会一直挂在地图角落，直到玩家主动点它并做出选择。**

3. **`TitleText` 在数据类与 VM 里各出现一次，且是同一个 key。** 本类型第 14 行 `new TextObject("{=6QoSHiWC}An alley without a leader")`，VM 的 `CreateAlleyLeaderDiedPopUp` 里第 23 行又写了一遍同样的字面量。**改翻译 key 要同时改两处。**

第二个心智锚点是 **`{DAYS}` 与「真的会消失」是两件事**。弹窗告诉你「N 天后被放弃」，但这个数字来自 `AlleyModel.DestroyAlleyAfterDaysWhenLeaderIsDeath`，**本类型不存储它、也不检查它是否已到**。真正的清理由别处（`AlleyModel` 的日结逻辑）驱动。要判断一条暗巷还剩多少缓冲期，得读 `Campaign.Current.Models.AlleyModel.DestroyAlleyAfterDaysWhenLeaderIsDeath` 并自己跟踪时间，不能读这条通知。

第三个锚点是 **`NavigationHandler.OpenClan(_alley)` 有 null 双重保险，而别处没有。** `OpenClanScreenAfterAlleyLeaderDeath` 写的是 `if (base.NavigationHandler != null && _alley != null)`——VM 侧判了两个 null。而 `_onInspect` 直接赋值 `CreateAlleyLeaderDiedPopUp`，中间不解引用 `_alley`。**`CreateAlleyLeaderDiedPopUp` 本身不碰 `_alley`**，只在后续的 affirmative 回调里用——所以 null `Alley` 会让弹窗照常弹出，点「了解更多」时静默无反应（因为条件不成立），**不会崩，但玩家会觉得按钮失灵**。

## 真实示例

mod 里手动发一条暗巷失去首领的通知（官方 1.4.5 不发）：

```csharp
Alley orphan = Settlement.Find("Epicrotea").Alleys.First((Alley a) => a.State == AreaState.OccupiedByPlayer);
if (orphan != null)
{
    TextObject note = new TextObject("{=mykey6}Your alley in {TOWN} has lost its leader.");
    note.SetTextVariable("TOWN", orphan.Settlement.Name);
    Campaign.Current.CampaignInformationManager.NewMapNoticeAdded(new AlleyLeaderDiedMapNotification(orphan, note));
    Debug.Print("notice raised, abandon deadline = " + Campaign.Current.Models.AlleyModel.DestroyAlleyAfterDaysWhenLeaderIsDeath.ToDays + " days", 0);
}
```

遍历玩家所有暗巷，找出「有主但可能因缺人而濒危」的那些：

```csharp
foreach (Alley alley in Settlement.Find("Epicrotea").Alleys)
{
    if (alley.Owner == Hero.MainHero && alley.Settlement != null)
    {
        int troops = Campaign.Current.Models.AlleyModel.GetTroopsOfAlleyForBattleMission(alley).TotalManCount;
        Debug.Print(alley.Tag + " troops=" + troops + " state=" + alley.State, 0);
    }
}
```

确认当前是否已有未处理的失去首领通知：

```csharp
bool pending = Campaign.Current.CampaignInformationManager.InformationDataExists<AlleyLeaderDiedMapNotification>(null);
Debug.Print("pending alley-leader-died notices = " + pending, 0);
```

## 风险与边界

- **官方 1.4.5 没有任何构造点。** `new AlleyLeaderDiedMapNotification(` 全树 0 命中（阳性对照 `new AllianceOfferMapNotification(` 在 `AllianceCampaignBehavior.cs:187` 命中 1）。只被存档注册与 UI 映射引用。**只能 mod 自己 `new`。**
- **通知不自己过期，也不订阅任何事件。** 不 override `IsValid()`（基类恒 true，读档时的 `RemoveAll` 清不掉），VM 构造器里**没有任何 `CampaignEvents` 订阅**。它一直挂到玩家点它为止——**这与 [AlleyUnderAttackMapNotification](../AlleyUnderAttackMapNotification) 的「进城即删」是两种截然不同的清理策略。**
- **`{DAYS}` 不是承诺，是常量。** 倒计时来自 `AlleyModel.DestroyAlleyAfterDaysWhenLeaderIsDeath`，本类型既不存也不校验它是否已到。**判断暗巷是否已被放弃要去查 `Alley.Owner`，不能查这条通知。**
- **null `Alley` 会让「了解更多」静默失灵。** `OpenClanScreenAfterAlleyLeaderDeath` 判了 `NavigationHandler != null && _alley != null`，条件不成立时**什么都不做、不报错**——弹窗照常弹出、照常可关，但「了解更多」点了没反应。
- **翻译 key 写了两遍。** `{=6QoSHiWC}` 在数据类第 14 行与 VM 第 23 行各出现一次。**改一处不改另一处，UI 会出现同标题两种语言的混搭。**
- **必须注册 VM。** 映射是 `MapNotificationVM.cs:122` 的硬写表项；未登记的自定义 `InformationData` 子类被静默丢弃。
- **`TitleText` 每次访问都分配。** 别在循环里反复读。
- **存档。** `AutoGeneratedSaveManager.cs:1605` 注册收集委托、`:1607` 注册 `AutoGeneratedGetMemberValueAlley`；`SaveableCampaignTypeDefiner.cs:254` 是 `AddClassDefinition(typeof(AlleyLeaderDiedMapNotification), 305)`。加字段必须三处同步。
- **`SaveableProperty` id 是 10。** 与 [Alley](../Alley) 的 `_owner` 与 [AlleyUnderAttackMapNotification](../AlleyUnderAttackMapNotification) 同号，但存档编号按类型独立。

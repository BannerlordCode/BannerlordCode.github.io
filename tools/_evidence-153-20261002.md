### 2.1 识别方法（两道独立判据）

**主判据 = 写作者溯源白名单。** 一页只有落在下列白名单内才算手写，白名单外**一律判生成**。溯源问的是「谁写的」，不是「长得像不像」。

**交叉验证 = 6 个模式信号并集**：
- `skeleton-self-description`：`自动生成的初始占位段落` / `自动生成类参考` / `Auto-generated stub for` / `Auto-generated initial placeholder` / `Auto-generated index of` / `Every leaf page is a stub`
- `policy-boilerplate`：`阅读时先通过属性了解状态` / `是 TaleWorlds.X 下的公开类型` / `null; // 替换` / `SomeValue` / `service = ...` / `从实际子系统 API`
- `generator-block`：`## 模块心智模型` / `<!-- BEGIN SECTION INDEX -->` / `<!-- BEGIN CARVE-OUT NOTE -->`

**一致性结果**：
- 13 663 个生成页**全部带至少一个信号**，检测盲区 **0**
- 37 个手写页中 4 页带 `generator-block` 信号 → **逐页核实为非污染**（见 §2.3）

那 10 页差额正是**没有 marker 的桶索引页** —— `en/api/<bucket>/_index.md` 写的是 `Auto-generated index of 706 public Campaign types... Every leaf page is a stub`，只匹配 `Auto-generated stub for` 会漏判。**「看起来像手写」不等于手写，反之亦然。**

## 8. 已知限制

- **本包所有数字都是 markdown 层 / data 层的。** `audit-links` 的 `RESOLVE_OK_FILE/URL`、`_check_deep`、`deep_pass`、锚定 grep 都能证明「内容写对了、链接解析得了、目录映射一致」，**不能证明站点能构建或能渲染**。全站 `zola build` 的 v1.4.6 阻塞（`_v146_stubs.mjs` 把 HTML 注释写进 YAML front matter）已随 lead-1 的撤回移走，但**构建通过与否需重跑确认**。
- **迁移指南的 134 / 158 两个数字目前无法从仓内重算。** `tools/_v153_diff_control.json` 存的是 1.4.5 基线（`provenance.baseVer: "1.4.5"`），不是 1.4.7；重跑 `--control` 会覆盖它。数字按 worker 当时的实测保留，**可复现性存疑**。
- **en 侧 0 个类页面。** 6 845 个英文生成页已全部撤回；英文侧只有 6 个结构页，类页面一篇没有。这是真实缺口，不是缺陷。
- **§2.2 的溯源白名单是人工维护的**，若后续新增手写页，必须同步更新 `tools/_v153_census.mjs` 的 `HANDWRITTEN_*` 数组，否则新页会被判成生成。
- **反虚构门禁只扫 ```csharp 代码块，散文里的裸类型名一个都不查** —— 结构页/桶索引恰好是它的盲区。本轮结构页的虚构是 worker 手工比对源码查出来的，不是门禁查出来的。
- **`popToSiteRoot` 负结果已存档**：旧三版（1.3.0 / 1.3.15 / 1.4.5）共 149 条跨版本链接，**0 处欠 pop**，不需要开缺口清单。

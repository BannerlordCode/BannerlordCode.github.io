## 概述

`CampaignObjectManager` 是战役层的**对象总账本**：游戏里每一个「战役对象」——聚落、移动部队、英雄、家族、王国——都在这里按类型分表登记。它通过 `Campaign.Current.CampaignObjectManager` 暴露，是 mod 遍历战役世界最权威的入口。

它的存储结构是**两层**的：第一层按对象大类分表（英雄、家族、王国、部队、聚落）；第二层把部队按 `PartyComponent` 语义再拆出九张视图表——商队、巡逻队、民兵、驻军、匪徒、村民、领主、自定义，以及一张「还没有 `PartyComponent`」的兜底表。英雄也按状态拆成 `AliveHeroes` 与 `DeadOrDisabledHeroes` 两张表。`Factions` 不是独立对象表，而是「家族 + 王国」的并集视图。

类共 998 行，其中约 200 行是存档系统自动生成的样板（`AutoGeneratedInstanceCollectObjects` 及配套的 static 访问器）。mod 对它的读远多于写：绝大多数 mod 通过它遍历对象、按 StringId 或条件查找对象；写操作（注册新部队/英雄/家族/王国）则通过 internal 方法完成，mod 一般不直接调。

## 心智模型

**它是「战役对象的总账本」，不是「对象工厂」，也不是「数据库」。**

- **它管「登记与查找」**：每个对象在哪张表里、按什么条件找、StringId 怎么保证唯一——这些是它的职责。
- **它不管「对象行为」**：部队怎么移动是 `MobileParty` 的事，英雄怎么战斗是 `Hero` 的事。账本只回答「谁在哪、怎么找」。
- **它不管「对象创建语义」**：`AddMobileParty` / `AddHero` / `AddClan` / `AddKingdom` 这些 internal 方法负责分配 `MBGUID`（带类型 ID）并登记，但「什么时候该创建」由战役逻辑决定。
- **它不管「加载时序」的细节**：加载分两阶段——`PreAfterLoad` 让每个对象先恢复引用，`AfterLoad` 再标记 `IsReady = true` 并跑后置逻辑。这是存档框架的约定，不是它自己的设计。

**为什么部队有九张表**：`MobileParty` 的「类型」由 `PartyComponent` 决定（`IsBandit` / `IsCaravan` / `IsLordParty` 等只是组件类型的缓存标志）。把部队按组件语义预先分表，可以让「遍历所有匪徒」「遍历所有领主队伍」这类高频查询变成 O(1) 的表选择，而不是全表扫描后过滤。

**三个常见误用**。一是**用 `Find<T>` 时 T 传子类**：`FindFirst` / `FindAll` / `Find` 都用 `typeof(T) == campaignObjectType.ObjectClass` 精确匹配，传子类查不到。二是**把 `Factions` 当独立集合遍历后试图增删**：它是视图，不是可写表。三是**在 `AfterLoad` 之前读对象**：加载早期对象 `IsReady` 还是 false，引用可能未恢复。

## 怎么用

### 怎么拿到

```csharp
CampaignObjectManager manager = Campaign.Current.CampaignObjectManager;
```

### 典型用法

```csharp
// 遍历所有聚落
foreach (Settlement settlement in manager.Settlements) { /* ... */ }

// 遍历所有匪徒部队
foreach (MobileParty bandit in manager.BanditParties) { /* ... */ }

// 按 StringId 精确查找
Hero hero = manager.Find<Hero>("hero_1");

// 按条件查找
MBReadOnlyList<MobileParty> lords = manager.FindAll<MobileParty>(p => p.IsLordParty);

// 生成一个不冲突的 StringId
string newId = manager.FindNextUniqueStringId<Hero>("hero_custom");
```

查找走泛型三件套：`Find<T>`（`CampaignObjectManager.cs:620`）按 StringId 精确查，`FindFirst<T>`（`CampaignObjectManager.cs:574`）取第一个匹配，`FindAll<T>`（`CampaignObjectManager.cs:591`）收集全部匹配。

### 坑

- **`Find<T>` 的类型参数要精确**。`FindFirst` / `FindAll` / `Find` 内部用 `typeof(T) == campaignObjectType.ObjectClass` 判断该查哪张表，`Find<MobileParty>` 不会返回 `Hero`，反过来也一样。
- **`FindNextUniqueStringId<T>` 是「探测」不是「保留」**。它只返回一个当前不冲突的 ID（在已有最大后缀 +1），并不占位；真正注册时由 `CampaignObjectType<T>.FindNextUniqueStringId` 再算一次。
- **`Settlements` 是 `MBReadOnlyList`**。它直接包住了 `MBObjectManager` 的对象表，不要在遍历时增删。
- **`PartiesWithoutPartyComponent` 是兜底表**。新建但还没设 `PartyComponent` 的部队会落在这里；`BeforePartyComponentChanged` / `AfterPartyComponentChanged` 会在组件变化时把部队在九张表之间搬移。

## 真实示例

```csharp
// 一个 CampaignBehavior：定期把「离玩家太近的匪徒」标记为敌对
public class BanditWatchBehavior : CampaignBehaviorBase
{
    public override void RegisterEvents()
    {
        CampaignEvents.HourlyTickParty.AddNonSerializedListener(this, this.OnHourlyTick);
    }

    private void OnHourlyTick(MobileParty party)
    {
        if (!party.IsBandit) return;
        CampaignObjectManager manager = Campaign.Current.CampaignObjectManager;
        foreach (MobileParty bandit in manager.BanditParties)
        {
            if (!bandit.IsActive) continue;
            float dist = Campaign.Current.Models.MapDistanceModel
                .GetDistance(party, bandit);
            if (dist < 10f)
                bandit.SetMoveEngageParty(party, MobileParty.NavigationType.All);
        }
    }
}
```

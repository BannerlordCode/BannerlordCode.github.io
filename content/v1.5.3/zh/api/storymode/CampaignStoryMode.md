# CampaignStoryMode

**Namespace:** StoryMode
**Module:** StoryMode
**Type:** `public class CampaignStoryMode : Campaign`
**Base:** `Campaign`（TaleWorlds.CampaignSystem）
**Source:** `bannerlord-1.5.3/StoryMode/CampaignStoryMode.cs`

## 概述

`CampaignStoryMode` 不是一个普通的行为类，而是**整个「主线战役」游戏类型的定义**。`SandBoxGameManager` 平时用 `SandBoxCampaign` 当 GameType，走沙盒流程；一旦玩家从「New Campaign」开局，换成 `new CampaignStoryMode(...)`，这个类型就接管了整个战役的生命周期。它自己代码极短（不到 90 行），只做四件事：持有一个可存档的 [StoryModeManager](../StoryModeManager)、把 [TrainingField](../TrainingField) 注册进 `MBObjectManager`、在加载状态机的两个特定节点插入自己的初始化、最后把自己加进存档的对象引用图。它不含任何剧本逻辑——剧本全在被它持有的 `StoryModeManager` 里。

## 心智模型

它插在引擎的两层之间：上层是 `Game.GameType`（谁在驱动这个战役），下层是 `Campaign` 基类（引擎已经写好的通用战役）。谁想知道「当前跑的是不是主线战役」，唯一可靠的判断就是 `game.GameType is CampaignStoryMode`——[StoryModeSubModule](../StoryModeSubModule) 的 `InitializeGameStarter` 和 `OnGameEnd` 都是这么写的。反过来，[StoryModeManager.Current](../StoryModeManager) 也是靠把 `Game.Current.GameType` 向下转型成 `CampaignStoryMode` 来拿自己。

生命周期顺序：

1. `new CampaignStoryMode(CampaignGameMode.Campaign, new AdvancedStartOptionsData())` 被交给 `MBGameManager.StartNewGame`，构造函数里立刻 `new StoryModeManager()`——注意此时 `MainStoryLine` 已经建好，但英雄还没建。
2. 存档对象注册阶段：`BeforeRegisterTypes` 把 `TrainingField` 这个 `SettlementComponent` 类型登记进 `MBObjectManager`，XML 里的 `tutorial_training_field` 才能被反序列化成带背景网格的组件。
3. `DoLoadingForGameType` 走到 `InitializeFirstStep` 且状态真的前进时，调用 `StoryMode.InitializeStoryModeObjects()`——此刻才创建 [StoryModeHeroes](../StoryModeHeroes) 和 [StoryModeBannerEffects](../StoryModeBannerEffects)，因为它们要读 `Campaign.Current.CampaignObjectManager`。
4. 走到 `LoadVisualsThirdState` 时，把 `tutorial_training_field` 的地图实体塞进 `MapSceneWrapper`，让练武场在地图上有实体可点。
5. 走到 `PostInitializeFourthState` 时 `OnSessionLaunched()`，把龙旗 `ItemObject` 从 ObjectManager 取出来缓存进主线。
6. 存档写入时，`AutoGeneratedInstanceCollectObjects` 把 `StoryMode` 加进引用图；`[SaveableProperty(9999)]` 负责序列化。

**坑**：`InitializeFirstStep` 分支上带了 `nextState != gameTypeLoadingState` 的判断——加载失败或状态不前进时初始化**不会执行**，此时任何 `StoryModeHeroes.ImperialMentor` 都会 NRE。另外 `StoryMode` 属性是 `private set`，外部无法替换；战役结束也不置空，唯一的清理在 [StoryModeManager.Destroy()](../StoryModeManager) 间接调用的 `StoryModeData.OnGameEnd()`。

## 怎么用

### 怎么拿到它

`public class CampaignStoryMode : Campaign` 声明在 `bannerlord-1.5.3/StoryMode/CampaignStoryMode.cs:14`，全文 86 行。**不要自己 new**：它由战役创建流程作为 `Game.GameType` 造出来。取用的唯一正规途径是 `Game.Current.GameType as CampaignStoryMode`，而这条路径在 [StoryModeManager](../StoryModeManager) 内部已经封装好了：`StoryModeManager.Current` 就是 `((Game.Current).GameType as CampaignStoryMode)?.StoryMode`（`StoryModeManager.cs:36`→`:39`→`:42`）。

构造顺序决定了所有取用时机。构造函数（`:23`）第一句就是 `this.StoryMode = new StoryModeManager()`（`:26`），所以 `Story` 节点在战役对象建好的那一刻就存在；`StoryModeManager` 构造函数又会 `new MainStoryLine()`（`StoryModeManager.cs:71`）。

注册点：`BeforeRegisterTypes`（`:28`）里 `objectManager.RegisterType<TrainingField>("TrainingField", "TrainingFields", 1U, true, false)`（`:33`）——[TrainingField](../TrainingField) 能被反序列化出来全靠这一行。

三个阶段回调按 `GameTypeLoadingStates` 顺序触发：

| 状态 | 动作 | 位置 |
| --- | --- | --- |
| `InitializeFirstStep` | `StoryMode.InitializeStoryModeObjects()`，建剧情英雄与旗帜特效 | `:40`→`:42` |
| `LoadVisualsThirdState` | 把 `tutorial_training_field` 加进地图场景 | `:44`→`:46` |
| `PostInitializeFourthState` | `OnSessionLaunched()` → `StoryMode.MainStoryLine.OnSessionLaunched()` | `:55`→`:57`→`:64` |

`Story` 属性带 `[SaveableProperty(9999)]`（`:19`），存档时它作为战役的一个成员被收集（`AutoGeneratedStaticCollectObjectsCampaignStoryMode`，`:68`→`:77`）。

### 典型用法

```csharp
// 推荐：走封装，不要自己转型
if (StoryModeManager.Current == null) { Debug.Print("不是主线战役"); return; }
MainStoryLine story = StoryModeManager.Current.MainStoryLine;
Debug.Print("已完成=" + story.IsCompleted + ", 第一阶段=" + (story.FirstPhase != null));

// 需要 Campaign 专有成员时才直接转型（RegisterType 只在这里发生）
CampaignStoryMode mode = (CampaignStoryMode)Game.Current.GameType;
TrainingField training = null;
foreach (Settlement s in Settlement.All)
{
    if (s.SettlementComponent is TrainingField f) { training = f; break; }  // 能取到即说明 :33 生效
}
Debug.Print("主线战役类型=" + mode.GetType().Name + ", 练武场=" + (training != null));
```

### 最容易踩的坑

在 `InitializeFirstStep` 之前去碰 `StoryMode.StoryModeHeroes`。`StoryModeManager.InitializeStoryModeObjects()` 直到 `GameTypeLoadingStates.InitializeFirstStep` 才被调（`:42`），在那之前 `StoryModeHeroes` 和 `StoryModeBannerEffects` 两个属性都是 null。mod 里早挂的 campaign 行为若在自己的 `RegisterEvents` 里就 `AddNonSerializedListener(StoryModeHeroes.ElderBrother.XxxEvent, ...)`，读档瞬间就 NRE。判据很简单：**能拿到 `MainStoryLine` 不等于能拿到 `StoryModeHeroes`。**

## 主要成员

- `StoryMode StoryMode { get; private set; }`：故事模式状态根节点，带 `[SaveableProperty(9999)]`。战役运行期任何地方要拿主线/事件/剧情英雄都从它进，不要自己 new。
- `CampaignStoryMode(CampaignGameMode gameMode, AdvancedStartOptionsData startOptions)`：构造函数。第一个参数决定游戏模式（主线固定传 `CampaignGameMode.Campaign`），第二个是开局选项。构造函数体内只做 `new StoryModeManager()`。
- `protected override void BeforeRegisterTypes(MBObjectManager objectManager)`：调 `base` 后注册 `TrainingField`（id 字符串 `"TrainingField"`，集合名 `"TrainingFields"`）。自有 SettlementComponent 类型必须在这里登记，否则读档时 MBObjectManager 不认识这个 type。
- `protected override void DoLoadingForGameType(GameTypeLoadingStates gameTypeLoadingState, out GameTypeLoadingStates nextState)`：三个钩子都集中在这里。`InitializeFirstStep` → 初始化剧情对象；`LoadVisualsThirdState` → 往 MapScene 加练武场实体；`PostInitializeFourthState` → 会话启动。每个分支都有对应的状态推进条件判断。
- `private void OnSessionLaunched()`：转发给 `StoryMode.MainStoryLine.OnSessionLaunched()`，缓存 `DragonBanner`。

## 使用示例

```csharp
// 开一局主线战役：StoryMode.View 里的 StoryModeViewSubModule 就是这么做的
MBGameManager.StartNewGame(new SandBoxGameManager(
    () => new CampaignStoryMode(CampaignGameMode.Campaign, new AdvancedStartOptionsData())));

// 在任意战役回调里判断「是不是主线战役」，并取到主线状态
public override void OnDailyTickEvent(DailyTickEvent dayTickEvent)
{
    CampaignStoryMode storyCampaign = Game.Current.GameType as CampaignStoryMode;
    if (storyCampaign == null)
    {
        return; // 沙盒战役或还在主菜单，直接跳过
    }

    MainStoryLine line = storyCampaign.StoryMode.MainStoryLine;
    if (line.TutorialPhase.IsCompleted)
    {
        Debug.Print("教学阶段已结束，当前阵营：" + line.MainStoryLineSide);
    }
}
```

## 风险与边界

- **不能自己 new 一个 Campaign 用**：`CampaignStoryMode` 是 `GameType`，只能在 `MBGameManager.StartNewGame` 的工厂委托里创建。把它当 GameType 之外的东西用没有意义。
- **存档强绑定**：`StoryMode` 是 `[SaveableProperty]`，对应的类型注册在 [SaveableStoryModeTypeDefiner](../SaveableStoryModeTypeDefiner) 里 id=1。跳过那个 definer，读一个主线存档就会在 `Campaign` 成员解析处失败。
- **加载顺序敏感**：剧情英雄在 `InitializeFirstStep` 之后才存在。在更早的钩子（如 `OnGameStart` 的模型注册阶段）访问 `StoryModeHeroes.*` 一定 NRE。
- **`StoryMode` 永不为 null 但可能半初始化**：属性只在构造函数赋值，之后没人清空；`StoryModeHeroes` / `StoryModeBannerEffects` 则在初始化前确实是 null。

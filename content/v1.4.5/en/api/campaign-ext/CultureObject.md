# CultureObject

**Namespace:** `TaleWorlds.CampaignSystem`  
**Module:** `TaleWorlds.CampaignSystem`  
**Type:** `public sealed class CultureObject : BasicCultureObject`  
**Base:** `BasicCultureObject`  
**File:** `TaleWorlds.CampaignSystem/CultureObject.cs`

## Overview

`CultureObject` holds **all the static data for one cultural faction** in the campaign world: which troops it fields (`BasicTroop` / militia), which civilian and artisan NPCs spawn in towns, which clan and hero name pools it uses, what its primary banner color is, which policies it defaults to when a kingdom is founded, and which `PartyTemplateObject` the lords / caravans / patrols use. `Clan`, `Kingdom`, `Settlement`, and `CharacterObject` each keep only a reference to a `CultureObject`; at runtime, almost every "culture-related" appearance (troops, colors, naming) is read from this shared object. It is a globally unique, read-only configuration deserialized from the `SPCultures` XML, and nearly every mod that deals with "faction-distinct visuals and units" has to interact with it.

## Mental Model

Treat `CultureObject` as **"a faction's household registry plus an armory config table"**, not as an object that acts on its own:

- It does not participate in ticks and holds no logic; it is purely a **data container** that other systems read.
- Each culture is deserialized once from `SPCultures` XML by `MBObjectManager` during campaign initialization, then shared globally as a singleton. You usually should **not `new` a `CultureObject`**; instead obtain an existing instance through `Clan.Culture`, `Kingdom.Culture`, `Settlement.Culture`, `CharacterObject.Culture`, or `MBObjectManager`.
- It sits in the **data / configuration layer** (it belongs to the `TaleWorlds.CampaignSystem` object system, inheriting `BasicCultureObject` from `TaleWorlds.Core`), not the behavior layer (`CampaignBehavior`) nor the model layer (`Model`). If you want to "change a faction's behavior", modify the `Clan` / `Kingdom` that references it or the corresponding `Behavior` / `Model`, rather than rewriting this shared configuration.
- **When to use:** when you need to read a faction's troops, colors, name tables, or equipment, or when you build recruitment, naming, banner, or rebel-spawn logic around culture.
- **When not to use:** when you want to change which faction a clan / kingdom actually belongs to, change `Clan.Culture` (which is writable) or go through the kingdom-creation flow, instead of copying / creating a new `CultureObject`; when you want to change "how a unit performs in a particular battle", change `CharacterObject` or equipment, not the culture's global template (that would affect every unit of that culture).
- **Dependencies:** it is loaded by `MBObjectManager` and collected for save references; it is read by `NameGenerator` for name tables; and it is reverse-referenced by the various `PartyTemplateObject` / `CharacterObject` / `ItemObject` / `FeatObject` / `PolicyObject` types.
- **Failure mode:** many systems directly dereference `culture.DefaultPartyTemplate`, `culture.BasicTroop`, `culture.MaleNameList`, and so on; a culture missing those references will throw a `NullReferenceException` in the relevant systems (party generation, tournaments, naming) at runtime. Most fields on a culture are `private set`; only `MilitiaBonus` / `ProsperityBonus` are writable.

## Dependencies

### Upstream (who creates / owns / saves)

- [MBObjectManager](../MBObjectManager/) — deserializes all `CultureObject`s from `SPCultures` XML during campaign initialization, and collects their referenced `CharacterObject` / `PartyTemplateObject` / `ItemObject` etc. through `AutoGeneratedInstanceCollectObjects` on every save. **This is the save point for culture objects.**
- [BasicCultureObject](../../core-extra/BasicCultureObject/) — the base class, providing identity and appearance fields such as `Name`, `IsMainCulture`, `IsBandit`, `Color` / `Color2`, `ClothAlternativeColor*`, `BackgroundColor*` / `ForegroundColor*`, `Banner`, and `EncounterBackgroundMesh`.
- [TextObject](../../localization/TextObject/) — `Name`, `MaleNameList`, `FemaleNameList`, `ClanNameList`, and `EncyclopediaText` are all `TextObject`.
- [MBReadOnlyList](../../core-extra/MBReadOnlyList/) / [Banner](../../core-extra/Banner/) — most collections and the banner type come from these two low-level types.

### Downstream (who consumes this configuration)

- [Clan](../../campaign/Clan/) — `Clan.Culture` (`{ get; set; }`) decides the clan's troops, clan name, and banner color; it is writable and can switch a clan's faction at runtime.
- [Kingdom](../../campaign/Kingdom/) — `Kingdom.Culture` (`{ get; private set; }`) decides the kingdom's troops and banner, read-only from outside.
- [Settlement](../../campaign/Settlement/) — `Settlement.Culture` (`public CultureObject Culture;`) decides the civilian / artisan NPC templates and militia troops in the settlement.
- [CharacterObject](../../campaign/CharacterObject/) — `CharacterObject.Culture` (`public new CultureObject Culture`) decides the character's default equipment rosters and faction.
- [NameGenerator](../../campaign/NameGenerator) — reads `MaleNameList` / `FemaleNameList` / `ClanNameList` when generating hero / clan names.
- [FeatObject](../../campaign/FeatObject) / [PolicyObject](../../campaign/PolicyObject) / [PartyTemplateObject](../../campaign/PartyTemplateObject) / [ItemObject](../../core/ItemObject/) — the culture's feats, default policies, various party templates, and reward items.

### Behavior / Model (real call sites)

- [CampaignBehaviorBase](../CampaignBehaviorBase/) — most campaign `Behavior`s iterate all cultures through `MBObjectManager.Instance.GetObjectTypeList<CultureObject>()`.
- [RebellionsCampaignBehavior](../../campaign/RebellionsCampaignBehavior) — the rebellion / rebel logic iterates cultures to pick `RebelliousHeroTemplates`.
- [GovernorCampaignBehavior](../../campaign/GovernorCampaignBehavior) and [KingdomCreationModel](../../campaign/KingdomCreationModel) — when the player founds a kingdom, `KingdomCreationModel.GetAvailablePlayerKingdomCultures()` exposes the selectable culture list.

### Save point

Culture objects are held by `MBObjectManager`; `Clan` / `Kingdom` / `Settlement` / `CharacterObject` store their reference to a culture as an **id string**, which `MBObjectManager` resolves back to the same instance when loading. Changing or deleting a culture's id will make the reference unresolvable on load (yielding `null`), and downstream dereferences will then crash — this is the main save-corruption risk.

## Risks

- **Changing id / deleting a culture = corrupt save:** `Clan.Culture`, `Kingdom.Culture`, `Settlement.Culture`, `CharacterObject.Culture` all store the culture reference into the save as a string id. If your added culture id does not match an already-saved reference, or you changed a vanilla culture's id, `MBObjectManager` resolves it to `null` on load, and then lord party generation, naming, and banners will throw on dereference. Use a stable, unique id in your mod XML and keep it backward compatible.
- **Do not write read-only template fields directly:** `BasicTroop`, `DefaultPartyTemplate`, `Color`, `MaleNameList`, etc. are `private set`, and assigning them from outside is rejected by the compiler; forcing it through deserialization or reflection would affect **every** clan / settlement / unit of that culture, and would not be naturally restored by the save. For "custom units", change the specific `CharacterObject` or `PartyTemplateObject`.
- **A culture missing templates crashes at runtime:** many systems directly dereference `culture.DefaultPartyTemplate` / `culture.BasicTroop` / `culture.MilitiaPartyTemplate`. A self-made culture must fill in these references, otherwise lord parties, militia, and tournament generation will `NullReferenceException`.
- **`MilitiaBonus` / `ProsperityBonus` are writable but have global side effects:** these are the only two writable properties on `CultureObject`. Changing them during the campaign immediately affects the militia / prosperity bonus of every settlement of that culture; they are not a normal "balance tweak" entry point, so confirm that this is the exact scope you want before changing them.
- **Name tables may be empty:** `NameGenerator` already guards internally with `IsEmpty()`, but if you read `MaleNameList` / `FemaleNameList` directly and assume non-empty, you may get no name for some special cultures (such as `neutral_culture`).

## Key Members

### Identity and appearance (inherited from `BasicCultureObject`)

- `Name` (`TextObject`, read-only) — the culture's display name (e.g. "Sturgia"). Both `ToString()` and `GetName()` return it directly.
- `IsMainCulture` (`bool`, read-only) — whether this is a playable main culture; `KingdomCreationModel.GetAvailablePlayerKingdomCultures()` usually returns only cultures where `IsMainCulture == true`.
- `IsBandit` (`bool`, read-only) — whether this is a bandit culture (e.g. mountain bandits, sea raiders).
- `CanHaveSettlement` (`bool`, read-only) — whether this culture can own a settlement.
- `Color` / `Color2` (`uint`, read-only) — the faction's primary and secondary colors (ARGB hex, the "faction color"). `Clan` / `Kingdom` banner and map color block read from here.
- `ClothAlternativeColor` / `ClothAlternativeColor2` (`uint`, read-only) — cloth alternative colors.
- `BackgroundColor1` / `BackgroundColor2` / `ForegroundColor1` / `ForegroundColor2` (`uint`, read-only) — banner background / foreground colors.
- `Banner` (`Banner`, read-only) — the culture's default faction banner.
- `EncounterBackgroundMesh` (`string`, read-write) — the field-encounter background mesh name.

### Basic troops and militia (`CharacterObject`)

- `BasicTroop` (`CharacterObject`, read-only) — the culture's **tier-1 recruit** template, the start of the recruitment chain. Clan / town recruitment starts upgrading from here.
- `EliteBasicTroop` (`CharacterObject`, read-only) — the elite version of the basic troop.
- `MeleeMilitiaTroop` / `RangedMilitiaTroop` / `MeleeEliteMilitiaTroop` / `RangedEliteMilitiaTroop` (`CharacterObject`, read-only) — the settlement militia and elite militia templates, used by `MilitiaPartyTemplate` and village militia generation.
- Bandit templates `BanditChief` / `BanditRaider` / `BanditBandit` / `BanditBoss` (`CharacterObject`, read-only) — the units at each tier of that bandit culture; `BanditBossPartyTemplate` corresponds to `BanditBoss`'s party template.

In the read example below (see "Typical Usage Examples"), use `culture.BasicTroop` to get the recruitment start; do not guess troops by id yourself.

### Town / civilian / artisan NPC templates (`CharacterObject`)

The following fields are a set of **civilian and functional-NPC templates that spawn in settlements belonging to this culture**, usually used by `Settlement` / `Town` / `Village` and by the workshop and quest systems:

`TournamentMaster`, `Villager`, `CaravanMaster`, `CaravanGuard`, `PrisonGuard`, `Guard`, `Blacksmith`, `Weaponsmith`, `Townswoman` (and its `Infant` / `Child` / `Teenager` variants), `Townsman` (with `Infant` / `Child` / `Teenager`), `VillageWoman`, `Villager` (with `MaleChild` / `MaleTeenager` / `FemaleChild` / `FemaleTeenager`), `RansomBroker`, `GangleaderBodyguard`, `MerchantNotary` / `ArtisanNotary` / `PreacherNotary` / `RuralNotableNotary`, `ShopWorker`, `Tavernkeeper`, `TavernGamehost`, `Musician`, `TavernWench`, `Armorer`, `HorseMerchant`, `Barber`, `Merchant`, `Beggar` / `FemaleBeggar`, `FemaleDancer`, `Shipwright`, `MilitiaVeteranArcher`, `GearDummy`.

These fields are all read-only `CharacterObject`s; they decide "what a culture's town looks like". When customizing a settlement's ecology, take templates from here rather than building a separate set.

### Name / lord / clan template collections

- `MaleNameList` / `FemaleNameList` (`MBReadOnlyList<TextObject>`, read-only) — the hero name pool; read by `NameGenerator.Current.GetNameListForCulture(culture, isFemale)` and by hero naming.
- `ClanNameList` (`MBReadOnlyList<TextObject>`, read-only) — the clan name pool; read by `NameGenerator.Current.GenerateClanName(culture, settlement)`.
- `NotableTemplates` / `LordTemplates` / `RebelliousHeroTemplates` (`MBReadOnlyList<CharacterObject>`, read-only) — the notable, lord, and rebel-hero template collections; rebel / clan generation picks from these.
- `BasicMercenaryTroops` (`MBReadOnlyList<CharacterObject>`, read-only) — the mercenary base units this culture can recruit.
- `TournamentTeamTemplatesForOneParticipant` / `ForTwoParticipant` / `ForFourParticipant` (`MBReadOnlyList<CharacterObject>`, read-only) — the tournament team templates (grouped by participant count).

### Equipment rosters (`MBEquipmentRoster`)

- `DefaultBattleEquipmentRoster` — the culture's units' default battle equipment.
- `DefaultCivilianEquipmentRoster` — the civilian default equipment.
- `DefaultStealthEquipmentRoster` — stealth equipment (read by `CharacterObject`'s equipment-selection logic).
- `DuelPresetEquipmentRoster` — the duel preset equipment.
- `MarriageBrideEquipmentRoster` — the wedding bride equipment.

### Party templates (`PartyTemplateObject`)

- `DefaultPartyTemplate` (`PartyTemplateObject`, read-only) — **the most critical template**: lord parties / clan troop generation dereferences it to decide composition. When creating or replacing a culture, make sure it is non-null.
- `VillagerPartyTemplate` / `FishingPartyTemplate` / `MilitiaPartyTemplate` / `RebelsPartyTemplate` — villager, fishing, militia, and rebel party templates.
- `BanditBossPartyTemplate` / `VassalRewardTroopsPartyTemplate` — bandit boss party and vassal-reward troop template.
- `SettlementPatrolPartyTemplateWeak` / `Moderate` / `Strong` / `Naval` — the weak / moderate / strong / naval settlement patrol templates.
- `CaravanPartyTemplates` / `EliteCaravanPartyTemplates` (`MBReadOnlyList<PartyTemplateObject>`) — the normal and elite caravan template collections.

### Feats / policies / values / misc

- `Traits` (`CultureTrait[]`, read-only) — the culture's culture-trait array; check with `HasTrait`.
- `CultureFeats` (`MBReadOnlyList<FeatObject>`, read-only) — the culture-feat collection; read with `HasFeat` / `GetCulturalFeats`.
- `DefaultPolicyList` (`MBReadOnlyList<PolicyObject>`, read-only) — the policy set adopted by default when founding a kingdom.
- `PossibleClanBannerIconsIDs` (`MBReadOnlyList<int>`, read-only) — the list of banner-icon ids usable by the culture's clans.
- `MilitiaBonus` / `ProsperityBonus` (`int`, **read-write**) — militia / prosperity bonus; the only two writable properties in the whole class.
- `NavalFactor` (`float`, read-only) — naval weight, affecting naval-related logic.
- `BoardGame` (`BoardGameType` enum, read-only) — the culture's board-game type (`None` / `Seega` / `Puluc` / `Konane` / `MuTorere` / `Tablut` / `BaghChal`).
- `StartingPoint` (`CampaignVec2`, read-only) — the campaign start-point coordinates.
- `EncyclopediaText` (`TextObject`, read-only) — the encyclopedia entry description text.
- `DefaultCharacterCreationBodyProperty` (`MBBodyProperty`, read-only) — the default body shape at character creation.
- `AvailableShipHulls` (`MBReadOnlyList<ShipHull>`, read-only) — the available ship-hull collection (naval).
- `VassalRewardItems` / `BannerBearerReplacementWeapons` (`MBReadOnlyList<ItemObject>`, read-only) — the vassal-reward items and banner-bearer replacement weapons collections.

### Methods

#### `public bool HasTrait(CultureTrait trait)`
Checks whether the culture has a given `CultureTrait`.

```csharp
CultureObject culture = Clan.PlayerClan.Culture;
if (culture.Traits != null && culture.Traits.Length > 0)
{
    CultureTrait first = culture.Traits[0];
    if (culture.HasTrait(first)) // 判断该文化是否具备某个 CultureTrait
    {
        // 针对该特性做阵营加成或事件分支
    }
}
```

#### `public bool HasFeat(FeatObject feat)`
Checks whether the culture contains a given `FeatObject` (feat, e.g. "Forest Adaptation" / "Desert Adaptation").

```csharp
CultureObject culture = Settlement.CurrentSettlement.Culture;
foreach (FeatObject feat in culture.CultureFeats)
{
    if (culture.HasFeat(feat) && feat.IsPositive)
    {
        // 读取 feat 的战斗/地图修正（EffectBonus / IncrementType）
    }
}
```

#### `public IEnumerable<FeatObject> GetCulturalFeats(Func<FeatObject, bool> predicate = null)`
Returns the culture feats, optionally with a filter delegate. With no argument, returns all.

```csharp
var positiveFeats = Clan.PlayerClan.Culture.GetCulturalFeats(f => f.IsPositive);
```

#### `public override TextObject GetName()`
Returns the culture's display name (`base.Name`). `ToString()` also returns the string form of `Name`.

```csharp
TextObject name = Clan.PlayerClan.Culture.GetName();
InformationManager.DisplayMessage(new InformationMessage(name.ToString()));
```

#### `public override void Deserialize(MBObjectManager objectManager, XmlNode node)`
Internal method: deserializes all fields and child collections from an `SPCultures` XML node. **Not a mod-facing API** — called by the object system during the loading phase; calling it manually would corrupt the already-initialized global state.

## Typical Usage Examples

### Example 1: Get the player clan's culture and read its troops and colors

```csharp
// 真实获取路径：Clan.Culture（可写属性）
CultureObject playerCulture = Clan.PlayerClan.Culture;
if (playerCulture != null)
{
    CharacterObject recruit = playerCulture.BasicTroop;          // 一级新兵模板
    uint primaryColor = playerCulture.Color;                     // 阵营主色（ARGB）
    bool isBandit = playerCulture.IsBandit;                      // 是否强盗文化
    InformationManager.DisplayMessage(new InformationMessage(
        $"{playerCulture.Name}：基础兵种 {recruit.Name}，主色 #{primaryColor:X8}"));
}
```

### Example 2: Iterate all cultures, pick the main cultures, and generate clan names from their name tables

```csharp
// 真实获取路径：MBObjectManager.Instance.GetObjectTypeList<CultureObject>()
foreach (CultureObject culture in MBObjectManager.Instance.GetObjectTypeList<CultureObject>())
{
    if (!culture.IsMainCulture)
    {
        continue; // 只处理可游玩的主文化
    }

    // NameGenerator 读取该文化的 ClanNameList / MaleNameList / FemaleNameList
    TextObject clanName = NameGenerator.Current.GenerateClanName(culture, null);
    CharacterObject elite = culture.EliteBasicTroop;

    // 例如：为自定义招募逻辑收集每个文化的精英兵种
    if (elite != null)
    {
        // 加入你的招募池 ...
    }
}
```

### Example 3: Get a culture by id / from other objects (summary of common acquisition paths)

```csharp
// 1) 按字符串 id 直接取（原版文化 id 如 "empire"、"aserai"、"vlandia"、"sturgia"、"khuzait"、"battania"、"nord"、"neutral_culture"）
CultureObject empire = MBObjectManager.Instance.GetObject<CultureObject>("empire");

// 2) 从据点取
CultureObject settlementCulture = Settlement.CurrentSettlement.Culture;

// 3) 从王国取（Kingdom.Culture 只读）
CultureObject kingdomCulture = Clan.PlayerClan.Kingdom?.Culture;

// 4) 从英雄/人物取（CharacterObject.Culture 是 public new CultureObject Culture）
CultureObject heroCulture = Hero.MainHero.CharacterObject.Culture;
```

## Cross-Version Notes

- **v1.3.0:** this class already existed, but lacked `SettlementPatrolPartyTemplateNaval`, `NotableTemplates`, `RebelliousHeroTemplates`, `LordTemplates`, `TournamentTeamTemplatesForOneParticipant` / `ForTwoParticipant` / `ForFourParticipant`, and `BasicMercenaryTroops`; these were added in **v1.3.15**.
- **v1.3.15 (this page):** namespace remains `TaleWorlds.CampaignSystem`; the field set is essentially the same as in 1.4.5. Semantics follow the authoritative 1.4.5 source.
- **v1.4.5:** no material difference from 1.3.15 for this class; `Clan.Culture` is still writable, `Kingdom.Culture` is still read-only.

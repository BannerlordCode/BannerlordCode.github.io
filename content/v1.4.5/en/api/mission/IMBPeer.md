## Mental Model

Think of it as **the roster table at the back of a room where each row has its own lamp**. `is_active` asks whether a lamp is lit, `get_average_ping_in_milliseconds` and `get_average_loss_percent` report the quality of one row's signal, and `set_team` and `set_controlled_agent` write what that row is doing. There is no "the roster" — every operation names a row by index.

Two boundaries follow, and both are easy to get wrong.

First, **several members are server-only, and the managed layer enforces that rather than the bridge.** `NetworkCommunicator.IsSynchronized` reads `MBAPI.IMBPeer.GetIsSynchronized(Index)` only `if (GameNetwork.IsServer)` (`NetworkCommunicator.cs:114-118`) and otherwise returns the cached `_isSynchronized`; its setter likewise calls `MBAPI.IMBPeer.SetIsSynchronized(Index, value)` only inside the same `GameNetwork.IsServer` branch (`:125`). So on a client the bridge is never asked, and you get a cached value. Reading `IsSynchronized` on a client tells you what the local cache holds, not what the server holds.

Second, **`IsConnectionActive` guards against a stale index before touching the bridge.** `NetworkCommunicator.cs:100-103` checks `if (GameNetwork.VirtualPlayers[Index] == VirtualPlayer)` before calling `MBAPI.IMBPeer.IsActive(Index)` (`:103`), and returns `false` otherwise. That guard is not decoration: `NetworkCommunicator.Index` (`:69`) is read from `VirtualPlayer.Index`, and a peer that has already been removed from the session can leave an index that no longer names a live row. The bridge would be asked about a slot that is not there.

**A typical use.** A mod that ranks peers by connection quality reads the two measurement members through `NetworkCommunicator`:

```csharp
VirtualPlayer[] players = GameNetwork.VirtualPlayers;
if (players != null)
{
    foreach (VirtualPlayer player in players)
    {

        NetworkCommunicator peer = communicator as NetworkCommunicator;

        {

        }

```

**What to watch out for.** Caching a peer index and spending it later. Every member here takes a bare `int`, and the index is a session slot that is reused: `MissionPeer.cs:343` writes `MBAPI.IMBPeer.SetTeam(base.Peer.Index, -1)` when a peer leaves, freeing team assignment but leaving the index itself to the session. The consequence is that a stored index can come to name a different peer, and because `SetTeam` and `SetControlledAgent` write through silently, your cached value now points at somebody else — a peer joins mid-battle and inherits the team or agent your earlier code assigned. Hold the `NetworkCommunicator` reference, not the integer.

## Examples

Read the connection quality of every active peer, skipping anything not live:

```csharp
using TaleWorlds.MountAndBlade;

foreach (NetworkCommunicator peer in GameNetwork.VirtualPeers)
{
    if (!peer.IsConnectionActive)
    {
        continue;
    }
    Debug.Print("peer " + peer.UserName + " ping " + peer.AveragePingInMilliseconds
        + "ms loss " + peer.AverageLossPercent + "%", 0);
```

## Risks and crash boundaries

- **A mod assembly cannot call this interface.** `internal interface IMBPeer` (`IMBPeer.cs:7`), `internal static IMBPeer IMBPeer;` (`MBAPI.cs:32`), `InternalsVisibleTo` limited to three TaleWorlds assemblies (`TaleWorlds.MountAndBlade/Properties/AssemblyInfo.cs:8-10`).
- **Every member takes a bare peer index.** No pointer, no validity token. **A cached index can name a different peer after a reconnect**, and `SetTeam` / `SetControlledAgent` then assign the wrong one — `MissionPeer.cs:343` already writes `-1` for a departed peer, so the slot is in active use.
- **Two members are server-gated in the managed layer, not the bridge.** `GetIsSynchronized` / `SetIsSynchronized` are only called under `if (GameNetwork.IsServer)` (`NetworkCommunicator.cs:114-118`, `:125`). **On a client, `IsSynchronized` reports a local cache, not the server's answer.**
- **`IsActive` is guarded by a virtual-player identity check** (`NetworkCommunicator.cs:100-103`). Querying the bridge without that guard asks native about a slot that may no longer exist.
- **`EndModuleEvent` takes no index** (`IMBPeer.cs:34`). **An unbalanced `Begin`/`End` pair corrupts the message stream**, and because `End` closes whatever is open, a stray call closes someone else's event.
- **`-1` is the unassign sentinel for `SetTeam`** (`MissionPeer.cs:343`) and is not validated. Passing it for a team means "no team", not "team index minus one".
- **`GetPort` returns `ushort`.** Ports are 16-bit on this boundary; a value above 65535 is unrepresentable.
- **`GetReversedHost` is not `GetHost`.** Two separate members (`IMBPeer.cs:45`, `:48`); treating the reversed one as an address is a misread.
- **Per-peer relevance flags, not global.** `set_relevant_game_options` (`:42-43`) records what one client wants; a mod that assumes a global mute is wrong.
- **Not a save participant.** Peer state is session-scoped and rebuilt on join.

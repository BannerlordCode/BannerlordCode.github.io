## Mental Model

Think of it as the **catalogue index card rack behind a lending desk**, not the catalogue itself. `IMBActionSet` only ever hands back integers and strings that identify rows; the thing a modder actually holds is the `MBActionSet` wrapper that wraps one of those integers. That wrapper guards its own rows: `MBActionSet.GetName()` checks `if (!IsValid) { return "Invalid"; }` before it ever calls through (`MBActionSet.cs:38-41`), so an index of `-1` yields the literal string `"Invalid"` rather than a native call.

The consequence that follows: an out-of-range index on this interface does not throw. `GetSkeletonName(Index)` at `MBActionSet.cs:47` is a straight pass-through with no validity guard, so the only thing standing between a stale index and a native read is whatever the caller checked. The boundary condition is that **validity lives in the wrapper, not the bridge** — if you cache an `int` from `GetIndexWithID` and use it later without re-checking, the wrapper's guard no longer covers you.

## How to use

**How to obtain it.** You cannot. The interface is `internal` (`IMBActionSet.cs:6`), its `MBAPI` field is `internal static` (`MBAPI.cs:7`), and `TaleWorlds.MountAndBlade` only grants `InternalsVisibleTo` to `TaleWorlds.MountAndBlade.AutoGenerated`, `TaleWorlds.MountAndBlade.Multiplayer` and `TaleWorlds.Generator.Bannerlord` (`TaleWorlds.MountAndBlade/Properties/AssemblyInfo.cs:8-10`). A mod assembly referencing these symbols fails to compile. Reach the native registry through the public `MBActionSet` wrapper instead, whose `public static MBActionSet GetActionSetWithIndex(int)` and name lookup are the sanctioned door.

**A typical use.** A mod resolves an action set by the id string it authored in XML, then asks the wrapper for the skeleton that action set drives — the same call chain the engine itself makes at `MBActionSet.cs:72` and `:47`:

```csharp
using TaleWorlds.MountAndBlade;

MBActionSet actionSet = MBActionSet.GetActionSet("human_soldier");
if (actionSet.IsValid)
{
    string skeletonName = actionSet.GetSkeletonName();
    Debug.Print("action set drives skeleton " + skeletonName, 0);
}
```

**What to watch out for.** `GetNameWithIndex` and `GetSkeletonName` sit behind the `IsValid` guard, but the pass-through members further down the wrapper are not. The single most common mistake is caching the raw `int` from a name lookup and reusing it after the action set registry has been rebuilt; the consequence is a native read against an index that no longer names an action set, with no managed exception to catch it.

## Examples

Resolve an action set from the id used in module XML and read its display name, going through the wrapper that owns validity:

```csharp
using TaleWorlds.MountAndBlade;

MBActionSet actionSet = MBActionSet.GetActionSetWithIndex("human_soldier");
if (!actionSet.IsValid)
{
    Debug.Print("action set id not found in the registry", 0);
    return;
}
Debug.Print("resolved action set: " + actionSet.GetName(), 0);
Debug.Print("drives skeleton: " + actionSet.GetSkeletonName(), 0);
```

Enumerate the registry safely by asking for its own size instead of assuming a fixed number of rows:

```csharp
using TaleWorlds.MountAndBlade;

for (int i = 0; i < MBActionSet.GetNumberOfActionSets(); i++)
{
    MBActionSet actionSet = MBActionSet.GetActionSetWithIndex(i);
    Debug.Print("row " + i + " = " + actionSet.GetName(), 0);
}
```

Ask whether a specific clip exists before committing a transition, and read its duration:

```csharp
using TaleWorlds.MountAndBlade;

MBActionSet actionSet = MBActionSet.GetActionSet("human_soldier");
ActionIndexCache clip = ActionIndexCache.Create("act.notched_debug_sword_idle");
if (actionSet.IsValid && MBActionSet.CheckActionAnimationClipExists(actionSet, in clip))
{
    float seconds = MBActionSet.GetActionAnimationDuration(actionSet, in clip);
    Debug.Print("clip lasts " + seconds + "s", 0);
}
```

## Risks and crash boundaries

- **A mod assembly cannot call this interface.** `internal` interface plus `internal static MBAPI` field plus `InternalsVisibleTo` limited to three TaleWorlds assemblies (`TaleWorlds.MountAndBlade/Properties/AssemblyInfo.cs:8-10`). Attempts fail at compile time, which is the one friendly failure this layer offers.
- **There is no exception channel.** Every member returns a value. An unknown id or an out-of-range index surfaces as a default or as native garbage, not as a catchable `ArgumentOutOfRangeException`.
- **Validity is the wrapper's job.** `MBActionSet.GetName()` guards `IsValid` (`MBActionSet.cs:38-41`); `GetSkeletonName` (`MBActionSet.cs:47`) and the members below it do not.
- **`sbyte` bone indices cap at 127.** `GetBoneIndexWithId` returns `sbyte`, so a resolved index that would not fit arrives as a negative number and is indistinguishable from a miss.
- **`GetNumberOfMonsterUsageSets` is not a subrange of the action sets.** Using it as a loop bound over the main registry skips rows; using the action-set count to walk monster usage sets overruns.
- **`GetAnimationName` is duplicated across two bridges.** `IMBActionSet.cs:24` and `IMBAnimation.cs:48` both declare it against different native symbols. Verify which wrapper you are calling.
- **Not a save participant.** No `[Serializable]`, no sync surface; it is a stateless call-through.

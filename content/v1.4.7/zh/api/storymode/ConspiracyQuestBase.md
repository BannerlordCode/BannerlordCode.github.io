# ConspiracyQuestBase

**命名空间：** `StoryMode.Quests.SecondPhase`
**模块：** `StoryMode`
**类型：** `public abstract class ConspiracyQuestBase : QuestBase`
**基类：** `TaleWorlds.CampaignSystem.QuestBase`
**源文件：** `bannerlord-1.4.7/StoryMode/Quests/SecondPhase/ConspiracyQuestBase.cs`（声明见第 13 行）

## 概述

主线剧情进入第二阶段后，帝国与反帝国两条线都会持续产生「阴谋」事件，这个类就是这些事件任务的公共父类。它比 `StoryModeQuestBase` 厚得多：构造时把倒计时写死为 21 天并在构造体内再次刷新截止时间；启动时往地图上推一条通知、把导师的警告和任务目标写进任务日志；成功完成时反过来削减第二阶段的「阴谋强度」；同时它订阅了 `StoryModeEvents.OnConspiracyActivatedEvent`——一旦阴谋真正爆发，所有还挂着的阴谋任务会**直接以失败收场**。

它还暴露四个抽象属性，强制每个具体阴谋任务自己提供四段文本 / 数值：侧边通知文本、导师开场文本、任务日志开场文本、以及完成时应该扣掉多少阴谋强度。它另外提供一个受保护的工具方法，用来按等级把掠夺者模板里的兵种分摊进一支队伍。

## 心智模型

把它想成「阴谋事件的合同模板」：它规定了阴谋任务**必须**长什么样（四段文本 + 一个强度数值），并替子类办好了三件机械的事——计时、开日志、结算强度。子类要做的就是回答四个抽象属性，再加自己的推进逻辑。

状态从哪来？三个来源：一是 `QuestBase` 的任务状态机（ID、发布者、截止时间、日志）；二是全局的 `StoryModeManager.Current.MainStoryLine`，`Mentor` 和「完成时扣多少强度」都依赖它的当前阶段；三是 `StoryModeEvents` 的事件总线，它决定了任务会不会被阴谋爆发打断。

谁改它？游戏本体改。`OnConspiracyActivated` 是私有的，外部无法调用；能触发它的只有 `StoryModeEvents.OnConspiracyActivatedEvent` 这条事件。也就是说**任务的失败时机由剧情阶段决定，不由任务自己决定**。

子类要覆写什么？最少覆写四个抽象属性；需要自定义推进就在 `OnStartQuest` / `OnCompleteWithSuccess` 里加逻辑，**并且先调 `base`**——基类实现负责推通知、写日志、扣强度，跳过它就等于任务完成了但阴谋强度没降。它不负责：具体阴谋的对话与地图事件注册、子任务的创建与串联、以及自己的存档字段（它没有新增持久字段，`AutoGeneratedInstanceCollectObjects` 只是原样转发给基类）。

## 怎么用

它同样是 abstract（`ConspiracyQuestBase.cs:13`），只能派生。派生时最省事的路径是：构造函数只接一个 `Hero`，把任务 ID 和发布者转给基类，剩下四段文本用表达式体属性写死。

1. **倒计时是写死的 21 天**。构造函数接收 `(string questId, Hero questGiver)` 两个参数，内部固定用 `CampaignTime.DaysFromNow(21f)` 并立即调用 `ChangeQuestDueTime` 刷新截止时间，你无法通过参数改变它。见 `ConspiracyQuestBase.cs:66`。
2. **`IsRemainingTimeHidden` 返回 `false`**（`ConspiracyQuestBase.cs:47`），这与主线任务基类 `StoryModeQuestBase` 的 `true` 正好相反：阴谋任务是**显示倒计时**的，玩家能看见剩余天数，因为它是限时威胁。
3. **失败会被事件自动触发**。`RegisterEvents` 把 `OnConspiracyActivatedEvent` 挂到私有的 `OnConspiracyActivated` 上（`ConspiracyQuestBase.cs:73`），后者直接 `CompleteQuestWithFail(null)`。这意味着任务中途阴谋爆发时，你的 `OnCompleteWithSuccess` 永远不会跑，强度也不会下降——不要把关键结算逻辑只写在成功路径里。
4. **`Mentor` 随剧情阵营切换**。这个属性读的是 `StoryModeManager.Current.MainStoryLine.IsOnImperialQuestLine`（`ConspiracyQuestBase.cs:33`），帝国线给帝国导师、反帝国线给反帝国导师。任务开始时缓存它、任务结束时再用，中间玩家换了阵营就会拿到两个不同的导师。

## 真实示例

派生一个阴谋任务：四个抽象属性用表达式体一次写全，然后在成功钩子里调用基类实现，让阴谋强度真的下降。`base.OnCompleteWithSuccess()` 与 `base.AddLog(...)` 都是这里真实可用的调用。

```csharp
using System.Collections.Generic;
using StoryMode.Quests.SecondPhase;
using TaleWorlds.CampaignSystem;
using TaleWorlds.CampaignSystem.Party;
using TaleWorlds.Core;
using TaleWorlds.Localization;

public class MyConspiracyQuest : ConspiracyQuestBase
{
    public MyConspiracyQuest(Hero questGiver)
        : base("my_mod_conspiracy_quest", questGiver) // 倒计时固定 21 天
    {
    }

    public override TextObject SideNotificationText => new TextObject("{=my_mod_side}A conspiracy stirs nearby.");

    public override TextObject StartMessageLogFromMentor =>
        new TextObject("{=my_mod_mentor}Your mentor warns you of the coming plot.");

    public override TextObject StartLog => new TextObject("{=my_mod_start}Break up the conspiracy.");

    public override float ConspiracyStrengthDecreaseAmount => 0.5f;

    protected override void OnCompleteWithSuccess()
    {
        base.OnCompleteWithSuccess(); // 关键：真正扣减阴谋强度的是基类
        base.AddLog(this.Mentor.Name, false);
    }

    // 需要往队伍里塞掠夺者时，直接用基类给的按等级分摊工具
    protected void FillRaiderParty(PartyTemplateObject raiderTemplate, PartyBase party)
    {
        this.DistributeConspiracyRaiderTroopsByLevel(raiderTemplate, party, 40);
    }
}
```

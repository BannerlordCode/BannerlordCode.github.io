### 0.3 「门禁全绿」这句话本身也需要门禁

每一次 lead 说「全部通过」而没有同时说明「通过了哪几类、漏了哪几类」，那个「全部」就只是修辞，不是证据。

**本树的门禁覆盖：** 链接可解析性（双口径互证）、类页深度（`deep_pass`）、虚构 API（反虚构门禁 + 阳性对照）、
陈旧页数计数、承诺式措辞。

**本树的门禁不覆盖：**
| 未覆盖类别 | 为何发现不了 |
|---|---|
| 纯文本里的路径陈述 | 不是链接，断链审计结构上无法看见 |
| 页面是否完整列出「该列的内容」 | 列表可以少列而不违反任何现有检查（§0.1(1)） |
| 页面声称的规模是否仍然成立 | 只要页面不自相矛盾，「过时」与「错」在检查上不可区分（§20） |
| 域是否从树里消失 | 「那个域从来就没出现过」在任何计数口径下都成立（§0.2） |

> **「数字会过时」是一类缺陷，「链接会断」是另一类。前者没有任何自动门禁能发现，因为它的失败模式就是「所有检查都通过」。**

因此本包的每一个「0 断链 / 0 陈旧计数 / 0 虚构」都必须连同本节一起读：**它证明的是所列类别的通过，不证明树是完整的。**

## 3. 本轮最有价值的发现：链接层级系统性缺陷

### 3.1 缺陷本体

生成器把**跨桶**链接少写了一层 `../`：

```
错：content/v1.4.7/zh/api/activitysystem/Activity.md -> ../campaign/FastModeSubModule/
对：                                                            ../../campaign/FastModeSubModule/
```

根因：本仓库链接按 **route-relative** 解析，每个页面 route 即自身目录，一个 `..` 只弹一层。从 `/api/<bucket>/<Name>/` 弹一次只回到 `/api/<bucket>/`，因此单个 `../` **只能到达同桶兄弟**。

### 3.2 证据链（不靠猜）

**(a) 权威门禁的比值指纹**

```
FILES=1803  TOTAL_LINKS=11533  BROKEN_LINKS=11513
RESOLVE_OK_FILE=9330   RESOLVE_OK_URL=20   RESOLVE_OK_BOTH=0
RESOLVE_NEITHER=2183
```

`RESOLVE_OK_FILE=9330` 对 `RESOLVE_OK_URL=20` 是**链接层级**缺陷的指纹：链接在磁盘上存在，但解析不成 route。若只看 `BROKEN_LINKS` 总数，时序问题与真实缺陷会被搅在一起。

**(b) 与已发布树对照实测约定**（不靠记忆、不靠 AGENTS.md）

| 树 | 2+ `../` 跨桶链接 | 单 `../` 却带桶名的链接 |
|---|---|---|
| 已发布 v1.4.5 zh/api | **5,215** | 203 |
| 新生成 v1.4.7 zh/api | **40** | **4,135** |

样例（已发布树，正确）：`campaign/AccompanyingCharacter.md -> ../../campaign-ext/CampaignMissionComponent`

### 3.3 按成因分类（boss 要求：分类而非总数）

| 类 | 数量 | 判定 |
|---|---|---|
| A `../` 指向尚未落盘的桶/区块 `_index.md` | 1,802 | 时序，不动 |
| B 指向尚未写出的门面页 | ~372 | 时序，不动 |
| **C 跨桶链接少一层 `../`** | **~9,330** | **系统性缺陷，改生成器** |
| D `./` dot-slash 残留 | ~9 | 低优先 |

**A+B ≈ 2,174 为时序；C ≈ 9,330 为真实缺陷。** 按 boss 口径：不在产物页面上逐条手改（会被下一次生成覆盖），只改生成器，并加 route-relative 断言门禁。

## 4. lead-2 自身工具的两次自我修正（boss 要求原样记录）

> 这两条比任何数字都重要：**一个"看起来在工作"的校验器，如果解析口径错了，它会系统性地掩盖它本该发现的那一类缺陷。**

### 修正 1：filesystem-relative 掩盖了 9,330 条系统性缺陷

第一版 `tools/_v147_verify.mjs` 用 `resolve(dirname(fromFile), href)` + `fs.existsSync` 解析链接，报出 **2,186** 条断链——看上去问题不大。实际它把 C 类 **9,330 条全部掩盖**：因为错层级的链接**作为文件确实存在**，存在性检查必然通过。

改为 route-relative 解析后，harness 报 11,513 条，与 `audit-links.mjs` 的 11,513 **完全一致**。

> **教训：本仓库的 `fs.existsSync` 不是有效链接检查。** 任何针对该站点的校验器必须 route-relative 解析，否则系统性低报。

### 修正 2：原始 `./` 计数制造幻影缺陷

统计 `](./` 出现次数时，已发布树 5,963、新树 5,544，看似"新树也有问题"。实际上这些绝大多数位于**代码围栏内**，门禁会跳过。

> **教训：原始字符串计数不是缺陷判据，只有门禁的裁决算数。** 我差一点把一个幻影缺陷报上去。

### 修正 3：未校准的校验器报出 14,548 条幻影缺陷

收尾阶段我用一段临时脚本分类断链，得出「真实缺陷 14,548 条」，与 worker-11 自报的 0 条严重冲突。**先怀疑自己的工具**，把该解析器跑在**已知为 0 断链的已发布树**上：

| 解析器 | 已发布 v1.4.5 zh/api（31,779 条链接，应为 0） |
|---|---|
| 有 bug 的版本 | **5,999 断链** ← 明显错误 |
| 修正后的版本 | **0 断链** ← 校准通过 |

bug 是 `routeOf()` 先剥掉 `.md`，又对类型名多切了 3 个字符，把每条 route 都切坏。校准通过后，同一脚本在新树上的结论从 14,548 变为 **真实缺陷 67 条**，与独立路径一致。

> **教训：校验器必须先在已知良好的基线上校准，它的数字才可采信。** 这是同一条原则的第三次出现（§4.1 filesystem-relative、§4.2 原始计数、本条未校准）。已把校准步骤固化为 `tools/_v147_verify.mjs` 的常驻步骤。

### 修正 4（单位错配）：报「6 条坏链」，实际是 10 条链

worker-15 自报 `zh/api/engine/MBDebug.md` 有 **6 条**断链，我的独立 harness 全程报 **10 条**。两者看似矛盾，实际是**单位不同**：

| 单位 | 数值 | 含义 |
|---|---:|---|
| 行（LINES） | 6 | 缺陷**所在行数** |
| 链（LINKS） | 10 | 实际**链接条数**（5 个目标各被链两次） |

5 个目标：`../campaign-ext/MBObjectManager`、`../mission/Mission`、`../mission/Agent`、`../gui/ScreenManager`、`../core/MBSubModuleBase`。

**与本会话早前的 `md=44/24/1`（把子目录数当页数数）是同一族错误。**

> **教训：计数必须声明单位，否则两个都对不上的数字会互相「校准」成假的共识。** 当 worker 报 6 而我报 10 时，最省事的做法是认定「其中一个错了」并取其一；正确的做法是先问「这两个数在数什么」。单位错配的特征是：两个数在各自口径下完全正确，但它们**不是同一个量**——这类错误不产生异常值，不触发校准直觉，只制造一种「总有地方不对、但说不清哪里」的持续摩擦。本会话至少出现两次（`md=44/24/1`、lines vs links），且两次都是**双方都没错**，因此任何单方校验原理上无法发现它。

## 14. 第九次同型事件：检测器跑在一棵正在被重写的树上

前八次是**检测器写错了**（过窄 / 过宽 / 未校准 / 仪器制造现象 / 作用域错位 / 世代错位 / 语言作用域 / 最终产物未验证）。第九次是新的形态：**检测器没写错，被检测的对象在动。**

### 14.1 事件

我曾报告「en 树 CJK 残留 0」。该结论是**错的**，实测为 61 行（后来 55 行）。原因不是检测器有 bug，而是：**我采样的那一刻，worker-16 正把 architecture 页删掉又在恢复**，en 树处于中间态；我从一个正在被重写的树上取了一个瞬时快照，并把它当成事实报了出去。

原话保留：

> **我早前测 CJK=0 时，worker-16 正把 architecture 页删掉又在恢复，我采了一个瞬时态并当成事实报了出来。**

同一次会话里，worker-17 报「61 CJK，nav worker 的」，worker-16 报「CJK 0」。**三个人三个数，其中我是唯一一个既没核实别人、也没核实自己采样时机的。**

### 14.2 为什么它比前八次都危险

前八次里，检测器是坏的，于是数字错；错误是**可复现**的——重跑一次就暴露。这次的形态相反：

- 树在变
- 检测器没变
- 于是**数字看起来稳定**，甚至比真实值更「干净」

它不会产生异常值，不会触发任何校准直觉，也不会被「两个数字对不上」暴露出来——因为**根本没有第二个数字**。它看起来像一次干净的通过。

### 14.3 沉淀规则：静止性（rest state）

> **任何普查 / 审计在开跑前，必须先确认目标树处于静止状态。若树在动，结论只能标为「瞬时采样」，不得作为验收证据。**

这与「阳性对照」是**互补的两个轴**，缺一不可：

| 轴 | 回答的问题 | 缺了会怎样 |
|---|---|---|
| 阳性对照（positive control） | 检测器**能看见**问题吗 | 检测器坏了却报「干净」 |
| **静止性（rest state）** | 被检测的**对象没在动**吗 | 检测器完好、对象瞬态，数字稳定地错 |

前八次几乎全部由第一个轴拦下；第九次**只能**由第二个轴拦下。本次会话中我之所以最终抓到自己那次假阴性，靠的不是任何检测器改进，而是「en 树 CJK 与我引用的 worker-17 数字对不上」——**运气加上交叉引用，不是纪律**。规则化之后就不必再靠运气。

### 14.4 顺带：另一处同类静态性违规

同一会话里我还犯了等价的一种：worker-11 报告 zh 树重生成后的页数时，树仍在被写入；我把该数字写进证据包并据此评估撤回代价。撤回代价最终按 §12.2 用**自己独立重跑**的数字给出，未采信该瞬时数值。若无那一次独立重跑，撤回决策会建立在一个瞬时计数上。

### 19.2 保留下来的四条纪律

1. 校验器需要**校准**（在已知良好数据上报 0）**加阳性对照**（在已知不良数据上必须报非零）

3. 恢复操作必须**先等逐文件分类返回**，且**分类者与执行者是两个人**，且**恢复源本身需要体检**（检查点 = 未损坏的手写版，≠ 当前正确的版本）

## 20. 一次被撤回的裁决：把导航缺陷当成了清理

Boss 撤回了「那五个桶入链为 0，所以不必建索引页」这条裁决，并写下撤回理由。这条留在证据包里，是因为**它是一次推理错误，而不是一次执行失误**——比执行失误更难被发现。

### 20.1 错误是怎么发生的

裁决所依据的事实全部为真：
```
zh/api/localization/  inbound=0     en/api/localization/  inbound=0
zh/api/storymode/     inbound=0     en/api/storymode/     inbound=0
en/api/save-system/   inbound=0     （该目录不存在，其 3 页在 zh 侧）
```
五个目录都不存在，且没有任何页面指向它们。**由此得出的结论「读者不需要抵达一个不存在的桶」在事实上成立，在结论上却是错的。**

真正发生的事：`Localization` 与 `StoryMode` **原本被链到**；链被删掉时，**名字也从散文里一起消失了**。所以缺的不是「一条路」，是「一个事实」——读者失去了「这个 SDK 有这个域」的认知。

### 20.2 两句话的区别

| 说法 | 对不对 |
|---|---|
| 「桶的缺失本身是信息」 | ❌ 错。当一个域的**链接**被删、连**名字**也被删时，读者失去的是关于 SDK 构成的认知 |
| 「域从树里消失是缺陷；消失且无人提及是双重缺陷」 | ✅ 对 |

后半句是修正后的形式，也是本节要留下的那句。

### 20.3 为什么这条错误特别危险

它**看起来像清理**。一个刚做完大清扫、正在把 3,598 个生成页移出的人，会自然地把「这个目录不存在了」读成「这个域已经处理好了」。但撤回生成页与抹掉一个域的存在是两件事：前者减少噪音，后者减少信息。
**推论：撤回/清理类操作之后，必须重新核对「哪些东西原本被提到、现在一次也没被提到了」，而不是只核对「还有没有断链」。** 断链审计对本缺陷完全无感——它本来就是零。

### 20.4 正确处置

不建空索引页（那仍是一个「这里本该有页」的暗示），改为**在既有 hub 页的散文里点名该域**：它是什么、为什么值得写、现在为什么没有页面。已由 worker-38 完成并经 lead 复核（4 个 hub 页、两种语言、零新增链接）。

### 20.5 顺带留档：只修数字不修叙述

worker-34 把版本根的「1,795 个类页面」改成「42 篇正文 / 40 个目录索引」时，**拒绝到此为止**，补了一段说明「这是一棵小型手写树，其余表面记为缺口」。
它的理由成立：**只降低数字仍然给出错误印象，等于把一个谎言换成一个小谎言。** 数字是事实，叙述是读者对事实的解释，两层都要修。
